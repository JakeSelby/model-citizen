## Story

As the maintainer, I want a native acceptance case and a pre-registered long-session eval for the context reset, so that v0.16.0 does not ship an unproven change to every session.

## Context and value

A reset can lose state the handoff missed. The fallback snapshot covers it in design; only a measured run shows it in practice. This story supersedes #751, the one-week trial of an earlier auto-compact window, with a controlled comparison.

## Acceptance criteria

1. **Deterministic:** the AH-S363 to AH-S366 unit tests run in the Gate.
2. **Native acceptance:** `case_context_reset` in `scripts/native_acceptance.py` (the AH-SP020 setup made permanent) asserts compaction fired, the reseed marker reached the model, every checklist item completed in one invocation and no user turn was added; it passes on both Claude Code CLI qualification targets.
3. **Behavioural:** scenario `context-reset-continuity` in the `model-citizen-evals` pack, a multi-step build with three recorded decisions and a checklist sized to cross a lowered reset point (window 100k at 40%) twice; checkpoints: task store saved before each reset, zero recorded decisions re-asked, no completed item redone (judged from the diff and transcript), checklist completion, cost per completed item.
4. Arms: reset on, reset off (native default), and a second reset point (plan decision 2).
5. The pre-registration in `benchmarks/preregistrations/` fixes the floor before the run: a reset with no human turn in at least 9 of 10 runs, zero re-asked decisions, and completion no worse than the reset-off arm by more than 0.125.
6. The eval meets its floor before the v0.16.0 tag; if it fails, the release ships with the reset off by default.

## Design

### Approach

- Run in containers through `python3 scripts/cost_bench.py replay --tier long-session --pack <pack> --tag <commit> --pack-digest ... --spend-cap 100 --pre-registration ...`, with `HARNESS_HANDOFF_BLOCK=on` in the arm.

### Decisions and alternatives

- **The eval blocks the tag, with a $100 spend cap** (plan decision 4). Rejected: reporting after the release.
- **Supersedes #751.** Rejected: an uncontrolled one-week trial on the host profile.

### Do not implement

- Host-profile runs; every arm runs in a fresh container with exactly its named components.
