## Goal

The Studio needs a UX contract before any screen is built. Run `bmad-ux` to write a `DESIGN.md` (visual identity and design tokens) and an `EXPERIENCE.md` (information architecture, flows, states, interactions, accessibility and journeys) for the Studio, beside the product's existing UX specification.

It covers the six flows the epics build: open and orient (overview, selection, library, activity); tune in a draft (selection, settings, module text, a new or forked module); review, apply and roll back; run a suite or one test against a target, with the spend confirm; compare two runs and test a draft; and the first run. Each screen gets its loading, empty, error, stale and refused states, its keyboard path and its phone-width layout.

## Acceptance criteria

1. Given each story in epics #955 to #959, when it is read against the specification, then every screen and state it builds is specified.
2. Charts follow the dataviz skill (form, colour formula, interval display), and no figure is shown without its interval when one exists.
3. WCAG 2.2 AA is the floor, and the specification names the checks that prove it.
4. Design tokens are defined once, in `DESIGN.md`, for light and dark themes.

## Dev notes

Blocks every UI story in this milestone. Traces to FR-77.

The approved direction is Briefing with the Clear palette: an airy, light-first operational hub
whose AI assessment is opt-in and read-only, whose aggregates drill into immutable reports, and
whose mutations remain visibly separate from observations and generated suggestions. The same
contract defines a matching dark theme and a one-column phone-width layout.
