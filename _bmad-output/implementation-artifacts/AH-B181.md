# AH-B181 — fix(delegation): the designer role is pinned to the frontier tier

## Reproduction

1. Run `bin/harness generate` on `main` and read `claude/agents/designer.md` and
   `claude/agents/design-judge.md`.
2. Both carry `model: fable`, the Claude Code adapter's `frontier` class, because their contracts
   in `primitives/roles/` declare `tier: frontier`.
3. The tiered delegation stance says never `frontier`. An exploratory audit of 265 host sessions
   counted 467 subagents on that model, about 786 USD (counts only, not evidence).

## Root cause

- The two design roles declared `tier: frontier` as a deliberate exception, recorded only as an
  `allow` list in `primitives/constraints.json` and a sentence in the delegation-tiering skill
  [Source: primitives/constraints.json].
- Nothing at generation time checked the resolved model, so the stance and the generated roles
  disagreed without any test failing [Source: lib/harness_core/catalog.py#role_binding].

## Acceptance criteria

1. **Given** the shipped roles, **when** they are generated for either adapter, **then** none
   resolves to the frontier model, and `designer` and `design-judge` resolve to `strong` at high
   effort.
2. **Given** a role declaring `tier: frontier`, or a class its adapter leaves unmapped so that it
   resolves upward, **when** the generation test runs, **then** it fails naming the role.
3. **Given** a frontier role whose contract records `frontier_exception: <reason>`, **when** the
   test and the stance constraint run, **then** it passes; an empty reason, or the field on a
   non-frontier role, is refused by `role_contract`.
4. **Given** the stance, the delegation-tiering skill and `docs/primitive-authoring.md`, **when**
   read, **then** they name the same rule: never `frontier` without a documented exception.
5. **Given** the change, **when** `bin/harness generate --check` runs, **then** it is clean.

## Design

- Move both roles to `tier: strong`; their adapter effort stays `high`.
- Replace the constraint's `allow` list with a `frontier_exception` frontmatter field, read by
  `excluded_roles` for a `tier: frontier` condition and validated in `role_contract`, so the
  exception is documented on the role that takes it. `allow` remains supported for other rules.
- State `class: strong, effort: high` on the `design-judge` row of `balanced.json`; the role is
  `posture: fixed`, so the resolver strips both and behaviour does not change.
- Rejected: keeping the design roles as a documented exception. The stance forbids the class and
  the audit spend gave no measured reason to keep it.
- Must not change: the spawn hook's refusal of a frontier model by request, and role effort.

## Regression test

`tests/test_role_frontier_tier.py`: no shipped role or generated Claude agent resolves to the
frontier model; a synthetic frontier role, and a strong role on an adapter that unmaps `strong`,
fail; a documented exception passes; an empty or misplaced exception is refused. Five of its
eight tests fail on the base commit.
