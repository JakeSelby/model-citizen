## Story

As a harness maintainer, I want observing the bare arm to change no model request, so that the bare arm stays a fair baseline for every comparison with the harness.

## Context and value

The harness is judged against bare Claude Code, so observing the bare arm must not change what its model sees. AD-23 gives observation its own entry point: observation only, failing open and silent, and the only harness component installed in the bare arm. The spine requires a test that compares every model request in each arm with observation on and off, not only the first.

Depends on #789. Traces to AD-23 and PRD §9 (v0.14.0).

## Acceptance criteria

1. Given a stub model endpoint that returns fixed responses, when a bare-arm task runs with observation on and then off, then every model request is byte-identical between the two runs.
2. Given the same comparison in the harness arm, then observation adds nothing to any request beyond what the harness profile itself adds.
3. Given an observation failure, such as an unwritable ledger or a crashed recorder, when a session runs, then the session proceeds unchanged and nothing reaches the model or the user.
4. Given a bare-arm install, when its files are listed, then the observation entry point is the only harness component present.

## Design

### Approach

- `lib/harness_core/observer.py` is the recorder: standard library only, importing nothing from
  the harness. For each hook event it appends one row to
  `~/.local/state/agent-harness/observation.jsonl` (`HARNESS_HOME` honoured): `ts`, `runtime`,
  `event`, `session_id`, `tool_name` where the event has one, `schema_version` 1 and
  `profile_fingerprint`. It prints nothing, returns no decision and exits 0 on every input. Any
  failure goes to `observation.errors.jsonl` beside the ledger, and a failure to write that is
  dropped.
- `adapters/<runtime>/observe.py` is the registered entry point beside `hook.py`, a shim like
  `hook.py` that calls the recorder and never the dispatcher. The catalog declares it a
  runtime-private adapter file.
- `lib/harness_core/observation.py` holds `registration(root, runtime)`, built from
  `lifecycle.EVENTS`, the table `hook.py` is registered from, and `bare_install(dest, runtime)`,
  which writes a bare arm's whole footprint: the recorder copied alone as `observe.py`, and the
  runtime's hook file registering it with `--profile bare`.
- `tests/test_zero_footprint_observation.py` drives a scripted session against a local stub model
  that returns fixed responses. It raises every event the arm installs and folds each hook's output
  the way Claude Code does, then compares every model request with observation on and off.

### Decisions and alternatives

- **Rows carry identifiers, never bodies:** no prompt, tool input or tool result is recorded, so
  the ledger raises none of the retention questions a message archive would.
- **The bare arm's rows say `bare`:** as the replay rows do since #789, a row from the arm that
  loads no profile is attributable to the empty profile, not unattributed. A harness row resolves
  the checkout's `posture.fingerprint()`, and stamps null when that is absent or fails.
- **A simulated runtime, not a live client:** the test runs each installed hook as a subprocess, as
  Claude Code does, and applies its folding rules: context and plain stdout on session start and
  prompt submit reach the next request, a `systemMessage` reaches the user, a deny, a rewrite or a
  block changes the conversation. A live Claude Code against the stub would need a signed-in
  client in CI. A control test registers a recorder that emits one line of context and proves the
  comparison then fails.
- **The recorder is a separate file from its registration:** the bare install copies the recorder
  alone, so it cannot import the event table; the registration reads the table at install time.

### Do not implement

- Registering the entry point in `harness sync`, doctor or uninstall. Doing so adds a process to
  every hook event on every user's machine and asks Codex users to re-accept hook trust; it is a
  separate change.
- Wiring the bare install into `scripts/cost_bench.py` replay arms.
- Moving the SessionEnd usage-log call out of the dispatcher.
- Per-module attribution (#790) and adherence events (#792).
- Clearing AD-23's status tag in the architecture spine.

## Dev notes

### Bound decisions and requirements

- AD-23: observation runs through its own entry point beside `hook.py`, outside the dispatcher,
  reads its events from AD-7's table, fails open and silent, and is the only harness component in
  the bare arm; the zero-footprint test compares every model request, per arm.
- AD-7: the event table in `lifecycle.py` is the one declaration of which events each runtime
  raises.
- AD-22: the profile fingerprint a row carries.
- AD-11: the ledger is additive, with a schema version on every row.

### Files to touch

- `lib/harness_core/observer.py`: the recorder.
- `lib/harness_core/observation.py`: registration and the bare install.
- `adapters/claude-code/observe.py`, `adapters/codex/observe.py`: the entry points.
- `compatibility/catalog.json`: `observe.py` in `runtime_files`.
- `docs/compatibility.md`: the runtime-private file list.
- `tests/test_zero_footprint_observation.py`, `changelog.d/791.added.md`.

### Testing

`tests/test_zero_footprint_observation.py`: `BareArmTests` (AC 1, and every installed event
raised), `HarnessArmTests` (AC 2, with the profile shown to reach the model so the comparison is
not vacuous), `FailureTests` and `RecorderTests` (AC 3), `InstallTests` (AC 4), and
`RegistrationTests` (events read from the one table).
