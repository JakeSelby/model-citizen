# AH-D011 — Decide whether a red smoke tier blocks the qualification round, as FR-52 says

## Context

FR-52 says a release "must pass a model-free smoke tier before any native case runs", and its first
testable consequence is "A smoke-tier failure stops the round before any model turn is spent"
[Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-52: One qualification round per release].
The smoke tier shipped under #334 in PR #581 as an advisory CI job instead. It is deliberately absent
from the ruleset's required checks, and `docs/releasing.md` says it is advisory "until it is decided
whether a red tier may block a freeze" ([#688](https://github.com/JakeSelby/agent-harness/issues/688);
[Source: _bmad-output/implementation-artifacts/AH-S124.md]).

**Current behaviour at HEAD.**
- `.github/workflows/ci.yml` has a `smoke` job that runs `python3 scripts/smoke_tier.py --skip credentials`
  [Source: .github/workflows/ci.yml].
- `docs/releasing.md` tells the operator to run the tier before the round and again at the freeze
  commit, and calls it advisory [Source: docs/releasing.md#Freeze the qualification branch].
- `scripts/qualification_round.py` runs the smoke tier once, records `passed`, `failed` or `timed out`,
  and then runs every target regardless. A failed tier only makes the round exit non-zero at the end
  [Source: scripts/qualification_round.py#run_round]. The runbook states the runner "decides nothing
  and stops for nothing" [Source: docs/qualification-runbook.md]. So at HEAD a red tier stops neither
  the CI merge nor the paid round.
- AH-S124 notes the job may go red for unrelated reasons, because some of its checks never ran in CI
  before [Source: _bmad-output/implementation-artifacts/AH-S124.md].

## Options

Recorded in the issue ([#688](https://github.com/JakeSelby/agent-harness/issues/688)):

1. **A red tier does not block the round.** The tier stays advisory, and FR-52's consequence is amended
   to say so.
2. **A red tier blocks, as a required check.** The `smoke` job joins the `main` ruleset's required
   checks.
3. **A red tier blocks, in the round runner.** `qualification_round.py` stops before any target runs
   when the tier fails.
4. **Both 2 and 3.**

The issue records no case for or against any option. [ASSUMPTION: option 3 alone matches FR-52's
wording most closely, because the consequence speaks of the round and of model turns, not of merges.]

## Decision

Decided by the owner on 2026-09-26: option 3, **a red tier blocks the round, in the round runner.**
`run_round` in `scripts/qualification_round.py` stops before any target runs when the tier fails, and
records why. No ruleset or required-check change: the CI `smoke` job stays outside the required
checks. This enforces what FR-52 already says, that the round passes the smoke tier before any native
case runs, so FR-52's consequence stands unchanged.

Terms of the build:
- A tier that fails or times out stops the round. `round.json` keeps the tier's result under `smoke`,
  adds `stopped`, the reason, and `not_run`, the targets it did not launch, and the command exits 1.
- `--skip-smoke` keeps its meaning, a tier already run green at this commit: the round records the
  tier as `skipped` and runs every target.
- Default taken: a tier that timed out blocks exactly as a failed one does, and no longer counts as a
  clean round, because FR-52 asks the round to pass the tier and a timed-out tier did not pass.

## Consequences

- The acceptance for this item: the decision is recorded here and in AH-S124, and either FR-52's text or
  the tier's enforcement changes so that the two agree
  ([#688](https://github.com/JakeSelby/agent-harness/issues/688)).
- AD-4's rule already reads "A model-free smoke tier runs before any native case", which holds at HEAD
  under every option; it does not say whether a failure stops the round
  [Source: _bmad-output/planning-artifacts/architecture-spines/architecture-agent-harness-2026-09-23/ARCHITECTURE-SPINE.md#AD-4: Evidence-backed compatibility [ADOPTED]].
- Option 3 or 4 changes `run_round`, which currently records the tier's result and continues, and needs
  a test that a failed tier runs no target. Option 2 or 4 changes the ruleset, which is a repository
  setting rather than a file in this tree.
- Option 1 amends FR-52 in the PRD, under FR-65's currency rule.
- Under the chosen option 3, FR-52's consequence text stands; its status line gains the runner's
  enforcement, and `docs/releasing.md` and `docs/qualification-runbook.md` no longer call the tier
  advisory or the runner one that stops for nothing.
