# AH-B104 — fix(remote-control): sessions a host starts never upload the files an agent sends

## Reproduction

1. Run a Remote Control host with `harness remote-control install`, then start a session from the
   iOS app.
2. Have the agent send any file with `SendUserFile`, from inside or outside the session's working
   directory.
3. The tool reports "not delivered: this session is not on a project thread, so it has nowhere to
   place a file", and the app shows the card greyed out; it does not open.

## Root cause

Claude Code 2.1.280 chooses an upload lane for `SendUserFile` from the session's surroundings: an
interactive terminal session with Remote Control on uploads, and so do cloud sessions and sessions
with `CLAUDE_CODE_BRIEF_UPLOAD` set. A session a `claude remote-control` host spawns matches none of
these, so the lane is `none`; without a project folder to place the file in, every attachment is
marked `upload_error` and the app has nothing to show. The upload itself, when a lane is chosen,
posts the file to the first-party file endpoint with the signed-in account's token, behind the
provider, privacy and organization-policy gates. [Source: Claude Code 2.1.280, the lane selector
and `uploadBriefAttachment`]

## Acceptance criteria

1. **Given** any folder the harness serves, **when** its launch agent is rendered, **then** its
   environment sets `CLAUDE_CODE_BRIEF_UPLOAD` to `1`.
2. **Given** a folder whose own `env` sets `CLAUDE_CODE_BRIEF_UPLOAD`, **when** its launch agent is
   rendered, **then** the folder's value wins, so `""` turns uploads off for that host.
3. **Given** a host running with the variable, **when** a session it starts sends a file, **then**
   the file opens in the iOS app.

## Design

`lib/harness_core/remote_control.py` adds `HOST_ENV` to every host's launchd environment, under the
folder's own `env`. The variable reaches each session the host spawns, as the one-host
experiment showed.

Rejected: a new `remote_control` configuration key, which would add a documented switch for an
undocumented variable when a folder's `env` already overrides it; asking you to start sessions
from a claude.ai project, which Claude Code's messages suggest gives a session a project folder to
place files in, but which the harness cannot set up.
The staging policy from #817 stays: it still serves a client that asks the session for a file that
was not uploaded, such as one past the upload size limit.

The fix must not change any other launch agent field or the heal agent.

## Regression test

`tests/test_remote_control.py::PlistTests::test_every_host_turns_on_uploads_for_the_files_its_sessions_send`
failed with `KeyError: 'CLAUDE_CODE_BRIEF_UPLOAD'` before the change and passes after it;
`test_a_folder_s_own_env_can_turn_uploads_off` pins the override.
