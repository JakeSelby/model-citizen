## Reproduction

1. A session in worktree `O` spawns a builder subagent, which creates its own worktree `W` and runs
   `harness intent claim lib/x.py` there. The claim records the session id, the runtime pid and `W`.
2. The builder edits `W/lib/x.py`. Its PreToolUse payload carries the parent's `session_id` and an
   `agent_id`, but `cwd` is `O`, because a subagent's shell resets to the parent's directory.
3. Observed on 2026-09-29: `intent-overlap` warns on the first edit and denies the second, naming
   the builder's own claim. Seven builders in one session hit it; the decision log holds the rows.

## Root cause

`own()` in `lib/harness_core/intents.py` requires the claim's worktree to equal `editor_root(cwd)`,
the worktree holding the payload's `cwd`. For a subagent that is the parent's worktree, never the
builder's, so the builder's own claim reads as a sibling's. The `cwd` rule was chosen in #856 so an
absolute path into a sibling's worktree cannot pass as the editor's own.

## Acceptance criteria

1. **Given** a subagent's claim in its own worktree, **when** it edits a claimed path there twice
   with its parent's `cwd`, **then** neither edit warns or denies and no row is logged.
2. **Given** another live session's claim on the path, **when** a subagent edits it, **then** the
   first edit warns and the second is denied.
3. **Given** two sibling builders of one session in different worktrees, **when** one edits in its
   own worktree a path the other claimed in its own, **then** it warns, then is denied, counted
   under the editing builder's worktree.
4. **Given** a payload without `agent_id`, **then** the `cwd` rule from #856 is unchanged.

## Design

- The hook passes `subagent=bool(event["agent_id"])` to `overlaps()` and `editor_root()`. For a
  subagent, the editor's worktree is the target's; otherwise it is still `cwd`'s. Ownership still
  needs the claim's session id or pid as well as its worktree.
- Signal: Claude Code documents `agent_id` as a common hook input field "present only when the hook
  fires inside a subagent call" (hooks reference, Common input fields), and `usage-feed.py`
  already relies on it to stay silent inside subagents. If a runtime omitted it, the behaviour
  falls back to today's, so the fix can fail only toward a spurious warning, never a missed one.
- Given up: a subagent that writes by absolute path into a sibling's worktree, under the same
  session, is not stopped by the sibling's claim there. The claim is written by the CLI, which
  never sees the payload's `agent_id`, so no recorded field ties a claim to one subagent.
- Rejected: always using the target's worktree, which would also drop the #856 protection for
  main-thread edits; recording `agent_id` in the claim, which the claiming shell cannot read.

## Regression test

`tests/test_intent_subagent_claims.py`: the self-claim, other-session, sibling, no-`agent_id` and
given-up cases. Against the unfixed code three of its five tests fail.
