# AH-B102 — sync misreads an aliased stance link as a user redirect when the variant changes

## Reproduction

1. In a throwaway home, run `bin/harness sync --adopt` from the checkout.
2. Replace `~/.claude/rules/harness-stances/voice.md` with a link to the same variant spelled through
   `<checkout>/claude/stances/voice/<variant>.md`, the spelling older syncs used.
3. Set `stances.voice` to another variant in the config and run `bin/harness sync`.

Observed: sync exits 2 with "voice.md was redirected after sync; preserving the user's link", the link
keeps its old variant, and `sync --adopt` exits 2 with the same result.

## Root cause

`claude/stances` is a symlink to `primitives/stances`, so every stance file has two spellings. The
journal records the canonical `primitives/stances/...` target. `ensure_link` first asks `_leads_to`,
which is alias-aware, whether the link already reaches the wanted target; after a variant change it
does not, so it falls through to the redirect check. That check compared the live link text with the
journaled `target` and `pending_from` as strings, so the alias spelling of the harness's own previous
target counted as a user redirect. The check returns before the `--adopt` branch, which is why adopt
could not recover it. [Source: bin/harness#ensure_link]

## Acceptance criteria

1. **Given** a managed stance link spelled through `claude/stances` that resolves to its journaled
   target, **when** the stance variant changes and sync runs, **then** sync exits 0, the link points
   at the new variant, and drift reports nothing.
2. **Given** a managed stance link the user re-pointed at a file outside the harness's stance
   sources, **when** the variant changes and sync runs, **then** sync reports the redirect, exits
   non-zero, and leaves the user's link untouched.

## Design

The redirect check uses `_leads_to` against the journaled `target` and `pending_from`, the same test
uninstall and drift already apply to managed links. A link that resolves to the file the harness
recorded is the harness's, whatever spelling reached it; anything else is still preserved.

Rejected: rewriting journaled targets or existing links to one spelling. It would fix only links the
migration sees and leave the comparison fragile for any other alias of the checkout.

## Regression test

`tests/test_harness.py`, `LinkAliasTests`:

- `test_changing_a_stance_relinks_a_link_spelled_through_the_alias` fails before the fix and passes
  after it.
- `test_changing_a_stance_preserves_a_real_redirect` guards the genuine-redirect case on both sides.
