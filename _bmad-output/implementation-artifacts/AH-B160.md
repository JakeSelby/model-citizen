# AH-B160 — fix(benchmarks): replay trials share a warm prompt cache, understating the harness arm's cost

## Reproduction

Run `scripts/cost_bench.py replay` with five reps on one task. In the 2026-10-02 pilot's saved streams the first assistant call of every rep read the 23.6k-token system prompt and tools from cache; rep 1 then wrote the rest of its first call (3.9k tokens bare, 14.4k harness) and reps 2 to 5 wrote nothing, reading all 27.5k (bare) or 38.0k (harness) from cache. The Cost-of-Pass ratio came out at 1.42 against about 1.66 with every session paying its own write.

## Root cause

Reps of one task and arm send an identical first call within the one-hour cache lifetime, and the prompt cache matches on a prefix, so a later rep reads the earlier rep's session segment (the first message after the system prompt: memory files, then the task prompt) instead of writing it. A real session writes its own. The bias is largest for the arm with the larger session segment, so it understates the harness arm's cost. [Source: scripts/cost_bench.py#_attempt]

## Acceptance criteria

1. **Given** two trials of one task and arm, **when** each launches, **then** each mounts a distinct nonce as the managed memory file `/etc/claude-code/CLAUDE.md`, so their session segments differ from its first token while the task prompt is identical.
2. **Given** a trial row, **when** it is written, **then** it records `cache_nonce` and `cache_basis: cold`.
3. **Given** saved rows, **when** `summarise` reports, **then** it states `cache basis: cold` only when every row carries a distinct nonce and `shared` otherwise, in text and as `cache_basis` in JSON.
4. **Given** a nonce file under a host path, **when** the launch is built, **then** it is refused like any other mount.

## Design

A per-trial nonce in a one-line managed memory file, mounted read-only per container. Claude Code loads the managed memory first, so the nonce opens the session segment; the system prompt and tools before it keep the cache a real session finds. Rejected: a nonce in the task prompt, which sits after the memory files and leaves the segment shared; `--append-system-prompt`, which would also re-write the system prompt and add the same cost to both arms, compressing the ratio; a cold-cache correction in `summarise`, which estimates rather than measures. Both arms get the file, so they still differ by image alone. The preflight launch keeps no nonce.

## Regression test

`tests/test_cost_bench_cold_cache.py`: two trials of one task and arm mount different nonce files with identical prompts; each arm of a rep gets its own; a nonce under a host path is refused; `summarise` states the basis in text and JSON.
