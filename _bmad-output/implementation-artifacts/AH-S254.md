## Story

As a harness maintainer, I want the static tier to price every counted file on its own and to name each file a change moved, so that a rule edit reads as that file's token and dollar delta rather than a moved total.

## Context and value

The static tier (FR-55) records one total for the always-loaded layer and the listings, so a rule change
reads as "the total moved" and CI can refuse growth only in aggregate. The cost side of a rule edit is
fully determined by its text and needs no model, which makes a per-file figure the cheapest tier of
testing rule permutations at cents per change.

Traces to FR-55. Parent: AH-E013.

## Acceptance criteria

1. **Given** a checkout, **when** `scripts/cost_bench.py static` runs, **then** its output carries a `files`
   map with each always-loaded rule, selected stance variant, output style and listed agent, skill and
   command description: its group, characters, estimated tokens, and USD per session start and per later
   turn for every model the totals are priced on.
2. **Given** that map, **when** it is summed, **then** characters equal the total exactly and tokens and
   dollars equal it within rounding, for this repository's committed figure too.
3. **Given** a seeded 200-token growth in one rule, **when** `static --check` runs, **then** its output names
   that file and its delta in tokens and dollars; **and when** `benchmarks/allow.json` records the new total,
   **then** the check passes and still names the file.
4. **Given** a file added or removed since the committed figure, **when** the check runs, **then** the line
   says so; **given** nothing moved, **then** it prints nothing.
5. **Given** a committed figure written before this change, **when** the check runs, **then** it says the
   baseline has no per-file figures and still gates the total.
6. `python3 bin/harness lint` is clean and the suite is green under `python3` and `/usr/bin/python3`.

## Design

### Approach

- `measure` builds a `files` map from the same rows `total` sums, keyed by repository path, and prices
  each file with the same `price` helper, now given the model table once rather than rereading it.
- `file_deltas` compares that map with the committed `benchmarks/static.json` and returns one line per
  file whose estimated tokens changed, largest move first, marking new and removed files. `--check`
  prints those lines to stdout before the growth gate, then the gate runs unchanged on the total.
- `schema_version` becomes 2, since the shape gained a map; `scopes` gains a `files` entry so the file
  alone says what the map covers.
- The committed figure is regenerated from the `v0.13.1` tag with the new code, so its totals are the
  release's own and only the `files` map and scope line are new.

### Decisions and alternatives

- **The gate stays on the total.** A per-file gate would refuse every rule edit until an allow entry
  named it; the issue asks for the delta to be visible, and the 5% budget stays the one refusal.
- **Deltas are priced on the model with the highest cache-read rate, named on each line.** One figure
  per line keeps CI output readable; the highest rate states the most a change costs per later turn.
  Every model per line was rejected as noise; a fixed model id would rot when the price table changes.
- **Per-file dollars for every priced model are written to the file**, so the map sums to the recorded
  totals model by model. The figure is written only at a release, so its length costs no review churn.
- **Regenerate the baseline from the tag, not from `main`.** Writing it from `main` would move the
  committed release figure mid-cycle and hide the growth since the release.

### Do not implement

- No per-file gate, and no change to the `allow.json` entry format.
- No change to the `harness lint` caps or to what the static tier counts.
- No live replay tier change.
