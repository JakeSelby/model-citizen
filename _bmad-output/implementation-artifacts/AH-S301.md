## Story

As a developer, I want to run a suite against my installed version, a release, a branch, a worktree or a draft in isolation, so that I compare versions and test drafts without touching my live harness.

## Context and value

Every run names its target, and the target's harness is built into a temporary home the way `cost_bench.py replay --tag` builds a tag, never into the live one. A target is the installed version, a release tag, a branch or commit, a managed worktree including its uncommitted work (snapshotted as a commit first), or a Studio draft at a checkpoint. A draft's configuration goes into the profile with it, so a stance change is what gets measured.

## Acceptance criteria

1. Given a draft target, then the run's profile carries the draft's modules and configuration, and the live home is unchanged, byte for byte.
2. Given a worktree with uncommitted changes, then the run records the snapshot commit it ran, and the worktree is left as it was.
3. Every run record carries the target's version, commit, draft and config digest.
4. Given a suite that does not support a target kind, then the catalog refuses the run before it starts.
