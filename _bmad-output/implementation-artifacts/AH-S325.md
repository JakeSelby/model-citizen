## Story

As a developer, I want to configure composition slots and Superpowers in Studio, so that the Studio supports the engines delivered in its milestone.

## Context and value

Deliver the Studio configuration changes with v0.17.0 Composable, using the same slot/adapter and selection authority as the CLI.

## Acceptance criteria

1. Available slots, adapters and Superpowers mode come from the core catalog and resolver; unsupported combinations show the same refusal as the CLI.
2. Changes remain in drafts with effective-selection provenance, preview, governed apply and rollback; opening a form never changes live configuration.
3. Each action shows its citizen equivalent, and fixture tests prove CLI/UI selection and validation parity.
4. Existing 0.16 forms remain compatible with earlier capabilities; unavailable later capabilities have explicit availability states.

## Design

### Approach

Adapt the existing Studio core and CLI contracts after the listed engine dependencies land. Preserve native result files as authority, keep UI actions on the same governed path as the CLI, and record capability availability explicitly. Detailed file-level design belongs to the future implementation session.

### Decisions and alternatives

Deliver this integration in the engine's milestone rather than postponing it to an unspecified UI release. Keep feature ownership separate from the cross-cutting post-Measured integration gate.

### Do not implement

Do not duplicate engine analysis or change live configuration outside governed apply. This roadmap filing does not implement the capability or authorize a release.
