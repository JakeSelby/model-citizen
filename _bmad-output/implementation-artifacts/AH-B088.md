# AH-B088 — A role-confinement refusal writes no decision-log row, and the usage ledger counts it as a subagent

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Reproduction

1. With the `delegation` stance at `tiered`, spawn `Agent` with `subagent_type: reviewer` (or a
   brief carrying a `harness-role: reviewer` line) four times in one Claude Code session.
2. End the session, then read `~/.local/state/agent-harness/decisions.jsonl` and the session's row
   in `usage.jsonl`.

Observed in the 0.13.0 BMad integration suite: each spawn was refused with "This constrained harness
role requires an isolated worker", the decision log held only `brief-guard` and `budget` rows and no
refusal, and the usage row reported `subagents: 4` for a session in which no subagent ran.

## Root cause

- In `dispatch`, a spawn whose `subagent_type` names a constrained role, and a spawn whose brief
  declares one on a `harness-role:` line, both go straight to `role_deny`, which composes the
  refusal and records nothing. Only `framework_deny` and `evasion_deny` call
  `decisions.record`. [Source: lib/harness_core/lifecycle.py#dispatch]
- The SessionEnd worker sets `subagents` to `max(len(agents), len(agent_calls))`, where
  `agent_calls` is every `Agent` tool use in the transcript, refused or not. A refused call writes no
  subagent transcript, so `agents` is empty and the call count wins.
  [Source: policy/hooks/usage-log.py#scan]

## Acceptance criteria

1. **Given** a native spawn naming a constrained role by `subagent_type`, **when** the PreToolUse
   coordinator refuses it, **then** one `role-confinement` decision row with answer `deny` is
   written, its input leading with the role and `subagent_type`.
2. **Given** a brief declaring a constrained role on a `harness-role:` line under an unconstrained
   `subagent_type`, **when** it is refused, **then** one `role-confinement` row is written whose
   input names the role and `harness-role marker`.
3. **Given** delegation `off`, **when** a constrained role is named, **then** the confinement row is
   still written.
4. **Given** a spawn of an unconstrained role, **when** it is dispatched, **then** no
   `role-confinement` row is written.
5. **Given** a transcript with four `Agent` calls whose results are errors and no subagent files,
   **when** the SessionEnd worker records it, **then** the session row reports `subagents: 0`.
6. **Given** an errored `Agent` call that left a subagent file naming its tool use id, or a call
   with no file and no error, **when** the session is recorded, **then** each still counts.

## Design

- `lifecycle.confinement_deny` records the row and returns `role_deny`; the named-role and marker
  branches call it. The input is `<role> (<what named it>): <brief fingerprint>`, so the row names
  the role without a new field on the decision row, and carries the same fingerprint the evasion
  guard compares on.
- `framework-spawn` and `evasion-deny` keep their own rows; neither goes through the new helper, so
  no refusal is logged twice.
- `role-confinement` is not added to `decisions.POINTS`, as `framework-spawn` is not: that tuple is
  mirrored by the runtime-controls point list, and a mode for a point with no shadow evaluation
  would be a control that controls nothing.
- `usage-log.refused_spawns` drops from the call count every `Agent` call whose result carries
  `is_error: true` and whose id no subagent row names. The count stays at least `len(agents)`, so
  a subagent that ran and failed, or whose meta names no call, is still counted.
- Rejected: matching the refusal text in the result. It couples the ledger to wording the stance
  test already pins elsewhere, and misses a refusal from any other hook.

fail on the unfixed code (five failures and one error, run against an export of the base commit)
and pass after it.

## Review findings

- CodeRabbit round 1, Major, `policy/hooks/usage-log.py`: an older-format transcript writes a
  subagent's turns into the session file as sidechain lines and leaves no subagent file, so a
  spawn that ran there and then failed was subtracted as refused. Valid; fixed. A session file
  holding any sidechain line keeps every errored call counted, with a regression test; current
  Claude Code session files carry no sidechain lines, checked on forty recorded transcripts.
- CodeRabbit round 2, Major, same line: with one sidechain run and one refusal in an
  older-format session, the refusal is counted. Answered, not changed: older sidechain lines carry
  no tool use id tying them to a spawn, so an association would be a guess that can undercount
  work that ran; that case falls back to the count before this fix.
- Shepherd check: three recorded transcripts show Claude Code writing `"is_error": true` on a
  hook-denied `Agent` result, the shape the count relies on.
