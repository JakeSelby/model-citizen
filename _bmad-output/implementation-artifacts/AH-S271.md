## Story

As a developer whose work spans several repositories, I want the `.code-workspace` files I already
keep to decide which folders belong together, so that I can see how each folder resolves and launch
Claude Code or Codex across a workspace's folders with one command.

## Context and value

- Claude Code loads project instructions from its working directory only. A folder added with
  `--add-dir` brings its skills, commands and agents, and its `CLAUDE.md`, `CLAUDE.local.md` and
  `.claude/rules/` only when `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` is set. It never loads
  an `AGENTS.md` from an added folder, and Codex reads only its own working directory's.
- The desktop app's sidebar groups hold only a name and an order, and
  `permissions.additionalDirectories` grants file access only, so neither can define a workspace.
  The `.code-workspace` files VS Code already reads are the one definition that exists.
- A spike on 2026-09-26 parsed six real workspace files with a stdlib reader: 29 folders, 10 of them
  in several workspaces. First position settles 2 of the 10, one folder is first in two workspaces,
  and one workspace names a folder that no longer exists. So a shared folder needs an explicit
  override, and a missing member must be reported rather than fatal.
- This story is the map and the launchers. The SessionStart hook that supplies member instructions
  where no surface loads them natively is the sibling story under the same epic, and it loads this
  resolver by file path.

## Acceptance criteria

1. **Given** `workspaces_dir` is unset, **when** `citizen workspace list` runs, **then** it says how to
   set the key and exits 1, and no command attaches a workspace.
2. **Given** `citizen config set workspaces_dir <path>`, **when** the path is absolute or starts with
   `~/`, **then** it is stored expanded; **when** it is relative or empty, **then** it is refused and
   the config file is not written.
3. **Given** a workspace file with `//` and `/* */` comments, comment markers inside strings, an escaped
   quote and trailing commas, **when** it is parsed, **then** it reads as VS Code reads it.
4. **Given** members as relative, `~` and absolute paths, a `uri`-only folder and a folder that does
   not exist, **when** the file is parsed, **then** members are real paths in file order, the `uri`
   folder is skipped and the missing one is reported apart.
5. **Given** a cwd in a member folder, a subfolder of one, or a linked git worktree of one, **when** it
   is resolved, **then** it matches the longest member on a path boundary, trying the worktree's main
   checkout when nothing else matches.
6. **Given** a folder in several workspaces, **when** it is resolved, **then** the first of these
   decides: `HARNESS_WORKSPACE`, an exact match of the launch `--add-dir` folders, the override,
   single membership, a unique first position; otherwise no workspace attaches and the candidates are
   returned. A `null` override attaches nothing, and an override naming an unknown workspace is
   reported and ignored.
7. **Given** a configured folder, **when** `citizen workspace list` runs, **then** it prints each
   workspace's members in order with their instruction size or `missing`, each shared folder with the
   workspace and rule that decided or its candidates, and each ignored override, and exits 0.
8. **Given** a workspace `demo`, **when** `citizen workspace open demo --dry-run` runs, **then** it
   prints `claude` in the first existing member with one `--add-dir` per other existing member and
   `HARNESS_WORKSPACE=demo`; with `--codex` it prints `codex -C <first> --add-dir …`; arguments after
   `--` come before the `--add-dir` flags; without `--dry-run` it runs that command in that folder.

## Design

### Approach

- New `lib/harness_core/workspaces.py`, standard library only and importing no other `harness_core`
  module, so a policy hook can load it by path. Its API is `read_jsonc`, `parse_workspace`,
  `workspace_map`, `read_overrides`, `resolve` and `member_instructions`, documented in the module
  docstring.
- The reader is one pass that copies string literals intact, honouring backslash escapes, and drops
  comments; a second pass removes a comma before `}` or `]` outside strings; then `json.loads`.
- No cache and no stored map: every call parses every file again, so the map cannot disagree with
  the files.
- `bin/harness` gains the `workspaces_dir` key in `coerce_config_value` and `workspace list` and
  `workspace open` as subcommands beside `create`. `open` sets `HARNESS_WORKSPACE`, changes into the
  first existing member and `execvpe`s the runtime.
- `list` counts the characters of instructions a session outside each member would need, with the
  resolver's `member_instructions`: `CLAUDE.md`, else `AGENTS.md`; `CLAUDE.local.md`; unscoped
  `.claude/rules/*.md`; their `@` imports to depth five, outside code.

### Decisions and alternatives

- **An override beats first position** (plan decision 2): launch facts, then override, then single
  membership, then a unique first position, else candidates. An explicit choice never loses to a
  heuristic, and `null` opts a folder out. Rejected: the earlier order that put first position before
  the override, since 8 of the 10 shared folders in the spike need an override either way.
- **Worked out at run time, never stored.** Rejected: a generated map file, which goes stale the
  moment a workspace file is edited in VS Code.
- **A hand-written JSONC reader.** Rejected: a third-party JSON5 or JSONC package, since the floor
  is the standard library and the needed subset is small.
- **Passthrough before `--add-dir`.** Claude's `--add-dir` is variadic, so a prompt after it was read
  as another folder in the spike.
- **`HARNESS_WORKSPACE` only decides among the folder's own workspaces**, so an inherited variable
  naming an unrelated workspace cannot attach it to a folder outside it.
- **An override naming a workspace that does not contain the folder is ignored and reported**, the
  same as an unknown name, rather than attaching a workspace the folder is not in.
- **Passthrough is split at the first `--` by the subcommand's parser**, because Python 3.9's argparse
  fills an optional positional with nothing when an option precedes `--` and then rejects the rest.

### Do not implement

- The SessionStart hook, its registration, ownership of
  `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` and the desktop grant: the sibling story.
- Writing `additionalDirectories` into settings, a stored map, or an overrides command such as
  `workspace pin`; the overrides file is edited by hand.
- A doctor line; `workspace list` covers the diagnosis.
