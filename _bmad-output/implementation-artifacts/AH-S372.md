## Story

As a solo or small-team agentic developer, I want a Hooks page that tells me which hooks are firing, failing or silent, so that I notice a hook that stopped working before it costs me.

## Context and value

Plan step 4. Reads `decisions.jsonl` (`policy/hooks/decisions.py:171`) grouped by `module` and `point`. Liveness is the last decision and error outcomes; the Safety log folds in here, worst first. Target artboards `Hooks.dc.html` and `HooksSettings.dc.html`.

## Acceptance criteria

1. **Given** decisions, **when** the Hooks page opens, **then** rows group by `module` and `point` with last decision and error outcomes.
2. **Given** an enabled hook with no decision in 7 days, **when** liveness computes, **then** it is labelled "silent"; a hook that never writes decisions is labelled "not observable", not silent.
3. **Given** Safety log entries, **when** the page renders, **then** they show on it, sorted worst first.
4. **Given** the page's route, **when** its API test runs, **then** it asserts period-stamped rows, the response shape, auth enforcement and error cases.
5. **Given** the page, **when** design-judge scores it against its round-3 artboard, **then** the score is at least 7, and node tests and an e2e flow cover it.

## Design

### Approach

- Group decisions by module and point; compute liveness at request time; fold in the Safety log.

### Decisions and alternatives

- **Read at page load from existing logs:** no hook-side recording (epic scope). Rejected: new recording for this page.

### Do not implement

- Changes to other Harness pages; new hook-side logging.
