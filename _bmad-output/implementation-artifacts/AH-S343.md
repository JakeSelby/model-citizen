## Story

As the maintainer, I want one generated scorecard per layer and overall, built from the evaluation's
registered rows, so that every layer's keep, trim or no-evidence verdict is published with its cost,
its effects, its intervals and the rows it rests on.

## Context and value

The definitive evaluation (#1175) produces production, rule-task, long-session, sweep and judge
rows. The pieces that read them already exist: the sweep's justification rule (#1184), pass^k and
the all-rules-at-once rate (#1180), equivalence verdicts (#1181), oracle metrics and the diff judge
(#1185). Nothing joined them into the one report the epic's acceptance names, and the evidence
bundle (#1102) had no place for one.

## Acceptance criteria

1. **Given** result directories passed by role, **when** the scorecard runs, **then** each layer (rule, stance, listing, hook, output style, instructions) reports prefix tokens and USD per run by model, behaviour against bare and against its own removal, the outcome effect, the cost effect for a cost-control layer, and the verdict with its deciding margin, interval and source rows.
2. **Given** production rows, **when** the headline is built, **then** each stratum reports the Cost-of-Pass ratio and interval, pass rate, pass^k, the all-rules rate and admitted judge win rates, each with an equivalence verdict.
3. **Given** a row field a pending tier adds (`stratum`, `row_kind`) is absent, **when** the scorecard runs, **then** rows group by model and the long-session reading says not measured, with the reason.
4. **Given** the same inputs, **when** the scorecard runs twice, **then** its JSON and Markdown are byte-identical.
5. **Given** an exploratory row, **when** the scorecard runs without `--allow-exploratory`, **then** it is refused naming the source; with the flag the whole output is marked exploratory.
6. **Given** an evidence bundle carrying a scorecard, **when** it is verified, **then** a non-exploratory scorecard built from the bundle's rows is reported and any other fails item 5.

## Design

### Approach

`scripts/layer_scorecard.py` loads every `results.jsonl` under each role's directories, tags each
row with a portable source id, gates registration, then builds the headline per stratum and one
card per layer per stratum. Every statistic comes from an existing module: `replay_stats.analyse`,
`replay_reliability.pass_k` and `joint_compliance`, `replay_judge.judge_section` and its clustered
interval, `ablations._score` for both behaviour comparisons and `ablations.justify` for the verdict,
and `equivalence` for every verdict against a margin. Output is sorted JSON plus a Markdown render.

### Decisions and alternatives

- Behaviour against bare uses the same score reader as the sweep, with bare as the removed arm, so both comparisons read as removed minus harness and share one sign convention.
- pass^k and the all-rules rate have no paired interval upstream; the scorecard reads each as a mean per-task difference with the judge's task-clustered bootstrap rather than adding a new estimator.
- Headline margins default to the pre-registration template's values and a `--plan` overrides them, because no registered plan names margins for pass^k, the all-rules rate or the judge yet.
- The bundle carries a hashed reference and checks it, rather than re-deriving it, because a scorecard reads rows a bundle does not hold.
- Prefix tokens prefer the rows' `context_attribution` over the static figure, because it is what the arm actually loaded.

### Do not implement

No change to `summarise`, `justify` or `cost_bench.py`; no new estimator in the shared modules; no
paid run.

## Dev notes

### Bound decisions and requirements

AD-22: a missing measurement is unknown, never zero, so an absent role or field reads not measured.
Standard library only, Python 3.9 floor. Every cited result follows docs/evidence-standard.md, so
exploratory rows never yield a citable scorecard.
