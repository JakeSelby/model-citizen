# AH-B132 — usage-feed prices a Workflow-tool agent against the soft budget of the role it is named for

## Reproduction

Does the subagent-finished path run for a Workflow-tool agent at all? Yes (validated from code and
local records, not from a fresh native run):

- **Code.** `on_subagent_event` journals every `SubagentStop` whose `agent_id` is an identifier,
  with no filter on how the agent was launched. It records the payload's `agent_type` and a
  transcript path, falling back to `agent_transcript`, which already looks under
  `subagents/workflows/wf_*/`. `ingest` moves the stop to `pending`, and `on_prompt` names it
  through `stop_line`, which priced it with `row_for(table, record["type"])`.
- **Local feed journals.** Six `stop` records across four sessions carry a transcript path under
  `subagents/workflows/wf_*/`, so Claude Code does fire `SubagentStop` for Workflow-tool agents.
  Five carry the type `workflow-subagent`; one carries `reviewer`, a budgeted role, and is exactly
  the case the issue describes.
- **Local transcripts.** About 2,900 Workflow-tool agent transcripts sit under
  `subagents/workflows/`; their meta files name `workflow-subagent` in almost every case, with a
  handful naming a harness or native role.

Given a Workflow-tool agent whose type names a budgeted role and whose spend passes that role's
nudge, the next prompt's feed said `… — over budget 2.0× its budget of 8,500 / 15`, while
`usage.jsonl` recorded the same agent `unconfined` with both budgets null.

## Root cause

`stop_line` in `policy/hooks/usage-feed.py` looked the budget row up by agent type alone. The
ledger (`policy/hooks/usage-log.py`, the `workflow` branch of the per-agent row) keys on the
transcript's `wf_*` parent directory and nulls both budgets, because the Workflow tool launches its
agents itself: no spawn hook routed them and no brief stated a budget. The fix for #577 (#831)
changed the ledger and left the feed out of scope.

## Acceptance criteria

1. **Given** a stopped agent whose transcript sits under `subagents/workflows/wf_*/` and whose type
   names a budgeted role, **when** the feed reports it, **then** the line carries its figures and
   no budget clause, no ratio and no `over budget` wording.
2. **Given** the same agent's stop without a transcript path in the payload, or with one outside
   the home or reached through a symlink, **when** the stop is journalled, **then** it decides the
   same way.
3. **Given** an agent of the same role spawned through the Agent tool, **when** the feed reports
   it, **then** its line still compares against the role's soft budget.
4. The feed and `citizen usage --by role` agree: neither prices a Workflow-tool agent.

## Design

At stop time `on_subagent_event` asks `workflow_agent(path)` of the unredacted transcript path it
was handed (or found), and journals `workflow: true` when the answer is yes. `workflow_agent` calls
`usage-log.py`'s `workflow_of`, the rule the ledger's per-agent row uses (a parent directory named
`wf_*`), so the two cannot drift; the feed already loads that module to sum the transcript, and the
ledger imports nothing of the feed's, so no cycle arises. `stop_line` passes no row for a record
flagged `workflow`, so `agent_line` drops the clause and returns no ratio, as it already does for
any unbudgeted role. A ledger that will not import answers no, and the line is priced as before.

Rejected: keying on the type `workflow-subagent`, which misses the role-named case the issue is
about; and classifying the journalled path, because `redact` blanks any path outside the home
prefix (a `CLAUDE_CONFIG_DIR` elsewhere, a symlinked home, a relative path), which the ledger, reading
the real path, still classifies `unconfined`.

Must not change: the line's figures, the Agent-tool spawn's budget line, the `thresholds` mode
rule that an unbudgeted line is not shown, or the ledger.

## Regression test

`tests/test_usage_feed_workflow.py`: a role-named Workflow agent at twice the role's budget reports
an unbudgeted line under the home, outside it, through a symlinked home, under any `wf_*` parent and
through the fallback lookup; the same figures through an Agent-tool spawn keep `over budget 2.0×`,
under the home and outside it. Each case also asks the ledger's per-agent row about the same file
and requires it to agree. The outside-home, symlink and bare-`wf_*` cases fail against the first
fix, which classified the redacted path.

## Review findings

1. Fixed: the check ran on the redacted journal path, so a Workflow agent outside the home or
   reached through a symlink kept its budget line. The stop now journals a `workflow` flag.
2. Fixed: the feed required `subagents/workflows/wf_*` where the ledger accepts any `wf_*` parent;
   both now call `usage-log.py`'s `workflow_of`.
3. Fixed: hook-path tests outside the home, through a symlink, and an Agent-tool spawn outside it.
4. Fixed: the direct helper tests were dropped; the hook-path tests cover them.
5. Left: a synchronous Agent return's record carries no path and is always budgeted. Nothing in
   the code or a recorded payload shows whether a Workflow agent ever produces an Agent
   `PostToolUse`, so no assertion was added.
