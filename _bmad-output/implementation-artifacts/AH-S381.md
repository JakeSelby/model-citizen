## Story

As a solo or small-team agentic developer, I want an Evals page that shows before and after for each setting change, so that I can judge a change by its measured effect.

## Context and value

Plan step 7. Evals re-homes Experiments, the runs pages and trends; lists `benchmarks/preregistrations/`; reads `compatibility/evidence/` through the compatibility reader; and shows before and after for each period boundary from AH-S369. The auto-trim eval compares context per call before and after the reset point's projection.

## Acceptance criteria

1. **Given** a real period boundary, **when** Evals opens, **then** it shows a before-and-after for it.
2. **Given** pre-registrations, **when** Evals renders, **then** it lists `benchmarks/preregistrations/`.
3. **Given** compatibility evidence, **when** Evals renders, **then** it reads it through the compatibility reader.
4. **Given** the old Experiments and Reports/trends routes, **when** opened, **then** they land on Evals with their runs and trends.
5. **Given** the routes, **when** their API tests run, **then** they cover shape, auth and errors; node tests and an e2e flow cover the page.

## Design

### Approach

- Move Experiments, runs and trends under Evals; add before-and-after from periods.

### Decisions and alternatives

- **One Measure page:** experiments and trends answer the same question. Rejected: keeping them separate.

### Do not implement

- New run kinds or estimators.
