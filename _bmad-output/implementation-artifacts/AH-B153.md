# AH-B153 — A pack test intermittently fails cleanup while git maintenance writes into its repository

## Reproduction

On Linux CI, `test_replay_pack.ArchiveSafetyTests.test_a_pack_commit_holding_a_symlink_is_refused_before_extraction` intermittently errors in `TemporaryDirectory` cleanup with `OSError: [Errno 39] Directory not empty: 'pack'` (PR #1150, two runs). It does not reproduce on demand locally.

## Root cause

The test module's `git()` helper commits into a scratch pack repository. After a commit git may start background auto-maintenance or auto gc, which keeps writing under `.git` while `TemporaryDirectory` removes the tree, so `rmdir` finds new entries. [Source: tests/test_replay_pack.py#git]

## Acceptance criteria

1. **Given** the pack test helper, **when** it runs any git command, **then** it passes `-c gc.auto=0 -c maintenance.auto=false` alongside its existing `-c` flags.
2. **Given** the fix, **when** the affected test runs 50 consecutive times, **then** every run passes.

## Design

Add `-c gc.auto=0 -c maintenance.auto=false` to the `git()` helper in `tests/test_replay_pack.py`. `tests/test_cost_bench_pack.py` builds its packs through the same `make_pack`, so it inherits the fix; its `git_head` only reads. Rejected: retrying cleanup with `ignore_cleanup_errors`, which needs Python 3.10 and hides the race instead of removing it. Production code does not change.

## Regression test

The flaky test itself is the regression check; it is run 50 consecutive times. The race cannot be forced deterministically.
