## Story

As a harness maintainer, I want a replay task set sized by power analysis, with long multi-turn tasks and at least five trials per task and arm, so that the run can detect the effect SM-2 states in advance, a delegation saving included.

## Context and value

SM-2 sets the power: at least five trials per task and arm, α 0.05 two-sided, joint power 0.8, and a minimum detectable effect of at most 15% stated before the run, with long multi-turn tasks included. Its stop condition also reads a long-task subset on its own. FR-34 puts delegation's break-even at 4.8 to 7.6 absorbed calls, so a set of short tasks cannot show a delegation saving even when one exists.

Depends on #793 and #794. Traces to SM-2, FR-34 and SM-4.

## Acceptance criteria

1. Given pilot variance from replay rows, when the power analysis runs, then it states the task count for joint power 0.8 at the pre-registered effect, and the set meets it.
2. Given the set, then its long multi-turn subset is large enough for its own ratio interval, and every long task sits above FR-34's break-even.
3. Given each task, then it has a held-back test and a reference solution that passes it.
4. Given a proof run, then the set is frozen and versioned before the first trial, and any change bumps the version.

## Design

### Approach

The task set is an evaluator pack: a versioned git repository outside this one,
`model-citizen-evals`, holding starting workspaces and, per task, a prompt, a held-back check and a
reference solution. `scripts/replay_pack.py` opens a pack at a pinned ref through `git archive`,
digests every archived file, validates the document and each task, copies a task's workspace into
a fresh one-commit repository for the arm, and checks each task for contamination against the
harness commit's checkout and history. `cost_bench.py replay` gains `--pack`, `--pack-ref`,
`--pack-set` and `--pack-digest`; a pack task is scored like a synthetic task, its check sent on
stdin to an isolated bare-image container. The dry run now runs the contamination control per task
at each tag's commit and exits 2 when one is refused. `scripts/replay_power.py` sizes k, n and m
from pilot rows. Pack 1.0.0 holds seven production tasks, four of them long, the micro tier's three
mechanism tasks re-homed, and #513's delegation task above break-even with its two-file control
[Source: scripts/replay_pack.py; Source: scripts/cost_bench.py#cmd_replay; Source: docs/benchmarks.md#evaluator-pack].

### Decisions and alternatives

- An evaluator pack outside the harness, the maintainer's choice for decision 1 of the v0.15
  evidence plan. Third-party repository fixes were rejected for this set: each needs a licence
  review and a training-cutoff date check, and its fix may be public.
- Long means more than 7.6 absorbed calls, the top of FR-34's range. A task's absorbed-call size is
  the median of its clean bare-arm runs' `gather_calls`, the definition `delegation_verdict` already
  uses for task size; the pack's `expected_absorbed_calls` is a design figure the pilot confirms.
- Contamination is decided by exact blob ids of each check and solution anywhere in the installed
  history, and by a pack-wide canary string in the tree or history. Ancestry or file-name matching
  was rejected: a copy can be renamed, and a canary survives rewording that keeps the line.
- The scorer stays the existing bare-image check container with stdin delivery, so no new
  infrastructure is needed; mounting the pack into a scorer container was rejected as unnecessary.
- The power command is an analytic normal approximation on the log scale with independence across
  the three tests, which understates joint power; a simulation of the bootstrap per candidate
  design was rejected as too slow for a grid search.
- The micro tier's manifest in this repository stays in place, still refused, so its tests and the
  #511 fixture keep their source; the pack's `micro` set is the runnable home.

### Do not implement

- Pilot or proof runs, pre-registrations, or any paid model call.
- A published pack repository or a GitHub remote for it; the maintainer creates and pushes it.
- Pack support for `--pair` or changes to arm declaration and parity code (#514).
- Retiring `benchmarks/micro/tasks.json`.

## Dev notes

### Bound decisions and requirements

SM-2's power, trial and effect bounds; FR-34's break-even range, whose top figure defines long;
SM-4; the evidence standard's items 2 and 9 and point 7; #1019's control, extended to pack tasks
[Source: _bmad-output/planning-artifacts/prd.md; Source: docs/evidence-standard.md].

### Files to touch

- `scripts/replay_pack.py` — the pack reader, validator, workspace copy and contamination check.
- `scripts/replay_power.py` — the power command.
- `scripts/cost_bench.py` — pack flags, workdirs, scoring, verification, dry-run contamination.
- `docs/benchmarks.md`, `docs/pre-registration-template.md` — the pack, absorbed calls, power.
- `tests/test_replay_pack.py`, `tests/test_cost_bench_pack.py`, `tests/test_replay_power.py` — new.
- `tests/test_cost_bench_tags.py`, `tests/test_cost_bench_protocol.py`, `tests/test_replay_pair.py`
  — dry-run expectations now that the dry run runs the contamination control.

### Testing

`tests/test_replay_pack.py` covers pinned reads, digests, refusals, validation, workspace copies and
each contamination route. `tests/test_cost_bench_pack.py` covers stdin scoring in an isolated
container, workspace isolation in a scored run, verification, per-commit contamination, the dry
run's exit codes, refused flag combinations, the registered run's digest pin and row stamps, the
micro set and the preflight. `tests/test_replay_power.py` checks the formula by hand, minimality,
monotonicity, refusals and the command line. The free preflights against pack 1.0.0 ran in Docker.
