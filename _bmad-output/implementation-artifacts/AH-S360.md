## Story

As a developer, I want the Studio to read as a clean, white, data-first operational tool, so that the numbers and their status carry each page and nothing else catches the eye.

## Context and value

The Studio follows the "Briefing" direction with the "Clear" palette (DESIGN.md, 2026-09-23): a headline summary, a two-by-two grid of report cards and generous padding. In use it reads card-heavy, with too much margin. On 2026-10-06 the operational direction, option A of five rendered studies, replaced it. Only the look changes: routes, data and workflows stay as they are.

## Acceptance criteria

1. The shell is a Mantine AppShell: a 220 px white navbar with a hairline border, a 52 px header holding the page title, the version and context, and the page's CLI command, and a white canvas.
2. The Hub has no cards: one number strip split by dividers, then sections separated by single hairlines, with compact tables (rows about 30 px, 13 px text, monospace only for ids, commands and numbers that need to align).
3. One muted teal accent; red, amber and green carry status only.
4. Configure, Library, Experiments, Activity, Reports and Setup use the same density, with tables and hairline sections in place of cards and papers.
5. A matching dark theme and the one-column phone layout.
6. The #999 accessibility suite stays green: contrast, focus, 320 and 390 px reflow and the planted defects.
7. `studio/dist` is rebuilt, the bundle manifest verifies, and the #1000 budgets hold: 360 KiB script and 48 KiB style gzipped, 1500 KiB raw.
8. DESIGN.md records the direction as an amendment, not a rewrite, and `studio/src/theme.ts` and `studio/src/styles.css` carry it.
9. Before and after screenshots of every page are captured with the end-to-end tooling.

## Design

### Approach

Theme and layout only. Replace the "Clear" palette with one muted teal accent (the target's active navigation item is `#087f5b` on `#e6fcf5`), hairlines `#e9ecef`, text `#212529` and secondary text `#868e96`; status red `#c92a2a`, amber `#e67700` and green `#2b8a3e`. Move the shell to Mantine `AppShell`. Replace cards and papers with the number strip, hairline-separated sections and compact tables on every page, and derive the dark theme from the same tokens.

### Decisions and alternatives

- Chosen 2026-10-06: option A of five rendered studies replaces the Briefing direction and the Clear palette.
- The target names Inter and JetBrains Mono, loaded from a web font service. The Studio makes no network requests, so name both first in their font stacks with system fallbacks, and bundle no font file: bundling one needs a licensing review.
- Status colours keep AA contrast on both canvases: adjust the shade, never drop the status.

### Do not implement

- Route, data or workflow changes.
- New product copy.

### Completion notes

- The shell is a static-mode Mantine `AppShell` (`layout="alt"`): the navbar spans the page height, and static mode keeps the header and navbar in the page flow, so no fixed bar can cover a focused control. Below 48em it is one column.
- The header's CLI command per page comes from `pageCommand` in `studio/src/navigation.ts`, each an existing command: `citizen doctor` (Hub), `citizen draft first-run`, `citizen selection`, `citizen catalog --library`, `citizen runs history`, `citizen activity`, `citizen reports trends`, `citizen usage --rules` and `citizen usage`.
- The Hub's number strip reuses the existing labels and values (installed version, the attention summary, the drift badge, the run count); no copy was added.
- Every section `Paper` lost its border and padding props; `styles.css` draws the hairline. The theme's spacing and type scales are tighter, so `Stack` and `Group` gaps tighten with them.
- Differed from the design: the target's secondary ink `#868e96` is 3.3:1 on white, under AA for 13 px text, so the Studio uses `#646C73`; amber and green keep the target's shades for status dots and use darker shades as text, per the design's "adjust the shade" decision.
- Status badges are a dot plus the status word in body ink; the hue is on the dot.
- Review round 1: the strip's doctor value is the count of checks the engine itself labels as needing attention (the overview payload has no separate count field), and it reads "Unavailable" when the doctor read failed. The system summary moved to the release line. The recent-runs strip item is gone, since the engine caps that list at five and reports no total. Running and info statuses take the neutral dot. The header has a 52 px minimum height and grows rather than overflowing. The footer sits outside `<main>`, so it keeps its contentinfo landmark. Each page heading is now one quiet line: no breadcrumb row, the heading at the header's weight, a 13 px description, and a subtle action button.
- Accessibility suite (`tests/test_studio_accessibility_browser.py`, `STUDIO_E2E=1`): run alone with the DevTools connect timeouts widened, it finished with `Ran 10 tests`, `OK`. Run alone at the stock timeouts under the same machine load, 9 of 10 errored before auditing a page: 7 times "Chrome did not accept a DevTools target" and twice a DevTools socket timeout. Neither is an audit finding. The phone selection-switch summary keeps a 36 px minimum height (2.25rem).
- Before and after screenshots of every page, the dark Hub and the 390 px Hub were captured outside the repository with the browser tests' DevTools helper, from the accessibility audit's populated fixtures on an isolated Studio instance, and shared for review.
- `python3 scripts/studio_bundle_manifest.py verify --source studio --committed studio/dist`: "committed bundle matches source". Budgets (`scripts/studio_budgets.py bundle`): script 294.4 KiB of 360, style 38.4 KiB of 48 (gzipped), raw 1209.9 KiB of 1500.
- The accessibility suite's run at stock timeouts is recorded with the merge commit's gate.
