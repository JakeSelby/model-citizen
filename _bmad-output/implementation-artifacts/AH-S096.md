## Story

As the maintainer, I want a small cohort of developers to try the documented install and first
experiment without coaching, so that onboarding friction is observed and fixed before the harness is
promoted more widely.

## Context and value

The adoption epic (#212) sets two principles this story carries out: recruit direct testers before
broad promotion, and fix observed onboarding friction before scaling channels. It also asks that
usable attempts, repeat use and actionable feedback be measured rather than impressions alone. The
launch story (#215) asks that blocking cohort findings be resolved or deferred first. The issue is open
and has no milestone.
[Source: https://github.com/JakeSelby/agent-harness/issues/214]
[Source: https://github.com/JakeSelby/agent-harness/issues/215]
[Source: https://github.com/JakeSelby/agent-harness/issues/212]

## Acceptance criteria

1. **Given** the cohort, **when** participants are recruited, **then** each uses at least one supported
   CLI.
2. **Given** each attempt, **when** it ends, **then** completion, time to the first useful result,
   confusion points and whether the participant returns are recorded.
3. **Given** feedback, **when** it is stored or published, **then** it is consented, holds no secrets,
   and public evidence is sanitized.
4. **Given** the findings, **when** they are triaged, **then** product friction is separated from
   requests for unsupported environments.
5. **Given** an actionable finding, **when** triage closes, **then** it is a dedicated issue before any
   broader promotion.
