## Story

As a developer who uses the superpowers skill library, I want a `superpowers` mode that hands planning
and testing process to that library while every harness hook stays on, so that the two layers do not
fight over process and the harness still enforces, measures and routes.

## Context and value

Epic #552's outcome: a `superpowers` mode ships out of the box and is measured against superpowers
alone [Source: https://github.com/JakeSelby/agent-harness/issues/552]. Skill libraries tell an agent how to work; the harness is the layer that enforces underneath.
Ceding a dimension still needs an explicit value, so this story adds a `delegated` variant for the two
dimensions the mode cedes. On `main`, `plan-ceremony` has `light` and `review-card` only, and `testing`
has `off`, `pragmatic` and `required`.
[Source: https://github.com/JakeSelby/agent-harness/issues/558]

## Acceptance criteria

1. **Given** `harness config set mode superpowers`, **when** `harness sync` runs, **then** it yields
   exactly the mode's state and `harness diff` is clean.
2. **Given** `plan-ceremony: delegated`, **when** a plan file is written, **then** the plan-card
   validator does not fire; the existing gate keys on `review-card`.
3. **Given** the new variants, **when** lint runs, **then** the lint total is unchanged and neither
   variant is the longest of its dimension.
4. **Given** a profile with a `superpowers@*` plugin enabled and no mode set, **when** a session starts,
   **then** exactly one suggestion line appears, none appears without the plugin, and `doctor` prints
   the same line.
5. **Given** the docs, **when** `docs/modes.md` is read, **then** it marks `superpowers` `unqualified`
   until the live set lands, and says what clears it.

## Design

### Approach

- `primitives/stances/plan-ceremony/delegated.md`: the host framework's planning process and plan format
  apply; no Review Card and no validator; wait for the host's approval step, then implement without
  per-step checks; `plan-authoring` stays available on request.
- `primitives/stances/testing/delegated.md`: the host framework's testing discipline applies; the harness
  adds nothing and still runs the existing suite before claiming a change works.
- `primitives/modes/superpowers.json`: `plan-ceremony: delegated`, `testing: delegated`; rules
  `decisions-and-plans` and `voice-and-format` off; skills `plan-authoring` and `worktree-per-agent` off;
  workflows `plan`, `build` and `review` off; every hook on; everything else inherits.
- Detection: `harness doctor` and the SessionStart hook print one line naming the mode when a
  `superpowers@*` plugin is enabled in the managed home and no mode is set.

### Decisions and alternatives

- **No auto-switch:** detection suggests the mode and never selects it.
- **Every hook stays on** in the mode, consistent with the epic's rule that enforcement is the harness's
  part. [Source: https://github.com/JakeSelby/agent-harness/issues/552]
- **`unqualified` until measured:** the epic's principle that a mode is `unqualified` until the live set
  (#560) says otherwise. [Source: https://github.com/JakeSelby/agent-harness/issues/552]

### Do not implement

- Automatic mode switching.
- Editing or trimming the library's own skills (FR-16 out of scope).

## Dev notes

### Bound decisions and requirements

- FR-16, Modes: the `superpowers` mode keeps every enforcement hook and cedes process primitives to the
  layered library; its detection reports when that library is present; `delegated` variants of
  `plan-ceremony` and `testing` keep those dimensions explicit.
- NFR-9, Standing-context budget: the lint total must not grow (AC 3).
- AD-2, One resolver, fixed invariants: invariants sit outside every switch, so a mode cannot cede them.
- [Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-16]

### Recorded gap

FR-16 also says that in a headless session `plan-ceremony` and the `delegated` variants proceed instead of
waiting for a go-ahead, with "no user present" as a session fact. This issue's `delegated`
`plan-ceremony` variant waits for the host's approval step, and its acceptance has no headless
criterion. The coexistence spike (#553) was to inform that behaviour and has not run.

### Files to touch

`primitives/stances/plan-ceremony/delegated.md`, `primitives/stances/testing/delegated.md`,
`primitives/modes/superpowers.json`, `docs/modes.md` (named by the issue); the SessionStart hook
`policy/hooks/harness-session.py` and `doctor` in `bin/harness`. The plan-card gate is in
`lib/harness_core/lifecycle.py`, which already dispatches the validator only when `plan-ceremony` is
`review-card`.

### Testing

Sync-and-diff for the mode; the validator not firing under `delegated`; the lint total; one detection
line with the plugin enabled and none without.
