## Story

As a harness maintainer, I want every saved replay stream read through the rule-detector registry offline, so that I can say which rules fired in which run, and how often per task, without inferring mechanism from cost or spending a model call.

## Context and value

The benchmark so far has inferred mechanism from cost. The registry in `policy/hooks/rule-detectors.py` already decides from a transcript alone whether a rule fired, but nothing ran it over the benchmark's stored `-p` streams. Reading them turns every kept stream into a corpus that answers "did rule X fire on task Y" at zero model spend: the offline tier of the programme's north star. The subcommand is worth having whether or not the registry's coverage is later extended.

## Acceptance criteria

1. **Given** a recorded stream with a known spawn whose return names a command, the run then executing that command as its gate, and a commit that skips the hooks, **when** `cost_bench.py detect --raw DIR` runs, **then** `DIR/detections.jsonl` reports `delegation/executed-from-summary` at the gate run's turn and `verification/no-verify` at the commit's turn.
2. **Given** a `--raw` directory, **then** every run file gets one row per registry detector, zero counts included, each with `count` and `turns`; a stream with no model call and a detector that raised are rows with `count` null and an `error`.
3. **Given** a replay with `--raw`, **when** each tag's set finishes, **then** `detections.jsonl` is written beside that set's `results.jsonl`, and the history row carries `mechanisms` (per task, what fired in the harness arm, in how many runs and how many hits), printed in `history.md`.
4. **Given** a root holding evidence sets, **when** `detect --backfill ROOT` runs, **then** every `results.jsonl` is left byte-for-byte untouched and `detections.jsonl` is written beside it; a run whose stream is missing, or found twice, gets error rows rather than a guess.
5. No model call anywhere; `python3 bin/harness lint` clean and the suite green.

## Design

### Approach

A new `scripts/replay_detect.py` holds the logic; `cost_bench.py` adds the `detect` subcommand, calls `detect_rows` in `replay_tag` when `--raw` is set, and passes the detections to `history_row` and `render_history`. `stream_events` turns the CLI's `stream-json` messages into the registry's event schema: a turn is a model call (a distinct assistant message id), counted from 1; a tool result takes its call's turn; messages carrying `parent_tool_use_id` are a subagent's and are skipped; the last assistant text is the final one. The run's own stream is read through `cost_bench.cli_messages`, so the older single-document raw files read too. The backfill walks the root for `results.jsonl`, finds each row's `<task>-<arm>-<rep>.json` in the results directory, a sibling `transcripts` or `raw` directory, or one level below them other than a nested set, and writes `detections.jsonl` beside the results. The replay instead reads each run from the stream it saved, as `save_stream` records it.

### Decisions and alternatives

- A turn is a model call, not the transcript's prompt counter: a headless run has one prompt, so the reader's counter would put every firing on turn 1 and answer nothing about when.
- Default taken: every detector runs with its stance gate lifted, because the bare arm has no stances and a gated detector would otherwise measure one arm only.
- Default taken: `Task` tool uses are read as `Agent`, because older Claude Code named the spawn tool `Task` and the detectors read `Agent`.
- Default taken: the replay writes `detections.jsonl` beside each tag's `results.jsonl`, not only in the `--raw` directory, because the runner reuses raw file names across tags and the next tag overwrites them.
- Default taken: a stream found in two candidate directories is an error row, not a pick, because two files of one name are two different runs.
- Default taken: a stream directory two sets search is ambiguous for both, and a replay run that saved no stream is an error row, because stream names carry no tag. Renaming the streams per tag was not taken: the diagnostic `backfill` command and the sets on disk read the untagged names.
- The registry has no detector that fires on a gate run or a spawn as such; its delegation detector fires on executing a command a subagent returned and its verification detector on a commit or push past the hooks, so the acceptance fixture is built on those.

### Do not implement

- No run of the backfill over the owner's untracked evidence sets and no committed output from them.
- No change to the registry, its detectors or `usage-log.py`.
- No field added to `results.jsonl` rows.

## Review findings

- An existing raw file that raised during `read_text` escaped the detector instead of producing
  the AC 2 unknown rows. Centralized path reads and translate I/O failures into one error row per
  detector.
- A run that timed out saved no stream, yet the replay read `<task>-<arm>-<rep>.json` from the
  shared `--raw` directory, so with two tags a tag-2 timeout was scored against tag 1's stream.
  `save_stream` now records each stream a run saves with its digest, and the replay reads a run
  only from that record (`detect_saved`); a run with none, or whose file changed, gets error rows.
- The backfill matched one stream to every sibling set sharing `../raw`, never flagging it, and
  overwrote a `detections.jsonl` the replay had written. A stream directory another set also
  searches is now ambiguous for both, found wherever the root is, and an existing
  `detections.jsonl` is replaced only with `--overwrite`.
- The story read `completed` before the backfill ran; it is `active` until the owner runs it.
- The unreadable-stream and raising-detector cases are now driven through `cost_bench.py detect`.
- `mechanisms` counted a repeated task and rep as two firing runs, and the subdirectory search
  read a nested set's streams; firing runs are distinct reps and nested sets are skipped.
- `mechanisms` discarded every detector error and counted only readable reps as the task's run
  denominator. It now stores total runs, per-detector measured denominators, and counted error
  reasons; `history.md` renders the same evidence.
