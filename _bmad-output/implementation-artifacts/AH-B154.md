# AH-B154 — Installing the harness leaves undeclared files that make every replay arm pair fail parity

## Reproduction

Build the two arms the registered delegation-nudge replay builds (`cost_bench.declarations` for tag
`59520dd339b340a0864d6cef6ae657c49c9b5b2e`, effort `high`), then `replay_arms.admit` each and
`replay_arms.admit_pair` the pair. No model call and no credential. Both arms are admitted alone;
the pair is refused with five lines `only in the harness arm, outside the harness component:` for
`home:.claude/plans`, `home:.config/git`, `home:.config/git/ignore`,
`home:.local/state/agent-harness/ownership.json` and `home:.local/state/agent-harness/sync.lock`,
exactly as the registered run printed before any trial.

## Root cause

`_treatment_paths` counts as the harness only its checkout, links into it, the regular files in
`HARNESS_WRITES` and directories that hold one of those. The sync writes more than that list
names: `ensure_gitignore_entries` appends the `claude/OWNERSHIP.json` ignore lines to
`~/.config/git/ignore`; `reconcile.Store` keeps `ownership.json` and takes its lock on an empty
`sync.lock` in the state directory; and the sync makes `~/.claude/plans`, which no link fills, so
it is not a parent of any treatment entry. `.config/git` follows from its file.

## Acceptance criteria

1. **Given** the arms the registered replay builds at its tag, **when** the pair is checked,
   **then** it is admitted with no difference and no model call.
2. **Given** a harness arm holding any other file or directory the bare arm lacks, **when** the
   pair is checked, **then** it is refused naming that path.
3. **Given** a lock file that holds bytes, or a declared directory that is a file, **when** the
   pair is checked, **then** it is refused.
4. **Given** a bare arm holding a harness write, **when** the pair is checked, **then** it is
   refused.

## Design

Decided per path, all in `scripts/replay_arms.py`, since the registered tag's install cannot change:

- `.config/git/ignore`: declared in `HARNESS_WRITES`. It is behaviour the harness ships (global
  ignore lines), so it is treatment; `.config/git` follows as its parent.
- `ownership.json`: declared in `HARNESS_WRITES`, beside the sync's `manifest.json` and
  `applied.json`; its bytes are deterministic, so the two-build check is unaffected.
- `sync.lock`: declared, but only while it is empty (`EMPTY_WRITES`). Removing it in the Dockerfile
  was the first choice; that edit was refused by the command grader, and an empty lock file is what
  a real install leaves, so the arm stays faithful to one.
- `.claude/plans`: declared in `HARNESS_DIRS`, accepted only as a directory. The sync makes it and
  the harness ignores it globally; dropping it would make the arm differ from a real install.

Rejected: treating every directory as treatment, or any generic loosening. The pair check is
tightened instead: a non-directory treatment path present in the bare arm is now refused.

## Regression test

`tests/test_replay_install_writes.py`: the five paths as the 59520dd3 manifest lists them are
admitted; an unrelated extra file (`home:.config/git/config`) and an unrelated empty directory are
refused; a non-empty lock and a plans entry that is a file are refused; the bare arm holding the
ignore file is refused. The first test fails before the fix with the five refusal lines.
