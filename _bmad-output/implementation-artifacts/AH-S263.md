# AH-S263 — Name the review-complete signal in /build step 6 and revisit its ten-minute wait

## Story

As an agent running `/build` step 6, I want to know what a finished bot review looks like and how long to wait for it, so that I never report a round as clean before the bot has reviewed it.

## Context and value

On #786, the first run of `/build` step 6 misreported CodeRabbit's second round as clean. When the bot chat-replies in a resolved thread, GitHub wraps the reply in an empty COMMENTED review, and a "new review since T" check fired on it. The reliable signal is the bot's commit status on the head commit: `pending: Review in progress`, then `success: Review completed`. The `Review skipped` status posted on every push is not a pass either. A requested re-review took about 8.5 minutes, and the repository's own instructions put a pass at seven to eleven minutes, so the ten-minute wait was too tight.

## Acceptance criteria

1. **Given** `/build` step 6, **when** an agent waits for the bot, **then** the step names the completed commit status on the head commit (`success: Review completed` for CodeRabbit) as the only sign a pass arrived.
2. **Given** a bot thread reply, **when** GitHub records an empty review, **then** the step says it is not a pass; **given** a `Review skipped` status or no review starting, **then** the step requests a pass with the bot's own review command before waiting.
3. **Given** the wait, **when** an agent reads step 6, **then** it waits up to fifteen minutes, not ten.
4. **Given** the 40-line command body cap, **when** the change lands, **then** `build.md` still fits it and no other step changed.

## Design

### Approach

Rewrite step 6 of `primitives/workflows/build.md` in the same seven lines: shorten the bot-detection clause, add one sentence naming the completed head-commit status as the pass signal and the two false signals, and raise the wait to fifteen minutes. Regenerate `claude/commands/build.md` with `bin/harness generate`.

### Decisions and alternatives

- Decided by the owner on 2026-09-26: build the issue as filed, naming the commit-status signal and allowing fifteen minutes, which matches the repository's own seven-to-eleven-minute figure plus margin.
- Name the signal generically ("the bot's status on the head commit completes") with CodeRabbit's text as the example, since step 6 also serves Greptile and other bots. Rejected: a CodeRabbit-only rule, which would leave other bots with no signal.
- Stay inside the cap by tightening step 6's own wording rather than reflowing other steps, which later builders in the same release depend on.

### Do not implement

- No change to `land.md`, `AGENTS.md` or any other `/build` step.
- No polling script or hook; the step stays prose.
