## Story

As a developer or an agent, I want one command that brings the Studio up, reports where it is and takes it down, so that opening the UI never needs setup.

## Context and value

One command brings the Studio up for a developer or for their agent. `citizen studio` starts a standard-library HTTP server bound to 127.0.0.1, serves the UI's static directory and a JSON API, prints the URL and opens it in the default browser. `--no-open`, `--port`, `--detach`, `--json`, `citizen studio status` and `citizen studio stop` make it scriptable. Until the front-end story lands, the static directory holds a placeholder page.

## Acceptance criteria

1. Given no Studio running, when `citizen studio --no-open --json` runs, then it prints one JSON object with the URL, port and pid, and the URL serves the static directory.
2. Given a Studio running, when `citizen studio` runs again, then it reuses that instance and prints its URL instead of starting a second one.
3. Given `--detach`, when the terminal closes, then the server keeps running, and `citizen studio stop` ends it and removes its state file.
4. Given SIGINT or SIGTERM with event streams open, then the server exits within two seconds and leaves no child process behind.
5. No flag binds beyond loopback, and a port in use falls back to a free one and says so.

## Design

### Approach

Add a small `harness_core.studio` package with a threaded loopback HTTP server and a
descriptor-anchored instance store. The public CLI starts the server in the foreground by default,
or relaunches the same executable in a new session for `--detach`; both paths publish the same
versioned state and return the same result shape. Status, reuse and stop all require PID-start
identity plus an authenticated control-health handshake before trusting the state file.

The server serves a deliberately minimal committed placeholder directory until AH-S283 replaces it
with the reviewed application bundle. It exposes only static GET/HEAD plus private health and stop
control routes; domain JSON APIs, browser sessions and event streams remain later stories.

### Decisions and alternatives

- Keep lifecycle and state mechanics in `lib/harness_core/studio/`; `bin/harness` only parses CLI
  arguments, reports results and opens the browser. This preserves AD-25's shared-core boundary.
- Anchor the state directory, lock and state file with no-follow descriptors. Hold the exclusive
  lock descriptor for the server lifetime and atomically replace a mode-0600 JSON state file.
- Use a random control credential in the state file for the private health and stop handshake.
  This is process control from AD-31, not the browser bootstrap/session security owned by AH-S282.
- A requested occupied port falls back to an ephemeral loopback port and records both the requested
  port and the fallback in the public result. No option accepts a bind address.
- Use daemon request threads and non-blocking server close so SIGINT/SIGTERM can terminate within
  two seconds even when a client keeps a connection open.

### Do not implement

- Browser bootstrap, cookies, Host/Origin/CSRF/CSP enforcement and redaction (AH-S282).
- The final React workspace or bundle verifier (AH-S283), shell, tokens or components (AH-S284).
- Domain APIs, SSE replay/live updates, drafts, experiments and run supervision.

## Review findings

- Architecture review: AD-25 required an owned route and response-schema registry rather than
  conditionals embedded in the HTTP handler. Resolved with an explicit duplicate-refusing registry,
  a closed AD-25 parity-exemption vocabulary, schema-checked success responses and registry contract
  tests.
- Quality review: startup signals now cover binding through serving, concurrent launch losers reuse
  the validated winner, unsupported methods use the registry error contract, and owned state
  directories and lock files are permission-checked before use. Added race, identity, browser,
  protocol and unsafe-inode regressions.
- Follow-up review: signal shutdown now covers handler installation itself, and concurrent reuse
  reports the winner's URL without misattributing a requested-port fallback to the losing process.
