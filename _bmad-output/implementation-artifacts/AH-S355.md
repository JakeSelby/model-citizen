## Story

As a developer, I want a draft's configuration to reach the replay arm, so that testing a draft measures a changed mode, stance, switch, identity or personal module, not only a source edit.

## Context and value

Testing a draft replays it against its base. The benchmark builds the harness arm from the commit's defaults, so the Studio refuses a draft whose configuration was edited (`replay_target_config_unsupported`): the arm cannot apply the change you want measured. This story is the engine side: `scripts/replay_arms.py`, the arm image and admission build the harness arm from the draft's configuration.

## Acceptance criteria

1. Given a draft whose configuration differs from the one it inherited, the replay engine builds the harness arm with that configuration applied, and the run records the configuration digest it measured.
2. The arm image carries the draft's configuration and nothing of the host's own configuration, credentials or home directory.
3. Admission accepts a configuration-edited draft only when the configuration resolves strictly (manifests, switches, modes), and refuses one that does not with a named reason.
4. A draft with an inherited or empty configuration runs exactly as the arm does today, with the same digests.
5. Tests cover each criterion, including a refused configuration.

## Design

### Approach

A replay target that names a draft carries the draft's configuration and its digest. When the digest differs from the inherited one, the harness arm's build context includes that configuration and the arm image installs it as the arm's user configuration before the sync, so the measured arm is the draft's selection. Admission resolves the configuration strictly before the build and records its digest in the run's declaration.

### Decisions and alternatives

- Build the configuration into the image rather than mount it at run time, so the declaration and the image digest name what was measured.
- Refuse a configuration that does not resolve rather than drop keys from it.

### Do not implement

- The Studio's refusal: #1270 lifts it.
- Anything from the host's own configuration, secrets or credentials in the arm.

## Tasks

- [ ] Carry the draft's configuration and digest from the replay target into the arm's build inputs (AC: 1)
- [ ] Install it in the arm image with no host state (AC: 2)
- [ ] Resolve it strictly in admission and refuse with a named reason (AC: 3)
- [ ] Keep inherited and empty configurations identical to today (AC: 4)
- [ ] Tests for each criterion (AC: 5)
