## Story

As the maintainer running a replay with config arms, I want `summarise` to report every arm and
compare each against bare and against the harness default, so that a maintainer or frugal-tiering
arm can be measured and reported, not only run.

## Context and value

#1183 added `--arm-config` arms and rows record `arm_config`, but `summarise` refused any arm other
than bare and harness, so a config-arm run could not be reported. The diff judge (#1185) reads a
saved `<task>-<arm>-<rep>.diff` when one exists and otherwise falls back to the stream's edit calls,
which miss shell-made changes. Part of #1175.

## Acceptance criteria

1. **Given** rows with bare, harness and a config arm, **when** `summarise` runs, **then** it reports
   each arm's pass rate and Cost-of-Pass, the reliability section over every arm, and each arm's
   paired task-clustered comparison against bare and against harness: Cost-of-Pass ratio and
   pass-rate difference with intervals, and oracle-metric differences.
2. **Given** rows from two strata, **when** `summarise` runs, **then** every section, the
   comparisons included, is reported per stratum and not pooled.
3. **Given** any such run, **then** the SM-2 verdict is harness against bare, and a config arm's
   comparison is labelled secondary unless the pre-registration's **Primary arm comparisons** field
   names it; naming one the run does not make is refused.
4. **Given** `--raw`, **when** a run finishes, **then** its final tree's diff against the task's base
   commit is saved as `<task>-<arm>-<rep>.diff` beside its stream, and the row records `diff_path`
   and `diff_bytes`, or `diff_error`.

## Design

### Approach

`replay_stats.analyse_arms` validates every arm on one trial set, then runs `analyse` once per
comparison pair (every arm against bare, every config arm against harness) and labels each with its
role. `cost_bench.summarise_arms` is dispatched from `cmd_summarise` when the rows name an arm
beyond bare and harness; it prints SM-2's report unchanged, then the every-arm section, per-pair
oracle metrics, the delegation verdict and reliability. Strata reuse `summarise_strata`, which
already calls `cmd_summarise` per stratum. `save_diff` runs after the launch, before scoring.

### Decisions and alternatives

- A two-arm set keeps its exact report; only rows with a config arm take the new path, so history
  rows and the evidence bundle are untouched.
- The primary list lives in a new optional template field under Run, read the way **Pooled
  analysis** is; it is not a required field, so earlier plans stay valid.
- The diff uses a fresh Git directory borrowing the tree's objects and a throwaway index, rather
  than Git in the tree, because the agent can write the tree's `.git/config` and a filter,
  fsmonitor or diff driver there would run on the host. The workdir is a host mount, so the diff
  is taken after the container exits and before the tree is removed.

### Do not implement

- No history row for config-arm runs, no Pareto plot of more than two arms, no multiplicity
  correction across the secondary comparisons.
