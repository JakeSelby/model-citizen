## Story

As a developer, I want the Studio to show and launch the definitive evaluation, so that I can see the multi-arm, stratified results and scorecard the v0.15 engines produce without dropping to the CLI.

## Context and value

v0.15.0's definitive evaluation epic (#1175) added engine capabilities the Studio could not present or launch: pack v1.1 and its rule-targeted and public outcome sets (#1176, #1178, #1179), config and removal arms (#1183, #1184, #1245), multi-model strata (#1182, #1233), the long-session tier (#1193, #1232), named metrics with declared directions (#1143, #1220), the cache basis (#1174), equivalence bounds (#1181, #1226), the diff-quality judge (#1185, #1236) and the layer scorecard (#1186, #1241). The generic analysis view already showed new `summarise` fields; this story covers the parts that needed Studio work. The definitive run's own design and budget (#1187) are not decided, so the launch path is built to refuse until a registered budget exists.

## Acceptance criteria

1. Given a run with three or more arms or per-model strata, the run and compare views show each arm and stratum as the engine reports it, with no Studio-computed values.
2. The replay form selects pack v1.1, the rule-targeted task set and the public outcome subset by name, version and digest, pinned as #1062's pack picker pins packs.
3. The layer scorecard and diff-quality judge verdicts appear on run detail exactly as the engine generates them, with a CLI parity fixture.
4. The spend guard respects the registered design and budget of the definitive run (#1187) and refuses a launch that exceeds it.
5. Per-task metrics declared by a pack (#1143) and the cache basis (#1174) show on run detail as the engine reports them, and the compare view uses the pack's declared direction rather than a Studio table.
6. Long-session rows (#1193) index under their session id without colliding with replay row identity.
7. Informative nulls (equivalence bounds) read as "equivalent within bounds" only when the engine says so, never inferred by the Studio.

## Design

### Approach

- **Run store (AC 1, 6).** Read every `results.jsonl` up to three folders below `benchmarks/`, so each stratum folder a multi-model run writes (`<version>/<tag>/<model>/results.jsonl`) is indexed. `evaluation.row_contract` reads a row whose `arm_config` stamp names its own arm as a `config-arm` contract, so a config arm is indexed instead of refused. A long-session row's identity adds `row_kind` and `checkpoint_index`, and its case is `<session_id>/<row_kind>/<checkpoint_index>`; a row without `row_kind` keeps the identity and case it had.
- **Run detail (AC 1, 3, 5, 7).** An imported benchmark row's detail carries `engine_row`, the engine fields `evaluation.ENGINE_ROW_FIELDS` names (stratum, strata, arm config, metrics, metric directions and errors, cache basis and nonce, saved diff, long-session keys), verbatim. `definitive.engine_reports` finds the `scorecard.json` that `layer_scorecard.py --out` wrote and a `judge/` folder in the row's folder or a parent up to `benchmarks/`; the scorecard is shown as written, and the judge as `replay_judge.py report --json` prints it. Both render as hairline tables of every leaf; an engine equivalence verdict (`assessment`, or `verdict` inside `equivalence`) adds the reading of the engine's own word, and only `equivalent` reads "Equivalent within bounds".
- **Pack sets (AC 2).** `packs.discover` offers one entry per production-tier set of each pack, each with name, version, commit, digest and set. A selection naming a set pins it and the native command carries `--pack-set`; a selection naming none keeps the identity, command and comparison key it had.
- **Registered budget (AC 4).** A pre-registered replay reads its budget from the plan's Guardrails **Spend** field through `experiment_protocol`'s readers (`<n> USD per run` and `a whole-run cap|stop of <n> USD`). With no readable budget the launch is refused (`replay_budget_unregistered`); a per-run budget, spend cap or spend-guard estimate above it is refused (`replay_budget_exceeded`) at preview and again at start. The form shows the registered budget.

### Decisions and alternatives

1. **The registered budget is read from the pre-registration's Spend field.** No engine writes a machine-readable design or budget yet (#1187 is undecided), and the plan is what `cost_bench` admits a run under. Alternatives: a Studio default budget (refused by the brief) or a new design file format (would invent an engine contract).
2. **Every pre-registered replay respects its registered budget, not only one named definitive.** The Studio cannot tell which plan is the definitive one until #1187 lands; a registered run spending past its own plan is wrong for any plan.
3. **Scorecard and judge are found beside the rows, nearest folder first.** The nearest folder holding a document decides it; a broken one is an error, never a reason to show a farther one.
4. **The compare view is unchanged.** It already returns `replay_stats.compare` verbatim and overlays the pack's declared directions (`compare.preferred`); the two built-in measures keep the evidence standard's table because the engine declares no direction for them.

### Do not implement

- No runner for the full definitive design (several arms and models in one Studio launch); the launch is the existing replay path behind the registered budget.
- No default budget, and no paid run, in code or tests.
- No Studio-computed interval, verdict, ratio or direction.
- No product.json line.
