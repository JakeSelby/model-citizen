## Story

As the harness maintainer, I want the standing context the harness adds to every API call trimmed,
each change landed separately and measured, so that the harness's fixed per-call overhead shrinks
without changing which skills fire.

## Context and value

The issue measured 12,607 extra tokens in every API call against a bare profile, stable to within 15
tokens across eight task pairs, and reported that prefix as the whole of the harness arm's cost gap on
the first live set. That first set was later recorded as contaminated by the runner's sandbox fence and
a test-suite leak (#369), so the gap itself is not a clean figure; the prefix measurement is the part
this issue rests on. The issue also argues the prefix does not amortise on long tasks: it is re-read
alongside a growing conversation. The measured figure became the lint's always-loaded token cap in PR
#474 (`ALWAYS_LOADED_TOKEN_CAP`, a third of the measured standing context).
[Source: https://github.com/JakeSelby/agent-harness/issues/430]

The issue names three separable changes with a combined ceiling of about 25%:
1. defer the action-gated rules and stances behind the hooks that fire on the act (about -1,474 tokens);
2. trim the output style (about -900);
3. trim the 17 added skill descriptions (about -750).

## Acceptance criteria

1. **Given** the three changes, **when** each lands, **then** it lands separately with a recorded
   history row.
2. **Given** the trims, **when** they are measured, **then** the live prefix drops, stated as a measured
   number from a session transcript and never as an estimate from `benchmarks/static.json`.
3. **Given** trimmed skill and agent descriptions, **when** they change, **then** a before-and-after
   check on triggering accompanies the token count (the issue's "Risk" section).

## Design

### Approach

- **Changes 2 and 3** (delivered in PR #589 under #588) [Source: PR #589]: the `scannable` output style keeps all nine
  of its rules and loses its worked examples and register table; fifteen skill and eleven agent
  descriptions lose capability restatements and keep every trigger condition and literal user
  phrasing. A test freezes the trigger phrases per primitive.
- **Change 1** is framed as an unrun spike, `docs/spikes/2026-09-22-deferred-rule-text.md`, with a
  numeric exit criterion written before any run. Nothing is implemented for it.

### Decisions and alternatives

- **Change 1 is an architecture change and gets its own spike** (issue text): the rules layer has not
  adopted the defer-behind-a-hook pattern that `grade-bash` and `brief-guard` use.
- **History rows for static trims live as a table in `docs/benchmarks.md`** (PR #589):
  `benchmarks/history.jsonl` holds replay ratios and cannot take a static row.
- **Trigger phrases are frozen by test** rather than trusting token count alone (PR #589).

### Do not implement

Not recorded in the issue or pull request.
