## Story

As the maintainer measuring what a rule changes, I want an oracle check to return named numeric metrics beside pass or fail, so that correctness, conciseness and similar behaviour land on the same replay rows and are reported per arm.

## Context and value

The replay oracle contract admitted only pass or fail, which cannot show a behaviour change that leaves the pass rate alone. The behaviour graders of #1177 build on this contract, so it is their prerequisite on v0.15.0.

## Acceptance criteria

1. **Given** a task declaring `metrics` with a direction each, **when** its check returns `{"pass": bool, "metrics": {name: number}}`, **then** the row records each metric and its direction and `summarise` reports it per arm and per task with the task-clustered interval SM-2 uses.
2. **Given** a task declaring no metrics, or a check returning the original error list, **when** it is scored, **then** the row carries no metric field and the summary is unchanged.
3. **Given** a declared metric that is not a finite number, **when** it is scored, **then** it is recorded as null with its reason, never as 0.
4. **Given** an unknown direction or a malformed verdict, **when** the task loads or the check returns, **then** the task is refused or the attempt is a check error.

## Design

### Approach

A new `scripts/oracle_metrics.py` holds the declaration check, the verdict parser, the row fields and the per-arm report. `cost_bench.score` hands the check's JSON line to it, `_attempt` stamps the fields only for a declaring task, and `cmd_summarise` adds a `metrics` key beside SM-2's result. `replay_pack` validates and carries a pack task's declaration.

### Decisions and alternatives

1. Directions are declared in the task, not returned by the check, so a run cannot flip how a metric reads; rows carry them so `summarise` needs only the rows.
2. A malformed verdict or undeclared metric raises, making the attempt a check error; a bad value of a declared metric is unknown. Alternative rejected: recording a fail, which would blame the agent for a broken check.
3. The difference interval reuses SM-2's seed, resamples, method and percentile rank over tasks with a known value in both arms, rather than a new estimator.

### Do not implement

The #1177 behaviour graders and their reference tasks; metrics in pair, ablation or two-by-two reports; any edit to the evaluator pack repository.
