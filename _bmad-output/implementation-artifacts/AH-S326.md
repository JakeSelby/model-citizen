## Story

As a developer, I want to show calibrated compliance judge evidence in Studio, so that the Studio supports the engines delivered in its milestone.

## Context and value

Deliver Studio views of the v0.17.0 compliance judge evidence alongside its calibrated engine, without making the view an authority to change policy.

## Acceptance criteria

1. A judge result shows its compliance pack, calibration identity, measured agreement/bias limitations and source evidence; uncalibrated or unavailable evidence is labelled explicitly.
2. Provider/model and recorded judge cost are preserved, with unknown values distinct from zero.
3. CLI and Studio show the same results and evidence labels for fixed fixtures, without pooling soft estimates with measured effects.
4. This report does not implement stance promotion proposals; those remain with #996/#692 in v0.18.0.

## Design

### Approach

Adapt the existing Studio core and CLI contracts after the listed engine dependencies land. Preserve native result files as authority, keep UI actions on the same governed path as the CLI, and record capability availability explicitly. Detailed file-level design belongs to the future implementation session.

### Decisions and alternatives

Deliver this integration in the engine's milestone rather than postponing it to an unspecified UI release. Keep feature ownership separate from the cross-cutting post-Measured integration gate.

### Do not implement

Do not duplicate engine analysis or change live configuration outside governed apply. This roadmap filing does not implement the capability or authorize a release.
