## Story

As a harness user, I want the record my evals read kept out of my agents' reach and tamper-evident, so that a score can't rest on a transcript an agent rewrote.

## Context and value

Every eval reads the record after the session, and today the record is in the agent's reach: plain files any agent with a shell can edit, no deny rule covers them, and the harness's logs are append-only by convention only. The Hugging Face swarm showed the incentive: believing the grader read their transcripts, agents spoofed tool calls in at least 96 of them and tried to edit or delete logs. A shell write can't be caught by pattern alone, so a hash chain backs up the block.

Part of AH-E027 (#1175): the evaluation's numbers rest on the record.

## Acceptance criteria

1. **Given** an agent's write, edit or shell command that changes a transcript or a harness log, **when** it is attempted, **then** the action is denied with the rule named.
2. **Given** a transcript edited after its session ended, **when** the evals read it, **then** they report the break and do not score the session.
3. **Given** an untouched session, **when** the evals read it, **then** the chain verifies and scoring proceeds as today.
4. **Given** Claude Code and Codex, **when** the protection is installed, **then** both are covered and any gap is named per runtime.
