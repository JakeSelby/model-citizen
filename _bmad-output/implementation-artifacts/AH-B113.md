# AH-B113 — test_worker_context_budget rewrites a tracked role file in the real checkout

## Reproduction

1. Run `python3 -m unittest discover -s tests` in a checkout.
2. While `ResolutionTests.test_a_renamed_skill_directory_refuses_the_spawn_and_fails_the_run` runs,
   read `primitives/roles/design-judge.md` from any other process: it declares
   `skills: design-loupe`.
3. Observed on 2026-09-26: a second suite run in the same checkout failed `test_sync_renders_agents`
   with `role declares an unknown skill: design-loupe`. In the checkout that `sync` links into the
   home directory, a live spawn or sync in that window reads the broken role as well.

## Root cause

The test proved its point by rewriting the tracked role file under `REPO` and restoring it in
`finally`. The file is shared state: every other reader of the checkout sees the edit for as long
as the test runs, and a killed run leaves it broken. `lifecycle.constrained_role` reads the role
through the module-level `ROOT`, and `workers.resolution` through its `root` argument, so the test
needed a root of its own, not the checkout's.

## Acceptance criteria

1. **Given** the full suite, **when** it runs, **then** no test writes `primitives/roles/design-judge.md`
   or any other tracked file, and `git status --short` is empty afterwards.
2. **Given** a role whose declared skill directory does not exist, **when** the native spawn guard
   reads it, **then** it still returns a constrained contract, and **when** a worker resolves it,
   **then** resolution raises `unknown skill`.
3. **Given** the same broken root, **when** the guard reads `builder`, **then** it is still not
   constrained.

## Design

A helper, `broken_role_root`, builds a temporary root: every top-level entry of the checkout and
every `primitives` entry except `roles` is a symlink, and `primitives/roles` is a copy whose named
role has one line replaced. The test patches `lifecycle.ROOT` to that root for the guard and
passes it to `workers.resolution`, so both readers run their real parsing against the broken
role. Rejected: patching `catalog.role_contract`, since `GuardTests` already covers that path and
it would stop proving that the real parser rejects the renamed skill. Rejected: copying the whole
checkout, which is slow and unnecessary when only the role tree changes. Product code is unchanged.

## Regression test

`tests/test_worker_context_budget.py`,
`ResolutionTests.test_a_renamed_skill_directory_refuses_the_spawn_and_fails_the_run`, now also
asserts that the checkout's `design-judge.md` still declares `skills: design-loop` after the
run. The acceptance evidence is a full suite run followed by an empty `git status --short`.
