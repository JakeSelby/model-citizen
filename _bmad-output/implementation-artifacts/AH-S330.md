## Story

As a user running the tiered delegation stance, I want a Workflow script's `agent()` calls that
name a frontier model refused at launch, and those past my cost variant's ceiling logged, so that a
script cannot quietly run agents on a frontier model and I can count the ones that ran past it.

## Context and value

FR-30 routes unnamed spawns to a band, but a Workflow script's `agent()` calls never reach
`tier-agent-spawns`, and the call cannot be rewritten. #576 guarded the launch (logging, the
`delegation: off` refusal and constrained roles) and FR-30 still cited it for the routing gap. The
#540 spike suggested the launch read check the `model` or `effort` a script names against the cost
variant. This story adds that check within AD-14 and moves FR-30's status line to #915.

## Acceptance criteria

1. **Given** `delegation: tiered`, **when** a script's `agent()` call names a literal `model` whose
   class, through the adapter's model table, is `frontier`, **then** the launch is refused with the
   model to use instead, in the launch guard's style and on its `workflow-launch` row.
2. **Given** any delegation stance but `off`, **when** a script names a literal `effort` above the
   variant's highest row effort (never past `high`, on the ladder low, medium, high, xhigh, max),
   or under `delegation: tiered` a non-frontier class above the variant's strongest row class,
   **then** the launch goes ahead and its row answers `over-ceiling`.
3. **Given** a key, an assignment or an escaped key such as `mod\u0065l`, **when** it carries a
   literal, **then** it is judged as the plain form; a comparison or prose mention is not read.
4. **Given** a computed value, a shorthand property, a model the table does not hold or an effort
   off the ladder, **when** the launch runs, **then** it is let through and its single
   `workflow-launch` row answers `unresolved`, unless another value answers `over-ceiling` or a
   refusal.
5. **Given** `delegation: off`, **then** the existing refusal of every launch is unchanged, and a
   model outside `delegation: tiered` is not judged.
6. **Given** FR-30, **then** its status line cites #915 for the routing gap, with a memlog entry.

## Design

### Approach

`lib/harness_core/lifecycle.py` gains `workflow_options` (the literal and unresolved `model` and
`effort` values, read as written and with escapes decoded, as `workflow_role` reads a script),
`workflow_ceiling` (the variant's strongest class and highest effort from `posture.table_for`, and
the adapter's `{class: model}` table) and `workflow_limits` (the frontier refusal, the
over-ceiling list and the unresolved list). `workflow_results` calls `workflow_limits` when no
constrained role was refused, and writes the row's answer as `deny`, `over-ceiling`,
`unresolved` or `allow`, in that precedence.

### Decisions and alternatives

- **AD-14 stays as adopted, decided 2026-09-29:** for cost, hooks route unnamed spawns and refuse
  an undeclared `frontier` request, and no hook denies for cost. So the launch refuses only a
  frontier model; an effort above the variant's highest (`xhigh` and `max` with the shipped
  variants) and a non-frontier class above a custom variant's strongest are logged as
  `over-ceiling`, a distinct answer so `citizen usage` can count them apart from `unresolved`.
- Rejected: refusing every value above the variant's ceiling, the first implementation, because
  it denies for cost past AD-14's two enforcements.
- The ceiling is the strongest row the variant grants, not the default band, because a script
  may do any band's work and a named band worker may run at its own row.
- A cost table that cannot be read falls back to the stances' own ceiling, `strong` and `high`,
  never an open one.
- A model is matched to a class by the table's name appearing in the literal, so `claude-opus-4-1`
  reads as `opus`; any other name is unresolved rather than guessed.
- Rejected: refusing what cannot be judged, which would refuse ordinary scripts that choose a
  model at run time.
- Rejected: rewriting the call, which the spike found impossible.

### Do not implement

- Routing a script's agents to a band, or any change to `tier-agent-spawns`.
- Usage-ledger separation of workflow spend (the spike's second follow-up).
