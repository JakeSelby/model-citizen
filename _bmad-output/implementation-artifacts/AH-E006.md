## Delivery amendment — 2026-09-28 (#1061)

Current delivery: **v0.18.0**. Earlier milestone references below are historical and superseded by [the roadmap amendment](../planning-artifacts/roadmap-2026-09-28.md). Capability status is unchanged.


## Goal

Turn the repository's clearer positioning and reproducible first run into sustained, evidence-led
developer adoption. Completion is observable in what the issue says to measure: usable attempts, repeat
use and actionable feedback, rather than impressions alone.

The issue's principles:

- Demonstrate one preference projecting into multiple runtimes, with inspectable output.
- Recruit direct testers before broad promotion.
- Fix observed onboarding friction before scaling channels.
- Measure usable attempts, repeat use and actionable feedback.

## Scope and requirement coverage

**In scope:** the two-runtime proof and demo, a direct tester cohort, a staged launch, and the adoption
work the 2026-09-21 amendment pulled forward: the standalone measurement package, the plugin manifest,
the packaged install path and the importer. These run as child epics AH-E008, AH-E009 and AH-E010. Later
children add the enterprise-review intake fixes (#516 to #527), the selection-model epic AH-E011, and the

amendment narrows that: anything that depends on the stable CLI contract still waits for v1, and work that
touches neither the v1 support floor nor the qualification matrix runs earlier.

## Architecture slice

- **AD-19 Distribution channels carry no second authority:** the plugin carries no hooks, the installer
  installs from `stable`, and landing, README and About copy come from `product.json` only. This covers
  AH-E008's channels and the copy work in AH-E010 and #648.
- **AD-13 Detector logic lives in `ruleprobe`:** the harness vendors a pinned `ruleprobe` wheel (AH-E009).
- **AD-12 Measurement invariants:** unknown and unpriced values are never zero (#517). The benchmark runner
  that #525 records beneath is also governed here.
- **AD-1 Shared primitive authority:** the tier restriction is recorded per runtime as `enforced`,
  `advisory` or `none` in `capabilities.json` (#520).
