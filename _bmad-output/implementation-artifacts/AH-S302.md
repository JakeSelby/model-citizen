## Story

As a developer, I want to see and confirm what a run will spend, with caps that stop it cleanly, so that measurement never surprises me on cost or limits.

## Context and value

A run that spends usage shows, before it starts, an estimate from past runs of the same suite and scale, the caps it will run under (`--max-budget-usd` per run and `--spend-cap` for the set), and whether it spends API credit or a subscription plan's limits. The developer confirms each such run. At a cap or a usage-limit error the run stops cleanly, keeps what it finished, and says why.

## Acceptance criteria

1. Given a suite that spends usage, then no process starts until the developer confirms the shown estimate and caps.
2. Given a run that reaches its cap, then it stops, records the finished cases and marks the rest as not run.
3. Given a usage-limit error from the client, then the run stops and reports the limit, not a failure.
4. The run's spend appears in the usage ledger under the run's ID.
