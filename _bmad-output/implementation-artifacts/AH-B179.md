## Reproduction

`uvx --from plugin-scanner==3.12.2 plugin-scanner scan <checkout> --format json` scored `main` at
1e06ce2e 83/100 (B) with 0 critical and 7 high findings: `HARDCODED_SECRET` on
`tests/test_cost_bench.py:194`, `tests/test_detector_narrowing.py:28` and
`tests/test_jev_outbound_controls.py:485`, each reported once per ecosystem, and
`RISKY_SKILL_INSTRUCTION` on `primitives/skills/sandbox/SKILL.md`.

## Root cause

Each is a false positive, from two kinds of cause. The scanner's provider shape (`sk-ant-` and 20
more token characters) and its generic shape (`secret`, `api_key` and kin, `=` or `:`, a quoted
literal of eight or more characters) are right; the fixtures wrote a stand-in token, a rule id under
the name `SECRET` and a placeholder key as one quoted literal each. The skill check is wrong: it
matches the SSH directory's path anywhere in a `SKILL.md`, so the sandbox skill's `denyRead` entry
reads as an instruction to read the keys. It cannot be fixed in this repository.
[Source: plugin-scanner 3.12.2 `checks/security_secret_patterns.py`, `checks/skill_security.py`]

## Acceptance criteria

1. **Given** this checkout, **when** the pinned scanner scans it, **then** it reports 0 critical
   and 0 high findings.
2. **Given** each rewritten fixture, **then** it holds the same value at run time and exercises the
   same code path.
3. **Given** the near miss of each false positive, **when** the scanner or the repository's mirror
   of its shapes reads it, **then** it is still flagged.
4. **Given** the sandbox skill, **then** its example settings still deny reads of the SSH, AWS and
   GitHub CLI credential directories.
5. **Given** any tracked file, **then** it holds no secret shape, and no `SKILL.md` names SSH key
   material.

## Design

The token stand-in is split into two literals that concatenate to the same value; the rule id is
renamed `SECRET_RULE`; the placeholder key is bound to `PLACEHOLDER_KEY` and passed by name. The
sandbox skill's settings example moves, unchanged, into `primitives/skills/sandbox/claude-settings.json`,
which the skill links and the Claude Directory bundle lists; the skill says why. Rejected: a
JSON-escaped dot or a wildcard deny, which hide the path or change what is denied; a
`.codexignore`, which the scanner ignores. Must not change: the deny list's entries.

## Regression test

`tests/test_plugin_scan_hygiene.py` pairs each fixed fixture with its near miss under a mirror of
the scanner's shapes, checks every tracked file and `SKILL.md`, the sandbox deny list and the split
stand-in's run-time value. Its shapes, run over `main`'s tracked files, find exactly the four
sources above and nothing else.
