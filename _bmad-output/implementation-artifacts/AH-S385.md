## Story

As a user who answers many decisions per session, I want every question waiting on me on one
private page I answer by clicking, so that I can accept a recommendation, reword it or write my own
without typing a reply per item, and nothing is applied until I say so.

## Context and value

Decisions are numbered blocks in chat, answered by typing, and the always-loaded
`decisions-and-plans` rule forbids a chooser widget. A maintainer-built page (cards with why, what
it unblocks, options with the recommendation badged, accept-all, free-text override, answers in the
page's database) proved the shape. A reasonable user could prefer either, so it is a stance, not a
rule change, and the default keeps today's behaviour.

## Acceptance criteria

1. **Given** no selection, **when** stances resolve, **then** `decisions` is `numbered-block`, whose
   text carries the rule's former "no chooser widget" line word for word.
2. **Given** `citizen config set stances.decisions decision-page`, **when** sync runs, **then** the
   variant and the `decision-page` skill are linked into the runtime.
3. **Given** the rule after the move, **then** its other three lines are unchanged.
4. **Given** the skill, **then** its template has a generic title, no project content, owner-only
   rules, and reads `content/*` and writes `answers/<item id>` with `choice` and `text`.
5. **Given** `decision-page`, **when** a plan is posted, **then** the Review Card keeps numbered
   decisions and the message links the page; the typed reply is the default's path only.
6. **Given** the change, **then** lint stays inside the always-loaded cap and the Gate passes.

## Design

### Approach

A new `decisions` stance dimension with `numbered-block` (default) and `decision-page`, registered
wherever a dimension is named (CLI, posture defaults, example config, both adapters, preferences
doc). A `decision-page` skill carries the page contract, item schema, apply step and a bundled
template. `plan-authoring`, the `review-card` plan-ceremony variant and the handoff workflow name
the page path under the variant.

### Decisions and alternatives

- Two variants, no `off`: the minimal mode keeps `decisions` like `cost` and `autonomy`, since how
  a question reaches the user is not ceremony.
- Page-wide "accept every open recommendation shown" control, scoped to the visible section, in
  place of the saved page's per-lane control.
- System fonts in the template, so it loads nothing from a font host.
- The `decisions/no-alternatives` detector stays ungated: items carry alternatives too, and gating
  it would change benchmark applicability.

### Do not implement

- No label or pairwise lane, no page build outside the artifact tool, no secret collection.
