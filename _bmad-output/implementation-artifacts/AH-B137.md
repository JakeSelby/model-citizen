## Reproduction

Run `tests/test_studio_run_history_browser.py`. Opening Experiments requests `/api/runs/catalog`, which spends about 6-7 s discovering the unit suite; `/api/runs/history` queues behind it, and the test fails with "Runs live event did not refresh history". Fails on every run on 7c452414 and b193b659.

## Root cause

`_runs_catalog` called `run_supervisor.catalog` through `handler.server.mutations.call`, the serial executor that owns the supervisor's SQLite connection. Catalog spawns `free_suites.discover_unit_tests`, so every run request waits for discovery. [Source: lib/harness_core/studio/server.py#_runs_catalog]

## Acceptance criteria

1. **Given** a catalog request blocked in discovery, **when** a run-history request arrives, **then** history answers without waiting.
2. **Given** the Studio browser suite, **when** the run-history browser test runs, **then** it passes.

## Design

Catalog is a read that touches no serialized supervisor state (it loads the suite catalog and runs discovery in a subprocess), so it runs on the request thread. History stays on the executor because the index connection lives there. Caching discovery was rejected for now: it needs invalidation on test-file changes and does not remove the head-of-line block.

## Regression test

`tests/test_studio_free_suites.py` `test_slow_catalog_does_not_block_run_history` blocks catalog in a fake supervisor and asserts history answers on the real executor; it fails on the old handler.
