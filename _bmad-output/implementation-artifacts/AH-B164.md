# AH-B164 — fix(security): grade-bash flags quoted text, misses equivalent discards, and drops log rows

## Reproduction

1. Write a probe beside its data, `S=<dir>; cat > $S/cases.txt <<'EOF'` holding a `git push --force` line, then `python3 $S/probe.py $S/cases.txt`: graded 3, because any path with a variable in it was taken to name every file the line wrote.
2. Run an edit script, `python3 - <<'EOF'` whose strings hold `git push --force` or `rm -rf /` but which calls nothing that runs a command: graded 3.
3. After `git checkout -- <path>` is refused, run `git restore --staged <path>`, `git reset`, `git read-tree`, `git checkout <rev> <path>`, `: > <path>` or `rm <path>` on a modified tracked file: each grades 1 and runs.
4. Make the output filter or any later dispatcher step raise after a refusal: the refusal reaches the agent and no decision-log row is written. A grader that runs past the hook's 10-second timeout is killed and the command runs ungraded and unlogged.
5. `ls`, `cat` or a reading `python3 -c` on the approvals store in a line that does anything else grades 3 as a write to the store.

## Root cause

- `_written_names` treated a `_wild` run word as naming every written file, and `_grade_program` graded every string of an interpreter's program as shell text whatever the program calls. A here-document written by `cat` was unknown content, so running any written file fell back to grading the whole line. [Source: policy/hooks/bash-grader.py#_grade_streams]
- `_git` graded only `reset --hard`, `checkout --`/`-f`/`.`, `restore` without `--staged`, `switch -f`, `clean -f`, `stash drop|clear`; nothing modelled `rm` or an empty write of a tracked file. [Source: policy/hooks/bash-grader.py#_git]
- `log_bash_decision` ran after `invoke("filter-output")`, so an exception there skipped it, and `main` turned any dispatcher exception into a deny without a row; grading had no deadline of its own. [Source: lib/harness_core/lifecycle.py#_dispatch]
- `grade_text` graded any non-read-only line that mentioned the store at all. [Source: policy/hooks/bash-grader.py#grade_text]

## Acceptance criteria

1. **Given** a destructive verb only inside a commit message, an argument, a here-document written to a file, or a string of a Python, Node, Lua or similar program that calls nothing able to run a command, **when** graded, **then** it is below 3.
2. **Given** the same verb inside `bash -c`, `sh -c`, `eval`, `xargs`, `$(…)`, a body a shell reads, or a program that calls `subprocess`, `os.system`, backticks (Perl, Ruby) or `exec`, **then** it grades 3.
3. **Given** a repository with a modified, a staged, a clean and an untracked file, **when** any route that discards working-tree or index changes runs, **then** it grades 3 with family `git-discard`; routes that lose nothing stay below 3.
4. **Given** any Bash answer the dispatcher gives (ask, deny, deny offering an approval code, allow on a consumed approval, deny from an error, a grade past the deadline), **then** exactly one decision row is written, carrying `approval`, `timed_out` or `error` where they apply.
5. **Given** grading past its deadline, **then** a destructive verb in the raw text is refused with a reason naming the deadline, and a read-only command stays open.
6. **Given** a line that only reads the approvals store, **then** it is not graded as a write to it; every write route still grades 3.
7. **Given** a program, inline (`python -c`, `node -e`, `perl -e`, `ruby -e`) or read from a body, that names a command runner or a delete in any form (a call, an alias, `map`, `getattr`), **then** its strings are graded as commands; one that may write a file reaching the approvals store grades 3.
8. **Given** a `git -c` or `git config` that changes what a command does (an alias, `clean.requireForce`, `remote.*.mirror`, a program git runs), an option abbreviated or a dry-run flag that is an option's value, a forced ref move (`branch -f`, `checkout -B`, `update-ref`), `--pathspec-from-file` or `apply -R`, **then** it grades as the command it becomes, or 3.
9. **Given** a delete whose path the grader cannot know (a variable, `$(…)`, `xargs`, `find -exec`), a path outside the repository beside one inside, a `cd` on the line, a file marked assume-unchanged or skip-worktree, an untracked file, or an overwrite (`>`, `cp`, `mv`, `tee`, `sed -i` that only deletes) of a modified tracked file, **then** it grades 3.
10. **Given** git status checks that are slow, **then** a line's checks stop well inside the deadline and fail closed, and past the deadline every discard route and status-dependent verb is refused; **given** any grade-3 command, a `HARNESS_CONFIRMED=1` one included, **then** one decision row is written in every permission mode.

## Design

- Item 1: `_written_names` keeps a variable path's literal base name; `_heredoc_inputs` feeds a quoted or expansion-free body to its command as standard input, so `cat > f <<'EOF'` writes known text; `_run_files` tags a script an interpreter runs (`_Program`), and `_grade_streams` grades such a file as that family's program only. `_inert_program` treats the strings of a `TEXT_FAMILIES` program as text unless `CALLS_RE` (process, shell, dynamic-code, destructive database calls) or, outside `NO_BACKTICKS`, `SHELL_SYNTAX_RE` matches. Unknown readers, make, sed and pwsh read as before.
- Item 2: `_git` adds `checkout` of paths (two operands, a pathspec, or an existing path), `--ours/--theirs/-p`, `restore --staged`, `reset` except `--soft`/`--keep`, `read-tree` (not `-n`), `checkout-index -f`, `rm -f`, `worktree remove --force`. `_emptying` grades `git show|cat-file <rev>:path > path` 3, and `rm`, `truncate`, `cp /dev/null` and an empty `>` 3 when `git status` reports working-tree changes for the file (`_dirty_tracked`, two seconds, sixteen calls a process, failing closed).
- Item 3: the log call moves into a `finally` around the output filter; `main` logs the error deny once (`log_bash_error`); `decisions.record` takes `fields` and survives a claim read failure.
- Item 4: `grade_within` bounds `grade_text` with a SIGALRM timer (five seconds, inside the ten-second hook timeout); past it `timed_out` scans the raw text.
- Item 5: `_store_write` walks the simple commands, tainting variables assigned from the store, commands after a `cd` into the state directory and commands fed by a pipe from one that reaches it; only a reaching command that is not read-only, a redirect into the store, a loop header naming it, or a body something runs, is a write.
- Review round (items 7 to 10 of the acceptance criteria): an adversarial review of the first commit found 11 bypasses, two introduced by it. The second commit closes them:
  - any reference to a process runner or a delete makes a program non-inert, including aliased and indirect calls, and inline `python -c`, `node -e`, `perl -e` and `ruby -e` programs are scanned the same way
  - any form of write to the approvals store grades 3
  - `git -c` aliases resolve or grade 3, and risky `-c` and `git config` keys grade 3
  - dry-run flags count only in position, and long options match git's unambiguous prefixes
  - `branch -f`, `checkout -B`, `update-ref -d`, `--pathspec-from-file` and `apply -R` grade 3
  - deletes and emptying writes with unknowable targets grade 3, as does any overwrite of a modified file (`>`, `cp`, `mv`, `tee`, `dd`, an emptying `sed -i`); content writes to a path the grader cannot name stay below 3 (governance tests rely on it), and a program's writes grade like `>`
  - the dirty-file check judges each path on its own, follows `cd`, treats assume-unchanged and skip-worktree as unknown, and grades untracked deletes like `git clean -f`
  - git checks on one line stop after 2 s in total and fail closed, and the past-deadline scan covers every discard route
  - the confirmed path logs its row
- Review round two (9 bypasses, 3 false refusals; the third commit):
  - every git process the grader starts runs hardened: `--no-pager`, `-c core.fsmonitor=false`, `-c core.hooksPath=/dev/null`, every filter driver the repository defines switched off by name, no inherited `GIT_*`, `PAGER` or `EDITOR`, and `GIT_CONFIG_NOSYSTEM=1` with `GIT_CONFIG_GLOBAL=/dev/null`; the alias lookup alone keeps global configuration, since it only reads it
  - a write into `.git/config`, `.git/hooks`, `.git/info` and the like, `chmod +x` there included, grades 3, as do `git config` keys that run commands (any `*.textconv`, `filter.*`, an `alias.*` starting with `!`)
  - a variable that runs a command (`GIT_SSH_COMMAND`, `GIT_EXTERNAL_DIFF`, `GIT_PAGER`, `PAGER`, `EDITOR`, any `GIT_CONFIG_*` and the like) set for a command, through `env` or by `export` grades 3; a pager or editor of `cat`, `less` or `true` does not
  - an interpreter program that deletes a file it cannot name, a tracked file or one holding work, or writes over one it cannot name or one holding work, grades 3; `node -pe`, `deno eval` and `python -m <module> <code>` hand their program on
  - `cd` through a line's own variable, `builtin cd` and `command cd` are followed, and `env -C` makes relative paths unknowable; `rsync`, `ln -f` and `git mv -f` over modified files, `patch -R`, `git send-pack --force` and a forced fetch into a local branch grade 3
  - index-only `git reset` and `git restore --staged` grade 1; `rm -f *.o` asks git about the glob; one line asks git three times per repository (configuration, status, file list), whatever number of paths it names
- Rejected: grading a plain file write (`open(..., 'w')`) inside an edit script, which is the routine way these sessions edit files. A program's write grades as `>` does (3 only over work or a path it cannot name), and one that writes back what it read is an edit, as `sed -i` is. Also rejected: grading `rm` of a clean tracked file, which git restores; and a thread-based deadline, because a long regex holds the interpreter lock.
- grade-bash is an accident guard over a blocklist, not a security boundary; `docs/runtime-controls.md` says so, and names OS sandboxing as the boundary.

## Regression test

`tests/test_grade_bash_quoted_text.py`, `tests/test_grade_bash_discard_routes.py`, `tests/test_grade_bash_decision_log.py` and `tests/test_grade_bash_review_bypasses.py`. Each fails against the previous `main` and passes after the fix; the last one covers every review bypass of both rounds by its exact command, and proves a planted fsmonitor hook and clean filter run under plain `git status` but not while the grader asks. `tests/test_grade_bash.py` and the discard-routes test keep `git restore --staged --worktree` at grade 3 and move index-only `git reset` and `git restore --staged` to the routes that keep the work; the discard-routes test lists `rm` of an untracked file.

## Dev notes

Files: `policy/hooks/bash-grader.py`, `policy/hooks/grade-bash.py`, `policy/hooks/decisions.py`, `lib/harness_core/lifecycle.py`; `claude/hooks` is a link to `policy/hooks`, so `bin/harness generate --check` stays clean. The dirty-file check runs `git status --porcelain=v1 -z` (untracked and ignored files included, once per repository per line) with `GIT_OPTIONAL_LOCKS=0`, so grading never takes the index lock. Paths are resolved against the event's `cwd`, a `git -C` directory and any `cd` earlier in the line, one path at a time. [Source: policy/hooks/bash-grader.py#_dirty_tracked]

## Review findings

- An isolated adversarial review of the first commit found 11 bypasses: inert-program aliasing, approvals-store writes through `.open('w')`, inline interpreter programs, `git -c` aliases and keys, dry-run and abbreviated options, ref and file routes, unknowable delete targets, the dirty-file check (outside paths, `cd`, assume-unchanged, untracked files), overwrites, the deadline, and the confirmed path's missing log row. The first two were introduced by that commit. All 11 are closed in the second commit, each covered in `tests/test_grade_bash_review_bypasses.py`.
