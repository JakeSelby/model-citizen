## Story

As a developer, I want to see my effective selection and where each value comes from, so that I know why my agent behaves as it does and which file to change.

## Context and value

Show the resolved selection (the mode, the stance variants, and the switches for rules, hooks, skills, workflows and roles) as `posture.selection()` resolves it, with the layer each value comes from (default, init, mode, user, project or session) and the file that sets it. A developer picks a repository to see its project layer, and sees the always-loaded context budget filled against its cap.

## Acceptance criteria

1. Given a value set in the user layer and overridden in a project layer, when that repository is picked, then the Studio shows the project value, the overridden user value, and both files.
2. Given a session variable such as `HARNESS_STANCE_*` in the Studio's environment, then the Studio labels that value as a session value, not a saved one.
3. The resolved selection equals `citizen selection`'s output for the same inputs, in tests.
4. The budget meter shows the always-loaded total against the cap `citizen lint` enforces, for each runtime.

## Design

### Approach

Add a read-only Studio selection provider that calls the same `posture.selection()` resolver as
`citizen selection`, then annotates that result with the ordered layer history and source identity
for every unit. Expose it through one authenticated, CSRF-protected Studio route. Configure gains an
effective-selection surface above draft editing: it can resolve the launcher environment or an
explicit project selection file, group rows by primitive kind, reveal overridden values, and show
the lint-enforced always-loaded budget for Claude Code and Codex.

### Decisions and alternatives

- The API includes the resolver's selection document unchanged, rather than reconstructing it in
  TypeScript; this makes CLI parity structural and keeps the Python policy kernel authoritative.
- Provenance is a separate ordered history per row. The effective source stays prominent while
  lower-precedence explicit values remain visible, including both files in an override.
- Session environment sugar is labeled `environment`, `saved: false`, and names the exact variable;
  saved session/project selections name their files. Collapsing both into `session` alone was
  rejected because it would hide the distinction the story exists to explain.
- Budget rows use the exact token and line totals and caps used by `citizen lint`, repeated for each
  managed runtime because the shared always-loaded authority is projected to both.
- Repository/project inputs are paths, not an open filesystem browser. Studio remains dependency-free
  at runtime and returns only resolved selection data, never arbitrary file contents.

### Do not implement

- Editing or applying selections; those remain governed draft work.
- Module manifests, projection previews, and per-module context cost; AH-S287 owns the Library.
- Live polling of external changes; AH-S289 owns live updates.
- Replacing the selection resolver or changing the CLI output schema.

## Review findings

- Acceptance audit: loading the extensionless `bin/harness` budget authority with a generic import
  spec failed. Resolved with Python's source-file loader and kept the exact lint functions and caps
  as the only budget authority.
- Rendered-behavior audit: the browser assertion could inspect the old report while a project refresh
  was still in flight. The regression now waits for the selected project path before expanding the
  row, proving both files are rendered from the refreshed response.
- Concurrency audit: an initial launcher request could return after a user-triggered repository or
  project refresh and replace it. Selection responses now carry an in-component generation guard,
  with a regression that rejects the older generation after a newer request begins.
- Scope audit: selection styles initially extended the shared stylesheet. Moved them beside the
  selection component so this story's source merges independently; only the generated bundle and
  required route/product wiring remain shared.
