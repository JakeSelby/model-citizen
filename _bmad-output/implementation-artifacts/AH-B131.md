# AH-B131 — The compaction detector counts a miss under a custom cost variant that allows compaction

## Reproduction

A custom cost variant extends `max` or explicitly allows compaction, but the detector counts
compaction as a cache-hygiene miss because only the shipped name `max` is exempted.

## Root cause

The detector gate uses a frozen variant-name set instead of the resolved compaction switch.

## Acceptance criteria

1. Custom variants inheriting or explicitly selecting `compact-allowed` do not count compaction as a miss.
2. A custom variant overriding an allowed parent with a restrictive switch still counts the miss.
3. Shipped variants and other cache-hygiene detectors retain their behavior.

## Design

The compaction gate loads the existing posture resolver and resolves the supplied session stance
map against configured primitive roots. It reads the resolved switch rather than duplicating
sidecar inheritance or interpreting variant names. Other detectors and the event scan are unchanged.

## Regression test

`CompactionPrecedenceTests` covers all shipped sidecars plus custom inheritance, explicit allowance,
and a restrictive override. Existing detector corpus tests protect unrelated detectors.
