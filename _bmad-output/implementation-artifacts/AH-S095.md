## Story

As a developer evaluating the harness, I want one concrete preference shown flowing into both Claude
Code and Codex CLI, with the generated result and a way to verify it, so that I can see what the
harness does before I adopt it.

## Context and value

The adoption epic (#212) opens with "demonstrate one preference projecting into multiple runtimes with
inspectable output" as its first principle, and says the program recruits direct testers before broad
promotion. This story is that proof: the artifact the feedback cohort (#214) and the launch (#215)
would point at. [ASSUMPTION: no issue records these links; they are inferred from #212's principles]
The issue is open and has no milestone.
[Source: https://github.com/JakeSelby/agent-harness/issues/213]
[Source: https://github.com/JakeSelby/agent-harness/issues/212]

## Acceptance criteria

1. **Given** a clean, documented starting state, **when** a reader follows the demo, **then** it runs
   without private context.
2. **Given** one stance or rule changed once, **when** the reader syncs, **then** the change appears
   correctly in both Claude Code and Codex CLI.
3. **Given** the demo's explanation, **when** a reader follows it, **then** it distinguishes the
   source, the generated projection and the runtime behaviour.
4. **Given** the README and the release notes, **when** a reader looks for the proof, **then** both
   link to the same demo.

## Design

### Approach

Not recorded in the issue or pull request. What exists at `origin/main`: `docs/stance-demo.md` flips
the `delegation` stance with `harness config set`, runs `harness sync`, and shows that Claude's
selected rule link and Codex's generated instructions carry the same file under
`primitives/stances/delegation/`. It says it describes deterministic adapter behaviour and is not a
native qualification result, and it names `tests/test_lifecycle.py` as the test that exercises both
runtimes' native spawn envelopes. The README links it twice ("See one switch end to end" and "The
complete reproducible example").
[Source: docs/stance-demo.md]
[Source: README.md]

### Decisions and alternatives

Not recorded in the issue or pull request.

### Do not implement

- Any claim of native parity: the demo shows projections, and the catalog carries the evidence for
  runtime behaviour. [Source: docs/stance-demo.md]
- Broad promotion of the demo: the epic puts direct testers first. [Source:
  https://github.com/JakeSelby/agent-harness/issues/212]
