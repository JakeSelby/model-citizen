## Goal

Bring the `bmad traceability` workflow back to green. After #1206 (merged as #1223) turned unreserved
accepted issues into warnings, the remaining findings were projection drift: mapped issues missing a
Planning block, `type::*` label or parent on GitHub, and parents GitHub records that the map lacked.
The map must adopt GitHub's parents before `apply` runs, because `apply` projects the manifest's
parent and would otherwise remove them.

## Acceptance criteria

1. `refresh` has copied GitHub's titles, states and parents into `_bmad-output/issue-map.json` and
   the story files, and that change is merged to `main`.
2. `plan` run on the merged `main` shows no parent removals.
3. `apply` has written the Planning block, `type::*` label and parent for every drifted issue.
4. `audit --live --ignore-lifecycle --warn-unreserved --grace-days 2` passes locally.

## Tasks

- [ ] Merge the refresh through a pull request (AC 1).
- [ ] Run `plan` on `main` and confirm no parent removals (AC 2).
- [ ] Run `apply` (AC 3).
- [ ] Run the workflow's live audit (AC 4).

## Dev notes

Only `_bmad-output/issue-map.json`, `_bmad-output/implementation-artifacts/sprint-status.yaml` and
story files change, all generated by `scripts/bmad_issue_sync.py`; nothing is hand-edited except
this file. Order matters: refresh before apply. [Source: docs/bmad.md#live-verification]
