## Story

<frozen-after-approval reason="human-owned intent — do not modify unless human renegotiates">

As a developer, I want a history of every run with its detail, reruns and flaky marks, so that I can see how results relate to past runs.

## Context and value

Every run, launched here or imported, in one filterable history (suite, target, status, cost, duration and date), and a detail page with the per-case table, the log, the artifacts, the exact command and a rerun button. A test that both passed and failed at the same commit is marked flaky, with the runs that show it.

## Acceptance criteria

1. Given two runs of one test at one commit with different outcomes, then the test is marked flaky in both runs and in its own history.
2. Given a rerun, then it uses the same target and parameters and links back to the original.
3. Given 10,000 runs, then the history filters in under 200 ms.

## Design

### Approach

Extend the rebuildable index with filter columns and normalized cases while sidecars/native artifacts
remain authoritative. Add keyset-paged history/detail/rerun APIs plus bounded evidence reads. Mark a
case flaky only when one case identity at one immutable commit has both passed and failed. Experiments
gets a history panel and `/experiments/runs/:runId` detail route with cases, lineage, exact command,
logs and artifacts. Rerun uses a retained allowlisted request, records `rerun_of`, and refuses target
drift.

### Decisions and alternatives

- Index filter fields/cases in SQLite; do not scan 10,000 JSON blobs.
- Use creation-time/run-ID keyset pagination; concurrent inserts must not shift pages.
- Derive flaky marks without rewriting evidence. Incomplete/imported records explain why rerun is absent.
- Read only authenticated, record-declared, bounded regular files under approved roots; expose no paths.

### Do not implement

- Editing evidence, redefining native formats, arbitrary replay, cross-commit flakiness, remote
  telemetry, report comparison, or changing launch/cap/cancel semantics.
- Treating unknown cost, duration, commit or case outcome as zero, pass or fail.

### I/O and edge cases

| State | Behavior |
| --- | --- |
| Mixed pass/fail for one case and commit | Both runs and filtered case history show `flaky`. |
| Same case on different commits | No flaky mark crosses the commit boundary. |
| Imported run without a canonical request | Detail works; rerun explains why it is unavailable. |
| Moving branch/draft changed since original | Rerun refuses drift before process launch. |
| Unsafe/oversized artifact | Report unavailable; leak no path or partial body. |
| 10,000 indexed runs | A representative filtered first page and DTO serialization complete under 200 ms. |
