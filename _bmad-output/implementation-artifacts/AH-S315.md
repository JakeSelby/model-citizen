## Story

As a developer who uses a keyboard, a screen reader or a phone, I want every Studio screen to meet WCAG 2.2 AA and work at phone width, so that the Studio works for me.

## Context and value

Every Studio screen meets WCAG 2.2 AA: keyboard paths for every flow, visible focus, labels and live regions for screen readers, contrast from the tokens, no information carried by colour alone (charts included), and layouts that work at phone width. An automated checker runs in CI and a manual audit is recorded. The checker must pass the licensing review; axe-core is MPL-2.0, so the review decides whether a CI-only use of it is allowed.

## Acceptance criteria

1. Given CI, then the automated checker runs on every screen and state in the UX specification and fails on any AA violation.
2. Given a keyboard-only pass and a screen-reader pass through the six flows, then the audit record lists each flow as passed.
3. Given a 390 px wide viewport, then every screen is usable without horizontal scrolling.

## Design

### Approach

Audit by machine first, then fix at the root. A hand-written rule set (`tests/studio_a11y_checks.js`)
runs in the existing headless-Chrome harness on every routed screen at 320 and 1280 px in both themes,
on the populated report screens, and on Configure with a draft loaded; a real `Tab` walk checks
focus order, visibility, obscuring and traps. Fixes go to the shared layer where one exists: the Mantine
theme maps every palette name to a DESIGN.md token, the shell gains a named workspace landmark, and
the global focus ring covers every focus stop.

### Decisions and alternatives

1. **Hand-written rules, not axe-core.** axe-core is MPL-2.0; the repository's licensing stance
   excludes copyleft without exception, CI-only use included. No new dependency.
2. **Palette names resolve to tokens in the theme** (`variantColorResolver` plus
   `cssVariablesResolver`) rather than editing each `color="red"` call site: one place, and new
   components inherit it. Filled variants swap the token and its wash, whose pair meets AA.
3. **NumberInput steppers are hidden by default.** Mantine stacks two steppers in a 44 px field,
   under the 24 px floor; arrow keys and typing still work. Conservative default, flagged for review.
4. **24 px (2.5.8) is the enforced target floor**; the UX specification's 44 px is recorded as a
   known limit, not enforced.

### Do not implement

- No new runtime or development dependency, and no product.json line.
- No screen-reader pass claimed: it needs a person, and the audit record leaves it open.
- No route-change focus management or 400% zoom and text-only zoom checks beyond the 320 px reflow.

## Review findings

Round 1 (quality and scope reviews), resolved in the fix round:

- Scroll-area viewport rings were clipped by Mantine's `overflow: hidden` root while the walk read
  them as visible: the viewport ring is now drawn inset, and the walk measures the ring band against
  every clipping ancestor (planted clipped ring fails).
- Trend chart labels painted SVG's default black in dark mode: they take `currentColor` from the
  page ink, and the checker reads `fill` for SVG text (planted faint label fails).
- Placeholders and typed values are measured; the placeholder colour maps to `ink-secondary`.
- Label-in-name covers fields with a visible `<label>`; focus visibility compares the focused and
  unfocused look; reach compares the sets of controls, not counts; an undecidable field boundary
  reports `non-text-contrast-undecided`; contrast minimums are hard, with no tolerance.
- Every rule the checker can report has a planted defect, asserted against the checker's own rule
  list, and each keyboard rule has one too.
- Populated compare, hook-matrix and replay panels are audited from the committed fixtures; 390 px
  runs beside 320; the `studio-e2e` job runs the module opted in. Populated apply and rollback
  remain unaudited by the rule set (see the audit record).

Round 2, resolved in the second fix round:

- Populated replay progress and result tables, a populated run page, the apply review and result,
  draft-test verdicts, a paid tier's analysis, native progress, and the rollback preview and a
  refused rollback are audited and walked, all from committed fixtures.
- The settle check marks the previous page's heading, so an audit cannot read the old route.
- The run guard refuses every POST outside an allow-list of reads, and the test fails on a refusal.
- Unit tests cover `toneFor` and each button variant's contrast against the tokens.
- Scroll-region names need a region or landmark role. SVG text honours `fill-opacity`. Chart labels
  stay at least 11 px, with the chart scrolling inside its region on a phone.
- Ring contrast is measured against what the ring paints over. A focus shadow needs 3:1. The walk
  also runs at 1280 px in the dark theme.
- The walk found defects, now fixed: Configure's sticky save bar covered focused controls, switch
  group summaries and alert fields clipped their rings, inline hashes and paid-tier commands widened
  a phone, and scroll-area code blocks scrolled themselves. A test now covers the toast region's
  pointer pass-through.
