# AH-B144 — A non-finite deduplication ratio counts as measured in usage totals

## Reproduction

Write a usage ledger (`~/.local/state/agent-harness/usage.jsonl`) with one session row whose `raw_vs_deduped` is `1.5` and others whose value is `NaN`, `Infinity` or `-Infinity`, then run `harness usage` and `harness usage --json`. The footer reads `raw totals were nanx the counted totals over 4 run(s)` and the JSON block reports `runs: 4, unknown_runs: 0` with a null ratio.

## Root cause

`cmd_usage` in `bin/harness` decided a row was measured with `isinstance(ratio, float)`. `json.loads` parses `NaN` and `Infinity` as floats, so a non-finite ratio passed the check, raised the measured run count and entered the token-weighted sum, which then became non-finite itself. [Source: bin/harness#cmd_usage]

## Acceptance criteria

1. **Given** a window with one finite and several non-finite ratios, **when** `harness usage` runs, **then** the footer reports the finite ratio over 1 run and counts the others as unknown.
2. **Given** the same window, **when** `harness usage --json` runs, **then** `raw_vs_deduped` is `{"ratio": 1.5, "runs": 1, "unknown_runs": 3}`.
3. **Given** a window whose only ratios are non-finite, **when** the report runs, **then** it says the ratio is unknown and JSON reports a null ratio with 0 measured runs.
4. **Given** a non-finite row carrying `days` slices, **when** the report runs by day, **then** its slices add nothing to the weighted ratio.

## Design

Require `math.isfinite(ratio)` alongside the float check where `measured` is decided, so both the run count and the per-slice and per-row accumulations treat a non-finite figure as unknown. Rejected: sanitising the ledger on read, which would hide the malformed value from other readers and widen the change. The fix must not change how a finite ratio, a missing ratio or the string `unknown` is counted.

## Regression test

`tests/test_usage_dedup_nonfinite.py` covers mixed finite and non-finite rows in the text footer and `--json`, an all-non-finite window, and the `--by day` slice path. All four tests failed before the fix and pass after it.
