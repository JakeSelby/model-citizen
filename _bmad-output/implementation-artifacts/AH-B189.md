## Reproduction

1. Run any role on Codex: `harness role run reviewer --runtime codex` (codex-cli 0.155.0-alpha.16.4).
2. Read the run's `status.json` under `~/.local/state/agent-harness/workers/<id>/`.
3. Observed: no `usage` key. On the maintainer's machine none of the 87 completed Codex worker records from the last 30 days has one, so their `harness usage` worker rows carry `input`, `output` and `cache_read` as unknown and go unpriced.

## Root cause

`adapters/codex/worker.py` `usage()` looked only for `info.total_token_usage`, the shape of Codex's rollout transcripts and of older exec builds' `token_count` events. `codex exec --json` reports the run's cumulative totals once, as a top-level `usage` object on `turn.completed` (`input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_output_tokens`). Each of the 87 runs' `stdout.log` has exactly one such event and none of the older shape, so the parser returned `{}` and `workers.py` left the key absent.

## Acceptance criteria

1. **Given** a recorded `exec --json` stream ending in `turn.completed`, **when** the adapter reads it, **then** it returns `input` net of the cached share, `cache_read`, `output` and `cache_write`.
2. **Given** that usage in a completed worker's status record with a priced Codex model, **when** `usage-log.py` builds its worker row, **then** the row carries the totals and `pricing.row_cost` prices it above zero.
3. **Given** a recorded failed turn (`turn.failed`, no usage), **then** the adapter reports nothing rather than zeroes.
4. **Given** the older `token_count` stream, **then** the last cumulative snapshot is still taken.

## Design

Take `turn.completed.usage` as the run's snapshot, last one wins, and keep the older shape as a fallback. `input` stays net of `cached_input_tokens`, as the transcript reader computes it, and `cache_write_input_tokens` maps to `cache_write`, as `CODEX_FIELDS` in `usage-log.py` already maps it for sessions. A reported zero is recorded; OpenAI charges nothing for cache writes, so pricing is unchanged by it.

Rejected: summing per-turn snapshots, since the event carries the thread's cumulative totals. Unchanged: `workers.py`, the worker row builder and pricing; past records are not backfilled.

## Regression test

`tests/test_usage_roles.py`: `AdapterUsage.test_the_recorded_exec_stream_yields_its_turn_totals_net_of_the_cached_share` and `WorkerIngest.test_a_codex_worker_recorded_from_its_exec_stream_is_a_priced_row` read `tests/fixtures/codex/worker-exec-json.jsonl`, cut from a real worker run; both fail on the pre-fix adapter.
