## Story

As the maintainer, I want agents to work through CodeRabbit's review and merge the pull requests
that clear it without asking me, so that finished, reviewed work stops waiting on a one-word reply.

## Context and value

CodeRabbit has reviewed pull requests into `main` since #785, and `/build` step 6 answers its
threads. `/land` still asks for an explicit go-ahead before every merge, and nothing in this
repository says what counts as a finished CodeRabbit pass. The commit statuses on #786, #815, #827
and #830 show why that matters: a requested pass ran seven to eleven minutes and ended
`success: Review completed`, while every later push got `success: Review skipped: incremental
reviews are disabled` within seconds. A check on the `success` state alone reads a skipped review
as a finished one.

## Acceptance criteria

1. **Given** `AGENTS.md`, **when** an agent has a pull request open here, **then** it works through
   CodeRabbit's review without asking: fixes pushed to the branch, threads answered and resolved,
   the next pass requested with `@coderabbitai review`, and a pass counted as finished only by the
   `CodeRabbit` commit status.
2. **Given** a pull request from a branch of this repository, **when** nothing waits on the
   maintainer, the gate passed before the last push, every required check is green on the head, and
   CodeRabbit's last pass after the last fix is worked through, **then** `AGENTS.md` names that as
   the go-ahead `/land` asks for.
3. **Given** anything short of that, or a pull request from a fork, **then** the agent reports what
   remains and waits; releases, tags and GitHub About changes keep their own approvals.

## Design

### Approach

A "CodeRabbit review and merging" section in `AGENTS.md`, between "How the checkout is used" and
"Issues, milestones and releases". Its first paragraph fixes the loop and the finished-pass signal;
three numbered conditions then stand as the go-ahead `/land` asks for.

### Decisions and alternatives

1. **Repository instructions, not the shared `/land` workflow.** The standing go-ahead is this
   repository's policy: `/land` keeps "get an explicit go-ahead", and `AGENTS.md` says what that
   go-ahead is here. A `/land` clause honouring any repository's standing go-ahead waits until a
   second repository wants one.
2. **The signal is `Review completed`, not the `success` state**, because every push earns
   `success: Review skipped`.
3. **Findings in the review body count, not only threads.** A merge with no one reading the report
   afterwards cannot leave them for it; #786's second round held real findings only in its body.
4. **Wait fifteen minutes for a pass here**, since observed passes took up to eleven. #822 settles
   the wait and the signal in the shared `/build` step 6.
5. **Forks are excluded.** A contributor's pull request brings third-party material, which stays the
   maintainer's call.

### Do not implement

- Any change to `/build`, `/land`, `.coderabbit.yaml`, the `main` ruleset or the required checks.
- The shared review-complete signal in `/build` step 6, which is #822.
