# AH-B134 — Studio tests leave draft branches in the shared repository

## Reproduction

Run the Studio browser suites (`tests/test_studio_configure_browser.py`,
`tests/test_studio_selection_editing_browser.py`) from any worktree. After the run,
`git for-each-ref refs/heads/draft/` in the shared repository lists `draft/configure-browser-*`
and `draft/selection-*` branches that no test owns, and a later `draft create` with the same
name fails because draft branches live in refs every worktree shares.

## Root cause

`draft discard` already removes the worktree and the branch. The browser fixtures registered the
discard before the Studio-stop cleanup, and `addCleanup` runs last-in first-out, so the discard ran
while the Studio server could still be finishing a save that holds the draft's writer lock.
Discard correctly refused with `busy`, and the configure fixture ignored the failure.
[Source: lib/harness_core/studio/drafts.py#discard]

## Acceptance criteria

1. **Given** a Studio that still holds a draft's writer lock, **when** the test's cleanup runs,
   **then** the Studio is stopped first and the draft branch and worktree are both gone.
2. **Given** a discard that cannot complete, **when** the cleanup runs, **then** the test fails
   instead of leaving the branch silently.
3. **Given** a Studio stop that raises, **when** the cleanup runs, **then** the discard still runs.
4. **Given** any test module that runs the real CLI's `draft create` in the shared repository,
   **when** the suite runs, **then** each create has its own later `draft_support` guard in the
   same function, multi-line calls and several creates per file included.
5. **Given** the guarded Studio tests, **when** they run, **then** `refs/heads/draft/` gains no
   branch they created.

## Design

`tests/draft_support.py` owns the cleanup: `discard_draft` stops any writer inside `try`, discards
in `finally` with a short retry on `busy`, and asserts neither branch nor worktree survives.
Fixtures register it right after the create's return-code check, before parsing its output, so a
failing assertion cannot skip it. A syntax-tree scan in `tests/test_draft_cleanup.py` enforces the
guard. Rejected: deleting leftover `draft/*` refs in bulk, which would destroy a sibling run's
drafts; a text match on the helper's name, which misses a second unguarded create in the same
file. Must not change `draft discard` or any Studio runtime code.

Leak checks are scoped to their own run, because every worktree sees every other worktree's
in-flight drafts and a before/after ref comparison failed whenever a sibling suite ran at the same
time. Each test process holds a run token `p<pid>r<random>`, and `draft_support.draft_name(prefix)`
embeds it in every draft name. `leaked_drafts` counts only branches carrying the token. A child
test process inherits the token through `DRAFT_SUPPORT_RUN_TOKEN`. That works only when the token
was minted by the child itself or its direct parent; a fixed or exported value is refused, and an
explicit token is validated. The guarded run hands its child a fresh token and a name log
(`DRAFT_SUPPORT_NAME_LOG`), then asserts as a positive control that the child named two drafts with
that token, the filter matches both, and neither branch survives. A second syntax-tree scan
requires every shared-repository create to take its name from `draft_name`: the CLI argument list,
a test home's `cli("draft", "create", ...)`, `git worktree add -b draft/<name>` and a POST to
`/api/first-run/start`. A hand-built name would otherwise leak past a token-scoped check.
Rejected: a registry file keyed by PID, which the guarded child would have to share with its
parent anyway.

## Regression test

`tests/test_draft_cleanup.py`: a lock-holding writer released by `stop`, a surviving branch that
fails the test, a raising `stop` that still discards, a subprocess run of the guarded
selection-editing tests whose logged draft names must carry its token and must be gone afterwards,
and both scans with their own multi-line, second-create, misplaced-guard, hand-built-name and
parameter cases. `tests/test_draft_run_token.py`: a foreign-token draft appearing mid-run is
ignored, a same-run leak is reported, a child stamps drafts with the inherited token, and a fixed,
foreign or malformed token is refused.
