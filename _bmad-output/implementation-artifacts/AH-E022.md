# AH-E022 — Open the Studio: one local UI that shows the whole harness, live

## Goal

`citizen studio` opens a local web UI that shows the whole harness: the installed version and its
health, the effective selection with the layer each value comes from, every module with its manifest,
projection and context cost, and what the harness decided and changed, live within two seconds of a
change on disk. It is locked to its launcher and needs no Node or package manager at runtime.

Completion is observable: on a clean install with no Node, `citizen studio` serves the UI; an
anonymous request, a foreign Host and a foreign Origin are refused; the selection it shows equals
`citizen selection`'s; and a change made with the CLI appears in the open page within two seconds.

## Scope and requirement coverage

**In scope:**

- The design gate: the Studio's UX specification (AH-T035) and its architecture decisions (AH-T036),
  with the reproducible-bundle spike (AH-SP017).
- The command and server (AH-S281), its security model (AH-S282), the front-end workspace and
  committed bundle (AH-S283), and the shell and component kit (AH-S284).
- The read-only views: the overview (AH-S285), the effective selection (AH-S286), the library
  (AH-S287), activity (AH-S288) and live updates (AH-S289).

**Out of scope:**

- Any edit, which is AH-E023, and any run, which is AH-E024.
- Reaching the Studio from another machine; the phone spike is AH-SP018 in AH-E026.
- A hosted or multi-user Studio: no feature may require a remote service (PRD §8), and the
  multi-user surface is the post-1.0 ceiling (PRD §2.2).
- Replacing OTLP export: the Studio reads local files, and export stays as it is.

**Requirement coverage,** against the PRD's §4.16 Studio:

- **FR-75 One command opens the Studio:** AH-SP017, AH-S281, AH-S283.
- **FR-76 A local surface locked to its launcher:** AH-S282.
- **FR-77 See the whole harness, live:** AH-T035, AH-S284 to AH-S289.
- AH-T036's decisions bind every Studio requirement, FR-75 to FR-84.

## Architecture slice

- **New ADs from AH-T036:** one core with two faces; a standard-library loopback server; the security
  model; React, TypeScript and Vite shipped as a committed bundle, amending AD-21; drafts as managed
  worktrees; the run store as an index; one instance per user.
- **AD-2 One resolver:** the selection view calls `posture.selection()` and nothing else.
- **AD-6 One effective policy for every consumer:** the Studio is one more consumer, never a second policy.
- **AD-11 Local ledgers are the system of record:** activity reads `decisions.jsonl` and the ownership journal.
- **AD-21 Dependencies:** amended for the bundle; no runtime Python dependency is added.
- **AD-22 Modules declare a manifest:** the library reads `primitives/manifests.json`.
