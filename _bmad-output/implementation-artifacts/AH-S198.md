## Story

As a developer using the harness, I want every lifecycle hook to have an id I can switch off, with the
core enforcement hooks behind an explicit acknowledgement, so that I can drop a hook I do not want
without being able to disable enforcement by accident.

## Context and value

Epic #552 makes every installed unit a switchable dimension; hooks are the kind that enforces, so they
need both an id and a guard. Its principle: nothing is claimed enforced without a hook id
[Source: https://github.com/JakeSelby/agent-harness/issues/552]. On `main`
today, `lifecycle.invoke(name, event)` dispatches to the modules in `policy/hooks/` with no selection
check, and hooks are not a kind in `catalog.KINDS`. `permissions_bypass_acknowledged` is the existing
acknowledgement pattern this story copies.
[Source: https://github.com/JakeSelby/agent-harness/issues/555]

## Acceptance criteria

1. **Given** each hook id set `off`, **when** its event fires, **then** a lifecycle test proves the
   module is not invoked, for both native envelopes.
2. **Given** no acknowledgement, **when** `harness config set hooks.grade-bash off` runs, **then** it is
   refused; **given** the acknowledgement, **then** it is accepted and a grade-3 command passes ungraded
   in the test envelope.
3. **Given** the catalog, **when** `harness catalog` runs, **then** it emits kind `hooks` with the id
   list.
4. **Given** Codex, **when** its adapter dispatches, **then** it reads the same id map; there is no
   Codex-only id, and the docs say so.
5. **Given** the docs, **when** `docs/runtime-controls.md` is read, **then** it lists the ids and the four
   core ones.
6. **Given** the change, **when** the gate runs, **then** lint is clean and the suite green.

## Design

### Approach

- **Ids are module basenames:** `allow-plan-webfetch`, `allow-readonly-bash`, `brief-guard`,
  `filter-output`, `grade-bash`, `harness-session`, `neutralize-tool-output`, `stop-gate`,
  `tier-agent-spawns`, `usage-feed`, `usage-log`, `validate-plan-card`.
- **Libraries have no switch:** `decisions`, `posture`, `pricing`, `telemetry`, `rule-detectors`,
  `otel-headers`, `filter-lines`.
- **`lifecycle.invoke(name, event)` consults the selection first** and returns `{}` for an `off` id.
- **Inline dispatch is keyed to its owning id:** Bash grading and the ask decision to `grade-bash`;
  plan-mode allows to `allow-readonly-bash`; role deny and evasion deny to `tier-agent-spawns`.

### Decisions and alternatives

- **Four core ids** (`grade-bash`, `stop-gate`, `brief-guard`, `neutralize-tool-output`) may be `off`
  only when `core_switches_acknowledged` is true.
- **Refusal happens at validation, before any file changes:** both `config set` and a mode file that
  tries without the acknowledgement are refused, on the pattern of `permissions_bypass_acknowledged`.

### Do not implement

- Codex-only hook ids.
- Switches for the library modules.
- The selection model itself (#554), which this story is blocked by.

### Completion notes

- `catalog.HOOK_IDS` is the one id list, carried as the `hooks` kind's `units`; `posture` counts an
  id installed when its module is in the checkout. The list has thirteen ids, not the issue's
  twelve: `stage-user-files` joined `policy/hooks/` after the story was written and answers
  PreToolUse on SendUserFile, so under the issue's own rule (every module that answers a lifecycle
  event has an id) it gets one. It is not core.
- `lifecycle.invoke` returns `{}` without loading a module whose id is `off`; `dispatch` resolves
  the hooks selection once per event, non-strictly. Bash grading, its ask and the Bash decision-log
  rows follow `grade-bash`; the read-only allow, plan-mode allows and `plan_allow_tools` follow
  `allow-readonly-bash`; band routing and the descriptor notice follow `tier-agent-spawns`. The
  `delegation: off` deny is the stance's and stays with every id off.
- Amended 2026-09-25 by the owner's decision on PR #863: role confinement is split out of
  `tier-agent-spawns` and is always on, so the switch controls band routing only. The
  constrained-role, `harness-role:` marker, framework and evasion denials run with every id off,
  as the Workflow launch guard (#847) already did, and their decision points
  (`role-confinement`, `framework-spawn`, `evasion-deny`, `workflow-launch`) name no module in
  `decisions.POINT_MODULES`. This replaces the design line keying role and evasion denies to
  `tier-agent-spawns`. `usage-log` is keyed where SessionEnd loads it.
- The core guard lives in `posture.selection()` over the resolved value, so it covers every layer:
  strict resolution (`config set`, `sync`, `harness selection`) refuses a core id `off` without
  `core_switches_acknowledged: true` in the user configuration, and a hook resolving non-strictly
  keeps the hook on. `CORE_HOOKS` and `CORE_ACK` are defined once in `posture.py`, shared with the
  modes story (#557); its separate mode-file core check was removed on merging it, so a mode that
  switches a core hook off unacknowledged gets this one refusal, and a hook applies the rest of the
  mode with the core hook on rather than dropping the whole mode.
  `config set core_switches_acknowledged false` is refused while a core id is off.
- Hook manifests ship in `policy/hooks/manifests.json`, which the manifest story (#788) left to
  this one; each installed hook id must declare one on strict resolution. Every hook is
  `unmeasured`.
- The Codex adapter already dispatches through `lifecycle.main`, so it reads the same map with no
  adapter change; a test pins that.

## Review findings

CodeRabbit, round 1 on PR #863:

- `policy/hooks/posture.py` `core_refusals`: a user configuration that parses to a non-object, such
  as `[1]`, raised `AttributeError` when the acknowledgement was read. Fixed: a non-object carries no
  acknowledgement, which matches how `main` resolved it, with a regression test.
- `bin/harness` `config_set`: the unit-membership check resolves the configuration without the new
  switch strictly, so a switch that would repair a selection the resolver already refuses can be
  refused. Not fixed here: the check came with the rule, skill, workflow and role switches (#851),
  hooks declare no dependencies, and changing it is outside this story. Raised for a follow-up.
CodeRabbit, pass on 3b9bb1a after the confinement split:

- `lifecycle.py` `workflow_results` (review body, outside the diff): the `plan_allow_tools` allow
  for a `Workflow` launch, merged from #847, ignored `allow-readonly-bash`. Fixed: it is keyed to
  that id like every other plan-mode allow, with a test for the off case.
- `lifecycle.py` Bash branch: `grade-bash` is still loaded as the classifier when only
  `allow-readonly-bash` is on. Not fixed here: the read-only allow needs the grammar, the switch
  stops grading and its ask rather than the library, and moving the classifier out of
  `grade-bash` is a refactor outside this story. Both ids off never loads it, as a test pins.
- Shepherd: the builder relabelled the `hooks` kind's projection to "lifecycle dispatch"; reverted,
  since the story does not ask for it.
