## Reproduction

- Run the replay with raw output kept, then read the delegation verdict from the saved rows; no
  model is called for the second step:

  ```sh
  python3 scripts/cost_bench.py replay --model <id> --tag <ref> --pre-registration <plan> --raw <raw>
  python3 scripts/cost_bench.py summarise --results <out>/<ref>
  ```

- Observed before this work: zero `Agent` or `Task` calls in either arm across 19 headless runs,
  then zero in 40. On `hook-inventory` the harness arm read all 18 files itself in 10 API calls
  against the bare arm's 11. The count came from grepping raw output, and a result-only run read
  `spawns` 0, so a run that could not show a spawn looked like one that declined.

## Root cause

Unknown until the close-out. The issue names two candidate answers that the data could not tell
apart: the stance does not bind under `claude -p` (a harness defect), or the pinned tasks sit below
delegation's break-even and declining is correct (a benchmark defect). This story first builds the
instrument that separates them; the registered #513 and #560 runs then answer it.

## Acceptance criteria

1. **Given** a stream whose init message lists `Agent` or `Task`, lists neither, or has no init
   message or `tools` list, **when** `parse_result` runs, **then** `spawn_offered` is true, false or
   None respectively.
2. **Given** a stream with no assistant message, **when** `parse_result` runs, **then** `spawns`,
   `gather_calls`, `absorbed_calls` and `workflow_launches` are None, never 0 (AD-12: unknown
   values are never zero).
3. **Given** rows for a task and a break-even figure, **when** the verdict runs, **then** the
   harness cell reads exactly one of `fired`, `declined-below-break-even`,
   `missed-above-break-even`, `not-offered` or `unknown`. Task size comes from the bare arm.
4. **Given** saved rows, **when** `summarise` runs, **then** the delegation block prints per task,
   labelled adherence, and SM-2's result is unchanged.
5. **Given** the registered #513 AC4 and #560 rows, **when** the close-out reads them, **then**
   #429 closes in one of two ways. Fixed: under the fired rule below, with the spawn cost split.
   Disproved: with per-task verdicts and the break-even used. Either way, FR-34 carries a dated
   amendment.

## Design

- **Row fields** (`scripts/cost_bench.py`, `STREAM_FIELDS`, so `backfill` derives them at $0):
  `spawn_offered` from the first `init` event's `tools`; `gather_calls`, the `Read`, `Grep` and
  `Glob` calls in every thread; `absorbed_calls`, those in a thread whose `parent_tool_use_id` is
  set; `workflow_launches`, the `Workflow` calls. With no assistant message the four counts are
  None; `tool_counts` keeps `{}`.
- **Verdict** (`scripts/delegation_verdict.py`, standard library only, pure over rows). Size is the
  median of the bare arm's `gather_calls`, since the harness arm's own count falls when it
  delegates. First match wins: any harness run not offered the spawn tool is `not-offered`; no size
  or no harness spawn count is `unknown`; a spawn in at least `FIRED_SHARE` of the harness runs is
  `fired`, shown with its size even below the break-even; any harness run of unknown spawns or
  unknown offer is `unknown`; otherwise `declined-below-break-even` at or below the break-even and
  `missed-above-break-even` above it. The bare cell carries the same counts with no verdict, as the
  control. The harness cell adds the mean cost of spawning and non-spawning runs, labelled
  "adherence, descriptive, not causal".
- **Report.** `summarise` prints the block after `replay_stats.render`, and under `--json` adds it
  as a separate `delegation` key; `history_row` carries it under `delegation`, and `render_history`
  prints indented `delegation:` lines. `replay_stats.analyse` is untouched. `--break-even` on
  `replay` and `summarise` overrides the figure, which the output always names.
- **Decisions taken** (the plan's recommendations, 2026-09-29):
  1. Absorbable calls are `Read`, `Grep` and `Glob` only: deterministic and an undercount, so a
     miss is conservative. Rejected: Bash commands the shell grader rates 0, which ties the
     verdict to the grader's version.
  2. Fired is a rate, `FIRED_SHARE = 0.75`, the three-of-four runs #513 registers, on every task
     above the break-even; FR-34 is amended to match. Rejected: one spawn, which credits a
     mechanism that almost never runs.
  3. No registered run of #429's own; the #513 and #560 runs are read instead. Rejected: a forced
     delegation arm, a new arm type and new spend.
  4. A `Workflow` launch is reported beside spawns and not counted until #915 routes Workflow
     agents to a band. Rejected: counting it now.
  5. The break-even is FR-34's 7.6, `BREAK_EVEN_CALLS`, pre-registered and labelled hypothetical;
     FR-34 is amended to name its source. Rejected: an estimator from row fields.
- **Must not change:** SM-2's analysis and figures, any hook or stance, and the upsert key of
  `history.jsonl`. Old history lines without `delegation` still parse and render.

## Regression test

- `tests/test_delegation_verdict.py::GatherCountTests::test_output_with_no_assistant_message_is_unknown_never_zero`:
  a result-only stream now gives `spawns` None; before, it gave 0.
- `tests/test_delegation_verdict.py::VerdictTests::test_a_task_above_break_even_the_harness_read_itself_is_missed`:
  a fixture shaped like the 2026-09-22 finding (spawn tool offered, 18 main-thread Reads, no
  `Agent` block) gives `missed-above-break-even`; before, there was no verdict at all.

## Review findings

- Fresh-context review of the instrument, all fixed with regressions in
  `tests/test_delegation_verdict.py`: errored rows (timeouts, effort mismatches) were read as
  whole runs; a denied or hook-blocked spawn counted; a spawn inside a `Workflow` agent's thread
  counted; an overridden break-even kept FR-34's label; a single run could read `fired`, with no
  mark of an unregistered run; the size was a median over only the bare runs that reported one.
