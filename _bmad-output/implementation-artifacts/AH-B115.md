# AH-B115 — A heredoc that only names the user config path is refused as a config change

## Reproduction

The governance check still treats a Bash command as a change to the harness configuration when a heredoc's text only names the user config path, after #924 narrowed the policy-file guard to real writes. In a mode that cannot prompt, the command is refused outright.

Reproduction, with `governance.provider` set to `local` in a session that cannot prompt:

```sh
cat > /tmp/example.md <<'EOF'
Configuration edits never touch ~/.config/agent-harness/config.json directly.
EOF
```

Expected: graded as a local write to `/tmp/example.md` and allowed. Observed: grade 1, with "Governance: this changes the harness configuration .config/agent-harness/config.json, which selects the decision provider, which is level 1", and the command is refused. Writing the same file with the editor's own file tool passes.

## Root cause

Not yet traced; the delivery finds it before the fix.

## Acceptance criteria

1. Given a heredoc or quoted string that only names the user config path, when the command writes elsewhere, then the check grades the file it writes and does not treat it as a config change.
2. Given a redirect, `tee`, `cp`, `mv` or `sed -i` that writes the user config file, then the level-1 check still applies.
3. Tests cover both cases, next to #924's.
