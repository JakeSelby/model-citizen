# AH-B115 — A heredoc that only names the user config path is refused as a config change

## Reproduction

The governance check still treats a Bash command as a change to the harness configuration when a heredoc's text only names the user config path, after #924 narrowed the policy-file guard to real writes. In a mode that cannot prompt, the command is refused outright.

Reproduction, with `governance.provider` set to `local` in a session that cannot prompt:

```sh
cat > /tmp/example.md <<'EOF'
Configuration edits never touch ~/.config/agent-harness/config.json directly.
EOF
```

Expected: graded as a local write to `/tmp/example.md` and allowed. Observed: grade 1, with "Governance: this changes the harness configuration .config/agent-harness/config.json, which selects the decision provider, which is level 1", and the command is refused. Writing the same file with the editor's own file tool passes.

## Root cause

The fallback guard searches the entire command for the configuration path, including literal
documentation content, after the shell walker already identified its actual output paths.

## Acceptance criteria

1. Given a heredoc or quoted string that only names the user config path, when the command writes elsewhere, then the check grades the file it writes and does not treat it as a config change.
2. Given a redirect, `tee`, `cp`, `mv` or `sed -i` that writes the user config file, then the level-1 check still applies.
3. Tests cover both cases, next to #924's.

## Design

Extend the existing strict literal lexer to recognize redirects for one data-only utility
(`cat`, `printf`, `echo`, `tee`). A quoted here-document or literal arguments may mention the
user configuration without triggering its fallback name search. Actual write paths are checked
first, including symlinks. Substitutions, interpreters, pipelines, command chaining, comments
and unquoted here-documents retain conservative handling. Governance policy files and explicit
config-set commands keep their existing guard; no general shell evaluator is introduced.

Security review narrowed the exemption to exclude utility option evaluation, unquoted expansion
and alternate redirect syntax. The shared write-redirection classifier now also recognizes
`>|`, `<>` and `&>>`, so those writes reach governance instead of being graded read-only.

## Regression test

`test_governance_text_data.py` covers quoted here-documents and strings, direct and symlinked
configuration writes, all listed writer commands, and executable/ambiguous rejection cases.
Regression cases assert the level-1 configuration guard for printf variable-subscript evaluation,
brace-expanded tee destinations, zsh force redirects and alternate write operators.

## Second security review amendment

The second pass found printf options after redirects, zsh variable-writing formats, force-clobber
redirects through symlinks and brace-expanded configuration names. The literal exemption now
accepts only string/escaped-percent printf conversions after separating redirects. The shared
tokenizer retains zsh force-clobber operators and their real destinations, and ambiguous
configuration expansions retain the configuration guard. Lifecycle regressions pass without
executing the payloads: 86 governance, 25 read-only and 36 grading tests on each supported Python.

## Final security correction amendment

The final bounded review identified combined zsh redirection operators, an attached printf
file descriptor, and a brace-expanded configuration directory. The lexer now recognizes the
write-operator families together, retains their destinations, strips only attached unquoted
numeric descriptors from printf arguments, and guards configuration-directory expansions.
Seven lifecycle regression methods (including the operator matrix), 25 read-only and 36 grading
tests pass on both supported Python versions. The preceding full Gate passed 4,046 tests;
these final corrections require the final-HEAD Gate before push.
