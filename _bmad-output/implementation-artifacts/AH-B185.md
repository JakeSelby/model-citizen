## Reproduction

Change a class mapping in `adapters/<runtime>/bindings.json`, or drop a class from it. No test fails: the only checks were that no role lands on the frontier model (`tests/test_role_frontier_tier.py`) and a few gatherer models in `tests/test_sync_renders_agents.py`.

## Root cause

Tier routing had no end-to-end check from a role's class to the model its adapter binds, so a broken or missing mapping silently changed which model a role ran on. [Source: adapters/claude-code/bindings.json, adapters/codex/bindings.json]

## Acceptance criteria

1. **Given** every cost variant, both runtimes and every role, **when** bindings are resolved, **then** each role's model equals the adapter's model for its class (the cost row's class, or the role's own tier when it has no row or is fixed).
2. **Given** an adapter missing a class, **when** the check runs, **then** the class is reported by name with what it falls back to.
3. **Given** each adapter, **then** it maps all four classes.
4. **Given** the committed Claude agent files, **then** they carry the balanced class model.

## Design

One new test module beside the frontier-tier test, reading the same resolver the sync uses, so it checks the model a role actually gets. The frugal tiering arm in the original issue is out of scope; it moved to #1277.

## Regression test

`tests/test_role_class_binding.py`: in a copy of the repo with Claude's `light` class removed and Codex `reviewer` pinned to the light model, both are reported and the suite fails (rc=1).
