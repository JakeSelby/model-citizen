## Story

As a developer reading the harness's rules and docs, I want them to describe sessions that reset themselves, so that no rule tells me to start a fresh session and the cache detector does not count the stance's own compactions against it.

## Context and value

The cost stance, cache-hygiene rule, detector, docs and landing copy all describe "start a fresh session" and `/clear` at task end. Once AH-S363 to AH-S365 land, that text is wrong and the `cache-hygiene/compact` detector would flag every harness-triggered reset.

## Acceptance criteria

1. `primitives/stances/cost/balanced.md` and `frugal.md` replace "write the handoff, then start a fresh session" with the reset behaviour and drop "a task ends with `/clear`" in favour of the task-end clear (AH-S228), each within its line budget.
2. `primitives/rules/cache-hygiene.md` says harness-triggered compaction is the stance working.
3. The `cache-hygiene/compact` detector in `policy/hooks/rule-detectors.py` exempts `trigger: auto` compactions at the projected reset point and still counts manual `/compact`; `tests/test_rule_detectors.py` and the golden updated.
4. `docs/preferences.md` "When a session should hand off" becomes "When a session resets", and `docs/usage.md` documents the block, the snapshot and the reseed.
5. `product.json` gains a capability line; a changelog fragment and a `compatibility/migration.json` entry for the PreCompact hook and the env projection are added.
6. Full Gate green; the landing-copy check passes.

## Design

### Approach

- Text edits to the stance, rule and docs; the detector exemption keys on `trigger: auto` and the projected reset point.

### Decisions and alternatives

- **Exempt only auto at the reset point.** Rejected: dropping the detector, which still catches manual `/compact`.

### Do not implement

- Codex wording beyond noting the gap.
