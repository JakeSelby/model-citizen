## Story

As a harness maintainer, I want every replay row to carry the CLI's own account of what the session loaded and the reasoning effort it ran at, and the replay to refuse arms that differ by more than the harness, so that a comparison between the arms cannot be moved by drift nobody declared.

## Context and value

The diagnostic ledger's first use caught a 1,700-token drift in the harness arm's standing prefix between two runs on one profile; the size-hash fingerprint could not see it, and the transcript's `init` event could: `slash_commands` went from 75 to 84 as a plugin auto-synced into the bench profile. The owner's later comment on the issue adds `first_call_context`, the first call's whole input, which is warmth-invariant where the cache write is not.

Decided by the owner on 2026-09-26: replay arms are fresh containers (#559), so the issue's profile-directory plugin parity becomes arm-manifest parity. The work is to record the loaded surface per row, refuse on drift, and pin and record the reasoning effort.

## Acceptance criteria

1. **Given** a run's recorded CLI output with an `init` event, **when** it is parsed, **then** the row carries `init_skills`, `init_agents`, `init_slash_commands`, `init_tools`, `init_mcp_servers` and `init_memory_paths`, each the length of that list; a stream without an `init` event stores `None` for each.
2. **Given** a set on disk with its raw output, **when** `backfill` runs, **then** it derives the six counts and `first_call_context`.
3. **Given** two built arms, **when** their declarations or manifests differ outside the harness component, **then** the replay refuses before anything launches and prints every difference.
4. **Given** a set in progress, **when** a run's loaded surface differs from its arm's first run, **then** the row is written with `surface_drift` and the set stops with the difference printed; with `--allow-surface-drift` it runs on and every row of the set says `surface_drift_allowed: true`.
5. **Given** `--effort <level>` (default `high`), **then** every arm's declaration records it, every launch passes it as `--effort`, every row records `effort`, and an arm with no pinned effort, or given `CLAUDE_CODE_EFFORT_LEVEL`, is refused.
6. **Given** a run whose stream reports an effort other than the pinned one, **then** its row is an error and the set stops, whatever `--allow-surface-drift` says.

## Design

### Approach

`cost_bench.loaded_surface` reads the first `system`/`init` event into the six `init_*` counts,
canonical content hashes, source marker and reported effort; `parse_result` adds them,
`first_call_context` and `observed_effort` to its fields, and `STREAM_FIELDS` carries them all, so
`backfill` derives them without replacing existing evidence when raw output is absent.
`replay_arms.admit` recomputes known-schema records and reports all defects. `pair_differences`
compares every entry except exact harness-generated files, links into its checkout and their
directory parents. The replay loop tracks each arm's first reported surface and stops after writing
a difference. `--effort` flows into every command; the manifest records baked overrides and both
the pre-flight and scored run compare any observed effort with the pin.

### Decisions and alternatives

- Claude Code 2.1.280 sets a headless run's effort with `--effort <level>` (`claude --help`, and the CLI reference); `CLAUDE_CODE_EFFORT_LEVEL` outranks it (environment variable reference), so the flag is the pin and the variable is refused. Pinning with the variable instead was rejected: it would also override skill and subagent frontmatter effort, which is part of the harness treatment.
- Default taken: `high` as the default `--effort`, because it is the level Claude Code documents as the default on most effort-capable models and every one of them accepts it without falling back.
- Default taken: effort is a launch input, kept in the declaration (and its digest) but out of the image name and build label, because it does not change what the image holds and should not force a rebuild.
- Default taken: row fields are prefixed `init_`, because a bare `tools` would collide in meaning with `tool_counts`.
- Default taken: a run with no `init` event is not compared for drift, because a missing surface says nothing about a changed one; its counts are `None`.
- Default taken: an effort mismatch stops the set with no override, because a different effort is a different arm, not drift in what it loaded.
- Observed effort is read from the `init` event's `effort`, which the Agent SDK reference says Claude Code sends only to Remote Control clients; on a headless run it is normally absent, so the check is a backstop and the flag is the pin.

### Do not implement

- No profile-directory plugin listing check: arms are containers, and pair parity over manifests replaces it.
- No change to SM-2's statistics or to history rows.
- No model call, image build or replay.

## Review findings

- The pair refusal truncated its report after 40 differences, contrary to AC 3's requirement to
  print every difference. Removed the cap and added a 45-difference regression.
- The six counts could not detect same-count member replacements and named no provenance. Added
  canonical per-field hashes and an explicit `cli-init` source without claiming unavailable IDs.
- Admission trusted nonempty digest strings, unknown schemas, and filtered malformed or duplicate
  harness components. It now recomputes both digests, checks schemas and validates components.
- Broad runtime-directory prefixes hid unrelated files and links from pair parity. Treatment is
  now exact generated files, links into the checkout and only their directory parents.
- A baked effort override was invisible and pre-flight discarded observed effort. The manifest
  records the override, admission refuses it, and pre-flight records and checks both values.
- Admission stopped at the first defect and surface drift omitted observed effort. Admission now
  reports every independent defect, and observed effort participates in per-arm drift evidence.
- Missing raw output overwrote existing backfilled evidence. Missing fields now default only when
  absent, preserving every diagnostic already stored on the row.
- Admission now validates every manifest entry's path and supported kind before any summary or
  treatment logic reads it. Link containment normalises parent segments, and refusal paths sort
  within each configuration kind.
- Generated Codex agents and workflow skills are treatment only when the declared checkout
  contains their exact role or workflow source. The fresh profile's generated harness config is
  also part of the treatment; similarly named personal files remain visible to parity.
