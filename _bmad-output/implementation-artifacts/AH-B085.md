# AH-B085 — A framework layer brief the orchestrator rewords in its own words is not refused

## Reproduction

1. Run the `spawn-confinement` native case (step 9 of `docs/compatibility.md`) on the Claude Code
   CLI with a sonnet orchestrator, as the 0.13.0 and 0.13.1 qualification rounds did.
2. Its plain-words request names the `code-review-layer` layer's prompt file,
   `_bmad/review-prompts/edge-case-hunter.md`, names no role and tells the model to write the
   subagent's brief itself.
3. The model's brief read, in part: "read the review instructions for this layer from
   _bmad/review-prompts/edge-case-hunter.md (in the current project directory) and follow them
   exactly". The spawn ran as an unnamed native subagent, unconfined, and no framework-spawn deny
   was logged. [Source: compatibility/evidence/claude-code-cli-macos-0.13.0.json]

## Root cause

`frameworks.classify` scored the brief (agents 0, identifiers 1, phrases 0). `_recognised` refuses on
a layer name, on an identifier with a phrase beside it, or on `corroboration` phrases, and a client
writing its own brief keeps the prompt file, because the subagent must read it, while quoting none
of the framework's sentences. The identifier alone was deliberately not enough, because a brief that
edits the override templates quotes the same path. [Source: lib/harness_core/frameworks.py#_recognised]

## Acceptance criteria

1. **Given** a native spawn naming no role, **when** its brief directs the subagent to follow or apply
   a declared layer prompt file in any wording, **then** it is refused with the same refusal the
   framework's own text gets.
2. **Given** a brief that edits, updates or rewrites that prompt file, or reads it for another reason,
   or mentions review, a diff or findings in passing, **when** it is spawned, **then** it runs.
3. **Given** step 9, **when** the model writes its own brief for the layer, **then** the case requires
   its refusal: a brief that runs fails the case, and a model that makes no call or names no declared
   prompt file leaves it unverified.
4. **Given** the catalog, **when** this lands, **then** the 0.13.0 rewording limitation is gone and the
   recognition limitation names the directive as a signal.

## Design

- A **directed identifier** is a declared identifier in a sentence that also carries an adoption
  directive (follow, apply, obey, adhere to, comply with, abide by, carry out, according to, per the,
  as instructed in, your review instructions, as your instructions), or whose next sentence says
  "follow it", "apply them" and the like. It is enough alone, because the directive is what an edit
  or a summary brief lacks.
- The directive must govern the file: a leading one ends at most six words before it with no
  comma, colon, parenthesis or conjunction between; a trailing one points back with a pronoun
  ("and follow them", "use it as your instructions"). A negated directive does not count.
- A sentence that edits the file (edit, modify, update, rewrite, rename, delete, remove, reword,
  refactor, lint, amend) is not a directive; a negated edit ("do not edit it") is ignored. The
  edit verb must govern the file the way a directive does, so "update your findings" does not
  cancel a directive in the same sentence.
- Only base and -ing forms count, so a third-person "a reviewer who follows it" describes rather
  than directs. Sentences split on terminal punctuation, a semicolon and a spaced dash.
- The verbs are generic English and live in `frameworks.py`, so descriptors need no new field and
  a framework adding identifiers gets the rule for free.
- Rejected: a descriptor-declared directive list (every framework would repeat the same verbs);
  treating any identifier as enough (refuses the template edits the descriptor exists to allow);
  an embedding or model classifier (a hook runs on every tool call and must be deterministic).
- Must not change: the refusal text, layer-name and phrase recognition, the input-roots rule.
- **Reversed, 2026-10-05: a declared prompt file now refuses by default.** The rejection of
  "treating any identifier as enough" above no longer holds. Its reason was the template edits,
  and an edit exception keeps those running. The directive list leaked: of 40 plain rewordings
  that adopt the file ("use the instructions in <path>", "do what it says", "review it
  accordingly"), 35 ran. So `_adopted` refuses an unnamed spawn naming the file unless every
  mention is work on the file: an edit verb, or summarise, count, copy, explain, compare, "tell
  me" or "check whether", each governing the file the way a directive does. A directive still
  refuses beside such a look. The eight bare-read near-misses ("Read <path>. Do not follow it")
  are now refused. A false refusal routes the work to the read-only reviewer worker, which can
  still read the file, so it costs a reroute rather than the work.
- A qualified "the <words> instructions", as a pointer back or as a sentence carrying the file
  forward, means the file only when its words are the path's own or generic (review, layer,
  prompt). "Follow the house-style instructions" and "the commit instructions are strict" no
  longer point back (the two follow-ups the #1043 review deferred).

## Regression test

`tests/test_framework_directed_identifier.py` classifies the brief the model wrote in the 0.13.0
round and asserts it is the `code-review-layer` reviewer spawn with the same refusal as the
framework's own sentences. With `_directed` stubbed to `False` its 11 assertions fail; with the fix
they pass. `tests/test_native_acceptance_spawn_confinement.py` now fails the case when the model's
own brief runs.

`tests/test_framework_default_refusal.py` classifies the 40 rewordings (35 ran before `_adopted`),
pins that a look must govern every mention of the file, binds the qualifier on both the pointer
back and the anaphor chain, and pins the eight-word `LEAD_GAP` boundary at eight and nine.

## Review findings

- Shepherd, before the PR: a negated directive ("Do not follow it"), a directive aimed at
  something else ("formatted according to the house template", "matches your review checklist",
  "per the docs"), "use it as a fixture" and a directive in another clause all refused a brief
  that only reads the file. Fixed: directives must govern the file and not be negated; each case
  is now in the undirected table.
- CodeRabbit round 1, `frameworks.py` (major): any edit verb in the sentence cancelled the
  directive, so "Follow <path> and update your findings" ran unconfined. Fixed: the edit verb has
  to govern the file, ahead of it or pointing back at it; both cases are tested.
- CodeRabbit round 1, `native_acceptance.py` (minor): step 9 passes on a refusal from the
  identifier-and-phrase rule too, not only a directed identifier. Answered, not changed: the claim
  is that the model's own brief is refused, whichever signal refuses it, and the note records
  what the classifier matched. CodeRabbit withdrew it.
- CodeRabbit round 2, `frameworks.py` (major): the path matched as a substring, so a directive at
  `<path>.bak` counted for the declared file. Fixed: the path must end where the declared one
  does; `.bak` and `-notes/` cases are tested, as is an absolute-path prefix that still counts.
- CodeRabbit round 2, `frameworks.py` (major): a trailing "follow the instructions in
  docs/other.md" counted for the declared file. Fixed: a trailing "the instructions" followed by
  in, at, from, of, under or inside names its own file; the same and next-sentence cases are tested.
- CodeRabbit round 3 (full review), review body only, `native_acceptance.py` (minor): the
  `spawn-confinement` case description still said the model's own brief is recorded as the
  claim's limit. Fixed: it now says that brief must be refused too.
- Shepherd, round 3: of the four briefs models wrote in the 0.13.x rounds, the macOS 0.13.1 one
  was not refused, by this fix as first built or after rounds 1 and 2, because its "follow them
  precisely" sits two sentences after the prompt file. Fixed: a directive up to three sentences
  on counts while each sentence between still refers to the file ("these instructions", "that
  file"). A test now classifies all four recorded briefs from the evidence files.
