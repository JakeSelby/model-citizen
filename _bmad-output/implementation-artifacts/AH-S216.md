## Story

As a developer reading `harness usage`, I want workflow subagent spend reported apart from spawned
subagents, and never priced against a confined role's budget, so that compliance and budget figures
describe only the spawns the harness actually routed.

## Context and value

The #540 spike, `docs/spikes/2026-09-22-workflow-tool-band-routing-and-ledger.md`, found that the usage
ledger is not bypassed ("`usage-log.py` records every workflow agent") but that "its reroute join is
empty for those rows, so compliance cannot be measured from them".

The issue adds two consequences:

- every workflow subagent row the spike examined carries an empty `tool_use_id` and `rerouted: false`,
  so any compliance figure over the ledger silently counts them as compliant spawns;
- a row labelled with a role name picks up that role's soft budget, although it ran unconfined.

At `origin/main`:

- `policy/hooks/usage-log.py` sets a row's `workflow` field when the agent's transcript sits under a
  `wf_` directory, and `docs/usage.md` documents it;
- `harness usage --by role` in `bin/harness` groups rows by `agent_type` alone, so a workflow row named
  for a role is grouped with that role's spawns.

## Acceptance criteria

From the issue's "Done when" section:

1. **Given** a ledger with workflow and spawned rows, **when** `harness usage --by role` runs, **then**
   workflow rows are reported under their own bucket, not as spawns, in the text and the JSON.
2. **Given** a workflow row named for a role, **when** it is priced, **then** it carries no
   `budget_output_tokens` from a role it did not run under, or it is marked `unconfined`.
3. A fixture ledger with workflow and spawned rows proves both.

## Design

### Approach

From the issue: separate rows whose `workflow` field is set from spawned-subagent rows in the `--by role`
report, and stop attaching a role's soft budget to a workflow row.

### Decisions and alternatives

The issue leaves one choice open for AC 2: drop the budget fields from a workflow row, or keep them and
mark the row `unconfined`. The implementation does both, which satisfies either reading: a workflow
row records both budget keys as `null` and carries `unconfined: true`, so the fork does not need a
call. The report keys on the `workflow` directory rather than on `unconfined`, so a row written
before this change, which still carries a role's budget, is bucketed too.

`harness usage` has no JSON output, so "the JSON" in AC 1 is read as the ledger's JSON rows, which
now mark a workflow row. A `--json` flag for `--by role` was not added.

### Do not implement

- Guarding the `Workflow` launch, which is #576 (AH-S217).
- Rewriting existing ledger rows. AD-11 allows only the usage worker's `upsert` to rewrite the ledger,
  and requires additive schema changes. [ASSUMPTION: the issue does not raise ledger rewrites; the
  constraint is read from AD-11.]

### Completion notes

- `policy/hooks/usage-log.py`: a row whose transcript sits under a `wf_` directory records
  `unconfined: true` and `null` for both budget keys instead of the role's soft budget. The key is
  additive (AD-11) and absent from spawned rows, like `partial`.
- `bin/harness`: `role_report` groups every row with a `workflow` directory under `(workflow)`,
  sorted last, and prints a footer line counting them. Legacy workflow rows are bucketed too.
- No existing ledger row is rewritten; a rescan rewrites a row only through `upsert`.
- The live usage feed (`policy/hooks/usage-feed.py`) still compares a workflow agent with the
  budget of the role it is named for. It is outside this story's file list and is left for a
  follow-up.
