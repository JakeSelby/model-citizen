## Story

As the harness's maintainer, I want a replay tier that drives scripted multi-turn sessions headlessly, so that I can measure whether delegation, narrow reads, test-output filtering and the hand-off thresholds cut cost where context grows over tens of turns.

## Context and value

The production and micro tiers run one prompt for a few minutes, so they cannot show the harness's cost case, which rests on long sessions. The evaluator pack's 1.3.0 `long-session` set holds three scripted scenarios with deterministic checkpoint graders; this story builds the harness side that runs them.

Part of AH-E027 (#1175). Relates to #1191 (tier bindings), #1192 (Bash gathers) and #1174 (cold cache).

## Acceptance criteria

1. **Given** a pack set at tier `long-session` listing `scenarios`, **when** it is loaded, **then** each `scenario.json` is validated, only its workspace is materialized for an arm, and its checks and solutions stay held back and are covered by the contamination control.
2. **Given** a scenario, arm and rep, **when** the replay runs it, **then** its turns run in order inside one CLI session, turn 1 started with `--session-id` and every later turn resumed with `--resume`, in the existing arm containers with one cold-cache nonce.
3. **Given** a branch turn, **when** it is reached, **then** the `pass` or `fail` prompt is sent by the earlier checkpoint's verdict.
4. **Given** the caps, **when** a session runs, **then** at most `max_user_turns` turns are sent, each turn is launched with `--max-turns` set to `max_agent_turns_per_user_turn`, and the session stops once its reported spend reaches the per-session cap (`--run-cap` when lower than the scenario's hint).
5. **Given** a checkpoint turn, **when** it finishes, **then** the checkpoint's check scores the tree with the stream of every turn since the previous checkpoint.
6. **Given** a finished session, **when** its rows are written, **then** there is one row per checkpoint with segment cost, the four token kinds, main-thread peak context and cost by model class, and one session row with totals and the per-turn curves as arrays.
7. **Given** a long-session results file, **when** `summarise` reads it, **then** it reports per arm checkpoint pass rates, cost per session, cost-per-turn slope, peak context and the cheaper-tier cost share with scenario-clustered intervals.
8. **Given** `--dry-run`, **when** the tier is planned, **then** every planned session is listed with each scenario's cap and the ceiling price.

## Design

### Approach

`replay_pack.load_scenarios` validates and loads a long-session set; `scripts/replay_session.py` holds the session sequencing, row building and summary as pure code driven by a turn callable; `cost_bench.run_long_session` supplies a container-backed driver and the checkpoint scorer, and `_replay` dispatches scenarios to it. `replay_arms.run_command` gains a session-store mount at the image user's `~/.claude/projects`, so each turn's fresh container can resume the transcript the previous one wrote.

### Decisions and alternatives

- Resume by `--session-id` then `--resume <id>` with a mounted transcript store, rather than one long-lived container driven by `docker exec`: it keeps every launch the same `docker run` shape the other tiers use and their timeout and kill handling.
- The per-session cap is passed as the remaining budget on every turn and checked before each turn, since the CLI's own budget is soft.
- A check that cannot run stops the session as an error rather than taking the `fail` branch, so an infrastructure fault never changes a trajectory silently.
- Scenario-clustered percentile intervals reuse SM-2's seed and rank, with scenarios as clusters.

### Do not implement

- No paid run, no history row for this tier, no change to the pack, and no `--verify-tasks` for scenarios (the pack's own verifier proves them).
- No delegation-window or hand-off event counts beyond what the checkpoint checks already report.
