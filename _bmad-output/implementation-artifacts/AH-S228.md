## Story

As a developer running one long session through several tasks, I want `/land` to refresh the handoff
after a merge once the session is large, so that a `/clear` at that task boundary loses nothing I need.

## Context and value

`/clear` is the cheap alternative to a cold resume, which re-writes the whole context at the cache-write
price; idle rebuilds were 10.7% of long-session spend over the 30 days to 2026-09-23
([#745](https://github.com/JakeSelby/agent-harness/issues/745)). It is only cheap when the next session
can pick up where this one stopped.

The pieces exist. `/clear` fires SessionStart with source `clear`
[Source: https://code.claude.com/docs/en/hooks], and `harness-session.py` injects the first 80 lines of
`.agent-harness/progress.md`, and the task contract when a task is recorded, on every SessionStart
whatever its source
[Source: policy/hooks/harness-session.py#handoff_lines]. What is missing is a current file: today it is
written only when someone runs `/handoff`, or when `/close-out` decides work continues. A merge is the
natural point to refresh it, and the cold-resume guard (AH-S229) offers `/clear` on the premise that the
handoff is current.

## Acceptance criteria

1. **Given** a session the usage feed has reported past its first fresh-session threshold, **when**
   `/land` merges and work in the repository continues, **then** `.agent-harness/progress.md` is
   rewritten in the `handoff` workflow's headings before the report, and the report says so.
2. **Given** a session under the threshold, or a cost variant with no thresholds, **when** `/land`
   merges, **then** the file is not touched.
3. **Given** `/close-out` running `/land`, **when** the merge completes, **then** the refresh is left to
   close-out's own handoff step, and the file is written at most once.
4. **Given** a refreshed file, **when** a session starts after `/clear`, **then** its Done and Next command
   sections fall inside the 80 lines the SessionStart hook injects.
5. **Given** the changed workflows, **when** the command tests run, **then** each body stays within the
   35-line cap, and the generated projections are current.

## Design

### Approach

- `primitives/workflows/land.md` gains a step before its report: when the usage feed has reported the
  session past its first fresh-session threshold and work continues, rewrite
  `.agent-harness/progress.md` with the `handoff` workflow's headings (Done, Open, Next command,
  Decisions needed, Learnings), within 80 lines. The step is skipped when `/close-out` invoked `/land`.
- `primitives/workflows/close-out.md` step 3 says that it owns the handoff when it runs `/land`.
- `bin/harness generate` refreshes the projections.

### Decisions and alternatives

- **Key off the feed's nudge.** A workflow cannot measure context, and the feed already says, once per
  threshold, when the session passes one [Source: policy/hooks/usage-feed.py#session_line], from the cost
  variant's `session_nudge_at` [Source: primitives/stances/cost/balanced.json]. Under `max`, which sets
  none, the step never fires. On Codex the feed is uncovered, so it never fires there either, a gap
  already declared [Source: adapters/codex/capabilities.json]. Rejected: refreshing after every merge,
  which spends a turn in short sessions that nobody will clear.
- **The agent writes it, not a hook.** Only the agent knows what is done and what comes next. Rejected: a
  Stop or SessionEnd hook that writes the file.
- **Fit the 35-line cap.** `land.md`'s body is at the cap today [Source: tests/test_commands.py], so the
  new step is paid for by tightening step 4, whose flag details `harness worktree remove --help`
  already gives. Rejected: raising the cap, which keeps every workflow short enough to read.
- **A refresh, not the full handoff.** The step rewrites the file only; recording durable learnings stays
  with `/handoff` and `/close-out`.

### Do not implement

- Any `/clear` automation (the epic's out-of-scope list).
- Changes to `harness-session.py` or to its 80-line injection.
- The cold-resume guard (AH-S229).
