## Story

As the maintainer pre-registering a replay of a real fan-out prompt, I want each trial to record
what the spawn hooks did to every spawn of its first wave, so that the replay shows the model each
spawn ran on, whether its brief carried a budget, and whether Workflow-launched agents escaped the
hooks, without paying for the whole fan-out.

## Context and value

- One research request became 350 top-tier agents. A pre-registered replay has to show what
  `tier-agent-spawns` and `brief-guard` do to each spawn of such a prompt, in both arms.
- `replay_pair.stream_spawns` already records each spawn's requested and actual model, but reduces
  the brief to a fingerprint, so budget presence was not captured, and nothing checked agents a
  `Workflow` script launched against the spawn hooks.
- Overlap: #1205 (observability) and #1199 (fan-out caps) read the same spawn and hook events.
  Everything here sits in one standalone module, `scripts/replay_spawns.py`, whose functions take
  a message list and return plain rows, so both can import it rather than re-derive it.
- The pre-registration that uses these pieces is filed separately.

## Acceptance criteria

1. **Given** a pack whose project carries BMad's research skill, **when** a trial replays a research
   prompt, **then** the skill is available to the agent in both arms.
2. **Given** a saved raw stream, **when** the detector runs, **then** each spawn row records whether its
   brief carried a budget, with null when the brief can't be read.
3. **Given** a trial that launched agents through the Workflow tool, **when** the check runs, **then**
   the row records whether each launch passed the spawn hooks, with null when unknown.
4. **Given** a fan-out trial, **when** its first wave of spawns has been issued, **then** the trial stops
   within the pre-set turn or spend bound, and the row says which bound ended it.
5. Each piece has tests on recorded fixtures; no live-service test.

## Design

### Approach

- **Pinned vendoring in the pack.** A pack workspace may name `vendor` entries: an upstream git
  source, a full commit, a permissive licence, path pairs and the digest of the placed files.
  `replay_pack.materialize` fetches those paths at that commit, checks the digest, refuses to
  replace a workspace file, and commits them with the workspace. The pack's own digest covers
  `pack.json`, so it pins the vendored bytes too. Both arms run one command line in the
  workspace, so `.claude/skills/` is offered to both; `requires_skills` makes each row record
  whether the `init` event listed the skill.
- **Brief detector.** `spawn_briefs` reads the brief a subagent received, from its thread's first
  message, then the PreToolUse hook's `updatedInput`, then the written brief when no spawn hook
  rewrote it, and judges it with `WORD_CAP_RE` and `BUDGET_RE` from `rule-detectors.py`.
- **Workflow check.** `workflow_launch_hooks` counts spawn-tool PreToolUse and PostToolUse
  `hook_response` events inside each launch's window beyond those its own spawn calls explain.
- **First-wave stop.** `first_wave_launch` wraps the arm's `docker run`, feeds each stream line to
  `FirstWave`, and stops the container by name once each call of the main thread's first spawning
  turn has reported its model, shown activity or been refused. `max_turns` and the run cap stay
  the bounds; `ended_by` names the one that ended the trial.

### Decisions and alternatives

1. Fetch BMad at a pinned commit rather than vendor it into this repository or the pack: the
   licence permits either, but fetching redistributes nothing, keeps `THIRD_PARTY_NOTICES` as it
   stands, and a digest pins the bytes as tightly as a copy would.
2. Judge briefs with the hook's own patterns, loaded from `rule-detectors.py`, not a second copy,
   so the detector and `brief-guard` cannot disagree about what a bound is.
3. Null over false: a brief that cannot be read, a stream without hook events, and a window whose
   events cannot be attributed all record null.
4. Stop on observed thread models rather than on the spawn call alone, so the row carries the
   model each first-wave spawn actually ran on; the cost is the first turn of each subagent.
5. A launcher stop leaves no priced result, so the spend ledger counts the run cap for it rather
   than estimating spend from token counts.

### Do not implement

- The pre-registration, and the research task in the evaluator pack repository.
- Any change to `policy/hooks/`, `primitives/`, `adapters/`, `claude/`, `bin/` or `product.json`.
- Restructuring `scripts/replay_arms.py` or `benchmarks/ablations.json`.
