## Story

As a harness maintainer, I want a cheap replay tier that exposes whether one intended mechanism
fired, so that I can smoke-test behavioural changes before paying for a production calibration.

## Context and value

The production replay is deliberately expensive and slow. Delegation, the stop gate and output
shape can first be probed with small, oracle-scored tasks on a pinned cheap model. That probe must
stay visibly weaker than production evidence: it answers whether a mechanism can fire in this
fixture, not whether the harness saves cost or how the production model behaves.

## Acceptance criteria

1. **Given** the micro manifest, **when** `replay --tier micro --verify-tasks` runs, **then** every
   parent fails its held-back oracle and every solved fixture passes it without a model call.
2. **Given** a complete micro replay, **when** rows are scored, **then** each reports oracle outcome,
   mechanism id, fired yes/no/unknown and cost, using stream counters or named offline detectors.
3. **Given** no overrides, **when** the tier is selected, **then** it pins
   `claude-haiku-4-5-20251001`, two repetitions, a 0.10 USD run cap and a 1.90 USD set stop, with
   the capped set below 2 USD.
4. **Given** micro results, **when** history is written, **then** their tier, series and files are
   separate from production and no cost or production-behaviour claim is emitted.
5. **Given** the implemented tier, **when** the repository gates run under current and system
   Python, **then** lint and unit tests pass; the reviewed live run establishes the under-15-minute
   observed pace before this story is closed.

## Design

### Approach

Add a small manifest and three synthetic oracles. Extend the existing container replay rather than
create a second runner: tier selection supplies the manifest, model and caps; the existing arms,
preflight, raw streams and held-back scorer remain authoritative. After offline detection, enrich
the micro rows with the task's mechanism result and write a dedicated ledger.

### Decisions and alternatives

- The manifest pins the model; a CLI override is refused so a series cannot silently change model.
- Raw streams are mandatory for a live micro run because missing detector evidence is unknown.
- A dedicated history name plus a tier guard prevents accidental production-ledger contamination.
- The tier states no ratio or verdict. Reusing the production verdict would overclaim from a
  smaller model and a mechanism fixture.

### Do not implement

Do not execute the live micro set before the owner's review gate. Do not replace the production
calibration, publish a savings claim, or infer production-model behaviour from micro results.

## Dev notes

### Bound decisions and requirements

- Both arms use the same fresh-container protocol and differ only by the harness.
- The credential remains name-only; raw streams and generated results stay out of source control.
- Unknown evidence stays unknown. A detector miss is `false` only when its stream was readable.
- The owner released the stale write-intent claims on 2026-09-27; no builder claim is added.

### Files to touch

- `benchmarks/micro/tasks.json` — tier manifest and pinned model.
- `benchmarks/oracles/micro_*.py` — held-back checks and synthetic solvers.
- `scripts/replay_micro.py` — validation, scoring, reporting and micro history.
- `scripts/cost_bench.py` — tier selection and replay integration.
- `tests/test_replay_micro.py` — offline regression coverage.
- `docs/benchmarks.md`, `changelog.d/512.added.md` — operator contract and release note.

### Testing

`tests/test_replay_micro.py` covers manifest validity, tri-state scoring, pinned defaults, the
under-2-USD cap arithmetic, raw-stream enforcement, claim-free history and mixed-tier refusal.
The existing cost-bench suite proves the shared runner remains compatible. `replay --tier micro
--verify-tasks` proves all three fixtures in the bare arm with zero errors. The live pace
observation is deliberately deferred to the owner's pre-run review.
