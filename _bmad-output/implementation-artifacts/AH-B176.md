# AH-B176 — fix(observability): hook decisions that cannot be measured from the logs

## Reproduction

An exploratory audit of the decision log (2026-09-21 to 10-03) and 30 days of transcripts, counts
only:

- `usage --by adherence` answered 45 of 45 fresh-session emissions `unknown` (`unobserved`).
- filter-output wrote no row, so its savings had no measure.
- 2 of 9 spawn reroutes seen in transcripts had a `tier-agent-spawns` row.
- allow-readonly-bash left 1 in 20 approvals as ungraded samples and nothing else.
- validate-plan-card, harness-session, workspace-session, allow-plan-webfetch and
  stage-user-files wrote no row at all.
- `decisions.jsonl` reached 20 MB in 13 days with no retention.
- 767 export failures to `localhost:4318` with no collector running.
- 63% of neutralize-tool-output notices were on the harness's own files.

## Root cause

- The adherence response is read from `observation.jsonl`, which only the observation entry
  point writes, and that entry point is an opt-in (`observation.enabled`, false by default). With
  it off nothing ever wrote the ledger.
- Logging was added point by point. Only band routing called `log_route`, and the hooks listed
  above had no call to `decisions.record`.
- `decisions._append` only appends. Nothing caps or rotates the file.
- `telemetry.export_rows` tries every batch on every session end and logs each failure.
- neutralize-tool-output scans every output and has no idea where the output came from.

## Acceptance criteria

1. **Given** a filtered test run, **when** it ends, **then** one `filter-output` row records
   bytes and lines in and out.
2. **Given** observation off, **when** a session ends within the window after a fresh-session
   nudge, **then** settling answers `followed`, read from the dispatcher's
   `session-events.jsonl`.
3. **Given** any reroute (band, one rung, top-class demotion), **when** the hook rewrites the
   spawn, **then** a row names the rule and the model before and after.
4. **Given** read-only allows in a session, **when** it ends, **then** one `summary` row
   holds the counts by kind.
5. **Given** each of the five silent hooks, **when** it decides, **then** it writes one row.
6. **Given** the log at `telemetry.decision_log_max_bytes`, **when** a row is appended, **then**
   the file rotates to `.1` and at most `telemetry.decision_log_keep` rotated files remain.
7. **Given** no collector listening, **when** an export fails to connect, **then** no export is
   tried again until a doubling backoff window (one minute up to six hours) closes.
8. **Given** output read from a managed file, **when** it matches, **then** no notice is given
   and the row says `excluded`.
9. **Given** `docs/runtime-controls.md`, **then** it names each hook's logged fields.

## Design

- **Adherence:** the dispatcher calls `adherence.note_event` on UserPromptSubmit, before the
  feed runs, and on SessionEnd. The rows have the observation ledger's shape, identifiers only.
  `observed_rows` reads a session from the observation ledger when the ledger holds it, and from
  the events file otherwise, so turning observation on never counts a prompt twice. The events
  file moves to `.1` at 2 MiB. Turning observation on by default was rejected: it changes what
  every install registers, and the comparison arms depend on it being opt-in.
- **Read-only counts:** `decisions.tally` appends one short line per allow to a per-session file,
  with no lock. `flush_tally` at SessionEnd turns that file into one `summary` row, and flushes
  orphans older than a day as `stale`. The grade-bash allow sample stays: shadow evaluation
  reads it, and it is 2% of the log by bytes.
- **Rotation:** in `_append`, under a non-blocking lock, rechecking the size once the lock is
  held. Reports read the rotated files with `history=True`. SessionEnd's `close_session` reads
  only the current file.
- **Backoff:** only for refused or unreachable connections, so an HTTP error status leaves no
  window. `usage-log` passes `export.backoff.json`. A CLI replay passes nothing.
- **Own files:** file tools by path; Bash only when every segment is a plain reader and every
  existing operand is managed. The managed set is the harness checkouts (found by a marker
  file), the files `sync` manages, and the config folder. Transcripts are not managed.

## Regression test

The new `tests/test_hook_decision_logging.py`, `tests/test_decision_log_rotation.py`,
`tests/test_adherence_lifecycle_events.py`, `tests/test_telemetry_backoff.py` and
`tests/test_neutralize_own_files.py`. Each one fails on main: no row, no events file, no rotation,
a retry every time, and a notice on a managed file.
