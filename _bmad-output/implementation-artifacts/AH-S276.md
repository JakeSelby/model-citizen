## Story

As the maintainer running the v0.17.0 field experiment, I want every burndown bot attempt assigned at
random before its first turn and recorded as assigned, so that the bot's work is intention-to-treat
evidence of the harness's effect on real bugs.

## Context and value

Randomising from the first attempt makes the bot's work evidence for the v0.17.0 field experiment
([#803](https://github.com/JakeSelby/model-citizen/issues/803)). Without it the data is biased by which
bugs the bot happens to take, and the backlog it leaves gets harder. The evidence standard sets the bar:
item 10 makes intention to treat the headline, "every trial as assigned, including crashes, timeouts and
fallbacks", and item 11 requires a sample-ratio check that stops the analysis at p below 0.001
[Source: docs/evidence-standard.md#10-estimand-labels]
[Source: docs/evidence-standard.md#11-field-checks].

Bugs close fast here (a median of 0 days over the 28 open when the plan was written), so the
pre-registration must set a minimum sample and a stop date before the first assignment. Traces to
FR-74 ([#947](https://github.com/JakeSelby/model-citizen/issues/947)).

## Acceptance criteria

1. **Given** the first assignment, **then** a pre-registration filled from
   `docs/pre-registration-template.md` has already merged, with hypotheses, primary metric, guardrails,
   sample size, stopping rule and exclusions for the bot stream.
2. **Given** an eligible bug, **then** its lane and, in the Claude lane, its arm (harness or bare, 1:1)
   are drawn at claim time, after the owner's label, and written to the issue before the first turn.
3. **Given** any attempt, crashes, timeouts, deferrals and caps included, **then** it is recorded as
   assigned, with lane, arm, harness tag, turns, tokens, wall time, CodeRabbit rounds, human commits and
   outcome.
4. **Given** the recorded assignments, **then** a sample-ratio check runs before any effect is read,
   and p < 0.001 stops the analysis.
5. **Given** the harvest command, **then** it rebuilds the attempt table from GitHub, and its tests run
   on recorded fixtures.

## Design

### Approach

- **Assignment** comment on the issue before the first turn: a fenced machine-readable block with the
  draw, lane, arm, harness tag and time. The draw happens at claim time, after the owner's label, so
  labelling cannot select for an arm.
- **Lane shares.** By default each eligible bug is drawn one third each to harness, bare and Codex:
  a third to the Codex lane, and the Claude lane's two thirds split 1:1 between harness and bare. The
  shares are a variable, fixed by the pre-registration (#950 holds the decision).
- **Outcome** comment when the attempt ends: result, turns, tokens (from the action's execution output;
  unknown for Codex), wall time, CodeRabbit rounds, human commits on the pull request, the pull request,
  and a revert within 14 days.
- **Harvest** rebuilds the table from these comments through the API; tests use recorded fixtures, never
  the live service.
- **Pre-registration** follows the template's headings: run, hypotheses, primary metric, guardrails,
  sample size, stopping rule, multiplicity, decision rule, exclusions, deviation log
  [Source: docs/pre-registration-template.md].

### Decisions and alternatives

- **Draw at claim time, after the label.** Rejected: drawing when the issue is filed, which lets the
  owner's labelling choice correlate with the arm.
- **Record on the issue, not in a local ledger.** The bot runs on GitHub's runners with no persistent
  disk, and the issue is public and durable. The harvest makes a table from it on demand.
- **Codex is a stratum, not an arm.** Codex cloud cannot carry the user-level harness, so its fixes are
  analysed apart from the harness and bare contrast.
- **The analysis stays with #803.** This story produces the record, not the estimate.

### Do not implement

- The effect analysis, intervals or any published figure (#803, v0.17.0).
- The lanes that consume the draw (#948, #950).
