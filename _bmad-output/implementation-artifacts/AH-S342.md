## Story

As the maintainer running the definitive evaluation, I want a blind pairwise judge on two runs'
final diffs and replies, calibrated on my own hand labels, so that scope discipline, design quality
and reply quality are measured where no deterministic grader can decide them, and only where the
judge has been shown to agree with me.

## Context and value

The oracles score pass or fail and the detectors score rule violations. Two passing runs can still
differ in whether they kept to the task, whether the change was well designed, and whether the
final reply was clear and true. A model judge can read those, but an uncalibrated judge carries
position, length and same-family biases. This is the minimum of #801 the evaluation needs: one
pinned judge, a calibration set, agreement and bias audits, and an admission rule.

## Acceptance criteria

1. **Given** two runs of one task, **when** pairs are exported, **then** each pair's runs appear in
   a seeded random order as `first` and `second` with no arm or run identity in the pairs file,
   and the identities go to a separate key file.
2. **Given** a pair, **when** it is judged, **then** the pinned model is asked with the pinned
   rubric twice, in a seeded random order and then swapped, and returns per dimension `first`,
   `second` or `tie` with a short reason, as JSON.
3. **Given** two answers that disagree on a dimension, **when** the verdict is formed, **then** that
   dimension is a tie flagged inconsistent, and the inconsistency rate is reported.
4. **Given** a rubric whose sha256 differs from the pin, **when** the judge loads, **then** it is
   refused.
5. **Given** a saved set, **when** `export` runs, **then** it writes 40 pairs by default, spread over
   tasks, as JSON and as a local HTML labelling form.
6. **Given** verdicts and hand labels, **when** `calibrate` runs, **then** it reports Cohen's kappa
   per dimension, a position-bias audit and a length-bias audit, and admits a dimension only when
   kappa reaches the pre-registered floor, 0.6 by default.
7. **Given** verdicts, the key and a calibration, **when** `judge_section` runs, **then** it returns
   per arm pair the win rate on each admitted dimension, a tie counting one half, with a
   task-clustered bootstrap interval, and lists the dimensions not admitted.
8. **Given** the tests, **when** they run, **then** no container is launched and no model is called.

## Design

### Approach

A new module, `scripts/replay_judge.py`, with four subcommands: `export`, `run`, `calibrate` and
`report`. The pin lives in `benchmarks/judge/judge.json` beside the rubric prompt
`benchmarks/judge/rubric.md`. `run` asks the model through `replay_arms.run_command`: a fresh
container of a built arm image with nothing mounted, the prompt on standard input, the credential
by name and the egress proxy. Every judging function takes an `ask(prompt)` callable, so the tests
pass a fake model. `judge_section` is a pure function over verdicts, key and calibration.

### Decisions and alternatives

- The judge model is `claude-sonnet-5-5` at medium effort, not the production replay model, to
  lower same-family self-preference without a second provider; the pin makes a change deliberate.
- Blinding is applied twice: the export's file order for the labeller, and the judge's own shown
  order per pass. Both are seeded, so a run can be reproduced.
- The diff is a saved `<task>-<arm>-<rep>.diff` beside the stream when one exists, else the
  stream's Edit, MultiEdit and Write calls. The runner does not save the final diff today, and
  changing it is outside this story.
- An unreadable answer is an error and left out, never a tie, so a failing judge cannot pass for
  an indifferent one.
- The win-rate interval is a task-clustered percentile bootstrap using the shared percentile from
  `replay_stats`, so it matches the replay's other intervals.

### Do not implement

No change to `scripts/cost_bench.py` or to `summarise`; no runner change to save diffs; no
same-family bias audit across providers, confusion-matrix calibration error or bootstrap of kappa,
which remain #801's.

`tests/test_replay_judge.py` covers the pin and its refusal, blinding of the pairs file and of every
prompt, the seeded orders, the order swap, the tie on inconsistency and its rate, error handling,
kappa against a hand-computed value, position and length bias, admission at and below the floor,
the summary section and its interval, reading runs from saved streams, the container command line,
and the export, calibrate, report and dry-run commands.
