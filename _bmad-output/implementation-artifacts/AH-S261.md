## Story

As a harness user who reads replies on a narrow screen, I want a `concise` voice that picks each
reply's shape by what the reply is for, so that a done message stays one line, a decision is
answerable by number, and no reply wears a template it does not need.

## Context and value

The shipped voices each impose one template on every reply, and the always-loaded rules repeated
the Scannable "What changed" template on top of whichever voice was selected, so a reply could be
told two shapes at once. Claude Code now ships a built-in `Concise` output style, which a variant
can select by name without copying any of its text. The plan is
`.agent-harness/plans/concise-voice-reply-shapes.md`.

## Acceptance criteria

1. **Given** `stances.voice` is `concise`, **when** `harness sync` runs, **then** Claude Code's
   `settings.json` carries `"outputStyle": "Concise"` and Codex's `AGENTS.md` carries the
   `Voice: concise` stance text.
2. **Given** a user chose `Concise` themselves, **when** a sync runs at `voice: off` or an
   uninstall runs with no journal record, **then** their `outputStyle` is left as it was.
3. **Given** the always-loaded rules, **when** they are searched, **then**
   `grep -rn "What changed" primitives/rules primitives/workflows policy/hooks` prints exactly
   one match, the `voice/scaffold-leak` detector's own label pattern in
   `policy/hooks/rule-detectors.py`, and `brief-guard` appends a label-free return shape only to
   a brief with no return bound.
4. **Given** `voice: concise`, **when** a final reply wears a template section label or opens
   on a heading, **then** `voice/scaffold-leak` or `voice/heading-first` records one hit, and neither
   fires under `scannable`, `answer-card` or `off`.
5. **Given** the full change, **when** the gate runs, **then** `python3 bin/harness lint` is clean
   within the raised caps, `python3 -m unittest discover -s tests` passes,
   `python3 scripts/detector_corpus.py --floor 0.9` passes and
   `python3 scripts/cost_bench.py static --check` passes.
6. **Given** wording adapted from openai/codex, openai/openai-cookbook and garrytan/gstack,
   **when** the notices are read, **then** each source is pinned to a commit in
   `third-party.json` and its licence text is in `THIRD_PARTY_NOTICES`.

## Design

### Approach

A new stance file, `primitives/stances/voice/concise.md`, holds six reply shapes and seven rules
in plain prose. `bin/harness` gains `BUILTIN_OUTPUT_STYLES = {"concise": "Concise"}` beside the
file-backed registry, and `voice_output_style` falls back to it. Codex needs no code change,
because `render_codex_agents` already emits the selected stance. The competing reply templates
are removed from the always-loaded rules, the `/research` and `/build` workflows, `brief-guard`
and two skills, and the answer-card and scannable voices are rewritten in plain prose. Two
detectors gated on `voice: concise` count template labels and heading-first replies.

### Decisions and alternatives

1. **Default voice stays `scannable`.** Changing the default's behaviour is a breaking change
   under `docs/compatibility-policy.md`; `concise` is measured first. Rejected: making it the
   default now, which would be a major-version change.
2. **The always-loaded caps rise.** The line cap goes from 200 to 225 and the token cap by the
   stance's measured 620 tokens, citing #811. Rejected: a 12-line stance with no examples and
   folding `cache-hygiene.md` into the `cost` stance.
3. **The Scannable `keep-coding-instructions` fix lands separately, first (#810).** This branch
   does not touch the style's frontmatter.
4. **`brief-guard` shapes only briefs with no return bound**, which keeps its parity with the cap
   detector exact. Rejected: every brief without a shape sentence.
5. **Notices live in `THIRD_PARTY_NOTICES.md`, `THIRD_PARTY_NOTICES` and `third-party.json`
   only.** Rejected: a comment line in the stance, which every turn would pay for.

### Do not implement

- Changing the default voice, Codex `model_verbosity`, or the plain-language rewrite of the other
  rules.
- The Scannable `keep-coding-instructions` key (#810).
- An `ATTRIBUTION.md` under `primitives/stances/voice/`, which would become a selectable variant.
- The `/review` report format and the design-loop judge's verdict-first line.

### Budget measurement

- Before the stance: `context: always-loaded is ~3858 tokens of 4202 and 199 lines of 200`.
- With the stance, before the caps moved: `context: always-loaded is ~4346 tokens of 4202 and 223
  lines of 200`, over both caps.
- Final: `context: always-loaded is ~4359 tokens of 4822 and 223 lines of 225 (instructions, rules
  and the longest variant of every stance; benchmarks/static.json counts a wider set)`.
- Style probe: `claude --version` printed `2.1.280 (Claude Code)`, and that client's binary
  registers a built-in style named `Concise`. The interactive `/output-style` listing was not
  opened; versions before 2.1.280, including the Linux client pinned at 2.1.278, are unverified.

### Gate and verification record

- **The AC 3 grep** has one expected match: the `voice/scaffold-leak` detector's own label
  pattern in `policy/hooks/rule-detectors.py`.
- **Throwaway-home sync** with `{"stances":{"voice":"concise"}}`: `harness sync` returned 0,
  `settings.json` carries `"outputStyle": "Concise"`, and the Codex `AGENTS.md` carries the
  `Voice: concise` stance. The dry run prints neither, so the check ran without `--dry-run`.
- **openai/codex NOTICE** at commit `1f17a0a04b5c53ef2ea89b7d874764139321b26a` exists. It reads
  "OpenAI Codex / Copyright 2025 OpenAI" plus a Ratatui attribution, and is reproduced in full in
  `THIRD_PARTY_NOTICES` ahead of the Apache-2.0 text, as Section 4(d) asks.
- **`python3 scripts/cost_bench.py static --check`** returned 0 with no output in the final gate:
  no growth past the 5% allowance, so no `benchmarks/allow.json` entry was needed.
- **A user's own `Concise`** is adopted, not installed: when the live value already equals the
  built-in style being applied, the sync does not journal it as harness-applied, so a switch away
  and an uninstall both leave it in place (`tests/test_voice_output_style.py`).
