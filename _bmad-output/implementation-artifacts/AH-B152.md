# AH-B152 — Move the Bash command grader out of grade-bash so the read-only allow does not load a switched-off hook

## Reproduction

Select `grade-bash: off` (with `core_switches_acknowledged`) and leave `allow-readonly-bash` on, then send any Bash command, `ls` included, through the lifecycle dispatcher on either runtime. The dispatcher loads `policy/hooks/grade-bash.py` and calls its `strip_marker` and `grade_text`. Make that load raise, as any fault in the switched-off hook would, and every Bash call is denied with "Harness policy is unverified". The delegation read count loads the same hook for `grade_text` whatever its switch. Found in the review of #863; present on main at 3391df70.

## Root cause

The read-only allow and the grading gate share one grader, and that grader lived inside the `grade-bash` hook script, so the dispatcher loaded the hook whenever either id was on. A load or grading fault raises out of `_dispatch`, and `lifecycle.main` turns any PreToolUse exception into a deny. [Source: lib/harness_core/lifecycle.py#_dispatch; lib/harness_core/lifecycle.py#main]

## Acceptance criteria

1. **Given** `grade-bash` off and `allow-readonly-bash` on, **when** a Bash command is dispatched on either runtime, **then** `grade-bash.py` is never loaded, and a read-only command is allowed as before.
2. **Given** the same switches and a `grade-bash.py` that raises on load, **when** the hook entry point answers a read-only command, **then** it is not a deny.
3. **Given** the same switches under an open posture in plan mode, **when** a grade-2 command is dispatched, **then** the plan-mode ask still carries the grade reason.
4. **Given** any switches, **when** the delegation read count classifies a Bash read, **then** it reads the grading library, not the hook.
5. **Given** `grade-bash` on, **when** any command is graded, governed or approved, **then** every decision is the one main makes: the move is behaviour-preserving.

## Design

The grader (constants, the read-only grammar and approvals siblings, grading, the reason line and the governance walk) moves verbatim into `policy/hooks/bash-grader.py`, a library with no id. `grade-bash.py` keeps its docstring, the stance resolution, `emit`, the approval channel (`approval_code`, `approved`, `deny_tail`) and `main`, and re-exports every library name, so its module API, its standalone behaviour and its output are unchanged. The dispatcher loads `grade-bash` only when its id is on and otherwise reads `bash-grader` for the read-only allow; the delegation read count reads `bash-grader` always.

Rejected: moving only the grading half and leaving governance in the hook, because the two share helpers and a test patching one copy would no longer reach the other; executing the library's source into the hook's namespace, because it hides the dependency. Must not change: any grade, ask, deny or reason text. Not changed: the library still loads `allow-readonly-bash.py` and `approvals.py` as siblings, as the hook did, so `grade-bash` on with `allow-readonly-bash` off still loads the read-only grammar; that is the grammar, not the allow.

## Regression test

`tests/test_disabled_grade_bash.py`: each test makes loading `grade-bash` raise. On a `git archive` copy of main all 4 tests fail (3 failures, 5 errors); on the branch they pass. Behaviour preservation: the reviewers' probe sets for #1138 and #1141, and every probe command dispatched under each pair of Bash switches in four permission modes on both runtimes, produce identical decisions before and after.
