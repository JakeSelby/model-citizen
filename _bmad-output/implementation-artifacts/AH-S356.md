## Story

As a developer, I want to test a draft that changes configuration, so that the Studio's verdict covers the modes, stances, switches, identity and personal modules you actually edit.

## Context and value

The Studio refuses to replay a draft whose configuration was edited after it was created (`replay_target_config_unsupported` in the replay target), because the harness arm could not apply it. Once the engine builds the arm from the draft's configuration (#1269), the refusal can go.

## Acceptance criteria

1. Given a configuration-edited draft, testing it from the Studio or `citizen runs draft-test` starts a replay instead of refusing, and the run shows the configuration digest the engine measured.
2. A configuration the engine refuses shows the engine's reason; the Studio adds no check of its own.
3. Draft pre-registration (#1211) and staleness keep using the configuration digest, so editing the configuration after registering marks the registration stale.
4. Tests cover the lifted refusal, the engine's refusal and staleness after a configuration edit.

## Design

### Approach

Once #1269 lands and the Studio branch takes a merge of main that includes it, remove the `replay_target_config_unsupported` refusal, pass the draft's configuration and digest to the engine through the replay target, and show the digest the engine reports.

### Decisions and alternatives

- The engine decides whether a configuration is admissible; the Studio relays its reason and adds no check of its own.
- Admission and confirmation ask the engine through `cost_bench.py snapshot-config`, so a refusal
  arrives before anything spends. Once a draft edits its configuration, the run hands the draft's
  arm its configuration and the base's arm the one the draft was created with, from one snapshot
  taken at start, so the pair differs by the edit alone; an unedited draft runs source-only.
- The engine's refusal travels as the code `replay_target_<engine code>` with the engine's own
  reason beside it in the error payload, which the Studio shows after its sentence for the code.
- Evaluation tiers keep `replay_target_config_unsupported`: their commands build the harness arm
  from the commit's defaults and carry no configuration.

### Do not implement

- Configuration validation beyond what drafts already do.

## Review findings

- 2026-10-09 review round 1: decided that the base arm carries the draft's inherited
  configuration, so the pair differs by the edit alone and an unedited draft measures identical
  configurations; both digests are shown; any well-formed engine refusal code is relayed with its
  text; a summary whose `measures` contradicts its digests is refused.
- 2026-10-09 review round 2: an unedited draft runs source-only with no engine check; only an
  edit (clearing to `{}` included, via the target's `base_config_digest`) applies a configuration
  to both arms, and makes the replay exploratory with no history row; the draft is read once
  through the snapshot reader and snapshotted once at start, a held lock answering
  `replay_target_busy`; confirm re-runs the check; the error payload carries the engine's
  `reason`, and only its `config_*` codes are relayed.
