# AH-B091 — harness role run accepts a read directory as broad as /tmp

## Reproduction

1. Write a review brief and diff file to `/tmp`, as an orchestrating session did in the 0.13.0 BMad
   integration suite run with a keychain login.
2. Run `harness role run reviewer --runtime claude-code --workspace <worktree> --prompt-file
   /tmp/brief.md --read-dir /private/tmp`.
3. Observed: the run starts and records `/private/tmp` as a read root, so the worker can open any
   file there, including an earlier run's report naming the planted defects. The review cannot be
   shown to be blind.

## Root cause

`workers.run` in `lib/harness_core/workers.py` resolved each `--read-dir` and checked only that it
was an existing directory. Nothing compared it with the shared roots every other run writes into, so
`/`, the home directory and the system temporary roots were all granted as asked.

## Acceptance criteria

1. **Given** `--read-dir` names `/`, the home directory, `/tmp`, `/var/tmp` or the platform temporary
   directory, **when** `harness role run` starts, **then** it exits 1 before launching a worker or
   writing a worker record, naming the resolved directory and a dedicated `mktemp -d` alternative.
2. **Given** `--read-dir` names a directory above one of those roots, such as the home directory's
   parent or the directory holding macOS's per-user temporary root, **when** the run starts, **then**
   it is refused the same way.
3. **Given** `--read-dir` names a dedicated subdirectory under `/tmp` or under the home directory,
   **when** the run starts, **then** it is accepted as before.
4. **Given** a `--read-dir` that is missing or a regular file, **then** the existing errors are
   unchanged.

## Design

- `broad_read_root(path)` returns why a resolved path is too broad, or None. The roots are `/`, each
  resolved system temporary root (`/tmp`, `/var/tmp`, `tempfile.gettempdir()`, `$TMPDIR`) and
  `Path.home()`; a path equal to one, or any ancestor of one, is refused. Temporary roots are checked
  before home, so a macOS directory that is above both is reported against the temporary root.
- `granted_roots(read_dirs)` resolves the values, keeps the existing-directory check and raises
  `ValueError` with the refusal, which `cmd_role` already prints as `role worker: …` with exit 1.
- The check runs where the old check ran, before resolution, the native CLI lookup and the state
  directory, so a refused run leaves nothing behind.
- Rejected: refusing every ancestor of the workspace. A framework checkout above a worktree is a
  legitimate input root, and the issue asks only for directories as broad as `/tmp` or home.
- Rejected: a per-run allowlist. It moves the judgement to the caller who made the mistake.
- Must not change: the read roots recorded in `status.json` for an accepted run, or what is mounted.

## Regression test

`tests/test_worker_read_roots.py`: `test_role_run_refuses_tmp_before_any_worker_starts` runs
`cmd_role` with `--read-dir /tmp`; before the fix it launched the worker, after it the command exits 1
with the refusal and no worker record. The other tests cover each refused root, a directory above
home and above the temporary root, an accepted dedicated `/tmp` subdirectory, and the unchanged
missing-path and file errors.

## Review findings

- CodeRabbit round 1, `workers.py` `temporary_roots`: treat a dedicated `$TMPDIR` as a narrow
  read root and stop refusing its ancestors. Declined with a reply: `$TMPDIR` is the session's
  shared scratch root and a path cannot show it is dedicated; a `mktemp -d` subdirectory of it
  is accepted. Thread resolved.
- CodeRabbit round 1, Ruff S108 on the `/tmp` and `/var/tmp` literals: these name roots to
  refuse, not files to create, so no change.
