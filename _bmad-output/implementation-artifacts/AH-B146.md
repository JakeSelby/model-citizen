# AH-B146 — A here-document body that a shell runs is graded as inert text by grade-bash

## Reproduction

`python3 policy/hooks/grade-bash.py` grades each of these at 0 or 1 although bash runs the `git push` in the body (checked with a `touch` probe under `/bin/bash -c`, GNU bash 3.2): `cat <<EOF` with `$(git push)` in the body (0), `bash <<EOF`, `sh <<EOF`, `bash -s <<EOF`, `zsh <<EOF` (1), `cat <<EOF | sh` (1), `eval "$(cat <<EOF … EOF)"` (1), `source /dev/stdin <<EOF` and `. /dev/stdin <<EOF` (1). With `git push --force` in the body each still grades 1.

## Root cause

`_split_heredocs` removes every body from the shell text so that its lines cannot hide a verb or break the parse, and `_grade_reading` then grades a body only when a SQL client is named. Nothing graded a body the shell runs: bash expands the `$(…)` and backtick substitutions of a body whose delimiter is unquoted, whatever quotes surround them, and a shell, `eval` or `source /dev/stdin` that reads the body runs every line of it. [Source: policy/hooks/grade-bash.py#_grade_reading]

## Acceptance criteria

1. **Given** a body whose delimiter is unquoted, **when** it holds `$(git push)`, `` `git push` ``, `'$(git push)'`, `${x:-$(git push)}` or a substitution split by a continuation, **then** the command grades 2, and 3 for `git push --force`.
2. **Given** a body a shell reads (`bash`, `sh`, `zsh`, `bash -s`, a pipe into `sh`, `eval "$(cat <<EOF …)"`, `source` or `.` of `/dev/stdin`), **when** it holds `git push`, **then** the command grades 2, and 3 for `git push --force`, quoted delimiter or not.
3. **Given** a body with a quoted delimiter passed to `cat` alone, or an unquoted one with no substitution, **when** it names `git push --force`, **then** the grade is unchanged.
4. **Given** a body substitution that never closes, or more than the walk reads, **when** it is graded, **then** it grades unknown or as `_scan` finds it, never lower.
5. **Given** any of these commands, **when** the read-only check runs, **then** it refuses it.

## Design

Each body is now a `Body` (a `str` subclass, so existing callers and tests see plain strings) carrying whether its delimiter was quoted. `_grade_reading` grades the bodies through `_grade_bodies` and keeps the worse of that and the outer text's grade, the pattern #1088 set for readings it cannot choose between. An unquoted body's substitutions come from `_body_substitutions`, a walk that treats quotes as literal, removes backslash-newlines, reads `$((…))` as arithmetic only when it closes as one, and gives up (grade unknown or `_scan`) past `BODY_SUB_CHECKS` substitutions or `HEREDOC_CHECKED_LENGTH`. A body is a script when `_feeds_shell` finds a command that may run its input: a shell, `eval` or `ssh` word anywhere in a simple command, `.` or `source` or a substituted head past assignments and wrappers, in the outer text or any substitution. Both are graded at full grade, as the commands they hold. Rejected: tying each body to the command that receives it, which the split does not keep, so one shell on the line makes every body a script; and grading through `_inner`, which caps a push at 1. Must not change: a quoted body passed to `cat`, the long-body scan cap, the read-only refusal of every here-document.

## Regression test

`tests/test_grade_bash_heredoc_bodies.py`: `RUN` templates are proved to run under bash and must grade 2 with `git push` and 3 with `git push --force`; `DATA` templates are proved not to run and keep their grade; the substitution walk, the unreadable cases and a bounded-time check are covered. Against a `git archive` of `origin/main` the module fails 6 of its 12 tests.
