## Reproduction

With a decision provider configured (`governance.provider: local`), run
`gh issue create --title x --body 'harness config set governance.provider none turns the guard off'`.
The hook answers `ask` with "Governance: this changes the governance configuration, through
`harness config set`, which is level 1", though nothing runs that command. Observed on `main`
after #924; the regression test reproduces it.

## Root cause

`_policy_hits` in `policy/hooks/grade-bash.py` exempted `gh_text_only` lines from the policy-path
search (#924), but its `CONFIG_SET_RE` search ran on the whole command text with no exemption, so
a quoted issue or pull request body that names the command matched.

## Acceptance criteria

1. **Given** a configured provider, **when** a line is exactly one `gh issue|pr
   create|comment|edit|review` command and `harness config set governance` (or `citizen config
   set governance`) appears only in a quoted `--body`, `--title`, `-b` or `-t` value or in a
   quoted here-document fed to `--body-file -` or `-F -`, **then** the config-set check does not
   gate it.
2. **Given** a configured provider, **when** a real invocation runs alone, after `;`, `&&`, `||`
   or a pipe, in a subshell, through `eval`, `sh -c` or an interpreter, or on a line after a gh
   text command, **then** it is asked about as a level-1 action.
3. **Given** a configured provider, **when** any other command mentions it, such as `git commit
   -m` or `gh api`, or a gh text command carries it outside a quoted text value, **then** it
   stays level 1.

## Design

- The config-set check takes the policy-file guard's one exemption: `_policy_hits` skips the
  `CONFIG_SET_RE` hit when the walk decomposed the line and
  `gh_text_only(command, _names_config_set)` holds; a lexer error fails closed.
- `gh_text_only` gains a `names` predicate, defaulting to the policy-path one, so both checks
  share the #924 lexer and shape rules instead of a second parser.
- Words outside the quoted text values are also joined and searched, so an unquoted mention
  spread over several words, such as `--title harness config set governance`, is not exempt.
  For policy paths this changes nothing, since a path match cannot span a space.
- Rejected: stripping quoted text before the regex search, which would need its own quote
  handling and would miss the shapes the #924 review found.
- Not changed: the policy-file guard's decisions, `govern_file`, and every other hook.

## Regression test

`tests/test_config_set_mentions.py`,
`ConfigSetMentions.test_regression_gh_text_mentioning_config_set_is_not_gated`, fails on the
unfixed code and passes after it. `test_a_real_invocation_is_gated` and the
`GhConfigSetTextOnly` near misses pin criteria 2 and 3.
