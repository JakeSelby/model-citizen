## Story

As the maintainer, I want a removal arm for the user-level CLAUDE.md and for the autonomy and
plan-ceremony stances, so that the layer sweep judges every layer that costs tokens or turns.

## Context and value

The layer sweep (#1184, AH-S341) listed three layers as unbuilt. No selection switch withholds
CLAUDE.md, and the autonomy and plan-ceremony stances ship no `off` variant, so an arm could only
swap one variant for another. Without these arms the scorecard (#1186) has no verdict for them.

## Acceptance criteria

1. **Given** a selection holding `"instructions": {"CLAUDE.md": "off"}`, **when** the arm image is built, **then** the `harness-selected` stage deletes the synced `~/.claude/CLAUDE.md`, and the build fails when there is none to delete.
2. **Given** such an arm and control, **when** the run is admitted, **then** the arm passes only when its image manifest differs from control's by that file, its installed selection and the sync's own records, since the resolver cannot see the file.
3. **Given** the autonomy and plan-ceremony stances, **when** their variants are listed, **then** each ships `off.md` in the format the other dimensions use, and `autonomy: off` grades commands at the default variant's threshold.
4. **Given** `benchmarks/ablations.json`, **when** it is checked and dry-run, **then** it holds `no-claude-md`, `autonomy-off` and `plan-ceremony-off`, `unbuilt` is empty, the resolver accepts all three, and the dry run lists each one.

## Design

### Approach

The CLAUDE.md arm removes `instructions/CLAUDE.md`, so its declared selection is
`{"instructions": {"CLAUDE.md": "off"}}`. The resolver ignores a user-configuration key that is no
selection kind, and the sync writes CLAUDE.md regardless. A step at the end of the Dockerfile's
`harness-selected` stage reads the installed selection and deletes the file. `scripts/ablations.py`
holds the mapping (`WITHHOLDABLE`), its entry check and `withheld_differences`, the manifest parity
check `admit_arms` uses for such an arm in place of the profile fingerprint. The two stances gain
`off.md`, and `off` joins the grader's thresholds and the decision provider's levels at the
default's level.

### Decisions and alternatives

- The deletion lives in the Dockerfile, keyed on the installed selection, not in a new build target chosen by `scripts/replay_arms.py`, because another session held that file. The Dockerfile's digest is already in every declaration, so the image name still moves with the step.
- `autonomy: off` keeps the default's command-gate threshold. Unmapped, the grader treats an unknown variant as the strictest, so the arm would also tighten the gate and `rt-autonomy-dep` would measure the gate rather than the stance text.
- `plan-ceremony: off` needs no code: the sync installs the card validator only under `review-card`, so `off` behaves as `light` mechanically.
- Withholding CLAUDE.md also drops its `@` import of CLAUDE.personal.md. The file stays on disk, unloaded. The arm's `what` says so.

### Do not implement

No change to `scripts/replay_arms.py` or `scripts/cost_bench.py`, no new selection kind in the
catalog, and no paid run.
