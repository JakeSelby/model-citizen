## Story

As the repository owner, I want a fixed share of eligible bugs sent to `@codex` on the ChatGPT plan, so
that the bot's load spreads across two subscriptions and neither runs dry.

## Context and value

"GitHub issue and PR delegation with `@codex`" is available on Plus, Pro, Business and Enterprise and not
with an API key [Source: https://developers.openai.com/codex/pricing], so a second lane costs nothing
new. Codex cloud cannot carry the user-level harness, so its fixes are a stratum of their own, not a test
arm. Who may trigger `@codex`, and whether an App's comment counts, is undocumented; the spike (#943)
answers that first. Traces to FR-71 ([#950](https://github.com/JakeSelby/model-citizen/issues/950)).

## Acceptance criteria

1. **Given** a bug drawn for the Codex lane, **then** the lane starts a Codex task by the path the spike
   (#943) chose, and records the attempt as the Codex stratum before it starts.
2. **Given** a Codex pull request, **then** it meets the Claude lane's rules: base `main`,
   `bot::authored`, one closed bug, a filled story.
3. **Given** CodeRabbit findings on a Codex pull request, **then** they go back to `@codex` under the same
   three-round cap, and the pull request merges through #949's merge job.
4. **Given** the pause switch or the daily and weekly caps, **then** they apply to this lane too.

## Design

### Approach

- **Codex's share, default a third.** Each eligible bug is drawn at random: a third to the Codex lane,
  and the Claude lane's two thirds split 1:1 between harness and bare, so harness, bare and Codex each
  get a third. The daily caps, not the split, protect the owner's Claude limits. This is the recommended
  option, taken as the default pending the owner's confirmation; the share is a variable fixed in the
  pre-registration (#947).
- The trigger path follows the spike's decision rule: the App comments on the issue; or the lane opens a
  draft pull request and then comments; or the lane posts through an owner token limited to this
  repository's issues and pull requests. If nothing works, the lane is dropped and the split goes back
  to the owner.
- Codex reads `AGENTS.md` natively, so both lanes follow the same repository rules. The owner connects
  the repository in Codex's settings and sets up its environment; if the spike finds only the owner's
  account triggers, the owner adds the limited token.
- The budget gate (#946) runs before the trigger comment, and the attempt counts against the same caps.

### Decisions and alternatives

- **Codex's share (decision 1, default pending the owner's confirmation).** Chosen: a third, drawn at
  random per bug. Alternative: half, which halves the Claude lane's load but gives each Claude arm only a
  quarter of the bugs, lowering the study's power.
- **A stratum, not an arm.** Codex cannot run the user-level harness, so its outcomes are reported
  alongside the harness and bare contrast, never pooled into it.
- **Reuse the merge job.** One merge path means one set of merge conditions to test.

### Do not implement

- A Codex harness adapter for the cloud; Codex cloud cannot carry it.
- codex-action, which takes an API key only and bills per token.
- Any change to the Claude lane's arms (#948).
