# AH-B135 — An escaped quote inside $'…' hides a later git push from grade-bash

## Reproduction

Every case was run with `bash -c` (GNU bash 3.2.57) with `echo RAN` in place of the push, and
bash printed `RAN`; on `main` at ae5cd568 the hooks read them as follows.

1. ANSI-C quotes: `echo $'a\'b'; git -C /tmp/x push` and `echo $'it\'s'; git push origin main`
   grade 1. `echo $'x\'' ; git push #'` and `find . $'-delete'` pass `allow-readonly-bash` at
   grade 0, so neither is governed. `find . $"-delete"` and `git $"push"` are misread the same way.
2. Here-document markers: `echo '<<EOF'`, `echo x # <<EOF`, `cat <<<EOF` and `echo $((1<<X))`
   followed by a push line and the marker word drop the push as a body; so do a continuation on
   the operator line (`echo <<EOF \` then `; git push`) and a body delimiter matched after
   `.strip()` (` EOF` for `<<EOF`), which lets a later false marker swallow the push.
3. Delimiter quote removal: `cat <<'E'OF` then `EOF`, `git push`, `E` hides the push, which bash
   runs after its body ends at `EOF`.
4. `_sql` on a `mongosh` body of repeated `db.` takes 0.2 s at 6 KB and 3.3 s at 24 KB, which
   passes the hook timeout; a timed-out hook fails open.
5. `cd "~/x" && git push` and `cd ~"/x" && git push` are governed at `$HOME/x`; bash goes to
   `./~/x`, and zsh expands only `~"/x"`.

Found while fixing them: the read-only fast path also approved `cat <<EOF` with a body line
`echo '` followed by a push line and a closing `'`, and `echo 'a` / `x #'; git push; echo '`,
whose per-line comment stripping ignored the multi-line quote; `x=$(psql <<EOF` with
`DROP TABLE users;` graded 1; and `echo $$'\' ; git pu\` then `sh #'` graded 1 because the
continuation lexer read `$'` after `$$`. Decoding `$'…'` in the tokenizer then opened two
more: a NUL escape ends the string in bash (`git $'push\0x'` runs `git push`, and
`find . $'-delete\0'` graded 0), and `cd ~$''/x` or `cd $'\x7e/x'` resolved to `$HOME/x`.

## Root cause

Four lexers had no ANSI-C state, so `\'` closed the string: `tokenize`, `_match_paren`,
`_strip_subs` and `_strip_comment` in `policy/hooks/allow-readonly-bash.py`, and `_strip_comments`,
`_extract_subs` and `_unquoted_structure` in `policy/hooks/grade-bash.py`. `tokenize` also kept the
`$` of `$'…'` and `$"…"` in the word. `_split_heredocs` matched `HEREDOC_RE` anywhere on a line,
took the delimiter from a regex that does no quote removal, compared lines after `.strip()`, and
ignored continuations. `MONGO_RE` (`\bdb(?:\.\w+)*\.`) backtracks quadratically on repeated `db.`.
The `cd` walk passes the quote-removed operand to `_static_dir`, which cannot tell `"~/x"` from
`~/x`.

## Acceptance criteria

1. **Given** any command in the regression list, **when** it is graded, **then** the grade is at
   least that of the line bash runs (2 for a push, 3 for a forced push or `find -delete`), and
   `allow-readonly-bash` does not approve it.
2. **Given** an ANSI-C or locale string, **when** it is tokenized, **then** the word is the one
   bash passes (`$'pu\x73h'` is `push`); the read-only check refuses one holding an escape.
3. **Given** a `<<` that is quoted, in a comment, a here-string or an arithmetic shift, **then** no
   body is removed; **given** a real one, **then** its delimiter is quote-removed and matched
   exactly, after `<<-` tab stripping and unquoted-body continuations.
4. **Given** a here-document the hook cannot place for sure, **then** the line is also graded with
   nothing removed, at the worse grade, and no directory is taken from it.
5. **Given** a SQL client body of repeated `db.`, or long marker-heavy text, **then** grading is
   linear and well inside a tenth of the hook timeout.
6. **Given** `cd` to a tilde-prefix written with a quote or backslash next to the `~`, **then** the
   directory is unknown; an unquoted `~/x` still resolves.
7. **Given** the common `git commit -m "$(cat <<'EOF' …)"` shape, **then** it still reads as one
   certain reading with its body removed.

## Design

- One ANSI-C scanner, `ro._ansi_end`, is shared by every lexer; `$$` is paired first everywhere so
  the quote after it is a plain one. `tokenize` decodes escapes as bash 5 does; with `strict`, used
  by `command_ok`, it refuses an escape or a `$"…"`, whose reading differs by shell and catalog.
- The fast path refuses any `<<` other than `<<<` and strips comments over the whole text with
  quote state carried across lines, instead of per line.
- `_split_heredocs` is a lexer in the style of `_join_continuations`: operators only where bash
  reads one, bodies after the next newline token, delimiters quote-removed and matched exactly,
  unquoted bodies joined on odd trailing backslashes. What it cannot place sets `certain` false
  and `_readings` adds the raw text as a further reading; the existing multi-reading path grades
  the worse and drops the directory. Inside `$(…)`, a `ro._match_paren` result that differs from
  the lexer's close (not None, which is a 3.2 syntax error) marks bash 3.2's reading uncertain.
- `_scan` grades a chunk naming `git` and `push` at 2, as `governed_text` already did.
- `MONGO_CALL_RE` finds the call; `_mongo` walks back over the `db.` chain, linear because each
  walk stops at the previous call's `(`. A randomized test pins equality with the old expression.
- A decoded ANSI-C string is cut at its first NUL, as bash cuts it and as `execve` would.
- A line with a tilde next to a quote, a backslash or a `$`, or holding any `$'`, leaves every
  `~` `cd` operand unknown.
- Rejected: refusing every `$'` line outright, which loses `printf $'\t'` grading; running body
  scans on a capped prefix, which could miss a statement past the cap.

## Regression test

`tests/test_grade_bash_quoting.py`: every reproducer above as a template run through `bash -c`
where bash is installed (skipped otherwise) and through both hooks; decoding and strict mode;
splitter cases for delimiters, several operators, substitutions and unplaced markers; a
randomized `_mongo` equivalence; linear-scaling checks in the style of the 100 KB test; quoted
tilde governance. Against `main`, 19 of the 27 tests fail (28 failures and 8 errors in
subtests); the rest check bash's own reading or guard readings that must not change.
