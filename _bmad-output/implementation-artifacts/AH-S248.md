## Story

As a harness maintainer, I want Codex telemetry ingested and a Codex arm in the bench, so that the same analysis runs on Codex sessions and the harness on Codex can be compared with bare Codex.

## Context and value

The evaluation plane reads Claude Code's telemetry. Codex can export OpenTelemetry through the `[otel]` block of its configuration; ingesting it lets the same analysis run on Codex sessions, and a Codex arm lets the bench compare the harness on Codex against bare Codex. #292 and #293 fix the two Codex defects that would otherwise contaminate that arm.

Depends on #292, #293 and #789. Traces to PRD §9 (v0.17.0) and SM-C5.

## Acceptance criteria

1. Given a Codex session with telemetry export on, then its turns land in the usage ledger with fingerprint, tokens and cost, and an unpriced row is named, never counted as zero.
2. Given the bench, then a Codex arm runs the frozen task set under SM-2's analysis.
3. The PRD gains the requirement through `bmad-prd`, since Codex telemetry is absent from the text of record.
