## Reproduction

Run `python3 scripts/cost_bench.py summarise --results <dir>` on the 2026-10-04 Haiku calibration, which stopped at its spend cap after 27 of 42 runs. `money-rounding` holds one bare trial and two harness trials, and summarise exits with "cannot derive SM-2 ... task money-rounding has different trial ids in its two arms".

## Root cause

`replay_stats._cells` requires every task to hold one trial-id set in both arms and across tasks, the fixed-sample shape of a finished run. A stopped run breaks that in one cell, and `cmd_summarise` turns the ValueError into a refusal of the whole set. [Source: scripts/replay_stats.py#_cells]

## Acceptance criteria

1. **Given** a task with unequal trials in its arms, **when** `summarise` runs, **then** each arm keeps the smaller count, the latest trials by `rep` are dropped, and the balancing prints with its reason.
2. **Given** a task with no trial in one arm, **when** `summarise` runs, **then** the task is left out and the reason printed.
3. **Given** a partial set, **when** the verdict prints, **then** it reads `partial` with the count of cells used; for a registered run it reads `partial: no claim` unless the plan's stopping rule allows a partial set.
4. **Given** a partial set, **when** the reliability section runs, **then** it reads the balanced rows and drops the detections of dropped trials.
5. **Given** a complete set, **when** `summarise` runs, **then** the report is unchanged.

## Design

`replay_stats.balance` cuts each task to the smaller arm's count, or leaves a task with an empty arm out, and `analyse_set` analyses the balanced rows with a relaxed `_cells` that needs equal counts per task only, then marks the verdict. Balancing was chosen over leaving uneven tasks out because it keeps the trials both arms share. `analyse` itself stays strict, so ablation, pair and design paths are unchanged. `cost_bench.partial_claim_allowed` reads the plan's `Partial set` field at its recorded commit. It accepts `allowed`, `not allowed`, or `allowed when <reason>[, <reason>]` over the runner's stop reasons (`spend-cap`, `effort`, `surface-drift`), which `replay` records in `stop.json`; a conditional permission claims only when the recorded reason is one it names, and `replay` and `summarise` refuse any other value.

## Regression test
