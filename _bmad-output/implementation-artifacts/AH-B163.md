## Reproduction

1. Run `python3 -m unittest discover -s tests` on a machine that uses the harness.
2. Read the user's decision log: new `framework-spawn` rows appear with `session_id: "s"` and the
   review-layer brief as `input`, written by
   `test_native_acceptance_spawn_confinement.SpawnConfinementPartsTests`, which calls
   `lifecycle.framework_deny` with no temporary home. On 2026-10-03 the log held 1,647 rows with a
   non-UUID session id (`s` 1,333, `pid-862` 295, then `gov-check`, `probe`, `x` and others).

## Root cause

Every state writer resolves its directory from `HARNESS_HOME`, else `HOME`
(`policy/hooks/decisions.py` `home()`, and the same in `adherence`, `approvals`, `posture`,
`usage-log`, `harness_core.intents` and `harness_core.observer`). The suite isolated the home per
test, so any test that ran a hook without its own `HOME` patch wrote the user's real state. The
shared `tests/isolation.py` dropped `CLAUDE_CONFIG_DIR` from the process but left `HOME` alone.

## Acceptance criteria

1. **Given** the suite is run, **when** any test calls a hook without setting a home,
   **then** the row lands under a temporary home and never under the account's real one.
2. **Given** a hook runs as a subprocess with the inherited environment, **when** it writes a
   decision, **then** that row also lands in the temporary home.
3. **Given** the isolation is removed, **when** the guard test runs, **then** it fails.
4. **Given** a log already polluted, **when** the user reads `docs/usage.md`, **then** it shows
   how to count the test session ids and keep only UUID-named rows.

## Design

`tests/isolation.py`, already imported by `test_harness` and 69 modules and so by every
discovery run, now moves the whole test process onto a `tempfile.mkdtemp` home at import time,
removed at exit, and drops `HARNESS_*`. A test that patches `HOME` still wins; one that forgets
lands in the suite home. Per-test patches in the 138 modules that skip the helper were rejected:
a module-level fixture covers them all and does not churn shared files. Runtime precedence is
unchanged. The real log is shared with live sessions, so the guard checks a unique session id
in the bytes appended to it rather than its size or mtime.

## Regression test

`tests/test_suite_state_isolation.py`: the suite home is not the account home; every state
writer resolves under it; `lifecycle.framework_deny` and a subprocess `decisions.record` write a
unique session id to the suite log and never to the real one. With the fixture disabled, three
of its four tests fail.
