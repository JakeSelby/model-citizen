## Story

As a solo or small-team agentic developer, I want routines the Studio schedules on my machine, with their run history, so that audits run on their own and their results reach Home.

## Context and value

Plan step 8 and decision 4. The scheduler writes a per-user launchd agent, following `remote_control.py:127-359`, that runs `citizen studio routine run <name>` through `RunSupervisor` (`runs.py:445`). Definitions and history go under the Studio state directory. The first two routines are a rule adherence audit (`rule-detectors.py`, offline) and hook liveness.

## Acceptance criteria

1. **Given** a routine definition, **when** it is installed from the Studio with presence confirmation, **then** a per-user launchd agent is written, and removal deletes it.
2. **Given** an installed routine, **when** its schedule fires, **then** it runs through `RunSupervisor` and the run shows in Routines and on Home.
3. **Given** the rule adherence audit and hook liveness routines, **when** each runs, **then** it records its result in run history.
4. **Given** the routes and scheduler, **when** tests run in a temp home, **then** they cover shape, auth, errors and the launchd file; node tests and an e2e flow cover the page.

## Design

### Approach

- A routines module modelled on `remote_control.py`; `citizen studio routine run <name>`; the Routines page.

### Decisions and alternatives

- **Local launchd** (decision 4): transcripts stay on the machine. Rejected: Claude Code cloud routines.
- **Presence confirmation like apply:** installing a scheduled job changes the machine.

### Do not implement

- Cloud routines; routines beyond the first two.
