## Story

As an evaluator, I want each task's check to read the session it scores, so that behaviour visible only in the stream (what was read, what was spawned, what it cost) is scored beside pass or fail.

## Context and value

Pass or fail cannot show what a rule changes. #1143 let a check return named metrics, but a check saw only the final tree, so a metric about the session itself could not be measured. The evaluator pack's 16 rule tasks (model-citizen-evals v1.2.0) already implement `check(root, stream=None)` and return their stream metrics as null until a runner passes the stream. Part of AH-E027 (#1175).

## Acceptance criteria

1. **Given** a check taking a second positional argument, **when** an attempt is scored, **then** it is called with the path of the run's whole saved stream-json, subagent messages included, mounted read-only in the check container.
2. **Given** a one-argument `check(root)`, **when** it is scored, **then** it is called exactly as before.
3. **Given** a task declaring metrics, **when** its row is written, **then** it carries `metric_stream`, true only when the stream reached the check.
4. **Given** no stream reached the check, **when** its stream metrics are null, **then** `metric_errors` carries the reason; given one did, the check's own `stream metrics unknown` notes are carried.
5. **Given** the pack's `rules` set at v1.2.0, **when** `replay --verify-tasks` runs, **then** every task verifies.

## Design

### Approach

`_attempt` writes the run's stdout, the full `-p` stream, beside the tree as `session-stream.jsonl`, and the default scorer passes it to `score`. `score` mounts it read-only at `/session-stream.jsonl` (`replay_arms.SESSION_STREAM`) and the oracle driver, inside the container, reads the check's signature and passes that path as the second argument when it accepts one, printing a stream mark before the verdict line.

### Decisions and alternatives

- Signature detection happens in the container, because a pack check is never executed on the host. Two positional parameters or `*args` count as accepting the stream.
- A file mount, not stdin: stdin already carries the check, and a mount matches how the tree reaches it. Read-only, so a check cannot alter the record it scores.
- The stream is written for every scored run, not only under `--raw`, so stream metrics do not depend on keeping raw output.
- `metric_stream` lives only on rows of declaring tasks, so rows of a task without metrics stay byte-identical.

### Do not implement

No stream for `--verify-tasks` or for issue tasks' unit tests. No change to how `summarise` reports metrics, and no reading of metrics in pair, ablation or two-by-two reports.

## Dev notes

### Bound decisions and requirements

Every check runs in a fresh container with no network and no credential, the tree its only writable mount. The oracle-metric contract of #1143: an unknown value is null, never 0.

### Testing

`tests/test_oracle_stream.py`: a local Python stands in for the check container, with the driver's container paths rewritten to the mounted host paths; it covers a stream check, no stream, an unreadable stream, a one-argument check, a `*args` check, and a pack run through `run_one` whose row carries the stream metrics. Existing assertions on the check's mounts and the scorer's recorded metrics were updated.
