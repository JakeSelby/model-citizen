## Story

As a user of the renamed product, I want a `citizen` command that does everything `harness` does, so that
the command matches the brand while every script, hook and habit that runs `harness` keeps working.

## Context and value

The product is renamed Model Citizen (AD-24, the 2026-09-25 sprint change proposal). `harness` also collides
with another vendor's CLI, and no Homebrew, PyPI or npm package installs a `citizen` binary. The compatibility
policy lets a minor add a backward-compatible command, and removing `harness` would need a notice, the next
major and 90 days, so `harness` stays as a permanent alias with no deprecation. This is PR A of the plan; the
copy story (AH-S269) follows it so its `citizen` examples run.

## Acceptance criteria

1. **Given** a checkout, **when** `bin/citizen <subcommand>` runs, **then** it behaves exactly as
   `bin/harness <subcommand>`, because `bin/citizen` is a relative symlink to `harness`.
2. **Given** either name, **when** `--help` runs, **then** usage names the invoked command: `usage: citizen`
   through `bin/citizen`, `usage: harness` through `bin/harness`, and `citizen` for any other basename.
3. **Given** either name, **when** `--version` runs, **then** it prints `model-citizen <VERSION>`, and the
   other `agent-harness {VERSION}` banners print `model-citizen`.
4. **Given** a message in `bin/`, `lib/` or `policy/hooks/` that names the product or suggests a command,
   **then** it says Model Citizen and `citizen`, while every on-disk path on the keep list is unchanged.
5. **Given** hooks and the installer, **when** they locate the checkout, **then** they still find it through
   `bin/harness`, and checkout detection works when the CLI is invoked through either name.
6. **Given** the UX specification, **when** this story merges, **then** its command names in output read
   `citizen`, amended through `bmad-ux`'s update intent with a memlog entry.

## Design

### Approach

- Add `bin/citizen` as a relative symlink to `harness`. `bin/harness` stays the real file.
- Derive the parser's `prog` from the basename of `argv[0]`: `citizen` or `harness`, else `citizen`. Lead the
  usage docstring with `citizen`.
- Change the `agent-harness {VERSION}` banners, including the `--version` action, to `model-citizen`.
- Move messages that name the product or suggest a command to Model Citizen and `citizen`; leave every path.
- Add a changelog fragment `changelog.d/877.added.md`: "Added the `citizen` command; `harness` remains a
  supported alias."

### Decisions and alternatives

- **`bin/harness` stays the real file, and `bin/citizen` is the link.** Hooks and the installer locate the
  checkout by `bin/harness`, and lifecycle refusals print its absolute path; making `citizen` the real file
  would move every one of those lookups for no gain.
- **`harness` is a permanent alias with no deprecation notice** (the plan's Decision 1). The alternative,
  keeping `harness` alone, leaves the brand and command mismatched for good.
- **`prog` follows the invoked name,** so usage text matches what the user typed.

### Do not implement

- No rename of `~/.config/agent-harness`, `.agent-harness/`, `~/.local/state/agent-harness/`, launchd labels,
  `# harness:` markers, the `# agent-harness` PATH and ignore blocks, the Codex banner, or the `harness` rule
  and hook link names.
- No change to telemetry's `service.name`.
- No plugin ID change (AH-S268), no README or docs copy (AH-S269), no slug or site URL (AH-C079).
- The AGENTS.md Gate block and CI keep `bin/harness`.
