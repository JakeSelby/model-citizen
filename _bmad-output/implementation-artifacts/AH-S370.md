## Story

As a solo or small-team agentic developer, I want every Harness page to open on how the item is performing, with its settings one tab away, so that I judge effect before I change configuration.

## Context and value

Plan step 3. The frame is shared by the seven Harness pages: Efficacy rows carry setting, period dates and status from AH-S369; the Settings tab shows configuration with "last changed", and saving creates a draft routed to Changes through the existing `/api/configure/*` save paths.

## Acceptance criteria

1. **Given** a Harness page, **when** it opens, **then** the Efficacy tab is the default and each row carries setting, period dates and status.
2. **Given** a setting changed within 7 days, **when** Efficacy renders, **then** the row splits into before and "measuring, day N of 7", linked to Evals.
3. **Given** the Settings tab, **when** it renders, **then** each value shows its "last changed" date.
4. **Given** a Settings edit, **when** it is saved, **then** it creates a draft through the existing `/api/configure/*` path and the draft shows in Changes.
5. **Given** the frame component, **when** node tests and an e2e flow run, **then** they cover both tabs, the measuring split and the draft save.

## Design

### Approach

- One frame component used by every Harness page, fed by `/api/harness/periods`.

### Decisions and alternatives

- **Efficacy first:** the page answers "is it working" before "how is it set". Rejected: Settings as the default tab.
- **Saves create drafts:** reuse the governed path. Rejected: applying from the tab.

### Do not implement

- Page-specific content (S4 to S8, S11); new save routes.
