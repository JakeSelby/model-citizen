# AH-B169 — fix(hooks): the stop gate mostly times out or skips, so it verifies little

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Reproduction

1. In this repository's main checkout, change a file and end a turn: the Stop hook runs the whole
   `## Gate` block, whose unittest discovery takes 10 to 16 minutes, and releases at its 240-second
   budget as `timeout`. The decision log for 2026-09-21 to 10-03 shows 409 of 676 runs timed out.
2. In a linked worktree of the same trusted checkout, end a turn: the hook reports the folder as
   untrusted and skips the gate (1,141 runs in the same window).
3. A timeout or forced release left only an outcome in the log, with no reason or duration.

## Root cause

- `gate_commands` read only the `## Gate` block, so a repository could not give the hook a
  check that fits its budget [Source: policy/hooks/stop-gate.py#gate_commands].
- `trusted` looked up the worktree's own path in Claude Code's project list and `trusted.txt`;
  a worktree created outside the main checkout is never there, though it shares its repository.
- `run_gate` killed only the shell on a timeout, so a suite it started kept running unwatched.
- `log_gate` passed no fields, so a release row recorded neither its reason nor its elapsed time.

## Acceptance criteria

1. **Given** an `AGENTS.md` with `## Stop gate` and `## Gate` blocks, **when** the hook runs,
   **then** only the stop-gate block runs and a red result names that block.
2. **Given** only a `## Gate` block, **when** the hook runs, **then** that block runs as before.
3. **Given** a linked worktree of a checkout trusted by the dialog or by `harness trust`, **when**
   the hook runs in it, **then** the gate runs; a worktree of an untrusted checkout is skipped.
4. **Given** a gate that outlasts the budget, **when** it times out, **then** its process group
   is killed and the log row carries `release_reason` and `elapsed_seconds`.
5. **Given** eight consecutive red runs, **when** the turn is released, **then** the row carries
   `release_reason` and `elapsed_seconds`.
6. **Given** this repository, **when** the hook reads its `AGENTS.md`, **then** it runs the lint,
   the BMad checks and a targeted test selection, and `## Gate` keeps the full suite.

## Design

- A `## Stop gate` fenced block, parsed by the same reader as `## Gate`, takes precedence; the
  chosen heading is part of the tree hash, so editing either block invalidates a green result.
- Trust resolves `git rev-parse --git-common-dir` against `--git-dir`; when they differ and the
  common directory is a `.git`, its parent is the main checkout and its trust applies.
- The gate runs in a new session and a timeout kills its process group.
- Rejected: raising the hook timeout (a 16-minute stop blocks every turn), and a `harness trust`
  per worktree (worktrees are created by the hundred and would never be listed).
- Must not change: the full `## Gate` stays the push gate; trust of a worktree never flows back to
  its main checkout; the eight-block release and the stated-reason release are unchanged.

## Regression test

`main` (the rest assert behaviour that was already right).
