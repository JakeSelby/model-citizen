# AH-E020 — Rename the product to Model Citizen

This work item was authored as part of the repository's committed BMad planning system.

## Goal

Every living surface says Model Citizen, `citizen` runs everything `harness` does, the plugin installs as
`model-citizen@model-citizen`, and every old repository and site link still resolves, while on-disk names,
`AH-` IDs, telemetry's `service.name` and dated records keep `agent-harness` (AD-24). The repository side
ships inside the v0.14.0 milestone.

## Scope and requirement coverage

- **In scope:**
  - the `citizen` command beside a permanent `harness` alias (FR-17, FR-66);
  - the plugin and marketplace ID, with doctor recognizing the old one (FR-17, FR-18);
  - living copy: README, CONTRIBUTING, docs, `product.json`, primitives and their projections (FR-53,
    FR-54);
  - hardcoded links to the new slug and site, and a `retired-name` lint rule (FR-53);
  - the planning record: this epic's sprint change proposal and AD-24 (FR-9).
- **Out of scope:**
  - renaming on-disk paths, the `AH-` IDs, the issue map's slug, planning directory names, telemetry's
    `service.name` or dated records;
  - publishing to PyPI or npm;
  - the site, the GitHub rename, the About update, the tag and every outward post, which run under their
    own approvals outside these stories.

## Children

In delivery order:
1. AH-C078, #876: record the sprint change and reserve the stories.
2. AH-S267, #877: add the `citizen` command and keep `harness` as an alias.
3. AH-S268, #878: rename the plugin to `model-citizen` and keep recognizing the old ID.
4. AH-S269, #879: rename the product copy to Model Citizen.
5. AH-C079, #880: point hardcoded links at the new repo and domain, and add the retired-name lint rule.

## Architecture slice

- **AD-24** carries the rename's boundary: the brand changes, the stable identifiers do not.
- **AD-19:** landing, README and About copy still come from `product.json` only.
- **Components:** `bin/harness` and the new `bin/citizen` link, `policy/hooks/` messages, `lib/harness_core/`
  messages, `.claude-plugin/`, doctor, `product.json`, the lint in `bin/harness`.

## Sequencing

- AH-C078 first.
- AH-S267, AH-S268 and AH-S269 can run in parallel, except that AH-S269 merges after AH-S267, so its
  `citizen` examples run.
- AH-C079 runs after the GitHub repository rename, which is the maintainer's step.
- The v0.14.0 tag follows AH-C079 and the About update.

## Exit criteria

- A `retired-name` lint rule finds the old brand, slug and site host only on its allowlist.
- `bin/citizen doctor` and `bin/harness doctor` agree, and doctor recognizes both plugin IDs.
- `bin/harness generate --check` passes, and the gate is green on `main`.
- `python3 scripts/bmad_issue_sync.py audit` is clean with every child closed.
