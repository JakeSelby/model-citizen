# AH-B123 — Release validation misses staged files when comparing against HEAD

## Reproduction

Start from a released patch tag, prepare a presentation-only follow-up patch, and stage its
`VERSION` and release-record changes without committing them. Calling
`qualification_reuse()` during the commit hook resolves the target to `HEAD`; the validator reads
the new catalog from the working tree but `changed_files()` compares only the prior tag with the
committed `HEAD`. It therefore reports no `VERSION` delta and refuses the commit with
`qualification reuse release delta must change VERSION`.

## Root cause

`lib/harness_core/compatibility.py::changed_files` always invokes `git diff <prior> <target>`.
For the working `HEAD` target, that command omits the index even though the index is the exact tree
the commit hook is validating. Immutable commit targets correctly exclude staged work and must
retain that behavior.

## Acceptance criteria

1. **Given** a staged `VERSION` change and target `HEAD`, **when** release delta paths are
   collected, **then** `VERSION` is present.
2. **Given** the same staged change and an explicit commit target, **when** release delta paths are
   collected, **then** the staged path is absent and committed-tag validation is unchanged.
3. **Given** a committed-target or staged-target Git query fails, **when** release delta
   paths are collected, **then** the result is unavailable so qualification reuse fails closed.
4. **Given** the completed change, **when** the repository Gate and generation check run, **then**
   all commands pass under code compatible with the Python 3.9 CI floor.

## Design

For `target == "HEAD"`, compare the prior release directly with the index using `git diff
--cached <prior>`. This captures the exact pending tree, including staged reversions of changes
already in HEAD. For immutable targets, retain the prior-to-target commit comparison. Each path
scope fails closed when its Git query fails; unstaged and untracked changes are not included.

The initial implementation unioned prior-to-HEAD and HEAD-to-index paths. Independent review found
that this incorrectly retains a path staged back to its prior content. The direct index comparison
replaces that approach; the existing ancestry validation remains in the caller.

## Regression test

`tests/test_release_staged_delta.py` creates a temporary Git repository and proves the staged
`VERSION` path appears for `HEAD` but not for the same explicit commit SHA. Mocked subprocess
failures cover each path-scope query independently. A staged-revert regression proves the result
reflects the pending tree rather than the union of intermediate changes.

## Review findings

- Blind Hunter: unioning intermediate deltas falsely retained a staged revert. Reproduced with
  a real temporary Git repository; changed the working-HEAD comparison to prior-to-index and added
  a regression. All four focused tests pass on Python 3.14 and 3.9. Full gate rerun pending.
- Edge Case Hunter: the pending catalog and VERSION could differ from the index. The working-HEAD
  reuse check now refuses mismatched staged metadata, preserving immutable-target behavior. This
  is a fail-closed consistency check rather than a change to the evidence contract.
- Edge Case Hunter: newline-delimited path parsing quoted non-ASCII names and dropped whitespace
  names. The path query now uses NUL delimiters, covered by real Git filenames.

  rejected during triage as pre-existing out-of-scope concerns or contradicted by tests.
