## Story

As the maintainer reading a replay's evidence, I want pass^k per task and arm and the
all-rules-at-once rate beside each rule's own rate, so that a flaky task and rules that fail
together are visible rather than averaged away.

## Context and value

A mean pass rate of 0.9 can be one task failing every time or every task failing sometimes, and
only the second makes an agent unreliable in use. Likewise every rule can hold in 90% of runs
while far fewer runs hold all of them at once. Both readings re-derive from what a replay already
saves: `results.jsonl` and the `detections.jsonl` the runner writes when `--raw` is kept.

## Acceptance criteria

1. **Given** saved rows, **when** pass^k is computed, **then** each task and arm reports its
   trials, passes, whether every trial passed, and the unbiased estimate C(c, k) / C(n, k), and
   each arm reports the share of tasks whose every trial passed, the mean estimate and pass^1.
2. **Given** an errored run, **when** pass^k is computed, **then** it is a failed trial.
3. **Given** saved rows and detections, **when** the joint rate is computed, **then** each arm
   reports the share of runs with no detector hit over clean plus hit runs, with a Wilson
   interval, beside each detector's own compliance rate.
4. **Given** a run a detector could not read, or one without detection rows, **when** no detector
   fired on it, **then** it is unknown and outside the rate, never clean.
5. **Given** rows and optional detections, **when** `reliability_section` runs, **then** it
   returns a JSON-ready section and its text, ready for `cost_bench.py summarise` to print.
6. **Given** a saved set, **when** `cost_bench.py summarise` runs, **then** its text ends with the
   section and `--json` carries it as `reliability`, with `joint` read from the `detections.jsonl`
   beside the rows, or `null` when there is none.
7. **Given** an evidence bundle, **when** it is verified, **then** the derived result holds
   `reliability` re-derived from the bundled rows, with `joint` `null` because schema 1 bundles no
   detections.

## Design

### Approach

A new module, `scripts/replay_reliability.py`, holds pure functions over saved rows: `pass_hat_k`,
`pass_k`, `classify_run`, `joint_compliance`, `detections_beside` and `reliability_section`.
Attempts are validated by `replay_stats.attempts`, so the pass reading matches SM-2's; the
interval is the shared Wilson interval.

### Decisions and alternatives

- k defaults to the fewest trials any task-and-arm cell ran, so every cell is estimated at the
  same k; a caller may set it. A fixed k was rejected because sets differ in trial counts.
- The unbiased estimator uses every trial; taking the first k trials was rejected as wasteful.
- An unread run is unknown, as `rule_adherence` reads it, so a missing stream never reads as
  compliance.
- The module lives outside `cost_bench.py`; `summarise` calls `reliability_section` after the
  delegation report and adds it as a separate `reliability` key, so SM-2's fields are unchanged.
- The evidence bundle derives pass^k only. Adding a detections artifact would change bundle
  schema 1, so the joint reading there is `null` until a schema change carries detections.

### Do not implement

No change to the detectors, the runner, the row schema or the bundle schema.

### Testing

`tests/test_replay_reliability.py` checks the estimator against the closed form and against the
mean over every k-subset of trials, the flaky-task case, the errored run, unknown runs, unmatched
detections, the JSON round trip and the rendered text. `tests/test_replay_reliability_wiring.py`
checks that `summarise --json` carries `reliability` and its text prints the section, with and
without detections, and that a verified bundle's derived result holds it.
