## Intent

**Problem:** The repository was renamed to Model Citizen, but current public documentation still
uses the retired product name in transitional copy, the old GitHub slug in live changelog links,
and `bin/harness` in user-facing examples. Release-pinned sites cannot publish the corrections
until a patch release exists.

**Approach:** Correct living copy and examples, preserve operational identifiers and dated history,
then prepare the branding changes as unreleased work. Include #1038 in v0.14.1 and run one fresh
native qualification round on the frozen combined candidate before tagging or publication.

## Boundaries & Constraints

**Always:** Use approved Model Citizen positioning; keep `product.json` unchanged; preserve
`.agent-harness/`, checkout/config/state paths, telemetry names, `AH-` IDs, migration identifiers,
dated artifacts, old issue URLs and the `harness` alias. Retain the `agent-harness` GitHub topic for
rename discovery. Keep published release metadata at v0.14.0 until the combined candidate is
qualified, and retain separate Unreleased changelog fragments for #1036, #1040 and #1038.

**Never:** Carry v0.14.0 evidence onto the combined candidate, describe the branding-only branch as
v0.14.1 or released, qualify before #1038 is included, or tag/publish/deploy from a revision other
than the freshly qualified combined candidate. Site and external-submission edits remain separate
delivery issues and deploy only after the resulting tag.

</frozen-after-approval>
