# AH-B127 — config set refuses a switch that repairs a selection the resolver already refuses

## Reproduction

Write a configuration that switches `roles.builder` off while leaving its dependent
`workflows.build` at the default `on`, then run `citizen config set workflows.build off`. The
command rejects the repair with `workflows/build depends on roles/builder` and leaves the invalid
configuration unchanged.

## Root cause

`config_set` removes the proposed switch from a copy and calls `load_selection` to confirm that the
unit exists. `load_selection` always requests strict resolution, so this membership lookup fails
on any existing dependency or core-hook fault before the proposed repair can be validated.

## Acceptance criteria

1. **Given** `roles.builder` is off and `workflows.build` remains on, **when** the user switches
   `workflows.build` off, **then** the repaired configuration is written and resolves strictly.
2. **Given** a core hook is off without acknowledgement and an independent dependency fault also
   exists, **when** the user restores the core hook, **then** the command rejects the proposal
   because the resulting configuration still contains the dependency fault and writes nothing.
3. **Given** a valid selection, **when** commands load it normally, **then** resolution remains
   strict and invalid dependencies or unacknowledged core-hook switches are still rejected.

## Design

Allow `load_selection` callers to request non-strict resolution. Use that mode only for the
switch-unit membership lookup, then strictly resolve the complete proposed configuration before
writing it. Removing validation entirely was rejected because it would admit unknown units or
persist configurations that remain invalid.

## Regression test

`SwitchKindSyncTests` reproduces the builder/build repair and verifies the written configuration.
A second regression starts with both an unacknowledged disabled core hook and the builder/build
fault, restores the hook, and proves the remaining fault rejects the write atomically.
