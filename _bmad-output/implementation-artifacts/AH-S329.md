## Story

As a developer, I want `citizen usage --json` to expose the report's own aggregates, so that
scripts can consume usage data without parsing tables or reimplementing its bucketing rules.

## Context and value

The text report owns several non-obvious semantics: Workflow agents have a dedicated role bucket,
missing profile fingerprints are unattributed, rescanned stances are unknown and unavailable
metrics stay unknown. Machine readers currently have to duplicate those choices from the ledger.
Issue #995 also needs this output as the source for its spend view.

## Acceptance criteria

1. **Given** a usage ledger, **when** any supported `--by` report runs with `--json`, **then** valid
   JSON contains the same groups and numeric aggregates as the text report from one aggregation.
2. **Given** role, stance or profile rows, **when** JSON is requested, **then** Workflow,
   unattributed and unknown buckets retain their existing meanings.
3. **Given** `--rules` or `--conflicts`, **when** JSON is requested, **then** their groups and
   numeric values are machine-readable too, including empty windows.
4. **Given** missing or unpriceable data, **when** JSON is emitted, **then** unknown values are
   `null`, counts remain explicit and the document contains no NaN or Infinity.
5. **Given** an invalid option combination or `usage export --json`, **when** it runs, **then** the
   command fails on stderr and emits no success JSON.

## Design

### Approach

Build structured group records in the same loops that currently produce table cells, then render
either the existing text or one versioned JSON envelope. Expose structured cache-prefix figures
and conflict weeks from their existing helpers rather than parsing their formatted reports.

### Decisions and alternatives

- JSON uses raw numeric values and `null`; display rounding remains a text-only concern.
- Empty reports return successful envelopes with `groups: []` rather than prose or an error.
- The export subcommand rejects `--json`; its OTLP action is separate from local reporting.
- `--rescan --json` records the rescan result in the envelope so stdout stays one JSON document.

### Do not implement

Do not add analytics metrics, change ledger schemas, alter text output, or change export payloads.
