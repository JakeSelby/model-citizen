# AH-B143 — test_usage_json's multiday test fails when a run crosses midnight UTC

This work item was authored as part of the repository's committed BMad planning system.

## Reproduction

Run the full suite so that it starts before 00:00 UTC and reaches `tests/test_usage_json.py` after it. `JsonReportTests.test_multiday_session_counts_once_per_group_and_once_in_total` fails with `AssertionError: 2 != 1`. Run alone, it passes.

## Root cause

The module sets `NOW` from the clock at import time, but the test computed `yesterday` from `time.time()` when it ran. After midnight UTC, `yesterday` equals `NOW[:10]`, so the session's two day slices land in one group and are counted twice there. [Source: tests/test_usage_json.py]

## Acceptance criteria

1. **Given** a suite whose clock passes midnight UTC after the module is imported, **when** the multiday test runs, **then** it passes.
2. **Given** the test module, **when** it builds day keys, **then** every key derives from the one `NOW` reading.

## Design

Derive `yesterday` from `NOW` (`calendar.timegm` of `NOW`'s date minus one day) instead of reading the clock again. Rejected: freezing the clock for the whole module, which is broader than the defect. Must not change: the report code under test, or what the multiday test asserts.

## Regression test

`JsonReportTests.test_multiday_session_still_counts_once_after_the_clock_passes_midnight` runs the multiday test with `time.time` patched to a day past `NOW`; it fails with the old line (`2 != 1`) and passes now.
