## Goal

Close the should-fix gaps the strong-class assessment of 0.13.0's round 5 (source commit
`d86695b`) found between the native case drivers and the qualification procedure in
`docs/compatibility.md`. Each driver must observe its procedure clause from the run itself, or the
procedure must state the narrower claim the run does show, so a qualification record never claims
more than a driver read. [Source: https://github.com/JakeSelby/agent-harness/issues/742]

## Acceptance criteria

1. **Given** `cost-posture`, **when** the non-default variant is synced, **then** every role it
   leaves byte-identical is still installed as it was before the switch, the same link to the same
   target, and at least one such role is a link; a link replaced by an identical copy fails.
2. **Given** `cost-posture`'s routed spawn, **when** its brief is read, **then** it ends with the
   budget sentence `posture.budget_sentence` writes for the variant's default band row, not merely
   contains "Expected spend:".
3. **Given** `spawn-confinement`'s routed run, **when** it has passed, **then** the driver judges the
   same printed record again with the run's worker-state directory moved aside, requires that
   judgement to fail, and restores the directory.
4. **Given** `hook-composition`'s write turn, **when** it is read, **then** the transcript carries the
   harness coordinator's own `PostToolUse` notice for a Write, beside the user hook's log; its
   absence is `unverified`.
5. **Given** step 4, **when** it is read, **then** it states that on a client with no multi-file patch
   tool a multi-file patch is one turn writing each file with its file tool.
6. **Given** `migration-uninstall`, **when** a harness-owned setting is hand-edited, **then**
   `harness diff` names it as drift and exits 1 before uninstall runs, having not named it before
   the edit.
7. **Given** step 3 and `permission-controls`, **when** they are read, **then** both state that the
   auto posture is claimed as a mode, not as a restriction its classifier was seen to impose.
8. **Given** each change, **when** the unit suite runs, **then** a unit test covers it; **and** a live
   run of each changed case is recorded (owner-run, see the dev agent record).

## Dev notes

- **Gaps and dispositions.** Observed from the run: unchanged roles keep their link (AC 1), the
  brief ends with the row's sentence (AC 2), the missing-state rule on live output (AC 3), the
  harness's own `PostToolUse` entry (AC 4), drift before uninstall (AC 6). Narrowed in the
  procedure: the multi-file patch on Claude Code (AC 5), which has no single multi-file patch tool,
  and the auto posture (AC 7), because asking the provider's classifier to refuse something is
  neither deterministic nor safe to script.
- **Why the scanner notice.** The coordinator's `PostToolUse` writes no decision-log row for a
  Write. Its tool-output scanner (`policy/hooks/neutralize-tool-output.py`) returns additional
  context for a response matching `settings-json`, so the second patch file carries the benign line
  `beta keeps settings.json hooks` and the driver reads the notice from the raw transcript text. A
  unit test drives the real `lifecycle.dispatch` with a Write payload to pin that the line trips it.
  Whether the client records the context in its transcript is what the live run confirms.
- **Files.** `scripts/native_acceptance.py`, `docs/compatibility.md` (steps 3, 4, 7, 9),
  `tests/test_native_acceptance_driver_gaps.py` (new),
  `tests/test_native_acceptance_hook_composition.py` (fake writes the notice),
  `changelog.d/742.changed.md`.
- **Not changed.** The `compatibility/catalog.json` limitation naming #742 describes what the 0.13.0
  and 0.13.1 rounds read, which stays true of those records; retire it when a round under these
  drivers qualifies.

## Review findings

- **CodeRabbit round 1, thread on `harness_post_notice` (minor).** The notice was matched as a
  substring of the raw transcript, so a prompt, tool result or reply quoting it would have passed
  the case. Fixed: the driver now reads it only from an `attachment` record of type
  `hook_additional_context` whose `hookName` is `PostToolUse:Write`, the shape Claude Code writes
  for a hook's additional context; a test pins that quoted, `Bash` and `hook_success` records do
  not count.
- **CodeRabbit round 1, review body (trivial).** The hook-composition fake appends the notice
  itself, so it proves the transcript reading, not that the client emits `PostToolUse:Write`
  context. Not changed: that is the owner's live run under AC 8.
