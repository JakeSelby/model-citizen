## Story

As a developer, I want the Studio to open on my version, updates, health and drift, so that I see first what needs attention.

## Context and value

The Studio opens on what a developer needs first: the installed version and whether an update is available, each `citizen doctor` check with its status and fix, whether the projections have drifted from the selection (`citizen diff`), the active mode, and the latest runs.

## Acceptance criteria

1. Given a failing doctor check, then the overview shows it with the doctor's own message and the command that fixes it.
2. Given projections that differ from the selection, then the overview shows the drift and offers `citizen sync` through the governed path.
3. Given a newer release on `stable`, then the overview shows it with its changelog link, and nothing updates without the developer.
4. The overview reads the same functions as `citizen doctor`, `citizen diff` and `citizen catalog`, and matches their output in tests.

## Design

### Approach

Add one read-only Overview query assembled from the CLI's existing doctor, drift, catalog,
selection, and run functions. The private `GET /api/overview` route adapts that query into a
versioned response; it has no mutation path. The Hub renders the installed/release summary, doctor
checks, projection drift, active mode, and recent runs from that response, preserving the CLI's
messages and exact commands.

The stable-release check is local and deterministic: compare semantic versions from the installed
catalog and the checkout's local `origin/stable` or `stable` ref. When the ref is newer, derive the
changelog link from the configured Git remote. Network access, fetching, upgrade, and sync remain
explicit developer actions outside the query.

### Decisions and alternatives

- The CLI installs the Overview source adapter before starting Studio, so both faces invoke the
  same `cmd_doctor`, `_diff_lines`, `primitive_catalog.catalog`, `load_selection`, and
  `RunSupervisor.list` functions. A separate Studio implementation was rejected because it could
  silently diverge from CLI behavior.
- Doctor output is captured without rewriting it. Checks retain their exact message, and a
  backticked `citizen`, `bin/harness`, or `/plugin install` command is exposed as a fix when
  present, including multiple alternatives. A fix-bearing check needs attention; other rows remain
  informational rather than claiming health the CLI did not assert.
- Drift links to Configure's governed review: first copy `citizen sync --dry-run`, then explicitly
  acknowledge its output before the `citizen sync` apply command is revealed. Studio never runs
  either command. The newer-release card likewise links to the changelog and never updates.
- The Hub owns loading, partial-failure, current, drift, update, no-run, and recent-run states.
  Generic report aggregates and the opt-in AI card remain the existing non-authoritative shell.

### Do not implement

Do not implement live SSE refresh, notifications, AI generation, report snapshots, selection
detail, module-library detail, update installation, direct sync, or any other mutating Hub action.

## Review findings

- Diff audit: the Overview route is GET-only, remains behind the existing launcher session boundary,
  and exposes no sync or update mutation. Authenticated and anonymous behavior are covered directly.
- Diff audit: partial source failures stay `failed` rather than becoming empty or healthy; exception
  text is not serialized.
- Diff audit: generated assets were rebuilt with `npm run build`; the old content-hashed assets were
  replaced rather than retained beside the new bundle.
- Spec review: Configure now exposes the Hub's target anchor and requires dry-run review plus an
  explicit acknowledgement before revealing the apply command; parity tests compare response values
  with the CLI doctor, diff, and catalog outputs rather than only proving those functions were called.
- Quality review: Hub run summaries read sidecars without recovery, indexing, or admission; doctor
  fixes preserve installer and plugin alternatives; failed drift renders as unknown rather than green.
