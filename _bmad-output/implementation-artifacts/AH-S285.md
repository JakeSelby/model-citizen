## Story

As a developer, I want the Studio to open on my version, updates, health and drift, so that I see first what needs attention.

## Context and value

The Studio opens on what a developer needs first: the installed version and whether an update is available, each `citizen doctor` check with its status and fix, whether the projections have drifted from the selection (`citizen diff`), the active mode, and the latest runs.

## Acceptance criteria

1. Given a failing doctor check, then the overview shows it with the doctor's own message and the command that fixes it.
2. Given projections that differ from the selection, then the overview shows the drift and offers `citizen sync` through the governed path.
3. Given a newer release on `stable`, then the overview shows it with its changelog link, and nothing updates without the developer.
4. The overview reads the same functions as `citizen doctor`, `citizen diff` and `citizen catalog`, and matches their output in tests.
