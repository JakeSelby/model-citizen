## Story

As a developer, I want the Studio to reflect changes from the CLI, agents and editors within seconds, so that it never shows me a stale harness.

## Context and value

The Studio watches the configuration, the primitive roots, the ledgers and the run store, and pushes a change event to open pages over server-sent events, so a developer never reloads. The watcher polls modification times with the standard library, with no file-system watcher dependency, and a page refetches only the data a change touches.

## Acceptance criteria

1. Given the Studio open on the selection, when `citizen config set` changes a stance, then the page shows the new value within two seconds, without a reload.
2. Given a change to one module, then only the views showing that module refetch.
3. Given 20 open event streams and a library of 500 modules, then the watcher uses under 2% of one core.

## Design

### Approach

Run one standard-library polling watcher per Studio server, independent of the number of browser
connections. It snapshots only the user config, configured primitive module patterns, observation
ledger, and Studio run-store files, coalesces each polling interval into one scoped event, and
publishes it through a bounded in-memory broker. An authenticated SSE route streams ordered events
with `(instance_epoch, sequence)` IDs, replay, explicit gaps, heartbeats, and clean shutdown.

The React client owns one `EventSource` for the application. Page hooks subscribe to topics and
refetch only their own data; the Library additionally checks changed paths against the modules in
its current result. Duplicate or reordered events are ignored, reconnection uses browser-native
`Last-Event-ID`, and paused updates coalesce until Resume reports the queued count.

### Decisions and alternatives

- Poll every second, leaving another second for dispatch and rendering inside the contract. Reject a
  watcher per browser connection because CPU must not scale with 20 streams.
- Watch catalog-shaped paths and known state files rather than recursive repository or home roots.
  Recompute configured primitive roots after config changes so additions and removals take effect.
- Bound broker replay to 256 events. Reject silent best-effort delivery: wrong epochs, future
  cursors, and evicted cursors emit a gap that makes subscribers refetch their scoped state.
- Keep the endpoint cookie-authenticated and GET-only. No credential or arbitrary watched path is
  exposed; event paths are limited to already authorized local module/config/run sources.

### Do not implement

WebSocket transport, platform-specific file-system watcher dependencies, editor writes, draft
conflict resolution, and live regions for individual run log lines are out of scope.

## Review findings

Scope review found three verification gaps: paused updates retained an unbounded event array, the
selection propagation test stopped at the SSE payload, and the CPU test did not keep real streams
open. Paused state now keeps a bounded latest event per domain with capped paths and a 10,000-event
regression; the browser test mutates the CLI while Configure is open and checks the rendered value
and page identity; the performance test holds 20 authenticated streams open during the measured
500-module scan. All three focused checks pass.

Quality review found four correctness gaps: same-topic paused events could hide an earlier changed
path, overlapping Library reloads could resolve out of order, symlink targets were not observed,
and watch sets above 4,096 paths were truncated silently. The pending-state regression now proves
both visible and hidden path predicates, Library reloads use a request-generation gate, contained
symlinks fingerprint target identity, stat and content while outside targets are rejected, and the
capacity boundary keeps a stable aggregate and emits a topic-wide invalidation when it changes.
Focused Python and Studio suites pass.

Re-review found that configuration symlinks were not using the contained-target fingerprint and
that the overflow marker changed on every scan. User, project and session configuration links now
track edits and replacements within their approved parent while refusing outside targets. The
overflow marker is a stable constant-space aggregate of dropped paths, so five idle scans publish
no events while a changed dropped file publishes one topic-wide invalidation; both CPU ceilings
remain covered. The focused suite passes on Python 3.9 and the current interpreter.
