## Story

As a harness maintainer, I want a written evidence standard and a pre-registration template, so that every published proof set is checked against the same twelve items before it makes a claim.

## Context and value

SM-2 fixes a hypothesis, a decision rule and a stop condition in advance, and NFR-15 asks for experiment discipline. Neither says what a published result must carry. This writes the standard every proof set is checked against, with a pre-registration template for its first item. The twelve items:
1. a pre-registered plan: hypotheses, primary metric, guardrails, sample size, stopping rule and multiplicity;
2. a frozen task set with a reference solution per task, audited for task and outcome validity;
3. the pinned model, CLI, effort, date, container digest, seeds and fallback rate;
4. a dated price table;
5. paired per-task results with clustered or Wilson intervals, and the intra-cluster correlation;
6. a cost-effectiveness view, such as a Pareto frontier;
7. trajectories and a command that reproduces the run;
8. judge agreement: κ, a confusion matrix and bias audits;
9. a contamination check;
10. estimand labels: intention to treat, adherence, complier effects, and hypotheticals marked as such;
11. field checks: sample ratio, novelty, CUPED and dilution;
12. a "what we do not claim" section.

Traces to NFR-15, SM-2 and PRD §9 (v0.14.0).

## Acceptance criteria

1. A docs page states the twelve items, each with what satisfies it, quoting SM-2's definitions where they apply.
2. The pre-registration template covers the first item and is committed before a proof run's first trial, so the order can be checked.
3. The PRD records the standard through `bmad-prd`'s update intent, since the twelve items are not yet in the text of record.

## Design

### Approach

Decided by the owner on 2026-09-26: approved as proposed. Write the evidence-standard page and the
pre-registration template, and amend the PRD through `bmad-prd`'s Update intent, so that #799's proof
runs have the template in place before their first trial.

- `docs/evidence-standard.md` states the twelve items in the issue's order. Each item has a
  "What it is" line and a "Satisfied by" paragraph, and quotes SM-2 verbatim where SM-2 defines the
  term: the hypothesis, power and decision rule under item 1, the governing and descriptive intervals
  under item 5, Cost-of-Pass under item 6, the 23 Sep runs under item 9, and the magnitude bound under
  item 12. SM-4's credit rule is quoted under item 10.
- `docs/pre-registration-template.md` sits beside the page and covers item 1: hypotheses, primary
  metric, guardrails, sample size, stopping rule, multiplicity, the decision rule, exclusions and an
  append-only deviation log, with SM-2's values filled in as defaults.
- The order is checkable from git: the commit that adds a filled plan must precede the earliest trial
  start in the proof set's rows and be an ancestor of the commit the run was taken at.
- `docs/benchmarks.md`, the page that describes the replay, links both.
- The PRD's NFR-15 gains the twelve items and a pointer to the page; the v0.14.0 roadmap line cites
  #794 and NFR-15. SM-2 is quoted, never changed.

### Decisions and alternatives

- **The template lives in `docs/`, beside the page.** The issue names no location. `benchmarks/` was
  the alternative, but the template is documentation a person copies, and `docs/` is link-checked.
- **Filled plans go under `benchmarks/preregistrations/`, named by date and question.** Default taken:
  that path, because it sits beside the task manifest the plan pins; #799 may move it when it defines
  the bundle. No directory is created here.
- **The order check is the committer date of the adding commit against the first trial's start,
  plus ancestry, plus a push before the first trial.** A committer date alone can be set by hand; the
  push puts the date on a remote others read. A signed timestamp service was rejected as more than
  the claim needs.
- **The decision rule's two tests are one joint test and need no multiplicity correction.** Both must
  hold, so the family-wise error cannot exceed α. Further confirmatory tests name their correction.
- **Not applicable is allowed only with a reason the page gives,** such as item 8 when every outcome
  is a deterministic check, or item 11's novelty, CUPED and dilution for a replay-only proof set.
- **No test.** Nothing machine-checks the page or the template yet; `tests/test_doc_links.py` already
  checks their links. The verifier that checks the twelve items is #799.

### Do not implement

- No change to SM-2's text, `scripts/cost_bench.py`, the benchmark code or #799's run files.
- No verifier, bundle format or evidence card; those are #799.
- No `product.json` entry: the page is documentation for a process, not a user-visible capability.

## Review findings

- CodeRabbit, PR #892, round 1: item 1's order check relied on the committer date and ancestry, which
  the committer controls, so they could not prove the plan was public before the first trial. Fixed:
  the plan's pull request merges before the first trial, and the check compares GitHub's recorded
  merge time with the earliest trial; the date and ancestry checks stay as ordering checks.
- CodeRabbit, PR #892, round 1: the template sized for joint power 0.8 on the decision rule's two
  tests while the saving claim also needs the long-task subset's interval win. Fixed: a claim-power
  line asks for the joint power of all three conditions, sized for 0.8 or stated with a reason, and
  the power calculation covers both; SM-2's quoted power statement is unchanged.
