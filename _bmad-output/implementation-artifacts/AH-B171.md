# AH-B171 — fix(cost): sleep-and-poll loops instead of background notifications

## Reproduction

In a Claude Code session, wait for CI or a test run in the foreground: `sleep 600`, or
`until gh pr checks 12; do sleep 30; done`. The turn holds while the prompt cache ages, and past
five minutes the next call rewrites the whole context. An exploratory audit of 265 sessions
priced these waits at about 1.23 USD per 100 calls and 327 USD of subagent cache expiries.

## Root cause

Nothing in the Bash path recognised a wait. `grade-bash` grades `sleep` as read-only and
`allow-readonly-bash` approves it, so a foreground wait ran with no prompt and no pointer to
`run_in_background` or Monitor, which notify the session and cost nothing while waiting.
[Source: lib/harness_core/lifecycle.py#_dispatch]

## Acceptance criteria

1. **Given** a foreground `sleep` over 30 s, a `until`/`while`/`for` loop that sleeps, or an untimed `gh pr checks --watch`, `gh run watch` or `docker wait`, **when** Claude Code runs it, **then** the agent's context carries a note naming `run_in_background` and Monitor, and no permission decision is added.
2. **Given** a foreground sleep past 300 s, alone or summed in one command, **when** it is run, **then** it is denied with the same alternatives.
3. **Given** a sleep of 30 s or less, a `sleep` inside quoted text or a comment, a `timeout`-wrapped watch, a shell `&` or `run_in_background`, **when** it is run, **then** nothing is noted or denied.
4. **Given** any note, denial or exempted background wait, **then** one `steer-polling` decision row is written; a command with no wait writes none.
5. **Given** the `steer-polling` hook switched off or the Codex runtime, **then** the Bash path is unchanged.

## Design

A new hook id, `steer-polling` (`policy/hooks/steer-polling.py`), invoked from the coordinator's
Bash branch on Claude Code only, since Codex has neither background notifications nor Monitor.
It splits the command with `shlex` the way the shell would, so quoted text and comments are not
commands, and judges each simple command. A note is `additionalContext`; only a foreground sleep
past five minutes is denied, the prompt cache's lifetime. Extending `grade-bash` was rejected:
it is a core hook about reach, and this is advice about cost that a user may switch off alone.
Must not change any grade, allow or ask the existing Bash path gives.

## Regression test

`tests/test_steer_polling.py`: every pattern, the near misses, background exemption, the
decision rows, and the coordinator's deny, note, Codex and switch-off paths. Each fails before
the hook exists.

## Dev notes

- Thresholds: note above 30 s, deny above 300 s; a loop that sleeps is noted at any length.
- `for` loops are matched beside `until` and `while`, since a bounded retry loop is the same poll.
- Files: `policy/hooks/steer-polling.py`, `lib/harness_core/{catalog,lifecycle}.py`,
