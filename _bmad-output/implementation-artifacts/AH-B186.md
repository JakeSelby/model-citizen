# AH-B186 — fix(benchmarks): the replay pair check refuses an arm whose sync leaves an empty skills or agents directory

## Reproduction

Run any replay or ablation sweep on main (for example `cost_bench.py replay --pack <evals> --ablations benchmarks/ablations.json --tag <sha> ...`). Before any model call it refuses: `only in the harness arm, outside the harness component: home:.claude/skills`.

## Root cause

The `no-skill-listing` removal arm (97f583ad) switches every skill off, so `harness sync` leaves an empty `~/.claude/skills`. Every harness arm is pair-checked against bare, and `HARNESS_DIRS` declared only `plans` among the seven directories sync always creates. [Source: scripts/replay_arms.py#HARNESS_DIRS]

## Acceptance criteria

1. **Given** an arm whose sync leaves any of the seven directories empty, **when** the pair check runs, **then** it admits them as directories.
2. **Given** a file in place of a declared directory, an undeclared empty directory, or a non-harness link inside a declared one, **then** the pair is still refused.

## Design

Declare all seven sync-created directories in `HARNESS_DIRS`, directory-only, following #1155. Rejected: changing the install, which would make arms from registered commits fail.

## Regression test

`tests/test_replay_pair_sync_dirs.py`: 4 of 6 tests fail against the pre-fix runner with the reported line.
