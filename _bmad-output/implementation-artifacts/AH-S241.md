## Story

As a harness maintainer, I want unit evals that run one rule, skill or hook alone, the economy concern alone and both together against bare, so that the unit's effect is separated from the economy concern's and their interaction is measured.

## Context and value

PRD §1's second comparison tests one rule, skill or hook in a minimal profile, first alone and then with the economy concern switched on, so a unit eval never pays for the full context. #754 compares two arms that differ in one policy. This extends it to four cells (nothing added, the unit alone, the economy concern alone, and both together) beside a bare arm, which separates the unit's effect from the economy concern's and measures their interaction.

Depends on #754 and #795. Traces to PRD §1 (comparison 2) and §9 (v0.15.0).

## Acceptance criteria

1. Given a unit and a minimal profile, when the design runs, then the four cells differ only in the unit and the economy concern, and the parity check refuses anything else.
2. Given the four cells, then the report gives the unit's effect, the economy concern's effect and their interaction on adherence, pass rate and Cost-of-Pass, each with #795's intervals.
3. Given the unit tests, then they cover the parity refusal and the interaction arithmetic on fixed rows.
4. Given the committed four-cell fixture, when `summarise` reads it, then it emits result schema v1, which #1062 imports as its four-cell fixture.
5. Given a unit whose manifest names no `detector:` instrument, then every adherence figure is `unmeasured`, never zero (AD-22).

## Design

### Approach

The two-by-two runs on #514's declared-selection runner. `scripts/unit_economy.py` derives one base
profile from the tag's catalog and builds four cells from it: `base`, `unit`, `economy` and `both`.
Bare runs as a fifth arm. Before any spend, the tag's resolver reads every cell and `parity` refuses a
grid whose edges differ in anything but their factor. `cost_bench.py replay --design unit-economy
--unit <kind>.<id>` builds each cell as its own image, schedules the five arms from a recorded seed,
and stamps every row with its design and factor levels. After the set, `scripts/rule_adherence.py`
maps the unit's own detector instruments onto each run's saved stream. `summarise` dispatches on the
rows' `design` record and emits result schema 1.

### Decisions and alternatives

1. **Economy off.** `cost` moves to a new `off` variant, `delegation` to `session-model`, and the
   `tier-agent-spawns` and `usage-feed` hooks go off. `brief-guard` is core and stays on. Rejected:
   holding `cost` at `balanced`, because then the instruction half of economy is never measured.
2. **Base profile.** Every switch-kind module is off except the four core hooks, every stance is at
   `off` or its smallest variant, and the unit's dependencies are on. Rejected: the `minimal` mode,
   because every hook it keeps would sit beside the unit in every trial.
3. **Simple effects.** The report gives the unit against base, the unit with economy against economy
   alone, and economy against base. The interaction is the ratio of the two unit ratios, or the
   difference of the two differences for rates. Rejected: main effects averaged over the other factor,
   because an average across a real interaction describes neither economy setting.
4. **Bare as a fifth arm**, outside the factor analysis, with each cell's ratio to bare reported as
   descriptive. Rejected: treating protocol point 5 as not applicable.
5. **Delivery.** One pull request, because #514 merged before this was built, so nothing waited.
6. **The economy concern lives in its own manifest**, `benchmarks/unit-economy.json`, not in #514's
   strict schema-2 `ablations.json`. This leaves that validator unchanged.

### Do not implement

- Any live or paid trial. The grid run is registered in the evidence-runs plan by the maintainer.
- Screening with more than two factors (v0.17.0), four-arm work (#802), Studio (#1062), or the
  advice-following adherence of #798.
- Task loading or evaluator-pack code (#1145).
