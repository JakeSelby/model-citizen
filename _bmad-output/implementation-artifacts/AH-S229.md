## Story

As a developer coming back to a long session after a break, I want the harness to stop my first prompt
once and tell me what resending will cost, so that I can choose between paying for a rebuild and
continuing from the handoff after `/clear`.

## Context and value

A long session's prompt cache lasts an hour. After a longer break, the next prompt re-writes the whole
context at the cache-write price. Over the 30 days to 2026-09-23 that was 10.7% of long-session spend,
about half of all rebuild spend ([#745](https://github.com/JakeSelby/agent-harness/issues/745)).

`/clear` avoids the rebuild, and with AH-S228 the handoff it reloads is current. Nothing tells the
developer at the one moment it matters, though: after the break, before the prompt goes out. Claude Code
cannot run `/clear` for them (the epic's out-of-scope list), so the choice has to be theirs, made before
the cost is paid.

## Acceptance criteria

1. **Given** the switch on, a gap of 55 minutes or more since the last assistant entry, and a context at or
   above the first fresh-session threshold, **when** a prompt is submitted, **then** it is held once, with
   a message giving the idle minutes, the context size, the estimated rebuild cost and the two options.
2. **Given** a gap under 55 minutes, a context under the threshold, or the switch off, **when** a prompt is
   submitted, **then** the guard is silent.
3. **Given** a held prompt, **when** a prompt is sent again in the same gap, **then** it passes, and the
   saved copy is deleted.
4. **Given** a prompt being held, **when** the guard fires, **then** its text is saved for the next
   session somewhere git does not track.
5. **Given** a saved prompt, **when** a session starts with source `clear`, **then** `harness-session.py`
   injects it beside the handoff as quoted data and deletes it; a `startup` or `resume` start leaves it.
6. **Given** a client that AH-SP010 found cannot hold, **when** the guard fires there, **then** it adds a
   notice and never blocks.
7. **Given** a live 60-minute idle on a large context, **when** a prompt is sent, **then** it is held, and
   the transcript shows no assistant entry for it.
8. **Given** a model missing from the price table, **when** the message is built, **then** the cost reads
   as unpriced, never $0.

## Design

### Approach

- **Where:** `policy/hooks/usage-feed.py`, which `claude/hooks/` links to, in `on_prompt`, the
  `UserPromptSubmit` branch, beside `session_line`.
- **The gap:** now minus the timestamp of the last assistant entry in `transcript_path`, recorded while
  `advance` reads the transcript, so that the guard re-reads nothing.
- **The size:** the context the feed already stores from the last call (input plus cache read plus cache
  write), against the first value of the cost variant's `session_nudge_at`.
- **Once per gap:** a state key, `held_at`, keeps the last-assistant timestamp that was held; a matching
  value lets the next prompt through.
- **The hold:** `{"decision": "block", "reason": <message>}`, with the original prompt left visible in the
  block message. The message gives the idle minutes, the context size and the estimated rebuild cost as a
  list-price equivalent, then the two options: send again to continue here, or `/clear` to continue from
  the handoff with this prompt carried over. The estimate is the context times the session model's
  one-hour write price minus its read price, through `policy/hooks/pricing.py`, the excess AH-S227
  reports.
- **The carried prompt:** saved when held and deleted on the resend. On SessionStart with source `clear`,
  `harness-session.py` injects it after `handoff_lines`, framed as data, then deletes it. The plan saves
  it to `.agent-harness/held-prompt.md` (open question 3).
- **The switch:** a unit of #554's selection model, off unless selected (open question 2).
- **Landing copy:** a feature line under `spend-less` in `product.json`, with no savings figure.

### Decisions and alternatives

- **Open question 1: hold once, or warn only.** The plan recommends hold once.
  - For the hold: a warning at prompt submit arrives with the prompt already sent, so it cannot save that
    rebuild. Only a hold can.
  - Against it: AD-14 says "No hook denies for cost", and a hold is a denial for cost. Holding needs AD-14
    amended first, through `bmad-architecture`'s update intent, and AD-7's enforcement list extended with
    a prompt-submit block once AH-SP010 has probed it.
  - Either way, a client that AH-SP010 finds cannot hold gets warn-only (AC 6).
- **Open question 2: the default.** The plan recommends off for everyone and on for the maintainer. The
  alternative is on under the `balanced` cost variant. #554 makes a switch kind default to `on`, so an off
  default needs either a per-unit default in the selection model or the value set in the cost variants;
  the build settles which.
- **Open question 3: where the carried prompt lives.** `.agent-harness/` is visible to git in this
  repository by design [Source: .gitignore], and the harness manages no ignore list for other
  repositories, so `.agent-harness/held-prompt.md` could be committed. It is the developer's raw text.
  The options are an ignore rule wherever the harness writes the file, or the feed's state directory,
  keyed by project, which never enters a checkout. The state directory is the safer default; the project
  path is easier for the developer to find and read.
- **Carried as data.** A held prompt may carry an approval, such as "yes, merge it". Under AD-20 an
  approval never crosses a session boundary, so the injection quotes it as the prompt held before
  `/clear`, and the new session confirms any approval in it before acting.
- **55 minutes, not 60.** A five-minute margin under the one-hour lifetime, so a prompt sent as the cache
  expires is still caught. `[ASSUMPTION: the margin is the plan's choice; AH-S227's gap data can tune it]`

### Do not implement

- Any automatic `/clear` or compaction; AD-7 forbids triggering compaction from a hook.
- Keep-warm pings.
- Guards for the other causes: model switches, reloads and the tail.
- A savings figure in `product.json` or the docs before the epic's measurement.
