# AH-S258 — Nudge delegation from the existing detector through PostToolUse context, since the spawn hook only fires once a spawn is attempted

## Story

As a harness user, I want the tiered delegation stance to identify a real multi-file gathering
opportunity before I attempt a spawn, so that the existing worker routing can reduce coordinator
context instead of waiting for a decision that never happens.

## Context and value

Stored benchmark transcripts found no delegation spawns even on tasks where the counterfactual
break-even was favorable. The spawn hook can route a spawn but cannot create the opportunity. A
small deterministic PostToolUse signal makes that opportunity visible without adding context to
short reads or changing the user's chosen delegation variant.

## Acceptance criteria

1. **Given** the `tiered` delegation stance, **when** a session successfully reads three distinct
   files through native Read calls or conservatively classified read-only Bash commands, **then**
   the third event adds the variant's delegation message as PostToolUse context exactly once.
2. **Given** fewer than three distinct successful reads, repeated reads, dynamic Bash operands,
   or a delegation variant without a nudge sidecar, **when** PostToolUse runs, **then** it adds no
   delegation context and records no firing.
3. **Given** a custom primitive root, **when** its delegation variant supplies a valid bounded
   nudge sidecar, **then** the shared hook uses that variant's threshold and message without
   reading through a symlink outside the root.
4. **Given** the controlled `hook-inventory` native micro campaign, **when** four harness-arm and
   two-file control runs are executed under the evidence protocol, **then** the harness arm spawns
   in at least three of four runs and the two-file control never spawns.
5. **Given** the implementation, **when** repository checks run under current Python and Python
   3.9, **then** lint, focused lifecycle tests, and the repository Gate are green.

## Design

### Approach

Keep bounded per-session distinct-file state in `posture.py`, which already owns session records
and stance resolution. The lifecycle dispatcher extracts only explicit lexical file operands from
successful Read calls and a small allowlist of Bash commands that the shared grader first proves
read-only. On the first threshold crossing it appends the selected variant's message and writes a
decision-log row for later attribution.

### Decisions and alternatives

- The variant JSON sidecar owns the threshold and message. This keeps future variants data-only.
- Unknown shell syntax, expansions, compounds and ambiguous operands do not count. Executing or
  evaluating shell text to recover paths was rejected because a nudge cannot justify that risk.
- State updates use an exclusive bounded lock and atomic session-record replacement. Contention
  drops one observation so concurrent hooks cannot emit twice.
- Native spawn-rate acceptance remains pending a controlled campaign; unit tests establish the
  trigger contract but are not evidence that a model follows the nudge.

### Do not implement

Do not change spawn routing, invent a new analytics metric, execute paid model runs, broaden Bash
classification, or claim the native spawn-rate target from deterministic fixtures.

### Bound decisions and requirements

The dispatcher remains the single native lifecycle composition point. The stance ladder and custom
primitive roots remain owned by `posture.py`. Hook failures remain silent on PostToolUse, session
state stays bounded, and Python 3.9 is the syntax floor.
