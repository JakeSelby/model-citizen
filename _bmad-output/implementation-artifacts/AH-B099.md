# AH-B099 — fix(output-style): Scannable drops Claude Code's coding instructions

## Reproduction

1. Select the `scannable` voice, the default, and run `harness sync`, which links
   `claude/output-styles/scannable.md` into `~/.claude/output-styles/` and selects the `Scannable`
   output style.
2. Start a Claude Code session. The style's frontmatter carries only `name` and `description`, so
   Claude Code builds the system prompt without its default coding instructions.

## Root cause

Claude Code's custom output-style schema defines `keep-coding-instructions`: "If true, the default
coding instructions stay in the system prompt alongside this style." The key defaults to false, and
`primitives/presentation/scannable.md`, served through the `claude/output-styles` directory
symlink, never declared it, so a style meant to shape the final response also removed the coding instructions.

## Acceptance criteria

1. **Given** the shipped `Scannable` style, **when** its frontmatter is read, **then** it declares
   `keep-coding-instructions: true`.
2. **Given** any output style in `claude/output-styles/`, as `harness_output_styles()` finds them,
   **when** the unit suite runs, **then** a style without the key fails it.
3. **Given** the fix, **when** the style's body is compared with `main`, **then** it is unchanged.

## Design

Add the one frontmatter key to `primitives/presentation/scannable.md`; the body is untouched.
`claude/output-styles` is a symlink to `primitives/presentation`, so there is no separate served
copy to regenerate. Rejected: restating coding guidance in the
style body, which would duplicate Claude Code's own instructions and grow the always-loaded text.

## Regression test

`tests/test_output_style_frontmatter.py` reads every style `harness_output_styles()` returns and
asserts `keep-coding-instructions: true`. It failed with `None != 'true'` before the key was added
and passes after.
