# AH-S273 — Keep bot work out of benchmark task mining and require an explicit `--tag`

## Story

As the maintainer measuring the harness, I want bot-authored work kept out of the benchmark task set
and every live replay to name the harness ref it measures, so that the burndown bot neither writes the
reference solutions its model is scored against nor makes a default run measure whatever merged last.

## Context and value

Five of the seven replay tasks come from this repository's issue and pull request pairs; each carries a
`source` such as "issue 237, solved by pull request 238" [Source: benchmarks/tasks.json]. Once the
burndown bot merges fixes, a task mined from one of its pull requests would make the model under test
the author of its own reference solution, which is the contamination item 9 of the evidence standard
guards against [Source: docs/evidence-standard.md#9-a-contamination-check].

Bot merges also move the installed harness daily. `--tag` on the replay subcommand is repeatable and
defaults to `candidate`, "the installed harness as it stands" [Source: scripts/cost_bench.py#main], so a
live run that omits it would measure an unknown mix of the bot's recent merges.

This story merges before the bot opens its first pull request, so no bot-authored reference solution can
enter the set. Traces to FR-74 ([#944](https://github.com/JakeSelby/model-citizen/issues/944)).

## Acceptance criteria

1. **Given** a mined task recorded as bot-authored, **when** the task set is validated, **then**
   validation fails and names the task.
2. **Given** `cost_bench.py` run without `--tag`, **then** it exits non-zero and names the flag;
   **given** `--tag candidate`, **then** it still runs the installed harness.
3. **Given** `docs/benchmarks.md`, **when** it is read, **then** it states both rules and names the
   bot's label, `bot::authored`.

## Design

### Approach

- Each task mined from an issue and pull request pair records `source_author`, the login that authored
  the solving pull request, in `benchmarks/tasks.json`. `load_tasks` rejects a task whose
  `source_author` is the burndown bot App's login, naming the task, so validation needs no network
  [Source: scripts/cost_bench.py#load_tasks].
- The App's login is a constant beside `TASKS` in `scripts/cost_bench.py`, set once the owner registers
  the App (#945).
- `--tag` loses its default: the argument parser at `scripts/cost_bench.py` (the `replay` parser, about
  line 1697) makes it required, and `args.tag or [CANDIDATE]` becomes `args.tag`. The literal
  `candidate` keeps its meaning.
- `docs/benchmarks.md` gains both rules in its live-replay section.

### Decisions and alternatives

- **Record the author in the manifest.** Chosen, so validation is offline and deterministic. Rejected:
  looking the pull request up through the API at validation time, which adds a network dependency to
  every run.
- **Require `--tag` rather than warn.** A warning scrolls past in a long run; a non-zero exit cannot.
- **The plan names the subcommand `run`.** The parser variable is `run`, but the subcommand it registers
  is `replay` [Source: scripts/cost_bench.py#main]. The requirement applies to the subcommand that
  spends usage, whatever its name.

### Do not implement

- Any change to which tasks are in the set; adding `source_author` records existing facts only.
- The bot, its App or its labels (#945, #948).
- Changes to the static tier.
