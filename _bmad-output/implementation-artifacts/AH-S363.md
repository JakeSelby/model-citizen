## Story

As a developer on the `balanced` or `frugal` cost stance, I want Claude Code's native auto-compaction to fire at the stance's reset point, so that a long session resets its context at the harness's number instead of near 1M.

## Context and value

Past 400k a call costs about 3.3x, and today the harness can only block the turn and ask for a fresh session. Native auto-compaction already exists; it fires near 967k on 1M models unless its window is set. Projecting the stance's number into settings `env` makes the reset automatic.

## Acceptance criteria

1. **Given** a temp home, **when** `citizen sync` runs, **then** it writes the reset point as 400k for `balanced`, 200k for `frugal`, and nothing for `max` and `off`.
2. **Given** a variant that names no reset point, **when** sync runs, **then** the projection removes the vars it wrote earlier.
3. **Given** a user's own value for either var in settings `env`, **when** sync runs, **then** it keeps the value and warns.
4. `session_handoff_at` defaults to 0.9 of `context_reset_at` (360000 and 180000), still overridable per variant.
5. Tests green.

## Design

### Approach

- `primitives/stances/cost/{balanced,frugal}.json` gain `switches.context_reset_at` (400000 and 200000); `max` and `off` get null, which leaves the native default.
- `citizen sync` writes `CLAUDE_CODE_AUTO_COMPACT_WINDOW` and `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` into the projected Claude Code settings `env`. AH-SP020 says which pair resolves to the reset point on a 1M model.

### Decisions and alternatives

- **400k for `balanced`** (plan decision 2): the evidence-backed number; AH-S367 runs a 200k arm to decide a follow-up. Rejected: shipping 200k now, unmeasured.
- **The user's value wins.** Rejected: overwriting it on every sync.

### Do not implement

- Codex projection (no usage feed; follow-up on v0.16.0).
