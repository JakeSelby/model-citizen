## Story

As a solo or small-team agentic developer, I want each Harness item's efficacy rows stamped with the setting in effect and its dates, so that I can tell whether a change I made helped or hurt.

## Context and value

Plan step 2 and the system design. The spike (AH-SP021) decides whether usage rows' `stances` and `profile_fingerprint` (`policy/hooks/usage-log.py:1284-1288`) joined with `applies.jsonl` (`lib/harness_core/studio/apply.py:742`) separate setting changes; this story builds the module and route on its answer. Every Harness page and Evals read it.

## Acceptance criteria

1. **Given** a usage log and an applies log, **when** `periods.py` runs, **then** it returns per Harness item a list of periods with the setting in effect, start and end dates.
2. **Given** a fingerprint change with no attributable setting, **when** periods compute, **then** it is treated as noise, not a boundary.
3. **Given** 30 days of usage rows, **when** `/api/harness/periods` is requested, **then** it answers in under 2 s.
4. **Given** the spike failed, **when** periods compute, **then** they fall back to `applies.jsonl` plus config git history and the response carries a one-period note.
5. **Given** the route, **when** its API tests run, **then** they cover the response shape, auth enforcement and error cases on fixture logs.

## Design

### Approach

- A new `lib/harness_core/studio/periods.py`, read at request time, and a `/api/harness/periods` route.
- Ported from the spike's scratch script once it passes.

### Decisions and alternatives

- **Computed at page load:** no new hook-side recording (epic scope). Rejected: a periods ledger written by hooks.

### Do not implement

- Any hook change; UI (S3 renders it).
