# AH-S256 — Run every hook against recorded tool calls under each stance variant as a deterministic permutation matrix

## Story

As a harness maintainer, I want every hook run against a fixed corpus of tool calls under every stance variant, with each decision checked against a committed matrix, so that a change which flips what a hook does under one variant fails by name before it ships.

## Context and value

Each hook's decision on a given call under a given variant is deterministic and needs no model, and
the hooks are where most rules take effect. Nothing ran the hooks across the variants and asserted
their decisions together. This is the cheapest tier of the evaluation pyramid's permutation
comparison: every rule-by-variant combination the hooks implement, checked on every change, in
seconds, for nothing. It also gives the live benchmark a control, since a cost difference on a task
whose matrix row did not move is not the hooks.

Parent: AH-E013.

## Acceptance criteria

1. **Given** the committed corpus and matrix, **when** the suite runs, **then** every hook id in
   `catalog.HOOK_IDS` is run on every call under the base and under every non-default variant of every
   stance topic in `primitives/stances/`, and each decision matches the committed cell.
2. **Given** a variant that resolves so one hook's decision changes, **when** the test runs, **then**
   exactly one cell fails and the failure names the hook, the call and the variant.
3. **Given** an intended change, **when** `python3 tests/fixtures/hook-calls/hook_matrix.py --write`
   runs, **then** it rewrites the matrix deterministically, and `--check` exits 0 on the result.
4. **Given** the corpus, **when** it is read, **then** it holds only synthetic payloads: no real
   transcript content, home path or personal name, and `python3 bin/harness lint` is clean.
5. No model is called, the matrix runs in seconds, and `python3 -m unittest discover -s tests` is
   green under `python3` and `/usr/bin/python3`.

## Design

### Approach

- `tests/fixtures/hook-calls/calls/*.json`: one synthetic call per file, `{about, files?, git?,
  payload}`, covering PreToolUse (Bash by grade and permission mode, Write, Edit, Agent, WebFetch,
  Read, SendUserFile), PostToolUse (clean and instruction-shaped output, plan files, a subagent
  result) and Stop (outside a repository, an untrusted gate, a trusted failing gate). What a hook
  must read from disk is staged into a temporary home through `{home}` and `{repo}` tokens.
- `tests/fixtures/hook-calls/hook_matrix.py` dispatches each call through `harness_core.lifecycle`,
  the path both runtimes' adapters take, once per row: each hook id switched on alone through the user
  config's `hooks` kind, and `dispatcher`, every id off. Each dispatch gets a fresh home, the stance
  set through `HARNESS_STANCE_<TOPIC>`, and the decision log held off.
- A cell is the decision's shape (`allow`, `ask`, `deny`, `rewrite`, `block`, `context`,
  `message`, `none`), not its wording. A hook row's cell is `as-dispatcher` where the hook adds
  nothing, so logic every row shares is counted once, in `dispatcher`.
- `matrix.json` stores each row and call's base cell and only the variants that differ, and omits a
  hook row and call that is `as-dispatcher` throughout. `tests/test_hook_matrix.py` recomputes it.

### Decisions and alternatives

- **Dispatch through the lifecycle, not each hook script alone.** Bash grading and plan-mode approval
  live inline in the dispatcher under the `grade-bash` and `allow-readonly-bash` ids, so running the
  scripts alone would miss the hooks' main decisions. Isolation comes from the switches instead.
- **One variant changed at a time from the base, not the cross product.** The issue asks for every
  selectable variant; one-at-a-time gives 19 environments and attributes a flip to one variant. The
  full product of nine topics is thousands of environments and belongs to the factorial screening story.
- **A row the dispatcher never asked about reuses the `dispatcher` answer.** With the hook on, nothing
  differs until `enabled` asks about it, and a deterministic dispatch of the same input never asks. A
  test runs every row on a sample and holds the shortcut equal to the full run.
- **Hook rows relative to `dispatcher`.** Without it, role confinement and the delegation-off deny,
  which no switch turns off, appeared in all seventeen rows, and a flip there failed seventeen cells.
- **The shape, not the text.** Pinning reasons would fail on every rewording; the matrix is for answers.
- **Speed.** Variants run in up to four worker processes, code objects are unmarshalled once per
  process, `CLAUDE_PID` is fixed so the intent hook does not walk the process tree, and on macOS the
  real `git` binary is put first on `PATH` instead of the toolchain shim. The matrix takes about ten
  seconds on a laptop.

### Do not implement

- No SessionStart, SessionEnd or UserPromptSubmit calls: `harness-session` shells out to the CLI,
  `usage-log` starts a detached worker, and the issue names PreToolUse, PostToolUse and Stop. Those
  hooks' rows are present and read `as-dispatcher`.
- No Codex runtime pass, and no cross product of variants.
- No change to any hook, stance or the lifecycle.

covers every hook id, every non-default variant and every call; resolves `autonomy=ask` as `execute`
for one call and asserts exactly one moved cell with its names; runs every row on a sample to hold
the shortcut; and checks the corpus holds no home path.

### Completion notes

All five criteria implemented as designed. The corpus is 29 calls; the matrix is 17 rows by 29 calls
by 19 variant environments. Variant-sensitive cells today: `grade-bash` under the two autonomy
variants, `validate-plan-card` under `plan-ceremony=light`, `brief-guard` and the dispatcher under
`delegation=off`. Seven hooks read `as-dispatcher` on every call (`approvals`, `harness-session`,
`intent-overlap`, `tier-agent-spawns`, `usage-feed`, `usage-log`, `workspace-session`), because they
answer events outside the corpus or act only on state a fresh home does not hold, such as a live
sibling's claim. Default taken: the three events the issue names only, because
the others spawn subprocesses that would cost the matrix its seconds.
