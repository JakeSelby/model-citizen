## Story

As a developer, I want to adapt Studio to the landed Measured evaluation contracts, so that the Studio supports the engines delivered in its milestone.

## Context and value

After v0.15.0 lands, reconcile its evaluation contracts with the preserved Studio branch before the v0.16.0 release. This owns cross-cutting compatibility and the integration gate; existing suite/report stories retain their feature ownership.

## Acceptance criteria

1. Given the landed Measured result schemas, Studio imports two-arm, four-cell and variable-arm fixtures, reports unsupported versions explicitly, and preserves raw evidence and unknown/error values.
2. Sampling controls support the engine's registered power requirements; exploratory and proof runs remain distinct. Matched draft comparisons record compatible task/model/trial identities and become stale after edits.
3. CLI and Studio display identical analysis values, paired intervals, zero-pass/undefined ratios, metric nulls and proof status for the same fixtures; no browser-only inference replaces engine results.
4. Shared benchmark-runner changes preserve spend accounting, cancellation, target identity and history ownership. Rebuilding the index preserves source identities.
5. All retained 0.16 Studio qualification and parity checks cover the integrated candidate. No merge into main occurs before the Measured delivery boundary.

## Design

### Approach

The engines own every figure. `lib/harness_core/studio/evaluation.py` recognises which landed contract a
native row answers and carries its stamps through unchanged: the two-arm row, the one-policy pair
(`ablation` schema 1, arms `bare`, `reference`, `treatment`), the variable-arm ablation (`ablation`
schema 2, arms `bare`, `harness` and the manifest's ids), the four-cell design (`design`
`unit-economy-2x2`, result schema 1) and the evaluator pack identity (`pack`, `pack_version`,
`pack_commit`, `pack_digest`). The run store indexes each row with that contract under `evaluation`,
and run detail returns it; the Experiments run page lists it as label and value lines.

The replay form runs evaluator packs, since the repository's own task list is retired.
`lib/harness_core/studio/packs.py` finds a `pack.json` beside the checkout, or beside the main
checkout of a linked worktree, and opens each through `replay_pack.open_pack` at `HEAD`. The form
picks one by name and digest (default `model-citizen-evals`, the pack docs/benchmarks.md names, else
the first by name); the server resolves the path and pins `--pack`, `--pack-ref` and `--pack-digest`,
and refuses a target's rows that do not carry that digest and commit.

Sampling and evidence labels (AC 2). The server decides each replay's label: a whole set with a
pre-registration is pre-registered only when it runs the sample the registration states, read
through `experiment_protocol`'s section and field readers (Tasks, Trials per task and arm, Power
calculation) with `replay_power.MIN_REPS` as the floor; a whole set off that sample is refused. A task
subset, or a replay with no pre-registration, is exploratory, runs `--exploratory` and writes no
history, as `cost_bench` requires (`full_set_size`). The preview shows the label, the registered
sample and the request.

Matched draft comparisons (AC 2). Each draft target of a replay yields a comparison record: the
draft's checkpoint revision and configuration digest, the target it was matched against, and the
task, model, trial and pack identity, with a `key` that only an identical identity shares. The
record is stale once the draft has a newer checkpoint, a changed configuration or is gone. The
result route returns them; the side-by-side compare view is #990's.

Engine analysis (AC 3). After a replay, Studio runs `cost_bench.py summarise --json` on each
target's native rows and records the output verbatim (`analysis.json`), or the engine's refusal in
its own words. The result route returns it and the form shows every value as the engine wrote it, so
paired intervals, zero-pass and undefined ratios, metric nulls and the verdict are the CLI's.

Proof bundles named by `product.json` `evidence_cards` are indexed with the result of the same
`evidence_bundle.verify` call `citizen evidence verify --json` makes, loaded from this checkout. The
proof status is that result's `ok`, its errors and its unknown list, verbatim.

### Decisions and alternatives

- An unknown stamp version is a named skip at reindex (`unsupported ablation stamp schema: 3`),
  never a two-arm read. The reader's constants are tested equal to the engines' constants.
- A two-arm row keeps its original five identity fields, with or without a pack, so a rebuilt index
  keeps the run ids it had; one results file is one pack's run, and the digest stays on
  `evaluation.pack`. Ablation and design rows add their manifest digest and schedule seed.
- A pair row whose stamp names no schema reads as schema 1, as `replay_pair` reads it.
- A proof record's identity includes the verifier's result digest, so a re-verification that judges
  differently becomes a new record rather than an index collision.
- An unlabelled row reads `Unlabelled`, never exploratory or pre-registered.

### Do not implement

Studio and the browser compute no analysis value, interval, ratio or verdict: they display the
engine's. Live configuration is untouched. The side-by-side compare view of two comparisons is #990's;
the data, the matching key and staleness are built here.

sidecar on every pre-spend refusal and matrix-checked, locked history writes on top of main's pack,
