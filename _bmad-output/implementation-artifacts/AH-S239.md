## Story

As a harness maintainer, I want the replay to report Cost-of-Pass and pass rate with paired, task-clustered intervals, so that a result is judged by SM-2's decision rule rather than by point estimates.

## Context and value

SM-2 makes Cost-of-Pass the headline: the total cost of all attempts divided by total passes, pooled per arm, with the harness-to-bare ratio undefined when either arm passes nothing. Its governing intervals are paired and task-clustered at 95%, by bootstrap or the delta method; Wilson or Bayesian intervals on pass rates are descriptive. A result is supported only when the ratio's interval lies wholly below 1.0 and the lower bound on the pass-rate difference is above -0.125.

Depends on #793. Extends #754. Traces to SM-2 and FR-56.

## Acceptance criteria

1. Given a finished two-arm replay, when it is summarised, then each arm reports Cost-of-Pass and pass rate, and the ratio carries a paired, task-clustered 95% interval.
2. Given an arm with no passes, then the ratio is reported as undefined, never as zero or infinity.
3. Given pass rates, then each carries a Wilson or Bayesian interval labelled descriptive.
4. Given SM-2's decision rule, then the report states supported, not supported or inconclusive, whatever the result, and claims a magnitude only when the ratio's upper bound is at or below 0.85.
5. Given the saved rows alone, then every figure re-derives: each run row carries its task, arm, trial, pass or fail, and cost. The 2026-09-23 runs saved no pass or fail.
6. Given the finished pair, then a Pareto view plots cost against pass rate per arm.

## Design

Decided by the owner on 2026-09-26: count crashed and timed-out runs as failed attempts with their
cost (already true after #1010, kept), default the replay to five trials per task and arm, and give
it a default spend cap that fits a 70-run set (7 tasks, 5 trials, 2 arms) at the per-run cap plus the
preflights. Support a `long` mark in `benchmarks/tasks.json` without marking any task; #796 marks them.

### Approach

A standard-library module, `scripts/replay_stats.py`, turns saved rows into SM-2's result:
`attempts` normalises each row (intention to treat: an errored row is a fail with its cost),
`analyse` pools Cost-of-Pass per arm, computes the ratio and the pass-rate difference, and runs a
task-clustered paired percentile bootstrap over the same task draws for both; `decide` applies the
decision rule; `pareto` and `render` give the text report. `cost_bench.py` gains a `summarise`
subcommand over a `results.jsonl`, an `sm2` block in each history row and an SM-2 line under each
ledger line; every scored row gains `outcome` and `task_long`.

### Decisions and alternatives

1. Bootstrap rather than the delta method: it needs no variance formula for a ratio of pooled
   sums and handles small task counts without a normal approximation. Nearest-rank percentiles, so
   every bound is a resampled value. Seed 795 and 10,000 resamples by default, both recorded.
2. A resample in which the harness arm passed nothing sorts as infinity, one in which only bare
   passed nothing as zero; a bound landing there is reported undefined. Rejected: dropping those
   resamples (biased towards the harness) and declaring the whole interval undefined on any such
   resample (with seven tasks one resample in thousands would void a clear result).
3. Verdict: supported per SM-2; not supported when the data rule the claim out (ratio interval
   wholly at or above 1.0, or the difference's interval wholly below -0.125); inconclusive
   otherwise, including an undefined ratio. A supported result whose marked long-task subset does
   not also lie wholly below 1.0 claims no saving.
4. Decided by the owner on 2026-09-27: a timed-out run with no readable cost is charged at the
   2 USD per-run cap before the SM-2 analysis. Another error with no readable cost still leaves
   the ratio and its interval undefined; the statistics layer never invents a price.
5. The older mean-of-reps `status` stays on history rows so earlier rows remain comparable; SM-2's
   verdict decides a claim.
6. Default taken: `--spend-cap` defaults to 140.50 USD (7 x 5 x 2 runs at 2 USD plus two 0.25 USD
   preflights), because that is the smallest cap under which the replay's own stop rule launches
   every run of a full default set.
7. Default taken: the Pareto view is a Markdown table rather than an SVG, because it diffs in
   review and needs no renderer.

### Do not implement

The intra-cluster correlation and design effect of evidence-standard section 5, a Bayesian pass-rate
interval, any replay or model call, and marking tasks long (#796).
