## Story

As a developer, I want to review a draft and apply it through the same checks and locks as the CLI, so that a Studio change is as safe and auditable as a command.

## Context and value

A draft's review page shows every file and configuration key it changes against its base, with its lint status, the budget delta and the equivalent CLI commands. Apply runs through the governed path (`config_set` for keys, a fast-forward of the developer's own root for module files, then `citizen sync`) under the same lock as the CLI, with ownership journal and decision log rows that name the Studio and the draft.

## Acceptance criteria

1. Given a draft with lint findings, then apply is refused with the findings.
2. Given another writer holding the sync lock, then apply waits or refuses and names the holder, and never interleaves.
3. Given a draft that changes a core module in place, then apply refuses and offers a fork, or a branch holding the draft's commits with the commands to open a pull request.
4. Given an apply, then the doctor checks run and the overview shows the result, and the applied state equals running the CLI commands shown, in tests.
