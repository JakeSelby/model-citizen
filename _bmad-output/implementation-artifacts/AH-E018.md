## Goal

Cut the prompt-cache rebuild spend of long interactive sessions, starting with its largest cause, the
one-hour cache expiring while a session sits idle. Completion is observable in one report: over 14 days
with the cold-resume guard on, `harness usage --by rebuild` shows idle-over-an-hour rebuilds below 5% of
long-session spend, from a 10.7% baseline, judged alongside spend per merged pull request so that re-reads
after `/clear` cannot hide a loss ([#745](https://github.com/JakeSelby/agent-harness/issues/745)).

**Evidence (historical, measured on one machine on 2026-09-23).** Over the 30 days to 2026-09-23,
rebuilds cost 20.1% of the spend in long sessions, those of 200 or more model calls:

- idle over an hour, the cache expired: 10.7%;
- a model switch: 3.6%;
- a session reload in the VS Code extension: 2.3%;
- a tail of about 3.5%: instructions or tool lists reloaded mid-session, five-minute cache entries
  expiring, version and effort changes, compaction, and breaks that nothing recorded explains.

Almost every rebuild keeps only the system prompt and tools and re-writes the history, so a rebuild costs
roughly the whole context at the cache-write price, and its cost grows with context size. That is why
the guard and the handoff refresh key off the fresh-session threshold. AH-S227 holds the method.

## Scope and requirement coverage

**In scope:**

- Measurement: `harness usage --by rebuild` attributes each rebuild to a cause (AH-S227).
- Prevention at a task boundary: `/land` and `/close-out` refresh the handoff once context passes the
  first fresh-session threshold, so `/clear` is a cheap way back in (AH-S228).
- Prevention at the moment of cost: an opt-in cold-resume guard in the usage feed holds one prompt after
  a long idle on a large context (AH-S229). A spike first tests whether a prompt-submit block holds in
  the CLI and the VS Code extension (AH-SP010).
- A smaller context: a one-week trial of an earlier auto-compact window (AH-SP011).

**Out of scope:**

- Running `/clear` or `/compact` automatically, which interactive Claude Code offers no way to do:
  - hooks cannot run slash commands;
  - the Skill tool reaches only a few built-in commands, and the documentation names `/compact` among
    those it cannot;
  - SessionStart's `initialUserMessage` applies only in non-interactive mode, with `-p`;
  - the upstream request for hook- or idle-triggered compaction, anthropics/claude-code#77266, was
    closed as not planned.

  AD-7 also rules out triggering compaction from a hook.
- Keep-warm pings: role workers and the other headless runs the harness drives do not sit idle.
- Fixes for model switches, VS Code reloads and the tail. AH-S227 measures them, and a fix for any of
  them is its own issue.

**Requirement coverage,** checked against the 2026-09-23 PRD:

- **FR-23 Cross-runtime usage ledger:** `rebuild` joins the `--by` values its consequences list.
- **FR-24 Honest pricing:** the report and the guard's estimate price per model from the dated table,
  with one-hour and five-minute writes priced apart, and report an unpriced model as unpriced.
- **FR-32 Live usage feed and fresh-session nudge:** the guard is a new feed behaviour, and the handoff
  refresh keys off the nudge's thresholds.
- **FR-59 Session lifecycle workflows:** `/land` and `/close-out` gain the handoff refresh.

Each delivering pull request amends its requirement through `bmad-prd`'s update intent.

## Architecture slice

- **AD-14 For cost, hooks only route and refuse frontier:** "Budgets, feeds and nudges are information.
  No hook denies for cost." Holding a prompt to avoid a rebuild is a denial for cost, so AH-S229's
  hold-once option needs this rule amended, through `bmad-architecture`'s update intent, before it is
  built. Its warn-only option fits the rule as written.
- **AD-7 What a hook may and may not do:** its enforcement list has no prompt-submit block, and the event
  table in `lib/harness_core/lifecycle.py` changes only after a probe on a named client version.
  AH-SP010 is that probe. A client that does not hold is declared in the `limitations` of
  `adapters/claude-code/capabilities.json`.
- **AD-2 One resolver, fixed invariants:** the guard's switch is a unit of #554's selection model, not a
  new configuration key.
- **AD-11 Local ledgers are the system of record:** the report reads transcripts per call, which the
  ledger does not keep, and writes no second ledger.
- **AD-17 Behaviour read from client internals is pinned and checked:** some causes rest on transcript
  entries Claude Code does not document, so they are pinned to the client versions they were checked on.
- **AD-20 Continuity never moves authority:** the handoff and a carried prompt are data for the next
  session, never an approval.

## Sequencing

- AH-S227, AH-S228 and AH-SP010 have no dependencies and can run in parallel. AH-S227 goes first in
  practice, because every later judgement reads its report.
- AH-S229 waits for three things: AH-SP010's result, which sets hold or warn per client; the AD-14
  decision; and #554, so that its switch ships as a selection-model unit.
- AH-SP011 needs AH-S227 for its before-and-after comparison. It runs on the maintainer's machine and
  changes its settings, so it waits for the maintainer's go, and its window should not overlap AH-S229's
  measurement window.
- **Risk:** most long-session spend runs in the VS Code extension. If AH-SP010 finds that the extension
  cannot hold a prompt, the guard cannot reach the 5% target there, and the exit criterion is revisited on
  #745 rather than passed on the other clients alone.
- **Milestones:** none. The epic and its children are on the backlog.

- [ ] Over 14 days with the guard on, idle-over-an-hour rebuilds are below 5% of long-session spend,
