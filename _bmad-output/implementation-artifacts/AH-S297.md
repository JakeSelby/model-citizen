## Story

As a developer or an agent, I want runs launched only from an allowlisted catalog, supervised and cancellable, so that the Studio runs suites without becoming a way to run anything.

## Context and value

Runs launch from a declarative catalog: each suite's argv template, its parameters and their validation, its cost class (free, or spends usage), its expected duration and the targets it supports. The supervisor starts a run as an argv list with no shell, in its own process group, captures its output to files, streams it, cancels it, enforces a timeout and a limit of three parallel runs, and marks a run whose supervisor died as orphaned, as role workers do. `citizen runs start|list|show|cancel --json` is its CLI face.

## Acceptance criteria

1. Given a parameter outside its allowed values, then the run is refused before any process starts.
2. Given a cancel, then the run's whole process group ends within five seconds and the run is marked cancelled.
3. Given a Studio restart mid-run, then the run is recovered as running or marked orphaned, and never left running forever.
4. Given a fourth run while three are running, then it queues.
5. No catalog entry can run a command outside the catalog, in tests.

## Design

### Approach

Add a Python 3.9 standard-library `studio.runs` core shared by the CLI and future private Studio
transport. A versioned JSON suite catalog fixes each executable and argv template, declares the
only parameters and target kinds that may be substituted, and validates all input before creating
a run. The supervisor persists small per-run control records and captured stdout/stderr below the
state home, starts argv arrays without a shell in separate process groups, admits at most three
runs and drains a FIFO queue. A detached standard-library worker owns timeout and terminal-state
updates so a run outlives the launching CLI. Recovery verifies both PID and process start identity;
an unverifiable non-terminal run becomes orphaned.

`citizen runs start|list|show|cancel --json` calls this core directly. The shipped catalog is
initially empty: later suite stories add named entries without widening the command boundary.

### Decisions and alternatives

- Catalog argv templates are data, not command strings. The executable token must be literal;
  placeholders occupy whole later argv elements, so parameters cannot alter command structure.
  Reject shell strings and user-selected executables.
- Persist supervisor control records as atomic JSON plus output files. The authoritative hash-chain
  run store belongs to #981; this story retains only enough state to supervise and recover processes.
- Use a detached Python worker for each admitted run and a cross-process advisory lock for admission,
  cancellation and recovery. Reject an in-memory-only supervisor because separate CLI invocations
  could exceed the concurrency cap or lose terminal state.
- Verify process identity with Linux `/proc` start ticks or the platform process start string. PID-only
  recovery is rejected because PID reuse can keep a stale run apparently alive.

### Do not implement

- Concrete free, native and replay suite definitions (#982, #986, #987).
- Spend estimation or confirmation (#985), the authoritative SQLite/run sidecar store (#981),
  HTTP/SSE transport, and Studio UI.

### Testing

`tests/test_studio_runs.py` rejects unknown/extra/invalid inputs and executable placeholders; proves
rendered argv has no shell escape; exercises three running plus one FIFO-queued run; cancels a spawned
process tree within five seconds; proves normal and timed-out runs reap descendants before releasing a
slot; verifies timeout, stdout/stderr capture, terminal state, CLI JSON and identity-based orphan
recovery; fails admission closed on unreadable records; covers Linux process names with parentheses;
proves a launch failure drains the FIFO; proves bounded cursor reads while output is still live and
terminal EOF; round-trips successful CLI start, nonempty list, show and cancel through the persisted
path-free core DTO; and proves descriptor-safe state placement plus isolated HOME and XDG homes.
Additional failure-path coverage proves cancellation never signals the worker as a command fallback,
missing command identity and post-spawn state failure reap the command group, parseable malformed
records fail closed, macOS identity uses a stable locale, CLI I/O failures stay normalized JSON, and
byte cursors preserve complete UTF-8 code points across requested chunk boundaries.
Final race coverage proves a worker cannot execute until its authenticated starting handoff is durable,
targeted cancellation remains available beside unrelated corrupt state, and orphan capacity stays
reserved while its group lives but releases once that group is gone.
