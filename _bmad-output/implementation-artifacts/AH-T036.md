## Goal

The Studio adds a server, a front-end toolchain, a draft workspace and a run store to a standard-library CLI. Run `bmad-architecture` with update intent to record the decisions every Studio story builds on, as ADs in the architecture spine, each with the alternatives it rejects:

1. **One core, two faces.** The Studio calls the same functions as the CLI (`posture.selection()`, `config_set`, lint, sync, usage) and re-implements no resolution, validation or write. One core DTO/error/idempotency contract and route registry cover both surfaces; only transport/bootstrap/static/health/SSE routes are parity-exempt, while every domain query, composition and mutation has a displayed `citizen` equivalent.
2. **A standard-library server on loopback.** Threaded `http.server` on the Python 3.9 floor, threaded reads, one mutation executor/event broker, JSON over HTTP, and SSE with epoch/sequence cursors, broker-barrier snapshots and bounded replay. Rejected: FastAPI with uvicorn, whose compiled dependencies cannot ship as vendored, platform-independent wheels (AD-21); a Node server, which needs Node at runtime and a second implementation of the core.
3. **Locked to its launcher.** Loopback only at one random `<nonce>.localhost:<port>` origin. The sole Origin exception is a form-only local-file POST with no cookie and a valid one-shot token; success atomically consumes it and enters the exact app origin with session cookie and CSRF. Every later non-safe request requires exact Origin and CSRF. Process control is separate and versioned; the fixed header baseline and descriptor-relative file operations apply. This isolates browsers, DNS rebinding and accidental clients, not malicious same-UID code. The HTTP API is private under PRD §7.
4. **React, TypeScript and Vite, shipped as a committed bundle.** A single-page app built from a pinned lockfile, with its bundle committed so a curl install needs no Node; npm is a contributor build tool. This amends AD-21: bundled third-party code enters only after a licensing review, recorded in `third-party.json`. Every release verifies source, lockfile, bundle and shipped notices by the byte-identical rebuild mechanism AH-SP017 proved across three macOS and three Linux builds. Rejected: server-rendered HTML with htmx (no build step, but weak for a streaming log, a diff editor and interval charts); Svelte or Solid (smaller bundles, thinner ecosystems for the editor, charts and accessible primitives); Electron or Tauri (signing and packaging for no gain over a loopback tab).
5. **Drafts are managed worktrees.** One worktree per draft, one serialized writer, revision preconditions and `(draft_id, key)` idempotency bound to a canonical request digest. Checkpoint commit and result are one crash-recoverable journal transaction acknowledged only when durable. Only governed apply writes live state; rollback preserves later user edits (AD-3).
6. **Files stay the system of record.** Native results, ledgers and sequence/hash-chained event sidecars under stable run UUIDs stay authoritative (AD-11). Import validates creation, prior-event and terminal digests; truncation or rewrite conflicts. SQLite only indexes. Snapshots use canonical serialization and pin computation, source and field-level provenance plus partial-failure state.
7. **One instance per user.** Validated no-follow state-home traversal reaches an instance lock held by descriptor for process lifetime and a versioned atomic state file. CLI health/status/stop require matching state and control-protocol versions plus pid-start identity; restart rotates sessions and recovers or marks orphaned runs.
8. **Read-only, provider-neutral AI health assessment.** After opt-in, an adapter invokes the developer's
   configured model or tool against immutable evidence in a scrubbed, bounded, tool-disabled, read-only
   process through a qualified named adapter with a fixed executable/version/invocation; arbitrary tools
   are unsupported. Claims and single-flight identity include integration/account plus all execution and
   evidence provenance. Every attempt separately reserves worst-case usage in the persisted
   local-day/integration ledger, then settles actual usage; retries re-reserve and may stop. Eligible
   evidence coalesces for 60 seconds while the last good result remains stale.

## Design

The architecture spine is the durable build contract. It adds Studio as a planned second face over the
existing core, not as a second implementation. One owned command/query/result DTO, error/revision/
idempotency contract and route registry drive both transports. Transport, bootstrap, static, authenticated
health and SSE routes are the only CLI-parity exemptions and remain schema-bound and tested; every domain
query, composition and mutation exposes its exact `citizen` equivalent.

The server remains inside the Python 3.9 standard-library runtime envelope: threaded `http.server` on
loopback, threaded reads, one mutation executor/event broker, JSON request-response and SSE streams.
Broker-barrier snapshots return state with an epoch/sequence high-water cursor. Its private API uses a
random nonce localhost origin and a mode-0600 temporary local form for one-shot bootstrap, then session
and CSRF state. Bootstrap is the sole Origin exception: exact Host, form POST, null/absent local-file
Origin, valid unused token and no cookie; it performs only the atomic exchange and navigation into the
exact app origin. Every later non-safe request requires exact Origin and CSRF. Browser, DNS and
accidental-client isolation does not claim protection from malicious same-UID code. Protocols are
versioned, headers are fixed, and file mutations remain relative to retained no-follow directory
descriptors. PRD §7 records the matching public/private boundary.

The browser UI is a committed React/TypeScript/Vite/Mantine bundle built from an exact lockfile. AD-21's
build-time exception requires `third-party.json` plus preserved license texts and notices in the
distributed artifact, while runtime Python stays standard-library-only and clean installs require no
Node. CI and release preflight always verify source, lockfile, bundle and notices through the
byte-identical rebuild mechanism AH-SP017 proved across three macOS and three Linux builds.

Drafts use managed worktrees with a serialized writer, revision precondition and request-digest-bound
idempotency key. Checkpoint commit and result form a crash-recoverable journal transaction acknowledged
only when durable. Rollback preserves later user edits. Native files, ledgers and hash-chained per-run
event sidecars are authoritative; import validates creation, prior-event and terminal digests, while
truncation or rewrite conflicts. SQLite only indexes them. Snapshots have canonical bytes, computation
identity and field-level partial-failure provenance.

One no-follow lock descriptor held for process lifetime and a versioned atomic state file, both reached
through validated state-home traversal, own singleton lifecycle and version-matched recovery. The opt-in
AI overview accepts only qualified named adapters with fixed executable/version/invocation and isolated
temporary cwd/HOME; arbitrary tools are unsupported. Provenance and single-flight include
integration/account identity. Each attempt separately reserves worst-case usage, then settles actual use;
a retry must reserve again.

Rejected alternatives are recorded beside their decisions: duplicated Studio domain logic, FastAPI or a
Node runtime server, a public or unauthenticated HTTP API, htmx/Svelte/Solid/Electron/Tauri for this
surface, live or unversioned editing, SQLite as authority, multi-instance or memory-only lifecycle state,
and a provider-bound or mutation-capable AI assessor.
