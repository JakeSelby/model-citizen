## Story

As an agent running `/land`, I want step 1 to say which checks it waits on, so that a status that is not required, such as a review bot's, neither blocks the merge nor passes unmentioned.

## Context and value

Step 1 required every required check green, then said a pending, failing or stale check stops the workflow. It did not say whether "check" there meant a required one. CodeRabbit's commit status is not required, yet it sits pending for several minutes after each review request, so one agent would wait on it and another would ignore it silently. The review itself is gated elsewhere, by the repository's own merge conditions, so the status adds nothing a required check does not.

## Acceptance criteria

1. **Given** a pull request whose required checks are green and whose not-required status is pending, **when** `/land` runs step 1, **then** it names that status and its state and proceeds.
2. **Given** a required check, or an issue-ownership or closing-link check, that is pending, failing or stale on the current head, **when** `/land` runs step 1, **then** it stops and names the check.
3. **Given** the command's body, **when** the command tests run, **then** it stays within the 40-line body cap.

## Design

### Approach

Rewrite step 1 of `primitives/workflows/land.md` in place, keeping its five lines so the body cap holds once the other in-flight edit to this file lands, and regenerate the projections with `bin/harness generate`.

### Decisions and alternatives

Decided by the owner on 2026-09-26: `/land` names each check that is not required, with its state, but gates only on required checks, with the issue-ownership or closing-link check counted among them where the repository runs one. CodeRabbit's commit status is the motivating case.

- Rejected: waiting on every check. A review bot's status is pending for minutes after each request, and the review is already a merge condition of its own.
- Rejected: ignoring a check that is not required without naming it. A failing optional check can still be news the reader acts on.

### Do not implement

Other steps of `land.md`, `primitives/workflows/build.md`, `AGENTS.md`, and any code that queries check status.
