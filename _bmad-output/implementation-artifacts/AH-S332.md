## Story

As a harness maintainer, I want `replay --ablations` to run on a pinned evaluator pack, so that the registered prefix sweep for #514 has a contamination-safe task source.

## Context and value

`replay --ablations` refused `--pack` because the ablation runner did not run the pack's contamination check or pin its digest, and no in-repository task source passes the contamination control, so #1148's registered sweep could not run. The pack path from #796 already holds the check and the digest pin; this story routes the ablation path through them.

## Acceptance criteria

1. **Given** `replay --ablations benchmarks/ablations.json --pack … --pack-ref … --pack-digest …`, **when** it runs, **then** each pack task's contamination check runs at the exact commit `--tag` resolves to before any arm is built or launched, and a refused task stops the run with exit 2.
2. **Given** a registered ablation run on a pack without `--pack-digest`, **when** it runs, **then** it is refused before anything is built, as `replay --pack` refuses it.
3. **Given** an ablation run on a pack, **then** every row records the pack's name, version, commit and digest.
4. **Given** `--dry-run`, **then** it prints the arm schedule, the minimum detectable effect and the worst-case cost at the run's `--run-cap` (naming the default when none is given), and declares control from the commit `--tag` names.
5. **Given** the change, **then** the existing ablation, pack, pair and micro tests pass, and a regression test proves a contaminated pack task is refused on the ablation path.

## Design

### Approach

`open_pack_for` no longer refuses `--ablations`; `_cmd_replay` passes the opened pack to `replay_ablations`. After the manifest's entry check, `replay_ablations` runs `contamination_by_task` (the same per-task control `replay --pack` uses, `replay_pack.contamination_errors` for a pack task) at control's commit. The dry run prints one line per task and exits 2 on a refusal; a real run refuses with exit 2 before the first `build_arm`, then refuses a registered run with no `--pack-digest`. `common["pack_stamp"]` carries `replay_pack.identity(pack)` into the stamp every row copies. The plan prints a worst-case line from `replay_micro.ceiling_usd` over the run's `--run-cap` and the preflight cap, and labels the run cap's source [Source: scripts/cost_bench.py#replay_ablations].

### Decisions and alternatives

- Reuse `contamination_by_task` and the digest refusal's wording rather than a second check; a new pack-specific check for ablations was rejected as duplication.
- Run the check before any image is built, not only in `_replay`: an image build is not free, and the brief requires it before any arm launches. `_replay` keeps its own check as a second line.
- Run the new pre-build check only when the source is a pack: a `--tasks` source is refused by the same control already, and checking it pre-build would change the dry-run exit of the existing `--tasks` ablation tests.
- Name the run cap's source in the cost lines instead of refusing a run with no `--run-cap`, so a default stays usable but never reads as a chosen figure.

### Do not implement

- Pack support for `--pair`, which stays refused, or ablations on the micro tier.
- Any paid run, pre-registration or the #1148 sweep itself.

`tests/test_cost_bench_ablations_pack.py` covers each criterion: a clean dry run checks each task at the tag's commit and builds nothing (AC 1, 4); a canary and an exact-solution-bytes contamination are refused in the dry run and before any build in a real run (AC 1, 5); a registered run without a digest is refused before any build (AC 2); a pinned registered run builds control and the arm from the tag's commit, not HEAD, and stamps the pack (AC 3, 4); the worst-case figure follows `--run-cap` and names the default (AC 4); every ablation row from `replay` carries the pack identity (AC 3); `--pair` stays refused. Existing suites: `test_cost_bench_ablations`, `test_cost_bench_pack`, `test_replay_pack`, the pair and micro suites.
