# AH-B119 — The harness arm's image holds a checkout with every task's fix, so a harness-arm pass can be a copy

## Reproduction

Build the harness arm at any ref later than a task's `good_sha` (#559's `replay_arms`): the image's checkout of that ref holds the task's fixed files, readable by the agent in the arm, while the bare arm has none. Found while building #559 [Source: #1019].

## Root cause

The tasks are mined from this repository's own history, and the harness arm installs this repository at a later ref, so the install carries every task's solution [Source: #1019].

## Acceptance criteria

1. **Given** any task in the set, **when** the harness arm's image is built, **then** it carries no copy of the task's fixed files readable by the agent's tools, or the task is excluded, and a test proves it.
2. **Given** the v0.15.0 baseline, **when** it is pre-registered, **then** the pre-registration names this control.

## Design

Run an executable contamination check against the exact commit installed in the harness image
before the writable-worktree probe, preflight, or any scored model call. Every issue task mined
from this repository is refused while that repository remains installed, because ancestry cannot
exclude a cherry-picked, squashed or equivalent fix. A live synthetic task is refused when its
held-back oracle already passes on that checkout. Retire the five exposed issue
tasks with their full records and reasons, leaving the two synthetic tasks whose outputs are absent
from the installed tree. During scored runs, inspect tool-use inputs and fail an attempt that names
`/opt/model-citizen`, while retaining the installed checkout and every runtime mechanism it serves.

Removing `.git` alone was rejected because the fixed working-tree files would remain readable.
Pruning installed runtime source was rejected because the image's projected rules, hooks and skills
depend on that checkout. A declarative `clean` label was rejected because it did not test the image
and was already wrong for four issue tasks [Source: scripts/replay-arm.Dockerfile; Source:
benchmarks/tasks.json; Source: scripts/cost_bench.py#replay].

## Regression test

The cost-bench tests prove a same-repository issue task is refused even when an equivalent fixed
tree is not descended from its known-good commit, refusal occurs before a probe or model call, Git
errors fail closed, the two surviving synthetic oracles fail on the installed HEAD, every retired
issue fix is reachable from HEAD, and a scored transcript that reads `/opt/model-citizen` becomes a
failed attempt. The parity tests derive the new two-task count from the manifest.

## Dev notes

The live set intentionally has only two synthetic tasks after this change. It is not an adequately
powered set and supports no product claim; #796 owns expansion. The manifest bytes already rotate
the result series when tasks change. The control uses the installed commit recorded by the built arm
rather than the runner's working tree. Transcript detection records only the tool name and installed
root, not arbitrary command text [Source: docs/benchmarks.md; Source: docs/evidence-standard.md#9-a-contamination-check].
