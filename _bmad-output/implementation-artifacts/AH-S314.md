## Story

As an agent working for a developer, I want the whole draft, test and apply loop in the CLI and a rule for when to open the Studio, so that I tune the harness headless and show my human the result.

## Context and value

An agent runs the whole loop headless: `citizen draft` to make and edit a draft, `citizen runs` to test it, and apply through the same command the Studio shows. A skill tells an agent when to open the Studio for its human (`citizen studio --detach --json`) and hand over the link instead of describing the change. A test fails when a Studio mutation has no CLI equivalent.

## Acceptance criteria

1. Given the Studio's mutating API routes, then each maps to a CLI command, and a test fails on an unmapped route.
2. Given an agent session where the skill applies, then the agent hands over the URL from `--json`, not a screenshot or a description.
3. Given the headless loop run end to end in the test suite, then the applied state equals the Studio's for the same choices.

## Design

### Approach

Every Studio domain route already names a `cli_command` (AD-25). This story makes each one a command
that runs: it parses under `citizen`'s own parser and carries `--json`, and a test fails a route
whose command does not. Four routes named a `citizen runs spend-preview` that never existed, and
seven named `python3 scripts/...` commands that answered differently or not at all. The paid
admissions (replay, eval tier, native acceptance, draft test) gain
`citizen runs replay|eval|native|draft-test ACTION --request FILE`, which hand the request body to
the route's own handler through `studio/headless.py`, so the CLI's previews, confirmation tokens,
refusals and JSON are the Studio's by construction. `citizen runs start` refuses the paid suites
those admissions own, `citizen doctor --json` prints the Overview and `citizen catalog --library
--json` the Library. A `studio-loop` skill teaches the loop and when to hand the user the Studio
`url` from `citizen studio --detach --json`.

### Decisions and alternatives

1. **Run the route handler, not a second CLI implementation.** A CLI path that re-implemented the
   replay, eval, native and draft-test admissions could drift in what it refuses. Rejected: a
   generic `citizen api METHOD PATH` tunnel, which would make the private API public.
2. **Close the generic paid start.** `citizen runs start live-replay|native-acceptance|micro-tier|
   unit-eval` skipped target resolution, the dirty-worktree and edited-configuration refusals and
   evidence labelling. It now refuses and names the admission command.
3. **Spend and apply stay on the user's go in the skill.** The Studio asks a person to confirm a
   spend estimate and type the draft name before apply; the CLI carries a token and a revision. The
   skill tells an agent to show the estimate or the review and wait for an explicit go.
4. **A route's command spells out its arguments** (`{run_id}`, `{draft}`), so the parity check can
   parse it and an agent can run it as shown.

### Do not implement

- No new Studio route, UI change or bundle rebuild; the frontend does not render `cli_command`.
- No change to what `citizen draft apply` or `draft rollback` require; the Studio's typed draft
  name stays a Studio confirmation.
- No `product.json` line.

## Review findings

Round 1 (two reviewers), all fixed:

- The spend-guard test now previews the skill's own two-target example on fixture targets, then
  is refused with a forged token and with a real token for a changed request.
- `requests.md` beside the skill gives each `--request` shape with an example; a test checks every
  example's keys against the route handler's and parses the inner requests as the admissions do.
- `citizen runs GROUP ACTION` prints a supervisor `RunError` as JSON with exit 2.
- The `doctor --json` test asserts a real reading, not the unavailable fallback.
- Parity is now proved on a fixture (`tests/test_agent_studio_parity.py`): every domain route's
  command answers with the route's keys and schema, or refuses where the route does, and a route
  without an entry fails. It found two more mismatches, now fixed: `citizen selection --report`
  and `citizen usage --rules --health` print what the selection and rule-health routes send, and
  the register route shows its required flags.
- `headless.call_route` closes the run supervisor.
- AC3's Studio side runs through a live Studio over HTTP with a session, Origin and CSRF.
- The run line names the right module, and the `live-replay` refusal names both admissions.
- `benchmarks/static.json` is generator output; its new price rows come from `policy/prices.json`.
