# AH-B161 — fix(benchmarks): the delegation verdict ignores gathering done through Bash

## Reproduction

1. Run a replay task where the agent gathers through Bash, for example `cd /work && git log -5`, `sed -n 1,40p a.py` or `rg -n x | head`, and with `Read`, `Grep` and `Glob` rarely.
2. Read the row's `gather_calls` and the task's delegation verdict.
3. Observed: none of the Bash reads count, so the task's size, the bare-arm median of gather calls, is understated and the verdict reads `declined-below-break-even` for work that may sit above the break-even.

## Root cause

`scripts/delegation_verdict.py` defines a gather call as a `GATHER_TOOLS` call (`Read`, `Grep`, `Glob`) by tool name alone, and `scripts/cost_bench.py` counts stream blocks against that tuple. A Bash call's command is never read, though most real gathering runs through Bash. [Source: scripts/delegation_verdict.py#GATHER_TOOLS]

## Acceptance criteria

1. **Given** a Bash call whose command is read-only (`git log/show/diff/status`, `gh … view/list`, `rg`, `sed -n`, `head`, `tail`, `cat`, `wc`, `ls`, `find`), **when** `gather_call` reads it, **then** it is a gather call.
2. **Given** a `cd … &&` sequence or a pipeline, **when** every step is read-only, **then** it is a gather call; **when** any step writes or runs a program (`git commit`, `sed -i`, a file redirect, `tee`, `xargs`, `python3`), **then** it is not.
3. **Given** a saved stream, **when** `gather_threads` reads it, **then** it returns one thread per gather call, `GATHER_TOOLS` and read-only Bash alike, so absorbed calls can be counted.
4. The read-only judgement is the `allow-readonly-bash` hook's own `command_ok`, not a second list.
5. The pilot of 2026-10-02 is re-scored offline from its saved streams with the new count, before and after side by side.

## Design

`read_only(command)` loads `policy/hooks/allow-readonly-bash.py` once and calls its `command_ok`, which already decomposes pipelines, sequences, loops and substitutions and fails closed; any exception reads as not read-only. `gather_call(name, input)` keeps `GATHER_TOOLS` and adds a Bash call with a non-empty read-only command; `gather_threads(messages)` applies it to a stream.

Rejected: a separate allowlist in the verdict, which would drift from the hook; and loosening the count for `xargs grep`, which the hook refuses for safety, so the new count still undercounts and a `missed` verdict stays conservative. Unchanged: `GATHER_TOOLS`, the verdict rules, the break-even and the `absorbable` label, since stored rows were counted without Bash.

## Regression test

`tests/test_delegation_verdict_bash.py` covers single read-only commands, `cd … &&` sequences, pipelines, writes, redirects, runs and empty or malformed input, and `gather_threads` on a stream with a spawn thread. Before the fix `gather_call` and `gather_threads` do not exist and every case errors.
