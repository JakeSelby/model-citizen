## Story

As a user of the harness, I want the agent's shell fenced by the runtime's OS sandbox and a
recoverable snapshot taken before every risky command, so that a destructive command the grader
misses cannot reach past the workspace and a discard of uncommitted work can be undone.

## Context and value

Two adversarial review rounds on the grader found twenty ways to rephrase a destructive command
so it grades as safe. A blocklist catches accidents; it cannot stop an agent that rephrases. The
boundary belongs below the shell, with the grader kept as the accident guard on top.

## Acceptance criteria

1. **Given** the settings template, **when** it is read, **then** it carries a `sandbox` block
   with `enabled: true` and `autoAllowBashIfSandboxed: false`.
2. **Given** a user config with `sandbox.enabled` true, **when** `sync` runs, **then** the block
   is written with `filesystem.allowWrite` derived from the workspace; with it false or absent,
   nothing is written, and switching it off restores what the key held.
3. **Given** a command graded 2 or more in a git working tree, **when** the PreToolUse hook runs,
   **then** a snapshot of the tree and index is kept under `refs/harness/snapshots/<time>` and the
   tree is unchanged.
4. **Given** a snapshot, **when** `harness snapshot restore` runs after a discard, **then** the
   working tree and index return to their snapshotted state.
5. **Given** a command graded below 2, or a directory outside a repository, **when** the hook
   runs, **then** no snapshot is taken and the hook still answers.
6. **Given** the docs, **when** they describe the layers, **then** the sandbox is the boundary,
   the grader the accident guard and snapshots the recovery.

## Design

### Approach

The template carries the sandbox block; `sync` writes it through the native-ownership path the
telemetry and workspace keys use, gated on a `sandbox.enabled` config key. A new library,
`lib/harness_core/snapshots.py`, takes, lists, restores and prunes snapshots with hardened git;
`grade-bash` calls it before any grade-2+ command, from both its standalone hook and the
dispatcher. `harness snapshot list|restore|prune` is the CLI.

### Decisions and alternatives

- A config key (`sandbox.enabled`, default false), not a stance: the sandbox is per-machine
  configuration, and a stance would have to project into every runtime.
- `autoAllowBashIfSandboxed: false`: the sandbox adds a boundary and removes no prompt.
- `sandbox.strict` adds `allowUnsandboxedCommands: false` and `failIfUnavailable: true`; left
  off by default because the unsandboxed retry is how a blocked tool keeps working.
- `git stash create` plus `update-ref`, rather than a filesystem snapshot: portable and cheap,
  but it holds tracked files only.

### Do not implement

- The pre-push hook and server-side branch protection the issue lists.
- The trap-task eval arm in #1175.
- Codex sandbox settings; Codex keeps its own `sandbox_mode`.

## Dev notes

### Bound decisions and requirements

Native settings ownership follows `claude/OWNERSHIP.json`: a value the harness did not write is
reported and left alone. Hooks never raise.
