## Story

As a developer deciding which rules earn their place in context, I want every loaded instruction
source listed with its cost and every harness entry ablated one at a time against control, so that
a rule stays or goes on a measured effect with its interval rather than on judgement.

## Context and value

`cost_bench static` prices the whole layer as one block and `replay` compares the whole harness
against bare as one ratio; neither attributes cost to one rule. `ARMS` was a fixed two-tuple,
nothing enumerated the surface, no row named the entry its arm removed, `cost_per_passed` folded
two dependent variables into one, and the prefix figure moved with cache warmth (45,847 against
27,977 tokens on one profile with identical totals). The four ablations behind #428 were made by
hand-editing a profile, recorded only as a free-text `change_note`. This story builds the tooling;
it spends nothing. The measured prefix sweep is a follow-up (below).

## Acceptance criteria

The issue's "Done when" was amended on 2026-10-01 to the approved plan; these are those six.

1. **Given** a profile with harness modules, own files, a project, a plugin, an MCP server and
   hooks, **when** `citizen usage --surface [--json]` runs, **then** every loaded source is listed,
   grouped by owner (harness, own, project, plugin, mcp, hooks, runtime), each with a soft token
   estimate or `unmeasured`; MCP and hook sources read `unmeasured`, never 0; and `usage --rules`
   output is unchanged.
2. **Given** `benchmarks/ablations.json` declaring arms, **when** `replay --ablations` runs, **then**
   it builds one image per arm from a declared selection, admission accepts only that declared
   file, runs are ordered from a recorded seed with the leading arm rotating, each row's removed
   entry is absent from its attribution, and a manifest naming an unknown id is refused before
   any spend.
3. **Given** a cold and a warm stream of one prompt, **when** `parse_result` reads them, **then**
   the warmth-free prefix figure (`first_call_context`, the plan's `first_call_prompt_tokens`) is
   equal for both, and None when a field is missing.
4. **Given** saved ablation rows, **when** they are summarised, **then** cost, output tokens,
   standing prefix tokens, turns, tool calls and pass rate are each reported against control
   with n, spread and a task-clustered interval, and `cost_per_passed` is one measure among them,
   never the headline.
5. **Given** an ablation run, **then** the command states its minimum detectable effect before
   spending; an effect whose interval spans zero prints `inconclusive`; fewer than five trials
   prints exploratory; and results are ranked by effect size.
6. **Given** the default selection, **when** `citizen scorecard [--results <dir>] [--json]` runs,
   **then** each module has one row with its instruments or `unmeasured`, its tokens, and its
   effect or `unmeasured`; no row reads "no effect".

## Design

### Approach

- **Declared-selection arms** (`scripts/replay_arms.py`, `scripts/replay-arm.Dockerfile`).
  `declaration(..., selection=...)` records the selection and a `selection` component whose
  version is the sha256 of the bytes installed. A new `harness-selected` stage installs them as
  the agent user's configuration before `bin/harness sync`, which withholds what is switched off.
  `_configuration_is_declared` now checks that file: with a selection it must match the component;
  without one a harness arm may hold only the sync's copy of `config.example.json`, and bare none.
  A declaration without a selection is byte-identical to before, so existing image names hold.
- **The N-arm manifest is schema 2** (`benchmarks/ablations.json`, `scripts/ablations.py`): `name`,
  `planning` (`cv` and its `source`) and `arms`, each one `removes` or one `sets`. Bare and control
  are implicit. A schema-1 pair file still loads through `replay_pair.load`, and given to
  `--ablations` it runs the pair path exactly as `--pair` does.
- **The replay** (`scripts/cost_bench.py`): `replay_ablations` checks every entry against a clone
  of the tag with that tag's own resolver before printing a plan, prints the minimum detectable
  effect, then the schedule (`ablations.schedule`: leading arm rotates with the rep, the rest a
  permutation from the recorded seed). The live path builds bare, control and one image per arm,
  and `_replay` refuses an arm whose declaration differs from control's beyond its selection or
  whose selection resolves to control's fingerprint. Rows carry `ablation` (schema 2),
  `ablation_removes` or `ablation_sets`, `selection` and `schedule_seed`; their fingerprint and
  attribution resolve with the arm's declared selection. No history row.
- **Prefix** (`parse_result`): `first_call_context` is reused as the warmth-free figure and is now
  None when any of the three input fields is missing. `replay_stats.prefix_clean` is new: an arm's
  prefix is usable only when every run lies within 2% of its (task, date) median.
- **Per-arm report** (`replay_stats.compare`, `render_compare`, `minimum_detectable_effect`): six
  measures separately, then Cost-of-Pass, each with n, SD and per-task max over min, and a paired
  task-clustered percentile interval; `inconclusive` when it spans no effect; exploratory under
  five trials or with several arms and no `--correction bonferroni`; ranked by cost effect; an
  unusable prefix falls back to the summed `context_attribution`, labelled a soft estimate.
- **Post-run parity**: `replay_pair.surface_parity` takes a control and an `allowed` map of the
  fields each arm's declared entry may move. The pair passes none, so any difference refuses it
  with its original message; `ablations.surface_parity` passes each arm's entry's fields.
- **Surface and scorecard**: `lib/harness_core/instruction_surface.py` enumerates the surface and
  `lib/harness_core/scorecard.py` builds the rows, both side-effect free; `bin/harness` adds
  `usage --surface` and `scorecard`, and extracts `classified_rules` from `rule_coverage_lines`
  so both reports share the `usage --rules` classification.

### Decisions and alternatives

1. **Selection path (brief b): pair behaviour unchanged, ablation arms through the new path.**
   Pairs keep their by-value `HARNESS_STANCE_*`/`HARNESS_MODE` factor and one image; ablation
   arms carry the selection in the image. Unifying both would rebuild the pair's image per arm
   and change #754's launch-spec parity, which its tests pin.
2. **Schema 2 beside schema 1 (brief a)**, not a rewrite of the pair format: pair files stay
   readable and behave as before, and one flag reads both.
3. **Parity redefined (brief c)** as "differs from control only in the fields its declared entry
   may move", mapped per kind (skills and workflows the skill and command listings, roles the
   agent listing, rules and stances the memory paths, hooks nothing). The `init` event carries
   counts and hashes, not members, so the allowance is per field, not per item.
4. **`first_call_context` reused (brief d)** rather than a second field; only `prefix_clean` is new.
5. **Own sources are a local soft estimate** (plan decision 1), never an arm input; MCP, hooks,
   plugins and the CLI's system prompt are `unmeasured` with a reason.
6. **The minimum detectable effect is a planning figure** from the manifest's declared `cv`
   (0.25 in the shipped manifest, an assumption named as such), at 80% power and 95% two-sided,
   alone and under Bonferroni; it is never presented as a measurement.
7. **`citizen usage --surface` and `citizen scorecard`** (plan decision 5), not `cost_bench.py`
   subcommands.
8. **Named-float scorer metrics** (the issue's original sixth criterion) moved to #1143.

### Do not implement

- Any paid sweep; the replay release threshold; interaction or factorial designs (#797, 0.18);
  per-module Cost-of-Pass runs sized from #796's pilot; Codex's surface; hook output cost;
  wiring the scorecard into AH-S251's 1.0 gate; task-manifest loading and oracle scoring, which
  another change owns.
