# AH-B107 — grade-bash says `gh repo rename` locks the repository read-only

## Reproduction

Autonomy stance `execute`, any permission mode:

1. Run `gh repo rename new-name`.
2. `grade-bash` gates it at grade 3 with the reason `grade 3, irreversible: gh repo rename new-name locks the repository read-only for everyone — this cannot be undone (grade-bash hook, autonomy=execute)`.

Observed: the reason describes an archive. A rename locks nothing: GitHub moves the repository to the new name, redirects the old URLs, and the repository can be renamed back.

## Root cause

`_gh` in `policy/hooks/grade-bash.py` handles `("repo", "archive")` and `("repo", "rename")` in one branch that returns the `archive` family for both, and `reason` prints the clause of that family, `CLAUSES["archive"]`, "locks the repository read-only for everyone", for either verb.

## Acceptance criteria

1. **Given** the `execute` stance, **when** `gh repo rename new-name` is graded, **then** it grades 3 with the verb `gh repo rename` and the target `new-name`, as before.
2. **Given** that command, **when** the hook states its reason, **then** the clause is "moves the repository to a new name, and the old URLs redirect only while no repository takes the old name", and no read-only lock is named.
3. **Given** `gh repo archive o/r`, **when** the hook states its reason, **then** it is word for word what it was before this change.

## Design

**Fix.** Give the rename its own verb family, `rename`, with its own entry in `CLAUSES` beside `archive`, and return that family from the rename branch of `_gh`. The archive branch and its clause stay as they are.

- The clause states the move and the part that can become permanent. GitHub redirects the old name's URLs, git clone, fetch and push included, until a new repository takes that name; from then on the redirects stop working.
- The grade stays 3. The move itself can be undone by renaming back, but the redirects cannot be restored once the old name is reused.

**Rejected alternatives:**
- Grading the rename 2: the maintainer kept it at 3, because losing every redirect when the old name is reused cannot be recovered.
- The generic `remote` clause, "changes shared state": true, but silent about the redirect, which is why the rename is gated at all.

**Must not change:** the rename's grade, verb and target; the archive reason; the reason format, including the grade-3 gloss "this cannot be undone" that every grade-3 reason ends with.

## Regression test

`tests/test_grade_bash.py::HookTests::test_gh_repo_rename_carries_its_own_clause_not_the_archive_one` runs the hook on `gh repo rename new-name` and on `gh repo archive o/r` under the `execute` stance and compares both reasons word for word. Against the pre-fix tree it fails on the rename reason, which names the read-only lock. `GRADE3` also gains `gh repo rename new-name`, which pins the grade, verb and target and brings the new family under `test_every_family_in_use_has_a_clause`.

## Dev notes

- After a rename GitHub redirects everything except project-site URLs, git clone, fetch and push included; it does not redirect calls to an action hosted in the renamed repository; and a new repository under the old name ends the redirects. [Source: GitHub Docs, "Renaming a repository"]
- The reason line is verb, target, clause, then the grade's plain gloss, so a new family needs only its `CLAUSES` entry. [Source: policy/hooks/grade-bash.py#reason]
- `claude/hooks` is a symlink to `policy/hooks`, so the hook has one source; the tests load it as `claude/hooks/grade-bash.py`. [Source: tests/test_grade_bash.py]
- Files: `policy/hooks/grade-bash.py`, `tests/test_grade_bash.py`, `changelog.d/900.fixed.md`.
- Testing: `python3 -m unittest discover -s tests -p test_grade_bash.py`, then the Gate block. [Source: AGENTS.md#Gate]
