## Story

As a developer, I want a timeline of what my harness decided and changed, so that I can see its guardrails at work and trace any surprise to its cause.

## Context and value

A timeline of what the harness did: decision and Studio-action rows from `decisions.jsonl` (the
guard or hook, the grade, allow or refuse, and why), plus the ownership journal's current source
status. A developer filters by session, repository, hook and outcome, and follows a decision to the
rule or hook that made it.

## Acceptance criteria

1. Given a refused command in the decision log, then the timeline shows the hook, the reason and the session, linked to that hook's library page.
2. Given a Studio apply, then the timeline shows it with its draft and the files it changed.
3. Command text from decision rows is shown as data and never rendered as markup.
4. Given a log of 100,000 rows, then the timeline pages through it without loading it whole.

## Design

### Approach

Add one read-only activity query in `harness_core.studio.activity`. It reverse-scans the append-only
decision ledger from an opaque byte cursor and normalizes decision and Studio action rows into a
versioned public DTO. It reports the ownership journal only as current source provenance, never as
a timeline event. The private Studio endpoint and `citizen activity --json` call the same query.

The React Activity page requests one page at a time, filters by session, repository, hook and
outcome, and renders all source text as React text nodes. Decision rows link only a recorded,
canonical module that resolves to an existing hook. Legacy or invalid provenance stays explicitly
unlinked. Source availability is reported independently so a missing or malformed journal remains
partial evidence rather than an empty history.

### Decisions and alternatives

- Use reverse chunked reads and byte-offset cursors, not `read_text()` or an in-memory index. This
  keeps a 100,000-row ledger bounded while preserving newest-first paging. Each request also caps
  scanned rows and bytes, returning a continuation cursor even when selective filters match none.
- Keep Studio apply records in the existing decision ledger as `studio.apply` events. A second
  mutable activity database would violate files-as-system-of-record; parsing only current draft
  state would lose immutable history.
- Represent the ownership journal as an evidence-source summary outside the timeline. The existing
  journal is a snapshot, not an append-only event stream, so the UI does not invent a timestamp,
  actor, action or historical sync event.
- Use the private authenticated POST route for filters and cursor. Query parameters are rejected by
  the Studio transport and the read remains CSRF-bound under the existing launcher session.
- Bind every initial and older-page request to one generation and abort its predecessor. A filter
  starts with an empty timeline, so a failed replacement cannot leave stale evidence on screen.
- Report absent grade and repository fields as unknown and unfilterable, respectively. Activity
  never derives missing historical provenance from mutable current state.
- Compose each row's recorded identity with its immutable ledger offset, so repeated executions
  that intentionally reuse a decision id remain separate occurrences across page merges.
- Accumulate source health at its worst observed status while paging. An older clean page cannot
  erase a malformed-row or failed-source warning from an already loaded page.

### Do not implement

- Applying or rolling back a draft; those stories will write the `studio.apply` event this reader
  already understands.
- Replacing the decision or ownership ledgers, adding SQLite state, or changing telemetry capture.
- Live SSE updates, notifications, reports, or mutable activity actions.

## Review findings

- Resolved: ownership snapshot metadata is reported only as current source provenance; it no longer
  fabricates an immutable timeline timestamp, actor, action or command.
- Resolved: decision evidence links only a recorded canonical module that resolves to an existing
  hook; legacy, traversal and nonexistent provenance remain explicitly unlinked.
- Resolved: real writer rows retain unknown grade and absent repository honestly; selective scans
  are bounded with continuation, commands preserve the full query, and stale requests are aborted.
- Resolved: ledger offsets distinguish repeated deterministic ids, page merges retain worst source
  health, and bounded empty pages expose the remaining search instead of a false no-match state.
