## Reproduction

Build an installed target of this repository: about 11 s, of which most is one `git update-ref -d` subprocess per ref across about 700 refs. `POST /api/runs/start` for the unit suite then exceeds the 15 s client timeout in `tests/test_studio_free_suites.py` `test_authenticated_routes_launch_stream_show_and_cancel_one_discovered_test`, on the unfixed branch too.

## Root cause

`targets._clone` ran a `merge-base --is-ancestor` subprocess per tag and an `update-ref -d` subprocess per other ref, so build time grows with the shared repository's branch count. [Source: lib/harness_core/studio/targets.py#_clone]

## Acceptance criteria

1. **Given** a repository with many branches, an ancestor tag and a non-ancestor tag, **when** a target clone is made, **then** only ancestor tags remain.
2. **Given** any number of refs, **when** the clone strips them, **then** it issues at most one ref update.

## Design

One `for-each-ref --merged=HEAD refs/tags` query selects the kept tags, and one `update-ref --no-deref --stdin` batch deletes the rest; `--no-deref` deletes a symbolic ref such as `origin/HEAD` itself instead of updating its target twice.

## Regression test

`tests/test_studio_targets.py` `test_clone_keeps_only_ancestor_tags_in_a_constant_number_of_ref_updates`; the old loop made 46 ref updates for it.
