## Reproduction

Submit the repository root on the Claude Directory plugin form and run its validator. At commit
`e0cb535`, validation reads 1,597 files, stops after its 512-file review limit, and reports holds
against historical planning artifacts, symlink projections and installer material that the plugin
manifest does not load.

## Root cause

The marketplace manifest points at the repository root. That is valid for checkout-based installs,
but the directory treats the selected folder as the distribution boundary and has no exclusion
mechanism. The repository root therefore exposes far more than the manifest's skills, agents,
commands and output style. The sandbox skill also placed a credential environment-variable example
next to an unrelated remote documentation URL, triggering the validator's exfiltration heuristic.

## Acceptance criteria

1. **Given** the canonical plugin sources, **when** the directory bundle is synchronized, **then**
   it contains the 15 skills, 11 agents, 7 commands, output style, manifest, icon, README, privacy
   policy and licence as regular files.
2. **Given** the committed bundle, **when** its check runs, **then** every copied byte matches its
   canonical source, every manifest path stays inside the bundle, and the inventory is at most 512
   files with no symbolic links or extras.
3. **Given** a directory reviewer reads the bundle README, **when** they assess data handling,
   **then** Git remotes, GitHub, WebFetch, WebSearch, local access and retention are disclosed, and
   the bundled policy has no links to files omitted from the distribution.
4. **Given** the offline container example, **when** a security scanner reads it, **then** it finds
   no host credential-directory mount or credential environment-variable forwarding.

## Design

Generate `directory/model-citizen` from an explicit source allowlist. Keep the existing repository-
root marketplace source for checkout compatibility; the Claude Directory submission selects the
new subfolder. A checked-in snapshot keeps remote directory installs self-contained, while a
deterministic sync/check script and tests prevent it drifting from the authoring sources. A focused
README is generated with the snapshot so root installer and release history never enter the
distribution. The release process remains responsible for changing all version and qualification
records together; synchronization automatically carries that version into the bundle.

## Regression test

`tests/test_directory_plugin.py` checks the committed snapshot, regular-file and file-count limits,
declared surface counts, required external-service disclosures, and stale/extra-file detection.
