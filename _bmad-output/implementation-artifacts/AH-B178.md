# AH-B178 — fix(hooks): a pass claim or a push can follow an edit with no fresh gate

The issue carries the summary, discussion and acceptance evidence; this file carries the design.

This work item was authored as part of the repository's committed BMad planning system.
<!-- bmad-sync:end -->

## Reproduction

1. In a repository that declares a `## Gate` block, run the gate green, then edit a file.
2. End the turn with "All tests pass." The stop gate runs its subset, or is skipped on an untrusted
   folder or a timeout, and nothing compares the claim with the last run.
3. Commit and `git push` under the `execute` stance: grade 2 is below its threshold, so the push
   runs with no gate run on that commit. An exploratory transcript audit put 12% of pass claims
   after a failed run, 15% after an edit, and 34% of 1,667 pushes with no passing run since the
   last edit.

## Root cause

- No gate run outside the stop gate's own state was recorded, and that state holds only a tree
  hash, so no check could ask what ran on which commit [Source: policy/hooks/stop-gate.py#main].
- The Stop hook judged the tree, never the reply's claim about it.
- `grade-bash` grades a push by reach alone; the verification rule and commits stance require a
  gate on the pushed HEAD, but nothing read that at the push [Source: policy/hooks/bash-grader.py#govern].

## Acceptance criteria

1. **Given** a stop-gate run or a `citizen gate` run, **when** it ends, **then** a row with its
   commit, tracked-dirty flag, tree digest, block, exit code, status and time is recorded.
2. **Given** a final message claiming the tests or gate pass, **when** the newest run in the
   checkout is missing, failed, or on a tree edited since, **then** the Stop is blocked once with a
   reason naming which; the same claim on the same tree in that session is then released.
3. **Given** a reply that claims nothing, or a negated, conditional or questioning sentence,
   **when** the turn ends, **then** no claim check fires.
4. **Given** a `git push` the stance lets through, **when** no green `## Gate` run is recorded for
   HEAD with no tracked changes, **then** it is asked about, naming the commit and the last run.
5. **Given** a push whose added paths are documentation only, a branch deletion, or a repository
   with no gate, **when** it is graded, **then** the record is not required.
6. **Given** any checked claim or push, **when** it is decided, **then** a decision-log row
   carries the check and its verdict.

## Design

- `policy/hooks/gate-runs.py` is a sibling library: `runs.jsonl`, the newest run per checkout
  (claim check) and green full-gate runs per commit (push check, shared across worktrees).
- The stop gate records each run it makes and, when it lets the turn end, checks the claim; a
  red-gate block, decline or block cap settles the turn first. One-shot state is per session and
  tree digest.
- `bash-grader.gate_push` places each push with the governance walk; the lifecycle asks below the
  stance threshold and adds a `gate` note to the Bash row. `grade-bash.py` mirrors it.
- `citizen gate` runs the `## Gate` block and records it; the output filter trims it.
- Rejected: per-edit timestamps from the transcript (the tree digest is exact and cheap); counting
  the stop subset for a push (it is not the gate the commits stance names).
- Must not change: the stop gate's own block and release rules, or any grade.

## Regression test

`tests/test_gate_runs.py`: recording, freshness, the claim pattern, stop-gate and `citizen gate`
records, the one-shot claim block and its release. `tests/test_gate_runs_push.py`: each push
verdict, the dispatcher's ask and its row, and the standalone hook.
