## Story

As a developer, I want each measure's trend across versions beside the project's proof set, so that I see how the harness and my setup change over time.

## Context and value

Each measure over time: the benchmark's cost ratio, cache-normalised ratio and pass rate from `benchmarks/history.jsonl`, the static context figure, detector precision and rule adherence, by version and date, with each release's change note. The proof set's status from `citizen evidence verify` (#799) sits beside them, with what the project does and does not claim.

## Acceptance criteria

1. Given the benchmark history, then each series plots by version with its change notes, and ratios are compared across days, never dollars.
2. Given a point with an interval, then the interval is drawn.
3. Given the proof bundle, then its verify status and its claims show as `citizen evidence verify` reports them.

## Design

### Approach

A read-only report, `lib/harness_core/studio/trends.py`, served by `POST /api/reports/trends` and
shown at `/reports/trends` (linked from the Hub's report cards). Nothing in it measures, intervals
or judges:

- benchmark lines: the run store's `cost-benchmark-history` records (#981), each one
  `benchmarks/history.jsonl` row as `cost_bench.history_row` wrote it. A line is one `series` and
  `bucket`; points run in date then version order with each row's change note. Each point carries
  the mean-of-reps ratio, the cache-normalised ratio, SM-2's ratio and pass rates, and the
  intervals SM-2 stored, plus SM-2's own verdict, reason and limitation and the delegation tally;
- static context: the run store's `static-cost` records, estimated tokens by version;
- proof set: every bundle `product.json` binds a claim to, verified by `evaluation.verify_bundle`,
  the function `citizen evidence verify --json` prints, with its cards, its `unknown` items and
  which cards `product.json` publishes. With no binding, the page says the project publishes no
  measured claim.

Rows are read generically: a field the module does not know (`metrics`, say) is ignored, and
`cache_basis` is shown when a row carries it. The page draws each line as an SVG with interval bars
and repeats every value, interval and label in a table beside it.

### Decisions and alternatives

1. **Evidence label from the row only.** A point is pre-registered when its row says so: its own
   `evidence` label, or `delegation.registered`, the engine's record that every run of the set
   named a pre-registration. Anything else reads exploratory. Today's `history_row` writes no
   `evidence` key, so older rows without a delegation block read exploratory. Rejected: inferring
   registration from the file a row sits in.
2. **A line that holds an exploratory point says so** in words beside the chart, and exploratory
   points are drawn hollow; all meaning is also in the table text.
3. **Ratios only.** No dollar figure leaves the route; the page carries the history file's own note
   that ratios compare across days and dollars do not.
4. **Intervals as stored.** SM-2's ratio and difference intervals and its descriptive pass-rate
   intervals are drawn; the mean-of-reps and cache-normalised ratios have none and draw none.
5. **Proof verified on each read, in process.** The same function the CLI prints, so status and
   cards equal its output; a verifier that raises reads failed, never verified.
6. **Detector precision and rule adherence are listed as not tracked.** No engine keeps either by
   version or date; the page says so and links Rule health for the current reading, beside each
   row's delegation tally. Rejected: recording a new series here, which would be a new engine.
7. **Bounds.** At most 2,000 records per suite (paged at 200) and 16 bundles; past either the page
   says what it left out.
8. **No new CLI command.** The route names `citizen runs history --json`, and each bundle its
   `citizen evidence verify --json <bundle>`.

### Do not implement

- Any interval, verdict, regression line or trend statistic computed in the Studio.
- A history series for detector precision or adherence; the micro-tier history; dollar trends.
- A product.json line, and the Reports landing page itself.
