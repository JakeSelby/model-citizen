## Story

As a harness maintainer, I want the six replay defects that leave the harness and bare arms unequal fixed, so that a replay result can test SM-2's hypothesis.

## Context and value

The 2026-09-24 review of the live replay found six defects, listed in FR-56's status, that leave the harness and bare arms unequal or a task unfair. Until they are fixed, no replay result can test SM-2's hypothesis.

Traces to FR-56. Sibling fixes: #428 and #482.

## Acceptance criteria

1. The benchmark docs and the task manifest agree on the task count, and a test fails when they diverge.
2. Each task's `max_turns` reaches the CLI in scored runs, and a test asserts it is in the launched command.
3. The stop gate can fire in a replay snapshot: the snapshot is trusted for its run, and a run that ends with a red gate records stop-hook feedback.
4. Both arms get identical web access, whatever the fence allows.
5. The usage-prices task is passable by an arm that follows its prompt, or it leaves the set with the reason recorded.
6. Runs are captured as `stream-json`, so hook events and per-turn usage are in the saved record.
7. Given a fake launcher, the unit tests cover each fix.

## Design

### Approach

Every fix lands in `scripts/cost_bench.py`, the one runner both arms go through, so each fix reaches
both arms by construction.

- **Task count (AC 1).** The docs state the count as digits (`# 7 tasks x 2 arms x 2 reps`, `2 of the
  7 tasks are synthetic`), and a test reads every such phrase in `docs/*.md` against the manifest.
- **Turn cap (AC 2).** `arm_command` takes `max_turns` and emits `--max-turns`; `run_one` passes the
  task's own value, and the pre-flight passes its fixed three through the same parameter.
- **Stop gate (AC 3).** `trusted_run` lists the resolved snapshot in `~/.config/agent-harness/trusted.txt`
  for the length of the launch, the file `harness trust` writes and every stop-gate hook since v0.4.0
  reads, then removes exactly that line through `atomic_write`. A file the run created is removed.
- **Web access (AC 4).** The fence settings every arm launches with carry
  `permissions.deny: ["WebFetch", "WebSearch"]`. The web tools run outside the command sandbox, so the
  empty network allowlist never reached them; a deny outranks the harness profile's allow rules.
- **Usage-prices (AC 5).** The task moves, whole and unedited, to a new top-level `retired` list in
  `benchmarks/tasks.json` with a date and its reason. `load_tasks` reads only `tasks`.
- **Stream capture (AC 6).** Runs launch with `--output-format stream-json --include-hook-events`.
  `cli_messages` reads either the stream or a single JSON document kept earlier; `stop_hook_counts`
  counts `hook_response` events for `Stop` and those that blocked, as the new `stop_hooks` field and
  the existing `hook_blocks` field.

### Decisions and alternatives

- **Deny the web to both arms rather than allow it to both.** The command fence is network-off, and a
  task set that needs the web would not be reproducible offline. Allowing both the harness profile's
  domains would tie the bare arm to one profile's list.
- **Retire usage-prices rather than rework it.** Its held-back tests pin the shipped rates and call
  helpers (`price_for`, `load_prices`, `row_cost`) the prompt never names, while the prompt forbids
  prices from memory. A prompt supplying both would hand the arm its check.
- **Trust through the harness's own trust file, not the CLI's state file.** `.claude.json` is a
  credential-named file the runner never writes, and an environment switch would need a hook change
  that pinned tags older than it would not carry.
- **Trust every arm's snapshot, not only the harness arm's.** The bare profile has no hook to read it,
  and treating both arms alike keeps the arms different by profile only.
- **The pre-flight stays untrusted.** It runs lint in three turns; a full gate there would spend its cap.
- **A turn-capped run stays an error,** as a budget-capped run already is (AD-12).
- **No text fallback for hook blocks.** Block reasons also appear in the prompt and files the agent reads.

### Do not implement

- No change to the stop-gate hook or `harness trust`.
- No change to the publish threshold, δ, or the verdict arithmetic; those are SM-2's.
- No new live result, and no history row.
- The sibling fixes #428 and #482 stay separate.

## Review findings

CodeRabbit, round 1, on PR #833:

- **Serialize trust-file updates** (major). Fixed: the append and the cleanup both hold an
  exclusive lock on the trust file's folder, so two replays cannot restore a root the other removed;
  a test overlaps two cleanups and fails without the lock. A lock shared with `harness trust` would
  change that command, which this story rules out; that race is part of the owner's open question on
  the PR.
- **Recognize a one-message stream** (minor). Answered, not changed: a lone JSON object reads the same
  whichever format wrote it, and a real `stream-json` run always opens with the `system` init message,
  so every stream the runner saves has at least two lines and is read as a stream.
