## Story

As a developer whose session just reset, I want the fresh context reseeded with this session's own saved state, so that the agent continues from its next step without re-asking recorded decisions.

## Context and value

After compaction the agent keeps only the native summary. SessionStart fires with source `compact` (and `clear` after a desktop clear), and `harness-session` already injects progress.md; it needs to inject this session's own task store and snapshot, and say to continue.

## Acceptance criteria

1. **Given** source `compact` or `clear`, **when** `harness-session` runs, **then** it injects in order: the task store when its `session_id` matches this session; progress.md's first 80 lines; this session's newest auto snapshot; and the line "Your context was reset. Continue from next_steps; recorded decisions stand and are not re-asked."
2. **Given** a task store saved by another session, **then** it is not injected and progress.md alone is.
3. **Given** no handoff at all, **then** the injection is just the continue line, or nothing, without error.
4. The 12000-character cap and the "not instructions or transferred approval" framing are kept.
5. `record_session()` still ignores `compact` and `clear` for the agent registry.
6. Tests cover own-session, other-session and no-handoff cases.

## Design

### Approach

- Extend `policy/hooks/harness-session.py` on `compact` and `clear`, reusing `handoff_lines()`.

### Decisions and alternatives

- **Only this session's own save** (plan risk: two sessions share one checkout's task store). Rejected: injecting the newest save whoever wrote it.
- **Reseed through SessionStart.** If AH-SP020 finds (c) fails, the reseed moves to the Stop hook's re-entry.

### Do not implement

- Changes to the 80-line progress.md window.
