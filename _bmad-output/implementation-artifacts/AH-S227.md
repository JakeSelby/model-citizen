## Story

As a maintainer paying for long interactive sessions, I want `harness usage --by rebuild` to find each
prompt-cache rebuild and name its cause, so that I can see where rebuild spend goes and judge whether a
change such as the cold-resume guard cut it.

## Context and value

Over the 30 days to 2026-09-23, rebuilds cost 20.1% of long-session spend: idle over an hour 10.7%, model
switches 3.6%, VS Code session reloads 2.3%, and a tail of about 3.5%
([#745](https://github.com/JakeSelby/agent-harness/issues/745)). Those figures came from one-off
investigation scripts, and nothing in `harness usage` reproduces them. `--by prefix` reports the ledger's
cache-miss ratio per session [Source: lib/harness_core/cache_prefix.py], which can say that a session
rebuilt, but not which call did or why.

The rest of the epic is judged by this report: the epic's exit reads its idle row, and the auto-compact
trial (AH-SP011) compares two windows with it.

## Acceptance criteria

1. **Given** transcripts in the window, **when** `harness usage --by rebuild` runs, **then** it prints one
   row per cause with breaks, rewritten tokens, share of spend and cost per break, for long sessions (200
   or more calls) and for all sessions.
2. **Given** a call whose cache read falls 20,000 or more tokens short of the previous call's input plus
   cache read plus cache write, **when** the report runs, **then** that call is a break, and a call with a
   smaller shortfall is not.
3. **Given** a fixture transcript per cause, **when** the report runs, **then** each break is attributed to
   that cause, in the order the Design sets.
4. **Given** a break on a model with one-hour and five-minute write prices, **when** its excess is priced,
   **then** each tier is priced at its own rate through `policy/hooks/pricing.py`, and a model missing
   from the table is reported as unpriced, never at $0.
5. **Given** a transcript reachable through two paths, or lines older than the window, **when** the report
   runs, **then** the file is read once, and only calls stamped inside the window count.
6. **Given** the same window run through the 2026-09-23 investigation's scripts, **when** both run,
   **then** every cause's share agrees within one percentage point.

## Design

### Approach

A new module, `lib/harness_core/rebuilds.py`, ports the investigation's method, wired beside
`--by prefix`:

- **Input:** main-session transcripts under the Claude Code projects directory. Each file is read once per
  real path, because two project directories can be one store, and each line is kept or dropped by its
  own timestamp. Sidechain entries are skipped.
- **Calls:** one per API request, keyed by `requestId` or else the message id, because Claude Code writes
  one entry per content block, each repeating the request's usage. One-hour writes come from the usage's
  `cache_creation.ephemeral_1h_input_tokens`; five-minute writes are the rest of
  `cache_creation_input_tokens`.
- **Break:** the previous call sent input plus cache read plus cache write tokens; a call is a break when
  its cache read falls 20,000 or more tokens short of that. The tokens rewritten are the shortfall, capped
  at the call's own cache write. The excess is the tokens rewritten times the call's write price,
  weighted by its tier split, minus the read price.
- **Attribution, first match wins:**
  1. a model switch, split into after a `/model` command and without one;
  2. compaction, a compact summary or boundary;
  3. a gap of an hour or more since the previous call;
  4. a Claude Code version change;
  5. a gap of five minutes or more when most of the call's writes were five-minute entries;
  6. an event recorded between the two calls: a system-prompt snapshot, output-style instructions, a
     tool, agent or skill list change, instructions or environment reloaded, a date change, the session
     reload marker (`mode`), an effort change, plan mode, an auto-mode or permission change, an API error,
     or a remote session change;
  7. any other slash command;
  8. a gap of 5 to 60 minutes with no event;
  9. unexplained.
- **Output:** the table of AC 1, through the same output path as the other `--by` reports, with `--days`
  as the window, 30 by default.

### Decisions and alternatives

- **Read transcripts, not the ledger.** The ledger keeps one row per session
  [Source: policy/hooks/usage-log.py], and a break is a property of two consecutive calls.
  `cache_prefix.py` stays: it answers how much of a session missed, from the ledger; this module answers
  which call rebuilt and why, from transcripts. Each module's docstring says so. Rejected: storing
  per-call rows in the ledger, which would grow the system of record for a diagnostic (AD-11).
- **One pricing authority.** Price through `policy/hooks/pricing.py` and `policy/prices.json`, never a
  second table [Source: docs/usage.md]. Rejected: porting the investigation's own price model.
- **Keep the investigation's threshold and order unchanged,** so that AC 6 compares like with like.
  Tuning either is a later change, with this report as its evidence.
- **Pinned internals.** Causes 1, 6 and 7 read transcript entries Claude Code writes but does not
  document. Under AD-17 the report's documentation names the client versions its fixtures came from, and
  a cause whose marker disappears reads as unexplained, not as zero.
  `[ASSUMPTION: a note in the docs is enough of a pin until the doctor check planned under #636 lands]`

### Do not implement

- The cold-resume guard (AH-S229) or any change to the usage feed.
- Subagent and role-worker transcripts; this version reads main sessions only.
- Codex sessions: OpenAI prices no cache write [Source: policy/prices.json], so a rebuild there has no
  write excess to attribute.
- Dollar thresholds or alerts.
