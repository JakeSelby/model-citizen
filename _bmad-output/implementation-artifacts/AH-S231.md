## Story

As the maintainer of agent-harness, I want CodeRabbit to review every pull request into `main` and
`/build` to clear its threads before I approve, so that each pull request gets a second reviewer and
`/land` never meets a thread block by surprise.

## Context and value

CodeRabbit is free for public repositories, and on BMAD-METHOD#2957 it caught a real bug in a small
prose change. The `main-review` ruleset sets `required_review_thread_resolution: true`, and `/land`
merges with a plain `gh pr merge --squash --delete-branch`, which refuses a blocked merge unless
given `--admin`. `/land` never reads threads, so without this change the first bot comment would
only surface when `gh pr merge` refuses. Outside contributors also need to know the loop, because
`main` won't merge their PR while a review thread is open.

## Acceptance criteria

1. **Given** `.coderabbit.yaml`, **when** it is validated against
   `https://coderabbit.ai/integrations/schema.v2.json`, **then** it has 0 schema errors and 0 keys
   missing from the schema.
2. **Given** `/build`, **when** it has opened a pull request in a repository that runs a review
   bot, **then** step 6 waits up to ten minutes, fixes or answers each unresolved bot thread,
   resolves it, asks for one more review after a fix, stops after two rounds, and never resolves
   a human's thread.
3. **Given** `/land`, **when** the pull request has an unresolved review thread, **then** step 1
   names it and stops.
4. **Given** `CONTRIBUTING.md`, **when** an outside contributor reads `## Review`, **then** it tells
   them how to work with CodeRabbit's comments and how to ask for another pass.
5. **Given** the change, **when** the gate runs, **then** `bin/harness lint`, the unit tests and
   `bin/harness generate --check` pass.
6. **Given** the app is installed, **when** a pull request into `main` opens, **then** CodeRabbit
   reviews it.

## Design

### Approach

A schema-validated `.coderabbit.yaml`: the chill profile, one review per pull request into `main`,
no summary written into the PR description, prose linters off, path instructions for
agent-executed prose and the Python 3.9 floor, and generated projections and planning records
excluded. `/build` gains step 6, which answers the bot's threads (fix and push, or reply, then
resolve) before a pull request goes up for approval, and its report line names the bot threads
answered and any still open. `/land` step 1 stops on an unresolved review thread, by name.
`CONTRIBUTING.md` gains a paragraph on working with the bot.

```text
/build ── PR ──▶ GitHub ── PR opened ──▶ *CodeRabbit (.coderabbit.yaml)
                                               │
                                        review threads
                                               ▼
*/build step 6 ◀┄┄ waits up to 10 min ┄┄ unresolved threads
     │ fix and push, or reply; then resolve
     ▼
you approve ──▶ */land step 1: no open thread ──▶ squash merge
```

### Decisions and alternatives

- **No automatic re-review after a fix is pushed**, as BMad has it (`auto_incremental_review:
  false`). A contributor still gets a full review when the PR opens, asks for another with
  `@coderabbitai review`, and uses their own rate budget. The alternative, automatic re-review,
  confirms each fix unasked but roughly doubles review volume at about 35 PRs a day.
- **Fixes happen in `/build`, before approval, in one PR** with the config. `/land` only checks;
  a human's thread is theirs to resolve.
- **Two rounds at most** in step 6; whatever remains is reported rather than looped on.
- **`/build` asks for one re-review after pushing a fix**, so step 6's second round has a review
  to answer. Automatic re-review stays off, so contributors' pushes cost nothing extra.
- **Step 6 answers threads only.** Findings CodeRabbit leaves in the review body, such as
  outside-diff-range comments, are not read, because only threads block a merge; revisit with the
  hit-rate measurement.
- **CodeRabbit never commits to the branch on its own.** Unit-test generation, the CI fixer and
  the merge-conflict resolver are off: `/build` pushes to the branch, a bot commit there rejects
  its next push, and the issue map's conflicts need their own recipe. Docstrings and autofix stay
  available, because they run only when someone asks.
- **Greptile deferred.** It is free only through an open-source programme that requires attesting
  the repo is not part of a commercial product, and one bot is enough to start.

### Do not implement

- Greptile, any change to the `main-review` ruleset, CodeRabbit as a required check, landing copy
  or `product.json`.
- A `.coderabbit.yaml` in `templates/repo/`; wait until this one has run for a couple of weeks.
- Codex automatic review as a second reviewer; reconsider after measuring CodeRabbit's hit rate.
