## Story

As a developer, I want forms for my identity, preferences and integrations, so that I configure them correctly without learning the config format.

## Context and value

Forms for the rest of the user config (identity, permissions, governance, `primitive_roots`, telemetry and integrations), generated from one description of the keys (type, allowed values, help text), which this story adds where the validator has none, so a new key needs no UI change. Integration descriptors are validated as `citizen integrations doctor` validates them, and secret fields are write-only.

## Acceptance criteria

1. Given a key added to the key description, then the form shows it with its type and help text, with no UI change.
2. Given an invalid value, then the form shows the validator's message and saves nothing.
3. Given a secret or a header source, then the form never displays its value and saves a reference, not the secret.
4. Given the telemetry block, then the form states what native export sends, as `docs/telemetry.md` does, before export is turned on.

## Design

### Approach

Add a provider-neutral settings module beside the draft core. Its field descriptor is the single
form authority: each field carries its path, section, type, default, constraints, options, help and
provenance. The private Studio routes return that descriptor and a redacted draft view; preview and
save accept path-keyed changes, validate them through the same primitive-root, telemetry, governance
and integration contracts the CLI uses, and save only through the draft checkpoint transaction.
The route submits that checkpoint to the server's single domain-mutation executor; request threads
perform validation reads but never write draft state directly.
Thin `citizen draft settings schema|read|preview|save` adapters call those same core functions and
emit the same result DTOs. The descriptor supplies their exact command templates to both the route
registry and browser, so Configure displays the headless equivalent of every domain action.

The React Configure route renders every section and field generically from the descriptor. It loads
an explicitly named draft, tracks only changed fields, presents validation and unavailable states,
and after 750 ms of quiet requires a successful preview before it checkpoints. Header sources use
`{source, name}` in transport and form state, then persist only the existing environment-variable name
or file path; clearing the name removes the reference. No secret value is accepted, resolved or returned.

### Decisions and alternatives

- **One descriptor, generic renderer:** The server owns field meaning and the browser renders by
  `kind`; per-field React components were rejected because every added key would need two changes.
- **Existing validators own block semantics:** Primitive roots, telemetry settings, JEV controls and
  integration descriptors are validated by their shipped modules. A second Studio-only config
  validator was rejected because it would drift from `citizen sync` and `citizen integrations doctor`.
  Available integration adapters also run the same bounded `describe` health invocation as doctor.
- **References, never credential inputs:** Header fields accept a source plus reference name and
  persist the existing config reference. Password inputs and server-side resolution were rejected.
- **Debounced preview before checkpoint:** Structured changes preview and checkpoint after the AD-29
  750 ms quiet period. A save repeats validation and uses the draft revision plus a fresh idempotency
  key; edits made during an in-flight save remain queued. Failed saves retain the full change set and
  expose an explicit retry. Direct writes, manual form-save cadence and live-config edits were rejected.
- **Loaded draft owns pending edits:** Autosave uses the normalized identity returned by draft read,
  not the editable loader input. Switching pending changes to another draft requires an explicit load.
- **Explicit partial availability:** Missing drafts, invalid blocks and unavailable integration
  executables remain visible states; the UI does not imply a working adapter from valid syntax alone.
- **One mutation executor:** Read, preview and save routes wait on the server's serial executor because
  draft reads may recover an interrupted transaction. Request-thread mutation was rejected by AD-26.
- **One core and command map:** CLI and HTTP adapters return the shared core payload, including missing
  or stale draft states; only malformed transport input uses a transport error envelope. Domain routes
  carry no parity exemption, and the browser renders the descriptor's exact `citizen` commands.

### Do not implement

Stance or module selection editing (#974), the CodeMirror module editor (#976), draft creation and
apply/rollback flows, direct live-configuration writes, credential storage or resolution, integration
registration, and live-update subscriptions (#972).

### Testing

`tests/test_studio_settings.py` proves complete descriptor metadata, telemetry disclosure, registered
security-bound routes, exact CLI/HTTP payload parity and JSON transport errors, field and dependency
refusals before checkpoint, finite JSON, primitive-root resolution, reference-only header saves,
redaction of malformed existing references, integration `describe` health without response leakage,
fail-closed validation of persisted reference syntax, safe reference removal, preservation of unknown
config and draft-transaction delegation. Table-driven cases prove every required or present modeled
field is validated, including falsy malformed references. It also proves
recovery-capable reads serialize with saves, error propagation and closed or recursive executor refusal.
`studio/tests/configure.test.ts` proves new descriptor fields flow into the form model without route
code, defaults/current values hydrate consistently, validation errors bind to paths, JSON-object
fields reject arrays and scalars, the debounce is 750 ms and edits made during a save survive it. The
frontend lint, typecheck, tests, production build and bundle
manifest verifier cover the shipped browser artifact; the repository Gate covers integration.
`tests/test_studio_configure_browser.py` renders the production bundle in headless Chrome, proves the
first preview starts only after the 750 ms quiet period, holds the first save in flight, edits another
field, and proves that queued edit receives its own preview and checkpoint after the first completes.
It also forces a save failure, verifies preview alone did not clear pending state, confirms an edit to
the loader cannot retarget those changes, and retries the complete queued change set successfully.
The rendered malformed-reference state provides a one-click Clear repair and proves it checkpoints
the removal without revealing or requiring a dummy reference value.

## Review findings

- Hosted Linux qualification exposed a scheduling gap when an edit arrived during an in-flight
  checkpoint: React could render the remaining edit before the ref lock was released and never wake
  the autosave effect again. The successful-save path now releases the lock before batching the
  remaining changes and advances the existing save nonce to schedule the queued checkpoint.
