# AH-B118 — citizen config cannot unset workspaces_dir, so workspaces cannot be switched off from the CLI

## Reproduction

1. `citizen config set workspaces_dir ~/path/to/workspaces`, then `citizen sync`.
2. Try to switch the feature off: `citizen config set workspaces_dir ""` is refused with
   "workspaces_dir must be an absolute directory path", and `citizen config` offers only `get`
   and `set`.
3. Observed: the only way off is a hand edit of the user config, which the workspace page named
   only in passing. Found by the v0.14.0 exploratory check E14, step "Unset `workspaces_dir`".

## Root cause

`cmd_config` in `bin/harness` had no removal action, and `coerce_config_value` rightly refuses an
empty `workspaces_dir`, since an empty path is not a folder. The documented off state, the key
absent, therefore had no command that reached it.

## Acceptance criteria

1. **Given** `workspaces_dir` set, **when** `citizen config unset workspaces_dir` runs, **then**
   the key is gone from the user config, and `citizen workspace list` says how to set it and
   exits 1.
2. **Given** that unset, **when** `sync` runs, **then** it puts
   `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` back as the journal records, and a new
   session's start-up output carries no workspace block.
3. `docs/workspaces.md` names the command, with a test for each step above.
4. **Given** any key whose `config set` runs a check (a switch, an acknowledgement, a governance,
   stance, mode or integration key), **when** `config unset` names it, **then** it is refused and
   the config is unchanged.

## Design

A new `citizen config unset KEY` action removes one key from the user config under the same lock,
symlink refusal and atomic write as `config set`. It accepts only the keys in `UNSET_KEYS`, today
`workspaces_dir`: an optional key whose absence is a documented state. Everything else is refused
with a pointer to `config set`, so an unset can never skip the resolution `config set` runs on
core switches, acknowledgements and governance keys. Unsetting an absent key says so and exits 0.

Default taken: a dedicated `config unset` action with an allowlist, because `config` had no
precedent for optional keys and a general unset would bypass every check `config set` enforces.
Rejected: accepting `config set workspaces_dir ""` as removal, since an empty shell variable would
then switch the feature off silently and the refusal of an empty path is itself correct.

Must not change: `config set` validation, `sync`'s journal-driven restore of the settings key, and
the session hook, which already stay silent with the key absent.

## Regression test

`tests/test_workspace_unset.py`: `UnsetCommand` (criterion 1), `SwitchedOff` (criterion 2, a real
`sync` round trip and the Claude Code SessionStart adapter as a subprocess), `Documented`
(criterion 3), and `Guard` (criterion 4). Each fails before the fix, where `unset` is not a
`config` action.
