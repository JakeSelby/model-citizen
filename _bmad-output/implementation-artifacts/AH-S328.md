## Story

As a developer, I want to report field and Codex evaluation evidence in Studio, so that the Studio supports the engines delivered in its milestone.

## Context and value

Deliver the Studio reporting changes for v0.18.0 Real work, including Codex evaluation and affected telemetry/context controls. The field and telemetry engines own assignment, ingestion and analysis; this story owns their Studio integration.

## Acceptance criteria

1. Field reports preserve assignment and intention-to-treat outcomes, including failed/deferred attempts, with sample-ratio, novelty and other engine-provided diagnostics and limitations.
2. Codex results retain runtime/model/task/design provenance; incompatible comparisons are refused rather than pooled across runtimes.
3. Telemetry retention/availability, recorded mid-run spend and cache/context measurements use the core ledger/control semantics, preserving unknown, failed and partial states.
4. Every changed control or report has a citizen equivalent and CLI/UI fixture parity; unchanged existing views have explicit compatibility evidence.
5. Factorial launch belongs to the split #989 story; stance proposal actions remain #996 with #692. This story does not duplicate either workflow.

## Design

### Approach

Adapt the existing Studio core and CLI contracts after the listed engine dependencies land. Preserve native result files as authority, keep UI actions on the same governed path as the CLI, and record capability availability explicitly. Detailed file-level design belongs to the future implementation session.

### Decisions and alternatives

Deliver this integration in the engine's milestone rather than postponing it to an unspecified UI release. Keep feature ownership separate from the cross-cutting post-Measured integration gate.

### Do not implement

Do not duplicate engine analysis or change live configuration outside governed apply. This roadmap filing does not implement the capability or authorize a release.
