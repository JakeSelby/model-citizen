## Story

As a developer, I want my spend by day, model, role and repository from the local ledger, so that I manage cost without an external backend.

## Context and value

Spend by day, model, role, repository and session from the usage ledger through `citizen usage --json` (#909), with subagent spend and cache-rebuild attribution by cause (#748), and every figure labelled as a list-price equivalent. It reads the local ledger only; OTLP export stays as it is.

## Acceptance criteria

1. Given the ledger, then the totals equal `citizen usage --json` for the same window.
2. Given any figure, then it carries the list-price label and the pricing date.
3. Given a ledger holding a year of sessions, then the page loads in under a second.

## Design

### Approach

The Studio runs `citizen usage --json --by <grouping> --days <window>` in a child process and
returns the document unchanged inside an envelope that names the command and the pricing basis.
`POST /api/reports/spend` takes `{by, days}`; `by` is `day`, `model`, `role`, `repo`, `session` or
`rebuild`. The CLI gains `--by session` and, on every priced JSON report, `cost_basis` and
`price_as_of`, so the label and the pricing date come from the ledger's own computation. The page
renders the ledger's groups and its `totals` row; every dollar cell carries the label and date.

### Decisions and alternatives

1. **A child process per report, not an in-process import of `bin/harness`.** It is literally the
   CLI command the page shows, it takes no Studio lock, and a year-sized ledger answers in about
   0.5 s. Importing the CLI module was rejected: its module-level state is not built for a
   long-lived threaded server.
2. **`--by session` was added to the CLI** rather than grouped in the Studio, because the Studio
   computes no total the ledger owns. Codex subagent rows already carry the parent thread as
   `session_id`, so a Codex session groups with its children.
3. **The pricing date is `newest_as_of` of the table that priced the report**, the date `doctor`
   ages, rather than a per-row date, which would put one date on each cell of a group.
4. **Cache-rebuild attribution is on demand.** It scans transcripts on every call (seconds for a
   week), so it is a grouping the developer selects, outside the one-second page budget.
5. **Role spend is shown as the role report's percentiles.** That report carries no per-role
   dollar total, and the Studio does not sum one.

### Do not implement

- No OTLP export, no `--rescan`, no write to the ledger.
- No per-role dollar total, no new price table, no Studio-side aggregation or caching index.
- No product.json line.
