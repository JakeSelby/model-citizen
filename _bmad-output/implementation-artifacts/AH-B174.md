## Reproduction

Run `cost_bench.py detect --raw` over the #1144 pilot streams and read the all-rules-at-once
rate (#1186): the harness arm scores 0.057 (2 clean of 35) against 0.571 for bare, and
`voice/scaffold-leak` fires on 30 of the 35 harness runs. The calibration streams show the same:
21 of 21 harness runs hit, rate 0.000.

## Root cause

`replay_detect.ungated` lifts every detector's stance gate so the bare arm is scored too, and
nothing put the gate back per run. `voice/scaffold-leak` and `voice/heading-first` are gated on
the `concise` voice, but the harness arm runs the default `scannable` voice, which asks for the
section labels the detector counts, so the style working as intended scored as a violation.
[Source: scripts/replay_detect.py#ungated, policy/hooks/rule-detectors.py#_REGISTRY]

## Acceptance criteria

1. **Given** a run whose arm selected the concise voice, **when** it is detected, **then**
   `voice/scaffold-leak` is scored with a count.
2. **Given** a harness-arm run on the default `scannable` voice, **when** it is detected,
   **then** `voice/scaffold-leak` is a `not_applicable` row with no count.
3. **Given** a bare-arm run, **when** it is detected, **then** every stance-gated detector is
   `not_applicable` and every ungated detector is scored.
4. **Given** detections holding `not_applicable` rows, **when** the all-rules-at-once rate is
   computed, **then** those rows are neither a hit, clean nor unknown, and a run with only such
   rows is unknown.
5. **Given** an arm whose selection no row records, **when** it is detected, **then** its gated
   detectors are unknown, never guessed.

## Design

A detector's existing gate is its applicability declaration; no second declaration is added.
Detection still runs the ungated registry over the stream, then each row is marked by
`replay_detect.applicability` against the run's stances: ungated always applies, a gated
detector never applies to an empty selection, and otherwise applies as its gate reads the
stances. The replay resolves each arm's stances over the tag's checkout with
`posture.selection` (its session variables and declared selection, an empty home); the offline
`detect` reads the row's `arm_config`, a pair row's `selection`, or the checkout's defaults for
the harness arm. A not-applicable row keeps `count` null so an older reader sees unknown, never
clean. Rejected: a new per-detector field, which would duplicate the gate the live hook already
reads. Must not change: the live hook's gating and `summarise`.

## Regression test

`tests/test_detector_applicability.py` covers the applicable, inapplicable and bare runs, the
pair selection, an unrecorded selection and the joint rate; on the old code the harness run's
`voice/scaffold-leak` row carried a count and the run was a hit.
