## Goal

After the GitHub repository rename, point every hardcoded link at `JakeSelby/model-citizen` and
https://model-citizen.dev, and add a `retired-name` lint rule so the old brand, slug and site host cannot
creep back into living files. This is PR D of the approved rename plan, the first pull request after the
rename, and it precedes the About update and the v0.14.0 tag.

## Acceptance criteria

1. Every living hardcoded use of the old slug points at `JakeSelby/model-citizen`: the release notes script,
   the issue sync tool's repository constant, the installer, the issue template config, README,
   CONTRIBUTING, the install doc, the plugin manifest tests, and the plugin and marketplace `homepage` and
   `repository`.
2. Every living use of the old site host points at https://model-citizen.dev: README, `docs/releasing.md`
   and the plugin manifest.
3. `product.json` gains `"homepage": "https://model-citizen.dev"` and swaps the `coding-agent` topic for
   `model-citizen`, within the 20-topic cap; `tests/fixtures/gh/repo-view.json` follows.
4. `_bmad-output/issue-map.json` keeps the old slug.
5. A `retired-name` lint rule fails on "Agent Harness", the old slug and the old site host outside an
   allowlist of the dated areas, the on-disk names and the "Formerly" lines, with a test.
6. CodeRabbit still posts a completed pass on this pull request.

## Dev notes

- **Why the issue map keeps the old slug:** `planning_block` in `scripts/bmad_issue_sync.py` writes it into
  every mapped issue's body, so changing it would rewrite about 160 issues. GitHub redirects the old URLs.
- **The About homepage** is supported by `scripts/sync_about.py`; applying it is the maintainer's separate
  step, followed by `python3 scripts/sync_about.py --check`.
- **The allowlist** covers dated areas (`_bmad-output/`, `docs/plans/`, the changelog, compatibility
  evidence), on-disk names (AD-24's keep list) and the "Formerly" lines. The lint must stay clean on this
  checkout.
- **Bound by** AD-24 and AD-19; FR-53.
- **Line numbers** in the plan were taken at `a9968d9` and may have drifted; re-find each by its text.
- **Scope decided by the owner on 2026-09-26** in the v0.14.0 finish run's brief for this issue: the
  living files above, `product.json` and its fixture, the `bootstrap --repo` default, and the lint
  rule. PR #906 owns `API_REPOSITORY` and the API call sites in `scripts/bmad_issue_sync.py`.
- **The rule** lives in `lib/harness_core/retired_names.py` and runs inside `lint_files`, so the
  pre-commit path (`lint --staged`) applies it too. It binds only this repository, by the same
  `primitives/roles` guard the changelog fragment rule uses, so `citizen lint PATH` on another
  repository is not held to this project's rename. The brand is matched as written, since "an agent
  harness" is an ordinary phrase; the slug (also URL-encoded) and host are case-insensitive. The slug
  pattern refuses a longer name, so a sibling repository's slug is not caught.
- **The allowlist** is path prefixes with reasons (`_bmad-output/`, `docs/plans/`, `.agent-harness/`,
  `compatibility/evidence/`, the `tests/test_bmad_` fixtures that mirror the issue
  map's stored slug), any file named for its date, the changelog's released sections (headed by a
  version or a date, so `## [Unreleased]` stays linted), and lines opening with "Formerly". On-disk names
  need no entry: every pattern needs the owner prefix, the old site domain or the capitalised brand.
- **Plugin tests** that model an install recorded before the rename keep the old slug, assembled at
  run time as `OLD_REPOSITORY`, the convention `tests/test_harness.py` uses for lint-tripping
  fixtures. The migration steps in `docs/runtime-installation.md` now add the marketplace from the
  new slug; `citizen upgrade` still re-adds from whatever source an install recorded.
- **`tests/fixtures/gh/repo-view.json`** is hand-edited to the About panel `product.json` now asks
  for; regenerate it with `gh repo view --json description,repositoryTopics,homepageUrl` after the
  maintainer runs `scripts/sync_about.py --apply`.

  item 2.
