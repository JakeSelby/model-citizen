## Story

As the harness maintainer, I want the first four-arm live set committed with its summary and history
rows, so that the `superpowers` mode and the harness have a measured status, pass or fail, instead of an
unqualified one.

## Context and value

This is the measurement epic #552 builds toward: bare, superpowers, harness, and harness plus
superpowers [Source: #552]. It supersedes #369, the first two-arm live set. The live tier's only uncontaminated result
so far is 1.052 of bare on a four-task set, which failed the 0.85 publish bar, so no cost claim is
published and no saving has been measured. This set produces the next result in whichever direction it
falls.
[Source: https://github.com/JakeSelby/agent-harness/issues/560]
[Source: docs/benchmarks.md#Live replay]

## Acceptance criteria

1. **Given** 4 tasks, 4 arms and 2 reps, **when** the set runs, **then** `results.jsonl` holds 32 rows
   with errors counted apart from failures.
2. **Given** the summary, **when** it is read, **then** it states the model, both CLI versions, the
   superpowers version, the machine, and what was faked: single-shot prompts, the no-user preamble, two
   synthetic tasks, one superpowers version, Claude Code only.
3. **Given** the result, **when** it is judged, **then** the harness arm is judged against the existing
   threshold and the superpowers pair is reported without one.
4. **Given** the result, **when** `docs/modes.md` is updated, **then** `superpowers` flips from
   `unqualified` to its measured status.
5. **Given** a stalled superpowers run, **when** the set is scored, **then** it is an error reported as a
   finding, never hidden.

## Design

### Approach

Run 4 tasks by 4 arms by 2 reps under the `sandbox` skill with `--spend-cap`. Commit
`benchmarks/<version>/summary.md`, one `history.jsonl` row per arm as a ratio to bare plus the
harness-plus-superpowers over superpowers ratio, and re-render `history.md`.

### Decisions and alternatives

- **Only the harness arm faces the threshold;** the superpowers pair is reported without one.
- **A stall is an error, not a failure**, consistent with the runner's existing rule for errored runs.

### Do not implement

Not recorded in the issue or pull request. #369, which this supersedes, excluded runner changes,
published copy and the hero.
