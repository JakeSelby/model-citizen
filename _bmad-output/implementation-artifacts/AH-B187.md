## Reproduction

`python3 -c` over `policy/prices.json` on main at 758ab772: `claude-sonnet-5-5` has `cache_read: 0.2`, and `claude-haiku-5-5` has no entry, so `pricing.price_for(table, "claude-haiku-5-5")` returns None and every Haiku 5.5 row is unpriced. The pricing page (https://platform.claude.com/docs/en/about-claude/pricing, read 2026-10-12) lists Sonnet 5.5 cache hits at $0.10/MTok and Haiku 5.5 at $0.10/$0.125/$0.20/$0.01/$0.50 up to 100,000 prompt tokens, $0.50/$0.625/$1/$0.05/$2.50 above.

## Root cause

The Sonnet 5.5 entry was written on 2026-10-03 by analogy with Sonnet 5's 0.1x cache hit; the page prices Opus 5.5 and Sonnet 5.5 hits at 0.05x base input. Haiku 5.5 was left out, and the table had no way to express a price that depends on prompt length, so adding its base rate alone would have under-charged long-prompt sessions. [Source: policy/prices.json#_limitations]

## Acceptance criteria

1. **Given** the shipped table, **when** Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5 are read, **then** every rate equals the pricing page's, with its source URL.
2. **Given** a Haiku 5.5 per-model part whose largest prompt is at most 100,000 tokens, **when** it is priced, **then** it is charged at the base tier; **given** a larger or unrecorded largest prompt, **then** the row is unpriced.
3. **Given** a single request (a first turn, an ablation turn envelope) on Haiku 5.5, **when** it is priced, **then** it takes the tier of its own prompt.
4. **Given** a figure that cannot see the prompt (the static layer figure, the layer scorecard), **when** it would price Haiku 5.5, **then** the model is left unpriced.
5. No reader hard-codes a rate; `benchmarks/static.json` is regenerated from the corrected table.

## Design

`long_context` block on a price entry: `over_prompt_tokens` plus the six rates. `pricing.usable_rate` parses it (a malformed block makes the entry unusable) and `pricing.prompt_rate(rate, prompt, many)` picks the tier: one request takes the tier its prompt falls in; with `many`, `prompt` is the largest of several, so only at or under the threshold is the figure known. `usage-log.by_model` records `max_prompt` per part (input + cache reads + cache writes, as the page counts a prompt). `cost_bench` and `ablations` load `pricing.py` once and apply `prompt_rate`; the static figure excludes tiered models. Rejected: base rate only, which under-charges silently, the failure the table's own notes forbid; splitting each part into per-tier token sums, which needs the threshold inside the hook and is more than this fix needs.

## Regression test

`tests/test_prices_prompt_tier.py` pins the Claude 5 rates and the Haiku 5.5 tier against the page and covers the tier in `row_cost`, `normalised_cost`, `ablations.turn_cost` and the layer scorecard; `tests/test_prices_cover_streams.py` now expects Sonnet 5.5 at 0.1 and Haiku 5.5; `tests/test_usage_prices.py` covers `max_prompt`.

## Review findings

Fresh-context reviewer, 2026-10-12:
1. `rebuilds._call_cost`/`_break_cost`, `soft_estimates.reprice` and `evidence_bundle._token_cost` priced through `price_for` with no prompt size, so Haiku 5.5 took the base tier. Fixed: each call takes its own prompt's tier; an arm row (a whole run) is unpriced.
2. `cost_bench` first-turn prompt read a missing field as 0. Fixed: unknown when any field is absent.
3. A config override of one `long_context` rate replaced the whole block. Fixed: the tier merges field by field.
4. Tests for all of the above, and a Sonnet 5.5 positive control beside the unpriced flat Haiku row.

CodeRabbit, PR #1308:
1. A usage record omitting a prompt field was read as 0, giving `max_prompt` 0 and the base tier. Fixed: a message's prompt is known only when a record reports all three fields; otherwise its part carries no `max_prompt` and a tiered model is unpriced.
