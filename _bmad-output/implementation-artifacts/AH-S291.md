## Story

As a developer, I want to change my mode, stances and switches with previews and the CLI's own checks, so that I tune behaviour without hand-editing JSON or breaking a dependency.

## Context and value

Pick a mode, choose a variant for each stance, and switch rules, hooks, skills, workflows and roles on or off, in a draft. Each stance variant shows its operative lines, and each change previews the projected text before and after. The checks `config_set` runs through `load_selection` (switch dependencies and core hooks) run on every change before it is saved.

## Acceptance criteria

1. Given a switch whose dependency is off, when it is turned on, then the Studio shows the refusal `citizen config set` would give and saves nothing.
2. Given a core hook turned off, then the Studio asks for the same explicit acknowledgement as the CLI.
3. Given a variant change, then the preview shows the always-loaded budget before and after.
4. The saved draft config equals what the matching `citizen config set` commands would write, in tests.

## Design

### Approach

Add one selection-editing service beside the read-only selection report. It loads a draft's private
configuration, applies requested mode, stance and switch changes by executing the checkout's own
`citizen config set` command in a disposable home, then resolves the candidate through the shared
selection kernel. Preview and save use the same candidate builder; save checkpoints only the private
draft configuration through the existing revisioned, idempotent draft transaction.

Configure renders a draft-only selection editor after a draft is loaded. Its controls come from a
backend catalog of installed modes, stance variants and switch units. Each debounced edit shows the
effective selection and always-loaded budget before and after, including stance operative text, and
is checkpointed only when validation succeeds. Core-hook acknowledgement is an explicit checkbox
that is offered after the CLI refusal and travels in the same checked checkpoint.

### Decisions and alternatives

- CLI parity is proved by invoking the real `config set` implementation against an isolated
  `HARNESS_HOME`; duplicating switch dependency and core-hook rules in Studio was rejected.
- The API accepts a path-keyed change object (`mode`, `stances.<name>`, switch paths and
  `core_switches_acknowledged`) and rejects every other key before invoking the CLI.
- Preview returns bounded projected evidence: selected stance source text and the exact
  always-loaded selected-line budget before and after. Returning arbitrary projected files or
  source paths was rejected because this surface edits selection, not module content.
- Autosave keeps the existing 750 ms cadence and optimistic draft revision. A refused change keeps
  the user's controls populated and writes no checkpoint. Exact retries preserve their original
  idempotency key, and response generations from an earlier draft cannot update the loaded draft.
- Candidate configuration is compared to the persisted draft before saving. A no-op, including an
  edit reverted before debounce, reports unchanged and does not create or advance a checkpoint.

### Do not implement

- Live configuration or projection writes, applying a draft, and rollback.
- General settings fields, module text editing, module creation or forking.
- Project and session layer editing; this story changes the draft's user-selection document only.

### Completion notes

Implemented draft-only mode, stance and switch editing by running the public `config set` path in a
disposable home before every preview or checkpoint. Configure now loads installed choices, debounces
edits at 750 ms, preserves refused input, offers the exact core-hook acknowledgement, shows matching
CLI commands, and keeps before/after effective-selection, stance-text and budget evidence visible.

byte-identical. It also covers stale preview/save suppression across draft switches, optimistic
revision failure, durable lost-response recovery with the original request identity, no-op/reverted
edits, explicit keyboard retry and keyboard focus/activation across the selection controls.
