## Reproduction

Run `CompatibilityTests.test_qualified_claim_without_native_evidence_is_rejected` while the live
released compatibility catalog declares `qualification_reuse`. The test copies that catalog,
changes it into a candidate, and removes `qualification_source_commit`, but retained reuse metadata
causes catalog validation to stop on reuse provenance before checking the qualified client's missing
acceptance evidence.

## Root cause

The candidate fixture was derived from mutable live release metadata and cleared only one of the two
release-qualification fields. `compatibility.catalog()` validates `qualification_reuse` before
native evidence, so the retained field changed which invariant the test exercised.

## Acceptance criteria

1. **Given** a live released catalog with or without qualification-reuse metadata, **when** the test
   constructs its unrelated candidate fixture, **then** it removes both `qualification_source_commit`
   and `qualification_reuse`.
2. **Given** that independent candidate fixture with a qualified client and no native evidence,
   **when** catalog validation runs, **then** the test still asserts the missing-acceptance-evidence
   failure.

## Design

Clear `qualification_reuse` next to `qualification_source_commit` in the existing fixture. Keep the
existing assertion and production validation unchanged. A new helper or production-code exception
would broaden a test-isolation fix and is rejected.

## Regression test

`CompatibilityTests.test_qualified_claim_without_native_evidence_is_rejected` remains the regression
test. It now constructs only the candidate state required to reach its original `missing acceptance`
assertion, independent of future live release reuse metadata.
