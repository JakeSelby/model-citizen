## Story

As the repository owner, I want a Claude lane that fixes an owner-labelled bug in its randomly assigned
arm and opens one pull request, so that bugs get fixed while my machine sleeps and each fix is a trial
of the harness against bare Claude Code.

## Context and value

The Claude lane runs claude-code-action in GitHub Actions on the subscription token, so it costs
nothing new; the OAuth token path is documented for Pro and Max
[Source: https://github.com/anthropics/claude-code-action]. Randomising harness against bare within the
lane from day one makes every fix a real-work trial for #803. The lane builds on the benchmark hygiene
(#944), the App and owner gate (#945), the budget (#946) and the study record (#947). Traces to FR-71
and FR-74 ([#948](https://github.com/JakeSelby/model-citizen/issues/948)).

## Acceptance criteria

1. **Given** a bug labelled `bot::ready` by the owner, mapped in `issue-map.json` on `main` and drawn
   for the Claude lane, **then** the scheduled run claims it with `bot::claimed` and records its arm
   before the first turn.
2. **Given** either arm, **then** the harness arm runs the latest release, installed at its tag into its
   own config directory, and the bare arm runs a signed-in empty profile; the command line, prompt, turn
   cap and tools are otherwise identical.
3. **Given** a fix, **then** the pull request goes to `main` from `burndown/<issue>`, carries
   `bot::authored`, closes exactly its bug, fills the bug's story file and passes `issue-ownership` and
   `landing-copy`.
4. **Given** an issue labelled `bot::claimed`, **when** `/build` is asked to take it, **then** it stops
   unless told to take it over.
5. **Given** a labelled test bug, **then** one run in each arm is observed end to end and recorded on
   #948.

## Design

### Approach

- **Harness arm:** the latest release tag installed with `scripts/install.sh` into its own
  `CLAUDE_CONFIG_DIR`, so the bot never runs the rules it is editing. `install.sh` checks out a branch
  (`HARNESS_BRANCH`, default `stable`) and only fast-forwards it
  [Source: scripts/install.sh], so the tag is resolved to that ref and recorded per attempt.
- **Bare arm:** a signed-in empty profile through `CLAUDE_CONFIG_DIR`, as the live replay defines it
  [Source: docs/benchmarks.md#live-replay].
- **Equal otherwise:** the same prompt ("fix #N under `AGENTS.md`: fill its story, run the Gate, open the
  pull request with its closing and Landing copy lines"), turn cap, tools, web access and runner. Both
  arms load the repository's own `AGENTS.md` and project `.claude/` settings; the story lists what those
  give each arm, so the contrast is the user-level install alone. The six unequal-arm findings in
  `docs/benchmarks.md` (task count, turn cap, stop gate, web access, usage prices, hook capture) are the
  checklist.
- **Runner:** `ubuntu-latest` first; if the harness does not install there, a macOS runner, also free on
  public repositories.
- The agent job emits a patch and a structured result; the writer job from #945 pushes and opens the
  pull request.
- `/build` gains a stop on `bot::claimed`.

### Decisions and alternatives

- **Install the latest release, not `main`.** The bot edits `main`; running it would make the treatment
  change under the trial. Rejected: the checkout under test.
- **Equal arms by checklist.** The replay's 2026-09-24 review found six ways arms were unequal; the same
  list is checked here before the first real attempt.
- **One pull request per bug.** Rejected: batching fixes, which breaks one-trial-per-bug and the
  one-issue-per-PR rule.

### Do not implement

- Review rounds and merging (#949).
- The Codex lane (#950).
- Any change to the installed harness's own rules for the bot's sake.
