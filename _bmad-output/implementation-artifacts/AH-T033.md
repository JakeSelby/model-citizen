## Goal

Keep a plan written for this repository lint-clean from the moment it is posted, so the copy
`/build` commits into the pull request is the copy the reviewer approved. The lint rejects project
names it allows only under `docs/` and any email address; #782 and #786 both had to reword their
plans at build time, and the committed copies drifted from the approved ones.
[Source: https://github.com/JakeSelby/model-citizen/issues/821]

Decided by the owner on 2026-09-26, through the v0.14.0 finish-run brief (no numbered option was
offered): put the fix where plans are authored, as a general rule to lint the plan before posting
it wherever the repository names a lint, rather than hardcoding this repository's names into
shared content.

## Acceptance criteria

1. **Given** the `plan-authoring` skill, **when** an author reads it, **then** it says to run the
   repository's named lint on the plan before posting the review message and after each revision,
   and its self-check carries that item.
2. **Given** the skill's guidance, **when** a plan needs to name a withheld project or a trailer,
   **then** it says to name the check by what it does and to write "the Co-Authored-By trailer"
   without the address.
3. **Given** a plan copied alone into an empty directory, **when** `<harness checkout>/bin/citizen lint <that directory>`
   runs, **then** a docs-only project name and an email address are findings with a non-zero
   exit, and a plan written around them prints `0 finding(s)` and exits zero.
4. **Given** the change, **when** the gate runs, **then** lint, `generate --check` and the suite
   are clean.
