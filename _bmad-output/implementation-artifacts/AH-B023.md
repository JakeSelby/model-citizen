## Reproduction

Under Codex with `permissions=auto`, start a turn that launches an isolated role worker with
`harness role run --runtime codex`. The issue records the observation natively on `codex-cli-macos`
during the 0.11.0 qualification, with the four harness-routed BMad review layers:

- the workers launch and write their state;
- they then stall, reconnecting to their provider, until the deadline.

The same workers complete under an acknowledged bypass. The issue calls this the likely cause of an
earlier run's time-limit loss.

## Root cause

The issue attributes it to sandbox inheritance: the worker inherits the parent turn's sandbox,
`workspace-write` with `network_access: false`, so its provider call cannot reach the network.

What the code shows at `origin/main`:

- `bin/harness` maps the `auto` permission posture to Codex `("on-request", "workspace-write")`.
- `adapters/codex/worker.py` launches the worker with `--sandbox read-only` and
  `approval_policy: "never"`, and sets no network option.
- Nothing in the worker path detects a missing network and fails fast.

[ASSUMPTION: that the parent turn's sandbox, rather than the worker's own `--sandbox read-only`, is what
removes network access is the issue's diagnosis; no probe that separates the two is recorded.]

## Acceptance criteria

From the issue's "Wanted" section:

1. **Given** a Codex turn under `permissions=auto`, **when** it launches an isolated role worker,
   **then** the worker either reaches its provider by a route the permission posture sanctions, or
   exits promptly with one line saying why.
2. **Given** the same launch, **when** the network is unavailable, **then** the worker never stalls
   silently until its deadline.

## Design

Not decided. The issue names the two acceptable outcomes: sanctioned network access for the provider
call, or a fast failure with a one-line reason. It records no mechanism for either.

Do not implement: a route to the network that the permission posture does not sanction. The issue says
access must come "by a route the permission posture sanctions".

A worker that both reads a workspace and fetches pages is what AD-8 prevents. Any network route has to
reach only the model provider. [ASSUMPTION: the issue does not discuss AD-8; the constraint is read
from the spine.]

## Regression test

Not written. A test would launch a worker through the Codex adapter with network access unavailable,
and assert a prompt exit and a one-line reason rather than a run to the deadline.
