## Reproduction

1. Run the registered micro campaign (#1131) on evaluator pack 1.0.0: `micro-stop-gate` asks for a rename in `lib/hookbox/loader.py` with "edit only loader.py, run nothing".
2. `tests/test_loader.py` still calls the old name, so the correct edit leaves the workspace gate red; the harness arm's stop gate blocks and the agent updates the test.
3. Observed: the check requires every other file's sha256 unchanged and fails all five harness runs on `tests/test_loader.py`; the bare arm passes five of five with the tests red.

## Root cause

The task's prompt and check froze the tests that the rename breaks, so the only edit the stop gate accepts was scored a failure. This repository's own manifest of the task (`benchmarks/micro/tasks.json`, oracle `benchmarks/oracles/micro_rename.py`) carried the same prompt, and its check read `bin/harness` alone, so it passed a tree whose tests were red. [Source: benchmarks/oracles/micro_rename.py#check]

## Acceptance criteria

1. **Given** the task's parent tree, **when** `bin/harness` alone is renamed, **then** the check fails, naming each test that still calls the old name.
2. **Given** the rename with the three calling tests updated, **then** the check passes.
3. **Given** a calling test whose call was deleted or a calling test removed, **then** the check fails.
4. The prompt allows updating the tests that call the function.
5. The pack carries the same fix (pack 1.2.0), and the micro pre-registration records that any re-run names its pack version and digest.

## Design

Mirror the pack's fix in this repository's manifest: the prompt allows updating the calling tests, and the check requires them updated. The check first reads `tests/**/*.py` statically, naming the three calling modules at the parent sha so deleting a call cannot pass; when that finds no problem it runs `unittest discover -s tests` in the scoring container (about 8 seconds at the task's start, capped at 600), so a rename whose callers still fail scores a failure. The run was added after review. The pack fix itself shipped in evaluator pack 1.2.0, outside this repository.

Rejected: keeping the frozen-tests prompt and reading only `hook_blocks`, which leaves a pass rate that penalises the gate. Unchanged: the mechanism, the parent sha, the caps and the contamination refusal.
