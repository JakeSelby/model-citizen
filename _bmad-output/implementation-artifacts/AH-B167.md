# AH-B167 — fix(coordination): intent-overlap refusals are mostly the session's own claims

## Reproduction

1. One orchestrating session `S` spawns two builder subagents. Builder A creates worktree `A` and
   runs `harness intent claim scripts/cost_bench.py`; builder B creates worktree `B`.
2. Builder B edits `B/scripts/cost_bench.py`. Its payload carries session `S`, and the claim in `A`
   is recorded under `S` too.
3. Observed: the first edit warns and the second is denied, naming the session's own claim. An
   audit of the decision log from 2026-09-21 to 2026-10-03 counted 93 of 106 real overlap hits
   (88%) as refusals against a claim held by the same session.
4. A claim from a builder whose branch has landed also lingers while the worktree is kept, because
   only a dead pid or a removed worktree ended a claim, and a subagent's pid is the runtime's.

## Root cause

`overlaps()` in `lib/harness_core/intents.py` treats every claim that is not the editor's own as a
live sibling's, and `policy/hooks/intent-overlap.py` counts every overlap toward the
`coordination.repeat_overlap` denial. #993 fixed only the claim on the target's own worktree. A
claim under the same session id in a different worktree still counts, although the two copies of
the path cannot collide on disk. `stale()` knew no landing signal, so a finished builder's claim
lived as long as its worktree did.

## Acceptance criteria

1. **Given** session `S` claimed a path in worktree `A`, **when** `S` edits the same path in worktree
   `B`, **then** the hook warns on every edit, never denies, and logs `same_session: true`.
2. **Given** a different live session claimed the path, **when** `S` edits it, **then** the first
   edit warns and the second is denied, as before.
3. **Given** both a sibling claim and another session's claim cover the path, **then** the other
   session's claim decides the answer.
4. **Given** `S` writes into the worktree where it claimed the path, from another worktree, **then**
   the existing warn-then-deny rule holds, because that is one file on disk.
5. **Given** a claim whose worktree is removed, whose branch is deleted while the worktree moved on,
   or whose upstream is `[gone]`, **when** claims are read or swept, **then** the claim is removed.
6. **Given** `harness intent check` finds only sibling claims, **then** it warns and exits 0.

## Design

- Claims stay keyed by session and worktree, as `slot()` already names them. A new
  `intents.sibling()` marks an overlap whose claim carries the editor's session id and a worktree
  other than the target's; `intents.split()` separates those from the rest.
- The hook answers with the other overlaps first. With none left, it returns a sibling warning,
  logs it with `same_session: true` and does not call `hit()`, so a sibling never counts toward a
  later denial. The variant does not change this.
- `stale()` adds `landed()`: one `for-each-ref` for the branch's upstream track. A squash merge
  leaves no ancestry, so landed means the branch ref is gone while the worktree is on another
  branch, or the upstream reads `[gone]`. A detached claim (`HEAD`), an unborn branch and any git
  failure never read as landed.
- `check()` warns, never denies, when only siblings overlap.
- Rejected: one claim per session regardless of worktree, which would hide sibling builders from
  each other entirely; and an ancestry test for landing, which would sweep a fresh branch that
  has no commits yet.
- Must not change: another session's claim, the `/clear` rule from #993, the Codex `cwd` rule.

## Regression test

`tests/test_intent_sibling_worktrees.py`: the sibling edit warns four times with no denial, under
the `deny` variant too; another session's claim still warns then denies; another session's claim
wins over a sibling's; a write into the claim's own worktree still denies; `check` warns on a
sibling; and a deleted branch, a removed worktree and a `[gone]` upstream are swept while a live
branch, an unborn branch and a detached claim are kept. Two existing tests that asserted the old
denial now assert the warning.
