## Story

As a developer, I want to roll back an applied draft in one step, so that trying a change is never a risk.

## Context and value

Every apply records the state it replaced (the config keys, the root's previous commit and the projections) in the ownership journal. Rollback previews the reverse diff and restores that state through the same governed path, and it is recorded in turn, so a rollback can itself be rolled back.

## Acceptance criteria

1. Given an applied draft, when it is rolled back, then the config, the root and the projections equal their state before the apply, byte for byte.
2. Given a later apply that touched the same keys, then rolling back the earlier one is refused, naming the later apply.
3. Given a rollback, then the activity timeline shows it, linked to the apply it reversed.
