# AH-B180 — fix(benchmarks): a long-session turn can overshoot the spend cap

## Reproduction

The 2026-10-05 long-session re-check: `corpus-research`, bare and harness arms, Sonnet, one rep,
`--skip-preflight`, a 0.45 USD run cap and a 0.95 USD spend cap, against a dry-run ceiling of 0.90
USD. The harness session's sixth turn cost 0.24 USD and took the session from about 0.33 to 0.57
USD, past its 0.45 cap; the set spent 1.03 USD, past both the ceiling and the spend cap.

## Root cause

`replay_session.run_session` already launched each turn with what was left of the session cap as
its `--max-budget-usd`, but the CLI holds a run to that budget only between API calls, so one turn
can overshoot it. The whole-run stop in `cost_bench.replay` was checked once per session, against
the session cap, so the runner had no turn-level guard; and a session just short of its cap was
launched with a near-zero budget the CLI cannot act on.

## Acceptance criteria

1. **Given** a session with spend below its cap, **when** the next turn is launched, **then** its
   `--max-budget-usd` is the cap minus the spend so far, never below `MIN_TURN_BUDGET_USD`.
2. **Given** a session started with what is left of the whole run's stop, **when** the spend so
   far plus the next turn's budget would pass it, **then** the turn is not sent and the session
   stops as `spend_cap`, errored, so it is not scored as the arm's failure.
3. **Given** a long-session plan, **when** it is dry-run, **then** the ceiling counts every session
   at its cap plus the minimum turn budget, and says it bounds spend while each turn holds to its
   budget.
4. **Given** the replay loop, **when** a session's worst case would pass the spend cap, **then** it
   is not started.

## Design

- `turn_budget(cap, spent)` is the turn's budget; `session_ceiling` is the session cap plus
  `MIN_TURN_BUDGET_USD` (0.01), the most a session can spend if every turn holds to its budget,
  and `ceiling_usd` sums it. A turn with no priced result counts at its whole budget.
- `run_session` takes `run_left`; `cost_bench.replay` passes the spend cap minus what the set has
  spent, and its pre-session check now uses `session_ceiling`.
- Rejected: dropping the pre-session check for the per-turn one alone. It would let a lowered
  `--spend-cap` cut sessions short, which are then not comparable; keeping both means the per-turn
  check is a backstop.
- Must not change: how a turn's cost is read (#1243) or the per-session cap.
- Documentation note, since `docs/benchmarks.md` is edited elsewhere at present: the long-session
  ceiling is each session's cap plus 0.01 USD, an upper bound only while the CLI holds each turn
  to its `--max-budget-usd`; the CLI checks that between API calls, so one call can still pass it.

## Regression test

`tests/test_replay_long_session_budget.py`: the floor and the remaining-budget cases, a turn that
would cross the run stop is not sent, and the replay loop refuses a session whose worst case
passes the spend cap and passes each session what is left of it. Each fails before the fix.
