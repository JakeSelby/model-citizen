## Story

As a developer, I want every run, past and new, kept in one store that can be rebuilt from the result files, so that history is complete and never the only copy.

## Context and value

One run record for every suite: the suite, the target (kind, ref, commit, draft and config digest), the runtime, model, arms, trials, parameters and argv, the status and times, tokens and list-price cost, the per-case results and the artifact paths. The store is a SQLite index under the harness state home, with a schema version (AD-11). It imports the results the project already keeps (`benchmarks/history.jsonl`, `benchmarks/<version>/results.jsonl`, `benchmarks/static.json` and native acceptance outputs), and `citizen runs reindex` rebuilds it from the files.

## Acceptance criteria

1. Given the store deleted, when `citizen runs reindex` runs, then every imported and Studio-launched run is back with the same fields.
2. Given a result file in an unknown schema version, then the import skips and reports it, and never guesses.
3. Given a run's cost, then it is labelled as a list-price equivalent, as the ledger labels it.
4. Given a store written by an older schema, then it migrates forward without loss.

## Design

### Approach

Keep one append-only, hash-chained JSONL sidecar beside every supervised run as the durable
authority, and treat a versioned SQLite database under the Studio state home as a disposable query
index. Every lifecycle write appends and fsyncs a complete record before refreshing the operational
JSON cache and index. Reads verify the complete chain and repair only the cache; a broken chain is a
named error, never partial history. A state-root append-only authority ledger, independently hash
chained outside each run's sidecar and metadata pair, records the immutable creation digest,
current chain head and required terminal digest. It survives index deletion, so a valid earlier
prefix or a forged, validly rehashed sidecar and local metadata cannot masquerade as current
history. A separately persisted authority-head file anchors the global ledger itself. A durable
append intent makes sidecar, metadata, ledger and head updates idempotently recoverable after any
durability boundary. A state-root advisory lock serializes the full append and recovery path across
parent and worker processes, and intent recovery validates a canonical UUID before any path access.
Immutable creation fields and every lifecycle transition are checked against an explicit state
machine before append and read.

`citizen runs reindex` builds replacement contents from verified Studio sidecars plus explicitly
recognized benchmark and native-acceptance schemas, then applies them in one exclusive transaction
to the existing database inode so other live connections observe the commit. Unknown or malformed
external schemas are reported and skipped. Corrupt or tampered Studio
sidecars abort the rebuild because they are the authority. Flexible JSON records preserve every
source field while stable normalized fields cover suite, target, runtime, model, arms, trials,
parameters, argv, lifecycle, tokens, list-price-equivalent cost, cases and artifacts.
Every Studio and external record also carries a stable source identity and immutable digest. A
reindex accepts a verified Studio chain extension but rejects truncation, rewrite or changed
external evidence at the same key instead of overwriting the prior index silently.
Each external source file imports in one SQLite transaction, so any colliding row rolls back every
row from that source rather than publishing a valid-looking prefix.

### Decisions and alternatives

- Sidecars are authoritative and SQLite is rebuildable. Reject SQLite-only history because deleting
  or corrupting the index would make it the only copy, contrary to AD-11 and the story.
- Store full snapshots rather than event deltas. The bounded run lifecycle makes snapshots small,
  and reconstruction never depends on replay code remaining bug-compatible with older events.
- Use SHA-256 links over canonical JSON and fail closed on any missing, reordered or changed entry.
  A checksum only on the latest record would not detect deleted history.
- Anchor each sidecar's creation digest, chain head and terminal digest in a separate append-only,
  globally hash-chained state-root ledger. This distinguishes the authoritative current history
  from a cleanly truncated prefix or a fully rehashed sidecar-plus-metadata pair, survives SQLite
  deletion, and keeps the anchor outside the evidence pair it verifies.
- Persist the global ledger's current sequence and hash in a separate atomic head file, so truncating
  the sidecar, local metadata and authority ledger to mutually valid prefixes still conflicts after
  SQLite deletion. A write-ahead intent completes an interrupted multi-file lifecycle append on the
  next read; it never treats anchored evidence as a legacy record.
- Hold one cross-process authority lock from intent reconciliation through the completed append, so
  worker construction cannot recover or unlink its parent's in-flight intent. Intent run ids must
  be canonical UUID path components before recovery opens a run directory.
- Freeze every currently applicable AD-30 identity field in the creation record: target kind, ref,
  revision, draft and config digest; suite identity and version; case identities; spend estimate,
  cap and pricing identity; and the canonical run digest. Fields supplied only by later stories are
  explicit nulls rather than omitted or inferred values.
- Permit only explicit lifecycle transitions and require a terminal digest for finalized states.
  An orphan remains extensible while capacity is reserved, then finalizes when the process group is
  released, preserving the supervisor's existing recovery contract.
- Recognize the repository's current unversioned benchmark/native shapes as their exact legacy v1
  schemas, while honoring explicit `schema_version` and refusing any other value. Structural checks
  keep that compatibility from becoming schema guessing.
- Derive external record identities from native stable keys, not line positions, and compare their
  source identity plus immutable digest on collision. Changed evidence at an existing key is a
  visible conflict; only identical evidence or a verified Studio chain extension may replace it.
  Parse and import each external file in one transaction so a collision rolls back its entire file.
- Keep imported raw payloads in the indexed record beside normalized fields. Reject a lossy table
  projection because later reports need source fields that this story cannot predict.
- Rebuild SQLite in place under an exclusive transaction. Reject path replacement because another
  process can remain attached to the unlinked prior inode and serve stale history indefinitely.

### Do not implement

- New suite definitions, target resolution, spend confirmation, reports and UI.
- Editing benchmark or native-acceptance producers to add schema fields retroactively.
- Treating an external source parse failure like a Studio sidecar failure: the former is reported
  and skipped; the latter aborts because it is the sole durable authority for that launched run.

every complete record; imports all four supported source families twice and proves stable results;
asserts list-price-equivalent

bounds list queries. Existing supervisor tests prove every lifecycle transition still works through
the integrated sidecar/index path. Adversarial cases cover clean-prefix truncation, validly rehashed
creation mutation, a forged sidecar-plus-metadata pair rejected by the independent authority ledger,
illegal transitions, missing and wrong terminal digests, immutable AD-30 identity changes, and
external source-key collisions with whole-source rollback. CLI coverage proves JSON reindex output
and error normalization. A non-null frozen target revision is also proven through sidecar append,
stable normalized indexing, database deletion/rebuild and JSON serialization. Fault injection at
all eleven append fsync boundaries proves recovery to the previous or completed valid event. Tests
also cover full-prefix truncation against the external ledger head, missing-sidecar anchor refusal,
two live SQLite clients across reindex and malformed nested external records.
The parent/worker construction race proves the second store blocks until the writer clears its own
intent; traversal and non-canonical intent ids are rejected without path effects; every benchmark
history container and scalar family is rejected when malformed rather than partially normalized.
Table-driven source tests also enforce benchmark-result arm, rep, token, pass/error and scalar
shapes; complete benchmark-history summary/case fields; and static total, price and file-path
schemas. One malformed row rejects its entire source transaction.

## Review findings

- The fresh specification review found that an internally valid hash chain could still be truncated
  or rehashed, lifecycle legality and terminal evidence were not independently enforced, and an
  external source-key collision could overwrite changed evidence. Persisted authority seals,
  explicit state validation and collision-safe imports close all three gaps with adversarial tests.
- The specification rereview found that the local metadata seal shared the sidecar's trust boundary,
  several AD-30 identity fields were absent, source collisions could leave prefix rows, and AC1 was
  proven only for separate store populations. The independent ledger, complete creation identity,
  per-source transactions and mixed-store equality regression close those four proof/design gaps.
- The capped final review found the normalized Studio adapter reading a nonexistent `target.commit`
  instead of authoritative `target.revision`; the corrected mapping and non-null regression prevent
  silent revision loss.
- Quality review found the ledger itself lacked an external head, multi-file appends could strand
  partial state, missing sidecars could enter legacy migration, path replacement stranded live
  SQLite clients, and malformed nested inputs could escape validation. The authority head, durable
  intent recovery, anchor-first refusal, in-place rebuild and strict adapters close all five issues.
- Quality rereview found worker construction could race an in-flight parent intent, intent ids were
  trusted as path components, and benchmark-history nested shapes remained permissive. One shared
  authority lock, canonical UUID validation and full history-shape validation close the three gaps.
- The capped final quality review found remaining permissive scalar and nested shapes across all
  three benchmark adapters. Producer-derived exact validators and table-driven malformed-source
  regressions close those gaps without another review round.
