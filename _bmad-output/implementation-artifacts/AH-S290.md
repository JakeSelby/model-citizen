## Story

As a developer or an agent, I want every edit to land in a draft, so that I can change and test my harness without touching what is live.

## Context and value

A draft is where every Studio edit lands: a managed worktree made by the same code as `citizen worktree create`, based on the installed version or a release tag, with a checkpoint commit per save, so every state a draft passes through can be run and compared. Configuration edits live in the draft as a copy of the config file. No edit writes the live checkout or the live config.

## Acceptance criteria

1. Given `citizen draft create tone-down --base installed`, then a managed worktree exists outside the live checkout, and the Studio lists the draft.
2. Given an edit saved in the Studio, then the draft gains one checkpoint commit, and the live checkout, the live user config and every projection are unchanged, byte for byte.
3. Given the installed version moved since the draft was made, then the draft shows that it is behind and offers a rebase that stops on a conflict.
4. `citizen draft list|diff|discard --json` does from the CLI what the Studio does, and discard removes the worktree and its branch.
