## Story

As a developer or an agent, I want every edit to land in a draft, so that I can change and test my harness without touching what is live.

## Context and value

A draft is where every Studio edit lands: a managed worktree made by the same code as `citizen worktree create`, based on the installed version or a release tag, with a checkpoint commit per save, so every state a draft passes through can be run and compared. Configuration edits live in the draft as a copy of the config file. No edit writes the live checkout or the live config.

## Acceptance criteria

1. Given `citizen draft create tone-down --base installed`, then a managed worktree exists outside the live checkout, and the Studio lists the draft.
2. Given an edit saved in the Studio, then the draft gains one checkpoint commit, and the live checkout, the live user config and every projection are unchanged, byte for byte.
3. Given the installed version moved since the draft was made, then the draft shows that it is behind and offers a rebase that stops on a conflict.
4. `citizen draft list|diff|discard --json` does from the CLI what the Studio does, and discard removes the worktree and its branch.

## Design

### Approach

Add one provider-neutral draft domain module under `lib/harness_core/studio/` and keep `bin/harness` as the
thin CLI adapter. A draft uses the existing managed-worktree creation and removal path, with a reserved
`draft-<name>` worktree name and `draft/<name>` branch. Its private state and copied user configuration
live in the linked worktree's Git administrative directory, so they are attached to the draft but can
never enter a commit or a push.

The draft revision is its Git commit. Checkpoint saves take an expected revision and idempotency key,
serialize under a draft-local lock, durably journal the request before applying it, run the checkout's
lint, and commit only after the check passes. Recovery either completes a commit whose trailers match
the journal or restores only the journaled paths and private configuration. The public CLI and the
future Studio call the same create, list, diff, rebase and discard functions.

### Decisions and alternatives

- **Private configuration copy:** Store the live config copy outside the worktree filesystem in its Git
  administrative directory. Tracking it in the draft branch was rejected because a user config can
  contain personal paths or secrets and must never enter repository history.
- **Git commit as revision:** Use the full checkpoint commit SHA as the optimistic concurrency token;
  a stale save is refused before any write. A separate integer revision was rejected because it could
  drift from the artifact experiments actually run.
- **Durable exact-once saves:** Persist the canonical request digest and result per idempotency key.
  Exact replay returns the prior result; changed reuse conflicts. Last-write-wins and best-effort
  autosave were rejected by AD-29.
- **Explicit destructive discard:** Reuse managed-worktree cleanliness checks, then delete only the
  recorded draft branch. A force flag was rejected because it could erase an uncheckpointed buffer.
- **Conflict-stopping rebase:** Rebase onto the currently installed checkout revision and leave Git's
  conflict state intact for inspection. Automatic conflict resolution was rejected.

### Do not implement

Settings forms, module editing UI, governed apply, rollback, Studio HTTP transport, experiment runners,
and release-tag browsing beyond accepting an exact `v*` Git tag as `--base`.

### Completion notes

Implemented a shared draft domain and CLI parity for create, list, diff, rebase and discard. Draft
configuration and transaction records live in the linked worktree's private Git administrative
directory rather than repository history. Checkpoints use the commit SHA as the revision, reject stale
writers, replay exact idempotency requests, reject changed reuse, lint before commit, and recover a
prepared journal by completing the matching commit or restoring the recorded inputs. Rebase stops in
Git's ordinary conflict state; discard refuses dirty or conflicted drafts. No live checkout,
configuration or projection is written.

## Review findings

- The first focused run exposed that extracting worktree removal preflight had displaced the existing
  audit branch below `cmd_draft`, so `worktree audit` returned `None`. The audit branch was restored to
  `cmd_worktree`; all existing worktree tests pass with the new shared helpers.
- Quality review found case-insensitive `.git` traversal, mode-erasing saves, unlocked discard,
  forceful branch cleanup, non-transactional creation, and stale worktree enumeration. Saves now
  journal typed file images and preserve executable modes, safe symlinks require explicit opt-in,
  discard holds the draft lock and atomically deletes only the recorded ref, creation compensates on
  every post-worktree failure, and stale/prunable registrations are ignored before metadata lookup.
