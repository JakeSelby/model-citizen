# AH-B166 — fix(ci): the bmad traceability workflow is red on every main push

## Reproduction

On `main` at 804987dc, `python3 scripts/bmad_issue_sync.py audit --live --ignore-lifecycle
--grace-days 2`, the workflow's own command, exits 1 with 107 findings in three classes: 22 accepted
issues without a BMad ID, 79 mapped issues with projection drift (73 a missing Planning block alone,
4 also a `type::*` label that disagrees with the map, 2 also a parent the map holds and GitHub does
not), and 6 mapped issues whose GitHub parent the map lacks.

## Root cause

`live_findings` in `scripts/bmad_issue_sync.py` treats every class as a failure. The unreserved
backlog grows faster than reservations land, so the run is red regardless of whether anything else
broke, and a permanently red check is ignored.

## Acceptance criteria

1. **Given** an accepted issue past its grace period without a BMad ID, **when** the audit runs with
   `--live --warn-unreserved`, **then** it prints a `warning:` line for it and does not count it as a
   finding.
2. **Given** the same issue, **when** the audit runs with `--live` alone, **then** it is still a
   finding and the audit exits 1.
3. **Given** a missing mapped issue, title drift, a parent gap or projection drift, **when** the
   audit runs with `--warn-unreserved`, **then** each is still a finding.
4. **Given** the `bmad traceability` workflow, **when** it runs, **then** it passes
   `--warn-unreserved`.

## Design

A `--warn-unreserved` flag on `audit`, mirroring `--ignore-lifecycle`, demotes only the unreserved
class; the workflow passes it. A demoted message travels in the notices list with a `warning: `
prefix so `live_findings` keeps its two-value return, and the summary line counts warnings. The
full pre-release `audit --live` is unchanged. Rejected: demoting projection drift too, since a
missing Planning block or a disagreeing label is a real gap that one `apply` closes; and reserving
the backlog in this change, which is a separate map change per issue.

## Regression test

`tests/test_bmad_live_audit_severity.py` covers the default finding, the demoted warning, the grace
period taking precedence, every other class staying a finding, the command's exit codes and output,
and the workflow's flag.

## Tasks

- [x] Add `check_unreserved` to `live_findings` and `--warn-unreserved` to `audit` (AC 1, 2).
- [x] Keep every other class a finding (AC 3).
- [x] Pass the flag in `.github/workflows/bmad-traceability.yml` and document it in `docs/bmad.md` (AC 4).

## Dev notes

Making the check required is a repository setting and stays with the maintainer. The workflow stays
red on `main` until the maintainer runs `refresh` (6 parent gaps, a map commit) and then `apply`
(79 issue bodies, labels and parents on GitHub); refresh must come first or `apply` would clear the
parents GitHub already records. [Source: docs/bmad.md#live-verification]
