# AH-B156 — The freeze record still names release/v0.14.2 after its tag

## Reproduction

On `main` at b2bfbc8d, `compatibility/freeze.json` reads `state: frozen`, `branch: release/v0.14.2`, while `compatibility/catalog.json` reads `harness_version: 0.14.2`, `release_state: released` and the `v0.14.2` tag exists. Nothing in the gate or `scripts/release_preflight.py` reports it.

## Root cause

docs/releasing.md says to return `state` to `open` after the tag, but no check reads the freeze record against the released version, so the skipped step went unnoticed. `freeze_record` validates shape only.

## Acceptance criteria

1. **Given** the repository's freeze record, **when** it is read, **then** it is `open` with `branch` and `commit` null.
2. **Given** a freeze record frozen at `release/vX.Y.Z` whose tag `vX.Y.Z` is a strict ancestor of HEAD, whatever version the catalog has moved on to, **when** `stale_freeze_errors` runs, **then** it returns one error naming the branch.
3. **Given** the tagged release commit itself, a commit before or beside the tag, a branch not named `release/v…` or an open record, **when** the check runs, **then** it returns no error.
4. **Given** docs/releasing.md, **when** read, **then** the reopen step names the null fields and the test that enforces it.

## Design

Add `stale_freeze_errors(freeze, past_tag)` to `lib/harness_core/compatibility.py`: pure, no network; it reads the tag from the record's own branch and asks `past_tag`, which `tag_behind_head` answers from local git ancestry. It is not wired into `release_errors`, because preflight and the tag's release workflow run on the release commit, where the record may legitimately still be frozen. Enforcement is a repository test in the gate. Rejected: comparing against the catalog's `harness_version` and `release_state`, which misses a record left frozen after the catalog moves to the next version, and treating any present tag as stale, which would fail the release workflow on the tagged commit.

## Regression test

`tests/test_freeze.py`: `test_the_repository_record_names_no_released_branch` fails against main's freeze.json; `test_a_record_frozen_at_a_branch_whose_tag_is_behind_head_is_refused` covers the pure cases and `test_a_tag_counts_as_behind_head_only_once_a_later_commit_contains_it` the git ancestry.
