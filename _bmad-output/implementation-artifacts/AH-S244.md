## Story

As a harness maintainer, I want a slot model that lists each slot and its holder in a selection, and an adapter contract through which another framework's modules declare their manifests and cede or claim slots, so that the harness can run beside another framework, Superpowers first, without two modules holding one slot.

## Context and value

AD-22 gives every module a slot, and a shared slot is an error unless one module cedes it. Running beside another framework, Superpowers first (#558), needs two more things: the list of slots with each one's holder in a selection, and an adapter contract through which another framework's modules declare their manifest fields and cede or claim slots. The #553 spike informs the contract.

Depends on #788 and #553. Consumer: #558. Traces to AD-22 and PRD §9 (v0.16.0).

## Acceptance criteria

1. Given a selection, when it resolves, then every slot has at most one holder, and the resolved view lists each slot's holder.
2. Given an adapter, then it declares its framework's modules with the six AD-22 fields, and resolution fails on an unceded shared slot.
3. Given the Superpowers adapter, then the overlapping harness modules cede their slots and the selection resolves.
4. The PRD gains the requirement this implements through `bmad-prd`, since today it traces to §9 alone.
