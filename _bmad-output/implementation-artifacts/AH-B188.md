# AH-B188 — fix(usage): price worker rows recorded under a model alias

## Reproduction

Run any Claude Code role worker (`harness role run reviewer ...`); the role binding launches it as `--model opus`. The status record and the usage-log worker row then carry `"model": "opus"`, and `harness usage` reports the row with no cost. On one machine 427 of 541 reviewer runs over 30 days were unpriced.

## Root cause

`worker_rows` in `policy/hooks/usage-log.py` copied the status record's `model`, which is the CLI alias the adapter bindings choose (`adapters/claude-code/bindings.json` maps classes to aliases, not ids). `pricing.price_key` matches normalised full ids exactly and never by prefix, so an alias has no entry. The full id exists only in the result envelope's `modelUsage`, which the Claude Code adapter read no further than its `usage` totals. Those totals also leave out a helper model's tokens (a Haiku call beside the main model).

## Acceptance criteria

1. **Given** a Claude Code worker launched as `opus` whose envelope names `claude-opus-5-5`, **when** the usage sweep reads it, **then** its row names `claude-opus-5-5` and `row_cost` prices it at that model's rates.
2. **Given** a worker recorded before the adapter kept the model map, **when** the sweep reads it, **then** the map is read from the envelope saved beside the status record.
3. **Given** a run that also spent tokens on a helper model, **then** each model is priced at its own rate and the row's totals include the helper's tokens.
4. **Given** a model map with an unreadable part, or cache writes the TTL split cannot be placed on, **then** the row is unpriced rather than priced short.
5. **Given** a run whose writes were 1-hour, **then** they are charged at the 1-hour rate.

## Design

The adapter's `usage()` copies `modelUsage` into the status record as `usage.by_model`, unchanged. `usage-log.worker_parts` is the one place that translates it into the ledger's four columns, from the record or, for older runs, from `stdout.log`, which the worker run directory keeps. A non-empty map becomes the row's `by_model`, so `pricing.breakdown_cost` prices it; the row's totals become the map's sums so the two agree; `model` becomes the one part's id, or the one part the alias names.

`modelUsage` carries no TTL split of the cache writes, and a `-p` worker writes at the 1-hour rate. The envelope's top-level `usage.cache_creation` carries the split for the launched model, so the adapter records it and the sweep attaches it to the one part whose writes it sums to; writes it cannot place leave the row unpriced.

Rejected: a static alias-to-id map. The alias resolves to the client's current model, and the same `opus` alias ran `claude-opus-5` and then `claude-opus-5-5` within one month, so any fixed map misprices one of them. Codex rows already carry full ids and are left alone.

## Regression test

`tests/test_usage_prices.py::WorkerAliasTests`: the recorded-map and saved-envelope tests fail against the previous sweep (2 failures) and pass after it; the adapter test proves the map reaches the status record.

## Dev notes

Files: `adapters/claude-code/worker.py`, `policy/hooks/usage-log.py`, `tests/test_usage_prices.py`. Rows are upserted by every SessionEnd sweep over 30 days, so existing ledger rows reprice without a rescan. A Haiku 5.5 part stays unpriced: the envelope reports no per-request prompt size, which its prompt-length tier needs. [Source: policy/hooks/pricing.py#prompt_rate]

## Dev agent record

Claude Opus 5.5. Against the live worker directory, all 586 completed Claude Code worker runs in the last 30 days price after the fix, and their sum ($495.04) equals the sum of the client's own `total_cost_usd` for those runs. Codex worker rows carry no token totals at all, a separate gap left out of scope.

## Review findings

1. Fresh-context reviewer: worker cache writes were charged at the 5-minute rate, about 19% low on an Opus run, because `modelUsage` has no TTL split. Fixed by recording the envelope's split and attaching it to the launched model's part; tests now price at the 1-hour rate and cover an unplaceable split.
