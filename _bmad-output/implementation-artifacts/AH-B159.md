# AH-B159 — fix(hooks): the stop gate ignores a stated reason the gate cannot pass

## Reproduction

1. In a trusted repository whose `## Gate` block is red, end a turn: the stop gate blocks with "Fix it and finish, or say why it cannot pass".
2. Reply with a reason the gate cannot pass, for example a task that forbids editing the failing tests (the `micro-stop-gate` task in the registered micro campaign, #1131).
3. Observed: every further Stop is blocked again until the eighth consecutive block releases the turn.

## Root cause

`policy/hooks/stop-gate.py` decided from the gate's exit code and the per-session block count alone. It never read the turn's final message, so the exit its own block message offered did not exist. [Source: policy/hooks/stop-gate.py#main]

## Acceptance criteria

1. **Given** a red gate and a session already blocked once, **when** its final message holds a line opening `Gate cannot pass:` with a reason, **then** the turn ends, the state is `unverified`, the session's count is cleared and the decision log records `declined`.
2. **Given** the same state, **when** the final message is an ordinary finish, **then** the turn is blocked again and the count rises.
3. **Given** a red gate and no prior block, **when** the final message already states a reason, **then** the turn is still blocked once.
4. **Given** a final message that only mentions the phrase mid-sentence, or gives the marker with no reason, **then** the turn is blocked.
5. The block message names the `Gate cannot pass:` line.

## Design

Honour an explicit marker rather than interpret prose. The final message comes from the Stop event's `last_assistant_message` when present, else from the transcript through the decision log's bounded `read_claim`; any read failure keeps the block. A line counts only when `Gate cannot pass:` opens it (after an optional bullet, quote mark or bold) and at least 12 characters of reason follow. The release reuses `release()`, so the state is `unverified` and never green, and the log answer is `declined` with outcome `failed`.

Rejected: free-text reason detection, which would let an ordinary "done" with a caveat through; and dropping the exit from the message, which leaves out-of-scope red gates costing seven blocked turns. Unchanged: the green path, timeouts, the eight-block release and tree hashing.

## Regression test

`tests/test_stop_gate_stated_reason.py` replays Stop payload fixtures from `tests/fixtures/stop-gate-reason/`; the stated-reason case is blocked by the hook before this fix.
