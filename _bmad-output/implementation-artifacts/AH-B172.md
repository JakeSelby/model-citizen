# AH-B172 — fix(cost): fan-out and web-search caps are exceeded without a guard

## Reproduction

Under the `balanced` cost variant, spawn seven or more subagents in one message, or keep searching
past 200 calls in one session. Every spawn and every search goes through. An exploratory audit of
265 sessions found messages spawning up to 18 subagents, sessions running up to 26 at once, a
session with 747 searches and 31 subagents over 30 searches each.

## Root cause

The caps were prose only. The cost stance states `max_parallel` and the research rule states 200
searches per session, but the only code reading either was the usage feed's width note, which is
never a decision; nothing counted searches, and no PreToolUse policy compared a count to a cap.
[Source: policy/hooks/usage-feed.py#width_line]

## Acceptance criteria

1. **Given** as many live subagents as the cost variant's `max_parallel`, **when** a spawn or a `Workflow` launch is made, **then** it is denied with a reason naming the cap and the live count.
2. **Given** spawns in one message that have not started yet, **then** each counts as live until its `SubagentStart` arrives or 60 s pass.
3. **Given** a live subagent's `SubagentStop`, **then** its slot is released and the next spawn is allowed.
4. **Given** as many searches in a session as the research rule's cap, subagents' searches included, **when** another web search is made, **then** it is denied.
5. **Given** a count past 80% of either cap, **then** the call goes through with a warning: on every such spawn, once per session for searches.
6. **Given** a headless `claude -p` run, **then** nothing is denied and the row says `would-deny`, unless `HARNESS_SESSION_CAPS_HEADLESS=enforce` is set.
7. **Given** a stance change (`frugal`, `max`, the research rule switched off), **then** the caps move with it: 3, none, none.
8. **Given** any spawn, launch or search the guard judges, **then** one `session-caps` decision row is written.

## Design

A new hook id, `session-caps` (`policy/hooks/session-caps.py`), last in the coordinator's Agent,
`Workflow` and WebSearch branches and only when nothing earlier denied the call, plus the
`SubagentStart` and `SubagentStop` events, which it journals. State is one append-only journal
per session, with a lock around check-then-reserve so parallel spawns in one message cannot all
see room. The fan-out cap is the cost table's `max_parallel`, and the search cap is parsed from
the research rule's sentence, so a stance change moves both.

Extending the usage feed was rejected: it only journals while `turn_feed` is on, and it is
documented as never deciding. A `Workflow` script's `agent()` calls are not tool calls, so the
launch is the only point the guard can refuse; whether those agents raise `SubagentStart` is
unmeasured and the docs say so. Claude Code only, because Codex raises no stop event that would
lower a count. Must not change any answer when the counts are under the caps.

## Regression test

`tests/test_session_caps.py`: counting, the caps for each variant and with the rule off, denials
at the cap, release on stop, warnings, subagent searches, headless runs, `Workflow` launches,
Codex and a spawn another policy denies. Each fails before the hook exists.
