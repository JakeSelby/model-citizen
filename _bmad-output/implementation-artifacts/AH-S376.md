## Story

As a solo or small-team agentic developer, I want a per-call index of my Claude Code transcripts, so that Sessions and Skills can show real context, cost and skill use.

## Context and value

Plan step 6. The index reads Claude Code transcripts at request time with an mtime-keyed cache under the Studio state directory. Per assistant message it records input, cache and output tokens priced via `pricing.row_cost` (`policy/hooks/pricing.py:277`), `compact_boundary` markers and the reseed from `harness-session.py:420-460`.

## Acceptance criteria

1. **Given** a transcript, **when** the index reads it, **then** each assistant message has input, cache and output tokens and a cost from `pricing.row_cost`.
2. **Given** `compact_boundary` markers and reseeds, **when** indexed, **then** they appear as reset and reseed events.
3. **Given** Skill tool calls and the session's skill listing, **when** indexed, **then** the session has an invoked list and a loaded list.
4. **Given** an unchanged transcript, **when** it is requested again, **then** the mtime-keyed cache answers without re-reading it.
5. **Given** the module, **when** its tests run on fixture transcripts, **then** they cover every field above and a malformed line.

## Design

### Approach

- A new `lib/harness_core/studio/transcript_index.py`; cache under the Studio state directory.

### Decisions and alternatives

- **Read at request time:** transcripts stay on the machine; no hook change. Rejected: recording per call in a hook.

### Do not implement

- UI (S10, S11); any upload of transcript data.
