## Story

As a developer, I want to run the free local suites from the Studio, down to one test, so that checking a change costs a click and nothing else.

## Context and value

The suites that spend nothing run from the Studio: the unit tests (all of them, one module, one class or one test, listed by discovery), `citizen lint`, the static context figure (`cost_bench.py static --check`), the detector corpus (`detector_corpus.py --json`) and lifecycle acceptance. A developer picks one, watches its log stream, stops it, and sees each test or check with its result and failure detail.

## Acceptance criteria

1. Given one unit test picked from the discovered list, then only that test runs, and its result and traceback show.
2. Given the full suite, then progress shows per test as it runs, and the log streams without slowing the page.
3. Given a lint run, then each finding links to its file and line in the library.
4. The command chip on each run shows the exact command, and running it by hand gives the same result.

## Design

### Approach

Populate the existing versioned suite catalog with five free, installed-target suites: Python unit
tests, harness lint, the static context check, the detector corpus and deterministic lifecycle
acceptance. Add a `citizen runs catalog --json` core/CLI query that discovers unit tests through
`unittest` and returns only catalog-backed case identities, labels, exact argv arrays and copyable
commands. A selected unit module, class or test is accepted only when discovery returned that exact
identity; all-tests uses the catalog's fixed discovery argv.

Expose catalog, start, show, cancel and bounded log-stream routes through the Studio's owned route
registry. The handlers adapt to `SuiteCatalog` and `RunSupervisor` through the existing mutation
executor and name the matching `citizen runs` commands. A bounded SSE response reads stdout/stderr by
byte cursor, emits structured unit-test outcomes parsed from verbose unittest output, and ends after a
terminal state or a short idle window so reconnects remain cheap. Output files and run sidecars remain
the durable source; SSE is transport only.

Replace the Experiments placeholder with a Mantine suite browser and run console. The page selects a
suite and discovered unit-test scope, shows `No model usage`, the exact command and installed target,
launches through the authenticated CSRF route, follows the SSE stream without putting log text in a
live region, renders semantic completed/eligible progress, links lint findings to Library file/line
anchors, and keeps Cancel visible while a run is active.

### Decisions and alternatives

- Discover tests with Python's own `unittest` loader and flatten its `TestSuite` tree. Reject filesystem
  guessing because module/class/test identities must match what the runner can actually execute.
- Keep the executable and command structure entirely in `policy/studio/suites.json`; a case selector
  becomes one validated catalog parameter. Reject arbitrary command text and shell interpolation.
- Stream from the supervisor's existing cursor reads and parse presentation metadata separately. Reject
  a second in-memory log buffer because it would lose evidence on restart and could slow the run writer.
- Use one reconnectable bounded SSE request rather than an unbounded request-thread lifetime. It gives
  live delivery and backpressure while keeping the standard-library threaded server recoverable.
- Show the exact argv with POSIX shell quoting for copyability, but execute the argv list without a
  shell. The displayed command is derived from the same rendered argv, never maintained as duplicate copy.

### Do not implement

- Targets other than the currently installed checkout, paid/native/model suites, spend confirmation,
  comparison reports, history browsing and flaky-test classification.
- Editing or deleting run evidence, exposing state-home paths, or making the private HTTP API public.
- File-opening integration beyond a Library deep link carrying the repository-relative file and line.

### Testing

`tests/test_studio_free_suites.py` proves discovery at suite, module, class and method scope; rejects a
case absent from discovery before process launch; compares the displayed command to the exact argv the
supervisor records; parses passing, failing and traceback output; links normalized lint findings; and
exercises authenticated catalog/start/show/cancel/SSE routes including CSRF and bounded cursors.
`studio/tests/experiments.test.ts` proves command, progress, lint-link and reconnect state models plus
same-origin CSRF calls. Existing Studio browser acceptance proves the route renders and remains usable
at desktop and phone widths. The repository gate, Studio typecheck/lint/tests/build and committed-bundle
verification run after focused tests.
