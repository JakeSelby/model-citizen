# AH-B090 — Qualification provisioning installs BMad without shims, so integration apply reports drift

## Reproduction

1. Run `python3 scripts/qualification_provision.py --out <round> --bmad`, which installed BMad 6.12.0 with `--modules bmm,gds --tools claude-code,codex --yes` and no `--shims`.
2. Run `python3 bin/harness integration apply bmad <round>/bmad`.
3. It exits 1 with 8 drift findings such as ".claude/skills/gds-quick-dev/step-04-review.md: invoked skill `bmad-review-adversarial-general` is missing".

First observed by the 0.13.0 BMad integration suite; reproduced 2026-09-25 with the old argument vector in a temp directory (8 findings, exit 1).

## Root cause

`bmad()` in `scripts/qualification_provision.py` built its own installer command instead of the one `docs/bmad.md` gives the optional suite. It omitted `--shims`, so the legacy `bmad-review-*` skill names that GDS v0.7.2 workflows still invoke were never installed, and `integration apply` reports each missing invocation as drift. It also added the `gds` module and dropped `--output-folder _bmad-output` and npx's own `--yes`. [Source: docs/bmad.md#the-optional-integration-suite] [Source: docs/bmad.md (the `--shims` paragraph)]

## Acceptance criteria

1. **Given** the optional suite's install command in `docs/bmad.md`, **when** the provisioner builds its installer argument vector for a target, **then** it equals that command flag for flag, with the target as the framework root.
2. **Given** that argument vector, **then** it carries `--shims`.
3. **Given** `--bmad` provisioning, **when** `bmad()` runs, **then** it runs exactly that argument vector.
4. **Given** a freshly provisioned BMad root, **when** `harness integration apply bmad` runs on it, **then** it exits 0 with 0 drift findings.

## Design

A new `bmad_install_args(target)` returns the documented command: `npx --yes bmad-method@"$BMAD_VERSION" install --directory <target> --modules bmm --tools claude-code,codex --output-folder _bmad-output --shims --yes` with `BMAD_VERSION` pinned at 6.12.0, and `bmad()` runs it. A test parses the command out of `docs/bmad.md`, so the two cannot drift apart silently again.

Rejected: adding only `--shims` and keeping `bmm,gds`. It also exits 0 (checked 2026-09-25), but the issue asks for the documented install, and the documented install is `bmm` only; GDS is not a module the harness integration needs.

Must not change: the pinned installer version, the opt-in network step, and a missing `npx` or failed install being a reported note rather than a failed provision.

## Regression test

`tests/test_qualification_provision_bmad.py` compares the argument vector with the command in `docs/bmad.md`, asserts `--shims`, and mocks `run` to confirm `bmad()` runs it. All three error against the unfixed script and pass after it.
