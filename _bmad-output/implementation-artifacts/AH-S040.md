## Story

As a developer whose tasks need different budgets, I want context lifecycle and numeric budgets to be settings rather than fixed rule text, so that a task can raise or lower them and every consumer reads the same values.

## Context and value

Compaction policy, the gather and digest return caps and the review-round limit are either fixed or bundled into `cost` ([#123](https://github.com/JakeSelby/agent-harness/issues/123)). The epic's 2026-09-21 assessment rated the story Partial: numeric settings exist inside `cost` only, there is no `context` dimension, and word caps, the search cap and review rounds stay hard-coded in the rules ([#116 comment](https://github.com/JakeSelby/agent-harness/issues/116)).

That still holds on `main`:
- `cost` sidecars carry `compaction`, `session_effort`, `fast_mode`, `max_parallel` and the nudge thresholds [Source: primitives/stances/cost/max.json] [Source: policy/hooks/posture.py#SWITCH_VALUES].
- `primitives/rules/transcript-hygiene.md` fixes "gathering 400 words, research digest 600".
- `primitives/rules/research-and-verification.md` fixes a per-session search cap of 200 calls on Claude Code.
- `primitives/rules/working-style.md` caps review rounds "at two to three per story".

## Acceptance criteria

1. **Given** a configured budget, **when** the CLI and the hooks read it, **then** both consume the same effective value, and wrong types, negative values and unsafe or unbounded settings are rejected where applicable.
2. **Given** a non-default budget, **when** rules and skills are rendered, **then** none silently reinstates 400 or 600 words or a hard-coded search or review budget.
3. **Given** the precedence chain, **when** boundary values, budget exhaustion, the compaction detector policy and a `handoff` clear are tested, **then** each behaves as specified and a clear loses no outstanding work.

## Design

### Approach

The issue proposes `context` with `cost-default`, `preserve-cache`, `adaptive` and `handoff`, where `cost-default` keeps the existing cost intent, plus validated numeric settings for the gather and digest caps, the search budget, fan-out and review rounds. Cost presets supply the defaults and explicit settings win. Provider hard limits are kept distinct from user soft budgets ([#123](https://github.com/JakeSelby/agent-harness/issues/123)).

The plan adds that numeric schemas reject booleans posing as integers, publish their allowed ranges before exposure, and never let a larger user budget override a provider limit, and it preserves the 400 and 600 defaults [Source: docs/plans/stance-completeness.md#Step 5 — Settings and runtime behavior].

### Decisions and alternatives

- `cost-default` is the default, so today's cost-driven behaviour is the migration path [Source: docs/plans/stance-completeness.md#Step 5 — Settings and runtime behavior].
- Current vendor limits are not to be hard-coded as universal facts [Source: docs/plans/stance-completeness.md#Step 5 — Settings and runtime behavior].

### Do not implement

- Do not let a user budget exceed a provider's hard limit.
- Do not turn a soft budget into a hook that denies for cost. [ASSUMPTION: AD-14 of the 2026-09-23 spine, "No hook denies for cost", read onto this older issue; #123 does not say it.]
- Do not sync an unmerged candidate into the live installation.
