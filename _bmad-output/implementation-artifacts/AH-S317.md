## Story

As a new user, I want the Studio documented and in the product copy, so that I can find it and understand what it does.

## Context and value

`docs/studio.md` covers what the Studio is and is not, starting it, the security model, drafts and apply, runs and their costs, comparing and testing a draft, and the CLI equivalents. The README, getting started and usage docs point to it, the end-to-end suite captures its screenshots so they stay current, and `product.json` gains the capability, which carries it to the landing copy, the README grid and the About description.

## Acceptance criteria

1. Given `docs/studio.md`, then every command it names exists, and every screenshot comes from the end-to-end run.
2. Given `product.json`, then the Studio is listed as a capability only once the epics' exit criteria hold, and as an `on_the_way` entry before that.
3. Given the CHANGELOG, then its entry names the Studio, the new commands and the security model.

## Design

### Approach

One user guide, `docs/studio.md`, ordered as a reader meets the Studio: what it is and is not,
starting it, the security model, the pages, drafts (edit, templates and forks, review and apply,
roll back and recover), the first run, runs (targets, free suites, spend guard, native acceptance,
live replay, evaluation tiers, plugin eval import, history), testing a draft with pre-registration,
comparing runs, trends, rule health, spend, and the CLI. Each section states what is built on this
branch, read from the code and each story's completion notes, and links the page that already
explains a decision (benchmarks, evidence standard, pre-registration template, usage,
compatibility) rather than restating it. The README and getting started link to it. `tests/test_studio_docs.py` runs `--help` in process for every `citizen` command
the guide names and asserts each flag it shows is in that help (AC 1).

### Decisions and alternatives

- **`product.json` is unchanged.** The Studio landing group was approved on 2026-10-01; new feature
  lines are proposed for approval outside the repository instead. AC 2 is not settled here:
  `product.json` lists the Studio in both `capabilities` and `on_the_way`, and which one should
  stand before the epics' exit criteria hold is the owner's copy decision, deferred with it.
- **No screenshots.** AC 1 requires every screenshot to come from the end-to-end run that #1000
  adds; a hand-taken screenshot would break that rule, so they wait on a follow-up of #1000.
- **Only built commands.** The guide documents the agent loop's
  `citizen runs replay|eval|native|draft-test`, `citizen reports trends` and the studio-loop skill
  now that #998 is on the branch, including the paid preview, token and start flow.
- **Page addresses carry the hash.** The Studio uses hash routing and the server serves the page
  only at `/`, so the guide gives every page as `/#/...`.
- **The test parses the guide** rather than keeping a second list of commands, so a new command in
  the guide is checked without editing the test. A help call in process keeps it under a second.

### Do not implement

- No change to `product.json`, the Studio code, the bundle or any CLI behaviour.
- No screenshots, and no documentation of unbuilt stories (#989, #996, #999, #1063 to #1066,
  #1208). #998 is built on this branch, so its commands and skill are documented.

### Testing

- `tests/test_studio_docs.py`: every `citizen` command in the guide, inline or in a code block,
  answers `--help` with exit 0 and lists each flag shown; an unknown action fails the check; the
  README and getting started link the guide. Its first run caught `citizen catalog --json`, a flag that command
  does not have.
- `tests/test_doc_links.py` resolves every link and anchor in the docs, the guide's included;
  `tests/test_studio_docs.py` also asserts each of the guide's cross-doc anchors resolves.
- The command check reads option strings from `build_parser()`'s own actions, never help text,
  joins code-line continuations, checks a prose flag against every command its paragraph names
  before it (or the last command named), and is proved against fixtures: bogus commands and flags,
  a longer flag, and a flag named only in another option's help.

### Deferred, not done

- **`product.json`** (README grid, About description, AC 2's `capabilities` versus `on_the_way`
  listing and its proof): unchanged; the copy awaits the owner's decision.
- **Screenshots** from the end-to-end suite: not captured; deferred to a follow-up now that #1000 is
  on the branch.
