## Story

As a developer, I want to run the live replay benchmark on two targets from the Studio, so that I measure cost per passed task for a draft against a release.

## Context and value

Run `cost_bench.py replay` from the Studio with two targets (a release against a draft, say), the model, the repetitions and a subset of tasks, under the spend guard. Progress shows per task and arm, and the rows land in the run store and, for a release target, in the benchmark history the project keeps.

## Acceptance criteria

1. Given two targets, then each arm runs against its own built profile, and the run records both targets.
2. Given a replay with no explicit target, then the Studio refuses it, as `cost_bench.py replay` refuses one without `--tag` (#944).
3. Given a finished run, then the per-task table shows cost per passed task and pass rate for each arm.

## Design

### Approach

Add a replay-specific adapter around the native `cost_bench.py replay` runner instead of copying
its measurement logic into Studio. The adapter accepts exactly two already-resolved targets, runs
each target through the benchmark's own built-container profile, applies one whole-set spend cap,
preserves each native `results.jsonl` and authoritative `spend.json`, verifies every result against the target's immutable revision,
and derives the per-target/task/arm table from those rows. A small allowlisted wrapper emits the paid
suite result protocol for the shared supervisor. The Experiments panel owns selection, preview,
one-use confirmation and the result table; shared route and catalog wiring reuse the run supervisor.

### Decisions and alternatives

- Require two explicit target references and full resolved revisions. The installed profile is never
  an implicit fallback. The UI sends kind/ref to the AH-S301 resolver, preview returns immutable
  version/commit/draft/config identity, start consumes that resolved request, and a moved ref is caught
  when native rows do not match the resolved revision.
- Let `cost_bench.py` build the isolated arm profiles. A second profile builder would drift from the
  benchmark's declarations, manifests, admission checks and container fence.
- Run targets separately under one decreasing spend cap. This lets release targets use a committed
  pre-registration and project benchmark history while drafts remain exploratory and cannot pollute it.
- Consume the native replay's spend sidecar for cap accounting. Preflight charges, scored rows and
  fail-closed null-cost charges all reduce the same whole-set cap before target two is admitted.
- Preserve native rows as authority and index those rows with the existing run-store adapter. The
  replay summary and SQLite table are derived and rebuildable.
- Report intention-to-treat pass rate and cost divided by passed attempts for every target, task and
  arm. Missing cost remains unavailable instead of becoming zero.

### Do not implement

Generic target resolution and checkpoint creation belong to AH-S301; this adapter consumes their
immutable revisions. Comparison intervals and causal verdicts belong to AH-E025. Four-arm and
factorial runs belong to AH-S306. This story does not change the benchmark engine or publish results.

## Review findings

- Scope review: added the prepared handler/catalog seams while shared files remain claimed; changed the
  panel/start contract to consume AH-S301-resolved revisions; charged null cost at the per-run cap before
  budgeting target two. Complete server/page wiring remains serialized.
- Quality review: made native replay emit authoritative preflight/scored/charged spend accounting and
  reconciled it with native rows before decrementing the whole-set cap or emitting Studio spend cases.
- Fresh quality review: admitted every paid preflight against its remaining cap, persisted paid
  preflight spend through refusal and exceptions, reconciled the exact requested row matrix before
  the existing release-history writers, and generation-bound Studio previews.
- Post-merge review (twelve findings), each verified against the code before it was changed:
  1. A draft's configuration never reached the harness arm, which `cost_bench.py` builds from the
     commit's defaults, so a config-only draft measured the same bits as its base. Resolved by
     refusal: a target whose `config_digest` is not the empty-configuration digest is refused
     with `replay_target_config_unsupported`. Carrying configuration into the arm declaration,
     image and admission checks is a benchmark-engine design call this story does not settle.
  2. A dirty worktree resolved to a snapshot commit that lived only in a deleted clone and
     changed on every resolve. Resolved by refusal with `replay_worktree_dirty`; a clean
     worktree still runs, since its commit is in the shared object store.
  3. A refusal before any spend was charged the whole remaining cap. A target whose output
     folder does not exist is now charged zero and its cases stay `not_run` (corrected in the
     second round: see its finding 2).
  4. Indexed row IDs collided across runs of one revision and the rebuild skipped Studio rows.
     Row sources are now keyed under `runs/<run id>/`, and reindex re-reads each live replay's
     preserved summary from its run folder.
  5. The panel and catalog advertised a nonexistent `citizen runs replay`. The catalog route and
     payload now name `python3 scripts/cost_bench.py replay`, and preview returns the exact
     native command per resolved target, which the panel shows once both targets resolve.
  6. Preview and start built targets inside the single mutation executor. Target resolution
     now runs on the request thread; only the supervisor calls are serialized. The supervisor's
     own target build inside `start` is shared run-core behaviour and stays where it is.
  7. The sidecar-to-row reconciliation compared two independently rounded values exactly; it
     now uses the same one-micro-dollar tolerance as the component check.
  8. Release history is published only after the native rows and spend sidecar verify.
  9. Partly fixed: stale history stages a killed run left behind are swept under the lock at
     the next release transaction. The lock is still held for the whole release run.
  10. An errored native row now reports `errored` progress and reads "Errored" in the panel.
  11. The browser tests assert the `X-Studio-CSRF` header, a label for every input, the live
      region, both table captions and the header cells.
  12. The "Replay is not ready" alert waits until the form has been edited.
- Second post-merge review (four findings), each verified against the code:
  1. The configuration refusal caught every draft, because `drafts.create` copies the live
     configuration into each one. A replay now measures source only and says so in the panel,
     the result caption and the summary (`measures: source`). Only a draft whose configuration
     differs from the `base-config.json` it recorded at creation is refused; an inherited or
     cleared configuration runs. Covered with real drafts.
  2. The first-round claim was wrong: `cost_bench.py` creates the output folder before
     `replay()`, whose arm admission and workdir probe can still refuse unpaid. `replay()` now
     writes a zero spend sidecar when either refuses, and the Studio charges zero for a
     non-zero exit with no rows and a zero, uncapped sidecar, as it does when no folder exists.
  3. A preview that overlaps a draft save now fails with `replay_target_busy`, a retryable
     message, instead of the generic refusal.
  4. The not-ready list no longer uses `role="alert"`; a stable count is announced politely.
