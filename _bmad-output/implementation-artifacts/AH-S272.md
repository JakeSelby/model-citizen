## Story

As a developer whose repositories belong together in a `.code-workspace` file, I want a session opened
in any member folder to be told the workspace's other folders and to receive their instructions, so that
the agent follows every member's rules on the CLI, in VS Code, in the desktop app and in Codex without me
pasting them in.

## Context and value

AH-S271 made the `.code-workspace` files in `workspaces_dir` the only workspace map and gave `workspace
open`, which passes members as `--add-dir`. That alone leaves gaps: Claude Code loads an added folder's
`CLAUDE.md` only with `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` and never its `AGENTS.md`, a new
desktop chat has no added folders at all, and Codex loads no instructions from an added folder. The spike
of 2026-09-26 measured the existing start-up block at 8,953 of the 10,000 characters Claude Code allows a
hook, and showed that the cap applies per hook, so the workspace block needs an entry of its own.

## Acceptance criteria

1. **Given** `workspaces_dir` is unset, or the session's folder is in no workspace, **when** a session
   starts, **then** the workspace entry prints nothing.
2. **Given** a folder in one workspace, **when** a session starts there, **then** the block names the
   workspace, marks each other member `loaded natively`, `supplied by this hook` or `missing`, and carries
   each supplied member's `CLAUDE.md` or `AGENTS.md`, `CLAUDE.local.md` and unscoped rules, listing
   path-scoped rules by path.
3. **Given** a folder no precedence rule attaches, **when** a session starts, **then** one line names
   the candidates and the overrides file.
4. **Given** Claude Code with the variable set and a member passed as `--add-dir` to `CLAUDE_PID` that
   has a `CLAUDE.md`, **when** a session starts, **then** that member is marked loaded natively and not
   supplied; without the variable, or with only an `AGENTS.md`, it is supplied; on Codex every member is.
5. **Given** a block over 9,000 characters, **when** a session starts, **then** the instructions are
   written to `workspaces/<name>-<hash>.md` under the harness state folder and only the member list and that path,
   with an instruction to read it first, are inlined.
6. **Given** `CLAUDE_CODE_ENTRYPOINT=claude-desktop`, **when** a session starts, **then** the block asks
   Claude to request a member folder through the folder-grant tool on first use.
7. **Given** `sync` on either runtime, **when** it registers hooks, **then** SessionStart carries a second
   harness entry, `workspace-session` is a hook id that switches it off, and a second sync changes nothing.
8. **Given** `workspaces_dir` is set, **when** `sync` runs, **then** it owns
   `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` by the native telemetry rules: an identical value is
   adopted silently, a different one is left and reported, and on unset a held key returns to its prior.
9. **Given** the synthetic three-folder workspace, **when** headless `claude -p` runs from its root,
   with and without the members as `--add-dir` and with an oversized member, **then** it answers both
   members' codewords.

## Design

### Approach

A new policy module, `policy/hooks/workspace-session.py`, loads `lib/harness_core/workspaces.py` by path,
resolves the session's cwd through it, and builds the block. `lifecycle.registration()` emits a second
SessionStart entry per runtime, the same adapter with the argument `workspace` and the marker
`# harness:runtime-sessionstart-workspace`; `lifecycle.main()` routes that argument to `workspace-session`
alone, so the plain entry keeps `harness-session`. The id joins `catalog.HOOK_IDS` and
`policy/hooks/manifests.json`. `apply_native_claude` gains a second ownership block,
`claude.workspaces.env_keys` in `claude/OWNERSHIP.json`, applied by the same per-key rules.

### Decisions and alternatives

- An entry of its own rather than a section of the start-up block: the cap is per hook, and the start-up
  block alone is close to it.
- Past the cap, one bundle file whose path is inlined (plan decision 1); rejected: an index only, which
  relies on the agent remembering to read each member later.
- Desktop grants on first use, not at chat start (plan decision 3): each grant is a prompt outside bypass.
- The native-load skip reads the parent's arguments with `ps` (or `/proc` on Linux) because SessionStart
  input carries no added directories; relative `--add-dir` values resolve against the session's folder.
- The env variable reuses `apply_native_claude` rather than a second ownership path.
- Role workers get no skip logic: Claude workers run with `--setting-sources ""` and Codex workers get a
  fresh `CODEX_HOME`, so no user hook reaches them; a test pins both.

### Do not implement

- Writing `additionalDirectories` into settings, a stored map, or an overrides command.
- Fixing the existing start-up block's own overflow risk.
- A Codex path that bypasses hooks, and a doctor line.

## Review findings

A fresh-context review of the first commit, 2026-09-26, fixed in the next:

1. The native check matched a member path anywhere after `--add-dir`, prompt text included. The hook
   now reads the parent's exact argument vector (`/proc` on Linux, `sysctl` KERN_PROCARGS2 on macOS,
   nothing native elsewhere) and counts only `--add-dir` values.
2. The bundle name ignored its content; it is now `<name>-<12 hex of sha256>.md`, and bundles older
   than seven days are pruned on write.
3. The bundle folder ignored `HARNESS_HOME`; it now uses `posture.state_dir`.
4. The budget did not bound the work. `workspaces.py` now finds a worktree's main checkout by reading
   `.git`, `gitdir:` and `commondir` instead of running `git`, reads each instruction file up to 64 KiB,
   the hook caps the total at 256 KiB, and no bundle is written past the deadline.
5. Bad input on the workspace entry printed the policy-unverified message; it now prints `{}`.
6. `.claude/CLAUDE.md` now counts like `CLAUDE.md` for reading and for the native check, in
   `workspaces.member_instructions` and the new `workspaces.claude_files`.
7. A failed bundle write now falls back to the header and a list of each member's instruction file.
8. The plain-entry test ran the workspace argument on Stop; it now runs the plain entry on SessionStart.
9. A test pins that the telemetry removal line stays quiet when the workspace key is the only owned
   native path.
10. The settings template's bundle allow rule is dropped; `Read(~/**)` covers it.
