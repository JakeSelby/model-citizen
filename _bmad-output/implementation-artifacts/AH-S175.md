## Story

As a developer tuning the cost posture, I want a `class: none` rung below `light` in the cost sidecar
schema, so that work the harness already resolves deterministically is nameable as "no spawn, no
model", and the saving from resolving it that way is measurable.

## Context and value

The band ladder's floor is `light`, and the sidecar schema allows only `strong`, `standard` and `light`
on a row (`TIER_CLASSES[1:]` in `policy/hooks/posture.py`); no role is "no model". Yet the repository already runs a tier-0 classifier in production:
`grade-bash` is a deterministic grader with a tested time bound. A `class: none` row names that pattern
and gives the adaptive cost posture a rung below `light` to tighten into. The item came from the
2026-09-22 roadmap intake (B5). The intake's comment on #135 added it to this epic "in v0.14.0"; the
issue now carries the v0.15.0 milestone, whose PRD list includes the `none` capability class.
[Source: https://github.com/JakeSelby/agent-harness/issues/523]
[Source: _bmad-output/planning-artifacts/roadmap-intake-enterprise-review-2026-09-22.md#B5]

## Acceptance criteria

1. **Given** a cost sidecar row, **when** it carries `class: none`, **then** `posture.py` accepts it,
   `check_cost_sidecars` validates it, and `harness stances --json` prints it; a verifier with
   `posture: fixed` may not carry it.
2. **Given** a role or band that resolves to `none`, **when** the resolver runs, **then** it treats the
   result as "do not spawn".
3. **Given** a spawn that resolves to `none`, **when** the tier-agent-spawns hook runs, **then** it
   answers with the inline instruction rather than a model.
4. **Given** one shipped role or band, **when** it moves to `none`, **then** it states a confidence
   threshold and a fallback, and `harness usage` attributes zero-model resolutions so the saving is
   measurable.
5. **Given** the docs, **when** they are read, **then** the "The bands" section of
   `primitives/skills/delegation-tiering/SKILL.md` includes the rung and `docs/primitive-authoring.md`
   the schema line.
6. **Given** `extends`, **when** a custom posture inherits a `none` row, **then** it composes, with tests
   for the schema, the resolver and the hook path.

## Design

### Approach

Add `none` to the sidecar class enumeration, teach the resolver that `none` means no spawn, and have
`policy/hooks/tier-agent-spawns.py` return the inline instruction for such a spawn. Usage attribution
counts zero-model resolutions.

### Decisions and alternatives

- **A model is the fallback, not the path,** for a `none` row: the caller resolves the work
  deterministically.
- **Not on a `posture: fixed` verifier:** fixed verifiers keep their class.
- Other alternatives: not recorded in the issue or pull request.

### Do not implement

Not recorded in the issue or pull request.
