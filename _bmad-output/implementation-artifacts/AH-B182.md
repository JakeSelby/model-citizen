# AH-B182 — fix(cost): a subagent whose stop is blocked still counts as stopped

## Reproduction

Under the balanced cost variant, start six subagents in one session. One of them stops and another
`SubagentStop` hook blocks the stop, as Claude Code's hand-back enforcement does for a subagent
that stops before delivering its report. The subagent runs on, but the next spawn is allowed with
seven subagents working. Four of 835 subagents in the local usage-feed journals show exactly this:
turns written to the transcript after their last journalled stop, the first a meta `user` record
asking for the hand-back, and no further start or stop.

## Root cause

`session-caps` journalled a subagent as stopped on its first `SubagentStop` and ignored every stop
carrying `stop_hook_active`. Matching hooks run in parallel and no event reports whether one of
them blocked, so the first stop cannot know it was blocked, and the stop that ends the continued
run was dropped. [Source: policy/hooks/session-caps.py#run]

## Acceptance criteria

1. **Given** a subagent whose stop was followed by a turn timestamped after it, **when** a spawn is
   decided, **then** the subagent counts as live.
2. **Given** that subagent, **when** it stops again with `stop_hook_active` set, **then** the stop is
   journalled and the subagent no longer counts.
3. **Given** a final response flushed to the transcript after the stop but timestamped before it,
   **then** the subagent does not count as live.
4. **Given** a stop with no transcript path, an unreadable transcript, a torn line or only
   attachments after the stop, **then** the stop releases the slot as before.
5. **Given** a stop older than `RUNNING_TTL`, a stop with no start, or a start after the stop,
   **then** the transcript is not read.

## Design

Every `SubagentStop` is journalled with the transcript path and its size at the stop, and
`after_block` when `stop_hook_active` is set. Before a spawn is decided, `tally(..., probe=continued)`
reads each stopped subagent's transcript from that size, at most 256 KiB, and counts it as running
again when a `user` or `assistant` record is timestamped after the stop. Only spawns pay the read,
and only for a transcript that has grown. Rejected: live until a final stop, because only a
foreground `Agent` return marks one and subagents run in the background by default, so most would
hold a slot for `RUNNING_TTL`; and recording every subagent tool call, which costs a hook-path
append per call and misses a continuation that makes no tool call. Must not change: the guard
never denies on state it cannot read, and the search count.
