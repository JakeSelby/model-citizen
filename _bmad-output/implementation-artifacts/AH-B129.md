# AH-B129 — A named spawn of a role switched off in a project or session layer still launches from the definition the last sync wrote

## Reproduction

Sync a role such as `builder`, then select `roles.builder: off` in a project or session selection
without syncing again. A named Claude Code `Agent` call or Codex `spawn_agent` call still reaches the
stale native role definition and launches. Unnamed routing already avoids workers switched off in
the effective selection [Source: #918; Source: tests/test_switched_off_routing.py].

## Root cause

The lifecycle `Agent` branch checks the delegation stance and confinement rules, then invokes the
routing hook, but never checks the effective `roles` switch for the explicitly named role. Sync can
remove only user-layer files; a project or session switch therefore leaves the previously installed
native definition resolvable [Source: lib/harness_core/lifecycle.py#_dispatch; Source:
policy/hooks/posture.py#selection].

## Acceptance criteria

1. **Given** a named harness role switched off by the effective project selection, **when** either
   runtime requests that role, **then** lifecycle denies the spawn and names the project layer.
2. **Given** a session selection overrides a user or project role switch, **when** a named spawn is
   requested, **then** the session value and source decide whether it is denied.
3. **Given** an enabled named role, an unnamed spawn, a native tool alias, or a constrained role,
   **when** lifecycle handles it, **then** existing routing, normalization and confinement behavior
   remains unchanged.

## Design

Resolve the complete non-strict posture selection once per lifecycle dispatch, reuse it for hook
switches, and expose a helper that returns the winning source only when a named role is effectively
`off`. In the `Agent` branch, deny that call before confinement, routing, notices or brief rewrites,
with a reason naming the source layer. A missing or non-role native type takes the existing path.

Changing sync was rejected because project and session selection is intentionally ephemeral and
cannot reliably delete a shared user-layer definition. Putting the refusal in `tier-agent-spawns`
was rejected because AD-14 assigns that hook routing, while lifecycle owns cross-runtime permission
composition [Source: #918; Source: lib/harness_core/lifecycle.py; Source:
policy/hooks/tier-agent-spawns.py].

## Regression test

A new lifecycle test uses real selection files and both native envelopes. It covers user-off
project-on, user-on project-off, project-off session-on, project-on session-off, enabled roles,
unnamed spawns, Codex aliases, and the existing constrained-role denial. The issue case fails before
the lifecycle selection check because named stale definitions are allowed.
