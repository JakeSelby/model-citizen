# AH-B111 — grade-bash grades a redirect-only segment after a subshell as 0

## Reproduction

Grade `(ls) > out.txt` or `(ls)>out.txt` with `grade_text` from `policy/hooks/grade-bash.py`: both return grade 0, while `ls > out.txt` returns grade 1 (`redirect to out.txt`). `{ ls; } > out.txt` and `x=1 > out.txt` behave the same way. The read-only hook already refuses the line, but under the `ask` or `confirm-writes` autonomy stance the file write is not prompted.

## Root cause

`grade_tokens` strips redirections first and records the files they write, then returns grade 0 when no command tokens remain. A segment that holds only a redirect, which is what follows a subshell or a group once the parser splits it off, therefore lost the write it had just recorded. [Source: policy/hooks/grade-bash.py#grade_tokens]

## Acceptance criteria

1. **Given** the command `(ls) > out.txt` or `(ls)>out.txt`, **when** `grade-bash` grades it, **then** it grades 1 with verb `redirect to` and target `out.txt`.
2. **Given** a redirect-only segment whose target is in a temp directory, **when** it is graded, **then** it grades as the same redirect after a plain command does.
3. **Given** any segment with a redirect that writes a file, **when** it is graded, **then** the grade is at least 1; a `/dev/null` target stays 0.

## Design

The empty-segment case joins the read-only case: both return grade 1 with `redirect to` and the written target when a write was recorded, and 0 otherwise. Device targets keep returning grade 3 before this point. Rejected: special-casing subshells in the parser, since any segment reduced to a redirect has the same defect. The policy-file guard and its mention detection are not changed.

## Regression test

`GradeTests.test_a_redirect_only_segment_after_a_subshell_still_writes_its_file` in `tests/test_grade_bash.py` pins both spellings, a group and an assignment-only segment at grade 1, a temp target equal to its plain-command grade, and a `/dev/null` target at 0. It fails before the fix, where each grades 0.
