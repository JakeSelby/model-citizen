## Story

As a solo or small-team agentic developer, I want a Sessions page showing cost per turn and context per call, so that I see where a session got expensive and whether resets helped.

## Context and value

Plan step 6. Built on the transcript index (AH-S376). Context per call is drawn against the cost stance's 160k and 400k lines; auto-trim events and top-cost sessions are listed. It replaces Reports/usage.

## Acceptance criteria

1. **Given** indexed sessions, **when** the Sessions page opens, **then** it shows cost per turn and top-cost sessions.
2. **Given** a session, **when** it is opened, **then** context per call is drawn against the 160k and 400k lines with auto-trim events marked.
3. **Given** the same window as round 2, **when** the Sessions median context is computed, **then** it matches round 2's 256k.
4. **Given** the route, **when** its API tests run, **then** they cover shape, auth and errors; node tests and an e2e flow cover the page.

## Design

### Approach

- A Sessions route over the index and a page with the two lines from the cost stance.

### Decisions and alternatives

- **Lines from the cost stance:** the page shows the thresholds the harness acts on. Rejected: fixed chart limits.

### Do not implement

- Changes to the index (S9).
