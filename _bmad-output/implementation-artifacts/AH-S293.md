## Intent

**Problem:** Developers cannot safely edit rule, skill or stance text from the Studio while seeing the
same lint, context-budget and runtime-projection consequences that the CLI will enforce.

**Approach:** Add a draft-only CodeMirror editor whose live preview evaluates an in-memory candidate
through shared lint and projection authorities, while explicit Save or Cmd/Ctrl-S checkpoints only a
clean candidate through the existing revisioned draft transaction.

## Boundaries & Constraints

**Always:** Resolve a server-owned module identity to an existing regular UTF-8 file inside the managed
draft; preserve the unsaved buffer and focus on every refusal or external change; compare both draft
revision and source digest before save; show line-linked diagnostics, named Claude/Codex budget caps,
token deltas and bounded projected text; keep draft identity, checkpoint and `Nothing applied` visible;
make the editor keyboard-operable at 320 px and 400% zoom; make saved lint exactly equal `citizen lint`
on the resulting checkpoint.

**Never:** Accept client paths, follow symlinks, edit external primitive roots, mutate live files or
projections, autosave text, overwrite a stale source, add Studio-only validation while claiming CLI
parity, edit core modules in place, or implement module creation/forking, apply or rollback.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Clean edit | Supported draft module and valid text | Live clean diagnostics, budgets/projections, then one checkpoint on explicit save | Preserve buffer until canonical saved response |
| Lint refusal | Secret, personal value, broken local link or over-cap text | Mark exact line where available and disable/refuse save with the CLI reason | Focus one summary linking to the first diagnostic; write nothing |
| External change | File digest or draft revision differs from editor base | Keep local buffer and show conflict | Reload is explicit; never replace or checkpoint the buffer |
| Retry/race | Lost response, reused key, draft switch or stale preview response | Exact retry returns its canonical result; old generations cannot update the new editor | Different payload/key or stale base is a stable conflict |

**Acceptance Criteria:**
- Given a secret pattern typed into a rule, when live preview completes, then the editor marks its line
  and Save refuses the same finding without creating a checkpoint.
- Given an edit that exceeds an always-loaded cap, when preview completes, then the meter names the
  affected runtime, current delta and exact cap, and Save is refused.
- Given the draft file or revision changes after load, when Save is requested, then the local buffer is
  retained and a conflict is shown without overwriting either version.
- Given a successful save, when `citizen lint` runs against that checkpoint, then its normalized
  findings equal the editor's saved lint result.

## Implementation Notes

- Candidate previews run against a disposable checkout copy and return only server-owned identities,
  bounded projection text and normalized findings; draft paths never cross the HTTP boundary.
- Checkpoint transactions compare the editor's source digest after acquiring the draft writer lock,
  then run the public lint command before committing or acknowledging the idempotent result.
- The editor uses generation guards for module, draft and preview switches; explicit reload is the only
  action that replaces a retained stale buffer.

## Design Notes

Read snapshots revision, config, source identity and bytes under the draft writer lock using no-follow
regular-file semantics. Preview evaluates an ephemeral candidate through the complete public lint and
projection authorities with the same Git/config/external-root inputs as `citizen lint` and sync, then
removes its cache and module state. Coalesce preview work per draft so superseded requests cannot grow
without bound. Budgets derive from each runtime's actual final projected aggregate and round once.

Save repeats the snapshot and full evaluation under the writer lock, classifies revision/source drift
before generic dirty state, binds base revision, source digest, module identity and content into the
durable idempotency record, and returns the recorded canonical response before resolving current state.
Non-line findings remain visible in the summary instead of being fabricated onto a source line.

CodeMirror 6 is already pinned and licensed. Add no third-party dependency unless the licensing review
and committed inventory are updated; plain-text/JSON modes are acceptable before adding syntax packs.
