## Reproduction

Run `DISABLE_TELEMETRY=1 npx -y skills add JakeSelby/model-citizen --list` against the public
repository. The CLI reports five YAML parse errors and lists only ten of the fifteen skills.

## Root cause

Five `description` values use a colon followed by whitespace inside an unquoted plain scalar.
Model Citizen's deliberately small flat-frontmatter parser accepts that text, but a standard YAML
reader treats the suffix as a nested mapping and rejects the document.

## Acceptance criteria

1. **Given** the Model Citizen checkout, **when** the skills.sh CLI lists it, **then** all fifteen
   skills are present without YAML errors.
2. **Given** a `SKILL.md` description with an unquoted colon-space sequence, **when** the repository
   gate runs, **then** its frontmatter test names the skill and fails.
3. **Given** the five repaired descriptions, **when** the trigger and shape tests run, **then** their
   selection phrases and description budgets still pass.

## Design

Rewrite the five sentences as YAML-safe plain scalars and add a narrow lint check for the exact
interoperability trap. Do not add a YAML runtime dependency or change how frontmatter is rendered
for either supported agent.

## Regression test

`SkillFrontmatterYamlTests` scans every shipped skill and rejects the plain-scalar pattern that the
registry cannot parse. A local skills.sh listing is the end-to-end acceptance check.

## Dev notes

The public registry clones the repository, so public indexing must happen after the fix reaches the
default branch. The lint is intentionally limited to `SKILL.md` description scalars; it does not
claim to be a general YAML validator.
