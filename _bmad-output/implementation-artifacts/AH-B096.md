# AH-B096 — Provisioning leaves an untracked marker in the frozen clone, and the runner then refuses the clone as dirty

## Reproduction

1. From a clean checkout, run `python3 scripts/qualification_provision.py --out ../round-<version>`.
2. Run `python3 scripts/qualification_round.py` against that round, which drives `<round>/clone/scripts/native_acceptance.py` for each target.
3. Every case fails before a client turn with "the checkout must be clean: native evidence names a source commit", printed twice per target; 0 of 12 pass.

Observed 2026-09-23 on the first 0.13.0 round (`round-v0.13.0`, clone at fdaba1f). The operator worked around it by adding the marker to the clone's `.git/info/exclude` by hand.

## Root cause

`clone()` in `scripts/qualification_provision.py` writes `CLONE_MARKER` (`.harness-round-clone`) into the clone's work tree so a later provision can tell its own clone from somebody else's directory. Nothing excludes it, so `git status --porcelain` in the clone lists `?? .harness-round-clone`. `record()` in `scripts/native_acceptance.py` refuses any non-empty porcelain status in its own checkout, and the round runs that runner from inside the clone. [Source: scripts/qualification_provision.py#clone] [Source: scripts/native_acceptance.py#record]

## Acceptance criteria

1. **Given** a checkout of this repository, **when** `clone()` provisions a round's clone into a temp directory, **then** `git status --porcelain` in the clone prints nothing and the marker file still exists.
2. **Given** a provisioned clone, **when** its tracked files are compared with `HEAD`, **then** there is no difference: the exclusion lives in `.git/info/exclude`, never a tracked `.gitignore`.
3. **Given** a round directory holding this script's own clone, **when** it is provisioned again, **then** the new clone is also clean.
4. **Given** the marker line is already excluded, **when** the exclusion runs again, **then** the line appears once.
5. **Given** a clone that is still dirty after the exclusion, **when** provisioning finishes, **then** it stops with a message naming the clone instead of handing the runner a checkout it will refuse.

## Design

Provisioning writes `/.harness-round-clone` into the clone's own `info/exclude`, found with `git rev-parse --git-path info/exclude`, right after it writes the marker, then checks the clone's porcelain status and refuses to finish if it is not empty.

Rejected: teaching the runner's cleanliness check to ignore `CLONE_MARKER`. The runner that executes a round is the one inside the frozen clone, so a runner fix reaches only rounds provisioned at a commit that contains it, while this script runs from the operator's checkout and fixes every round at once. It would also weaken a check whose point is that native evidence names exactly one source commit.

Must not change: the runner's refusal of a dirty checkout, the marker's role in refusing to delete a directory this script did not create, and the clone's tracked content.

## Regression test

`tests/test_qualification_provision_clone.py` provisions into a temp directory and asserts the clone's porcelain status is empty. Three of its four tests fail against the unfixed script (the fourth errors, as `exclude_marker` does not exist there) and all pass after it.

## Review findings

Automated review of PR #837, round 1:

- **Failed status check read as clean** (inline, minor): `git()` never raises, so a failed `git status --porcelain` with empty stdout passed the cleanliness check. Fixed: `clone()` now refuses when the status command itself fails, with a regression test.
- **Dirty-clone refusal untested** (review-body nitpick): fixed with a test that makes the status check report a stray file and asserts the refusal.
- **Repository-selecting environment variables** (inline, major): with `GIT_DIR`, `GIT_WORK_TREE` or `GIT_COMMON_DIR` set, every `git -C` call in this script can act on another repository. Not fixed here: it predates this change and covers every git call in the script, including the checkout, so it belongs in its own issue rather than this fix.
