# AH-B147 — grade-bash grades text fed to a shell or interpreter's standard input as inert

## Reproduction

`grade_text` in `policy/hooks/grade-bash.py` grades each of these 1, with `git push` or `git push --force`, although bash runs the command (checked with a `touch` probe under `/bin/bash -c`, GNU bash 3.2): `sh <<<'…'`, `bash <<< "…"`, `echo '…' | sh`, `printf '…\0' | xargs -0 sh -c`, a here-document fed to `python3 -`, `perl`, `ruby`, `node`, `awk -f /dev/stdin`, `make -f -` or `osascript`, and `cat > x.sh <<EOF … EOF; ./x.sh`. `sh -c 'git push --force'` grades 3.

## Root cause

The tokenizer keeps a here-string's word as the operand of `<<<`, which `_redirects` drops, and `segments` flattens a pipeline into separate simple commands, so nothing tied the text an `echo` writes to the shell that reads it. `_feeds_shell` (#1109) only looks at here-document bodies and only for shells; no reader existed for other interpreters or for a file written and then executed. [Source: policy/hooks/grade-bash.py#_grade_reading]

## Acceptance criteria

1. **Given** a here-string or an `echo`/`printf` pipe (through `cat` or `tee` too) feeding a shell or `xargs sh -c`, **when** the text holds `git push`, **then** the command grades 2, and 3 for `git push --force`.
2. **Given** a program fed on standard input to Python, Perl, Ruby, Node, `awk -f /dev/stdin`, `make -f -` or `osascript`, **when** a line or string of it names `git push`, **then** it grades 2, 3 for `--force`, and never below 1.
3. **Given** a file written by a here-document or an `echo` and then run (`./x.sh`, `sh x.sh`, `. ./x.sh`, `python3 x.py`), **when** its text names a push, **then** it grades as that push.
4. **Given** plain data passed to a command that runs nothing (`echo 'git push' > notes.txt`, `cat <<'EOF'` bodies, `python3 script.py <<EOF`), **when** it is graded, **then** its grade is unchanged.
5. **Given** any of these, **when** the read-only check runs, **then** it refuses it; and grading a 200 KB program stays linear and inside the hook's CPU budget.

## Design

`segments` now comes from `_linked_segments`, which also records which command's output each command reads through a pipe (or `COMPOUND` for a group or loop). `_grade_streams` walks that list: a command's input is its here-string word or its producer's output, known when the producer is `echo`, `printf` (simulated by `_printf`, NUL read as a newline) or a pass-through `cat`/`tee`. `_grade_input` grades known input fed to a shell (`_runs_input`, reused from #1109) with `grade_text` at full grade, input to another interpreter (`_interprets_input`, `_reads_program`) with `_grade_program`, and words piped to `xargs` as its command's arguments. The same walk records files written by redirects and `tee`, and when a later command word, or a shell or interpreter operand, names one by base name, every body and every readable text written is graded as a script and as a program. Here-document bodies read by another interpreter go through `_feeds_program`, the `_feeds_shell` search with the interpreter reader. `_grade_program` is the unknown grade for text the hook cannot parse: at least 1, the whole text scanned for grade-3 families and a push, and each line, quoted string and line's joined strings that names a program the grader knows (`NAMED_RE`) graded as shell text, 64 at most. Rejected: parsing each interpreter's language, and grading unknown producers (`cat file | sh`, `curl … | sh`) above the 1 that `sh file` gets. Must not change: data bodies, data here-strings, `#1109` body grading and the read-only refusal.

## Regression test

`tests/test_grade_bash_stdin_text.py`: shell and interpreter templates are proved to run under bash where the program is installed and must grade 2 with `git push` and 3 with `--force`, never below `sh -c` of the same command; data templates are proved not to run and keep their grade; readers, `_printf`, pipe linking and a CPU-time bound on 200 KB programs are covered. Against a `git archive` of `origin/main` 8 of its 14 tests fail.
