# AH-B092 — A release pull request cannot pass the changelog rule without leaving a waiver behind

## Reproduction

1. Past the 0.13.0 cut-over, branch off `main` and run `python3 scripts/release_notes.py --changelog <version>`, then edit the status prose under `docs/`.
2. Commit and run `bin/harness lint`.
3. Observed: `changelog: this branch changes docs/... but adds no fragment`. The 0.13.1 release answered it with `changelog.d/769.none.md`, which stayed on `main` after the release.

## Root cause

`findings` in `lib/harness_core/changelog.py` accepts only a newly added fragment, or, before the cut-over, an edit to `## [Unreleased]`. A release branch deletes every fragment and adds a version section, so it matches neither and must add a waiver the assembly has already run past. [Source: lib/harness_core/changelog.py#findings]

## Acceptance criteria

1. **Given** a base past the cut-over carrying fragments, **when** a branch runs the assembly and edits `docs/`, **then** the lint reports no changelog finding and adds no waiver.
2. **Given** the same assembly left uncommitted, **when** the lint runs, **then** it passes the same way.
3. **Given** a branch that adds a version section by hand without deleting fragments, or deletes fragments without adding a version section, **when** it touches a governed root, **then** the fragment finding stands.
4. **Given** the release merged, **when** a later branch touches a governed root without a fragment, **then** the finding returns.

## Design

`assembles_release(root, fork)` returns true when the working tree's `CHANGELOG.md` has a `## [<version>]` heading the base's lacks and the branch deletes at least one fragment directly under `changelog.d/`. `findings` returns early on it, after the waiver-length check. Both halves are required so a hand-written section or a dropped fragment alone does not exempt a branch. Rejected: documenting the waiver as a release step with the assembly dropping it, since the assembly runs before the waiver is written and the waiver would still outlive the release. The pre-cut-over Unreleased exemption is unchanged. `changelog.d/769.none.md` stays on `main`; the next assembly consumes it.

## Regression test

`tests/test_changelog_release_branch.py`: `test_a_release_branch_that_assembles_the_fragments_needs_no_waiver` and `test_an_uncommitted_assembly_passes_the_same_way` fail on the previous rule and pass after the fix; the other three pin the rule's limits.
