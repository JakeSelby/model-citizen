# AH-B148 — grade-bash follows cd into the wrong directory for builtin, eval, CDPATH, HOME and physical forms

## Reproduction

Walked from a repository `alpha` with a sibling `beta`, `grader.governed_text` placed each `git push` below in a concrete directory bash is not in (bash behaviour checked with `/bin/bash -c '…; pwd'`, GNU bash 3.2, in a scratch tree): `builtin cd ../beta`, `command cd ../beta`, `eval cd ../beta` and `{cd,../beta}` stayed in `alpha`; `CDPATH=..; cd beta` went to `alpha/beta` where bash goes to `../beta`; `HOME=<beta> cd` and `v=HOM; eval ${v}E=<beta>; cd ~` went to the hook's home; `set -P; cd l/..` went to the logical parent. `builtin cd .agent-harness && echo {} > governance.json` got no policy hit.

## Root cause

`_walk` recognised a directory change only when the first word past assignments was `cd`, `pushd` or `popd`, so a `builtin`, `command`, `time` or `noglob` prefix, `eval`, and a command word bash expands were read as ordinary commands. It resolved a literal operand logically against the working directory with no regard for CDPATH or a physical-path option, and it tracked HOME only through commands naming it, not through `eval` or an assignment prefixed to the `cd` itself. [Source: policy/hooks/grade-bash.py#_walk] [Source: policy/hooks/grade-bash.py#_assignment_contexts]

## Acceptance criteria

1. **Given** `builtin cd D` or `time cd D`, **when** a later push runs, **then** it is governed at `D`.
2. **Given** `command cd D`, `noglob cd D`, `eval cd D`, `{cd,D}` or `c=cd; $c D`, **when** a later push runs, **then** its directory is unknown.
3. **Given** CDPATH set earlier in the line, prefixed to the `cd`, or in the hook's environment, **when** `cd b` runs, **then** the directory is unknown; an absolute, `~` or `./` operand still resolves.
4. **Given** `HOME=X cd`, or HOME assigned through `eval`, **when** a later push runs from `~`, **then** its directory is unknown.
5. **Given** `set -P`, `set -o physical` or `setopt chase_links`, **when** a `cd` operand holds `..`, **then** the directory is unknown.
6. **Given** `builtin cd .agent-harness && echo {} > governance.json`, **when** it is graded, **then** it asks as a level-1 policy write.

## Design

`_command_word` peels assignments and the prefixes that run a builtin in this shell: `builtin` and `time` certainly, `command`, `noglob` and `nocorrect` uncertainly, since zsh's `command cd` runs the external `cd`; `command -v` is not a change. A `cd` behind an uncertain prefix leaves the directory unknown. `_runs_unseen` marks `eval` and a command word bash expands; after one, the directory, HOME and `cd` resolution are all unknown. A new context key, `_CD_UNKNOWN`, set by `_moves_cd_resolution` (CDPATH named, or a physical option set) and by `CDPATH` in the hook's environment, passes into substitutions, `eval` and inner shells like `_HOME_UNKNOWN`; under it only an operand `_cd_certain` accepts (absolute, `~` or `./`, no `..`) resolves. Rejected: re-implementing CDPATH search and physical resolution, which depend on the file system at run time and differ between bash and zsh; separate flags for CDPATH and physical, which would let `../x` resolve under CDPATH at the cost of more state. Must not change: every existing `cd` and `git -C` expectation, and the here-document and pipe grading.

## Regression test

`tests/test_governance_cd_forms.py`: every form in the issue, its bash-verified expectation and the resolving controls. Against a `git archive` of `origin/main` the module fails 9 of its 13 tests.
