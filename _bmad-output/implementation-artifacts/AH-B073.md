## Reproduction

At HEAD ([#689](https://github.com/JakeSelby/agent-harness/issues/689)):

1. Start a round for one target with `scripts/native_acceptance.py --client <id> --out <file>`, which
   appends each finished case to `<file>.partial.jsonl`.
2. Kill it after some cases have finished.
3. Start it again with the same arguments, at the same commit.
4. Observed: `record()` runs every selected case again, whether or not the progress log already holds a
   result for it, and only then rebuilds the record from the log
   [Source: scripts/native_acceptance.py#record].

The one resume the tests exercise narrows the case list by hand: the resumed call passes only the
cases that had not finished (`names=CASES[1:]`)
[Source: tests/test_native_acceptance_progress.py#test_a_resumed_round_unions_its_cases_with_the_surviving_ones].
So today a skip exists only when the operator selects the remaining cases with `--cases`.

## Root cause

FR-52's third consequence says "Each case's evidence is written when the case completes, and a resumed
round skips completed cases"
[Source: _bmad-output/planning-artifacts/prds/prd-agent-harness-2026-09-23/prd.md#FR-52: One qualification round per release].
#339's pull request, #397, delivered writing each case durably and rebuilding a resumed round's record
by unioning its cases, with a rerun superseding the earlier result. It did not add a skip. AH-S129
records this gap between the PRD and the delivered work
[Source: _bmad-output/implementation-artifacts/AH-S129.md].

In the code, `record()` loops over `names` and calls the runner for each, with no lookup in the progress
log. `progress_lines()` reads the log only afterwards, to build the record, keeping lines whose header
matches on `kind`, `client`, `harness_version`, `runtime_version`, `client_version`, `platform`,
`source_commit` and `tier_routing` [Source: scripts/native_acceptance.py].

## Acceptance criteria

Criteria 1 and 2 are the issue's Acceptance section; criterion 3 is from its Scope
([#689](https://github.com/JakeSelby/agent-harness/issues/689)):

1. **Given** a progress log holding passing results for some cases of the same candidate commit,
   **when** the round resumes, **then** it does not rerun those cases.
2. **Given** a progress log whose passing results belong to a different commit, **when** the round
   resumes, **then** no case is skipped because of them, and a test pins this.
3. **Given** a case that is run again, **when** the record is built, **then** today's union and
   supersede rules still apply.

## Design

The issue's scope: when a round resumes, skip every case whose passing result is already recorded
for the same candidate commit; decide whether a failed case reruns on resume; and keep today's union
and supersede rules for cases that are run again.

**Approach.** Before the loop in `record()`, read `progress_lines(progress, header)`, which already
filters to lines with the same header, and drop from `names` every case whose recorded result is `passed`.
[ASSUMPTION: reusing the header match is the natural implementation; the issue does not name one.]

**What "the same candidate" means.** The skip is keyed to the candidate commit. The progress header
identifies a candidate by `source_commit`, together with the client version and the tier routing, and
carries no archive digest; `compatibility/freeze.json` likewise holds a branch and a commit
[Source: scripts/native_acceptance.py#HEADER_KEYS] [Source: compatibility/freeze.json].

**Decided: a failed case keeps its verdict and is not rerun on resume.** The skip covers every case
whose latest line under the header is a verdict, `passed` or `failed`, so the failure evidence stays
intact; an `unverified` case observed nothing and runs again, superseding its earlier line. No opt-in
rerun was added, since the acceptance criteria do not ask for one: an operator retrying a failed
case at the same commit gives the round a fresh `--progress` log. The existing
`test_a_rerun_case_supersedes_its_earlier_result` now reruns an unverified case rather than a failed
one, which keeps AC 3 pinned without contradicting the skip.

**Do not change:** the evidence schema's union, the rule that the latest line for a case wins, or the
rejection of a linked `failed` or `unverified` result
[Source: _bmad-output/implementation-artifacts/AH-S129.md].

## Regression test

Written in `tests/test_native_acceptance_resume.py`:
- kill a round after one passing case, resume it with all cases selected, and assert the runner is not
  called for the passed case;
- write passing progress lines at another commit, resume, and assert every case runs.

## Dev agent record

- **Default taken:** a resumed round keeps a failed verdict and does not rerun it, so failure
  evidence stays intact; no opt-in rerun, since the acceptance criteria do not ask for one.
- **Default taken:** an `unverified` case reruns on resume, since it observed nothing, and its new
  result replaces the old line as the case's latest.
- `settled()` in `scripts/native_acceptance.py` maps each case whose latest line is `passed` or
  `failed` to that verdict; `record()` reads it from `progress_lines(progress, header)` before its
  loop, skips those cases and names each skip on stderr. `unverified` cases run again.
- The header match is the existing one, so the skip is keyed to the source commit together with the
  client version, platform, routing and model run.
- The supersede test in `tests/test_native_acceptance_progress.py` now reruns an unverified case.
