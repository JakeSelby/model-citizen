# AH-B141 — Studio draft discard intermittently exits 1 with no message in browser cleanup

## Reproduction

1. Run the full suite, which imports `tests/isolation.py` and so sets `HARNESS_QUIET=1` in every child environment.
2. `test_studio_configure_browser.ConfigureBrowserTests.test_redacted_malformed_reference_has_a_working_clear_action` ends right after its repair save is sent. The cleanup stops the Studio and runs `draft discard` while that save may still hold the draft's writer lock.
3. Discard refuses with `busy` and exits 1. Under `HARNESS_QUIET` the CLI printed the refusal through `say`, which prints nothing, so both streams were empty. Run alone, without the isolation module, the busy JSON was visible, the helper retried, and the test passed.

`tests/test_draft_refusal_reason.py` reproduces the silent exit on the base commit: exit 1 with empty stdout and stderr while the writer lock is held.

## Root cause

- **Product.** `cmd_draft` in `bin/harness` reported every `DraftError` only through `say`, which returns without printing when `HARNESS_QUIET` is set. A refused draft command under a quiet shell exited 1 with no reason anywhere.
- **Test.** `tests/draft_support.discard_draft` retries while stdout contains the `busy` code. At the commits named in the issue it passed the quiet environment through, so it never saw `busy` and failed on the first refusal. Commit e22cf22c4 has since stripped `HARNESS_QUIET` in that helper. The test still ended before its save answered, leaving the race for the retry to absorb.

## Acceptance criteria

1. **Given** `HARNESS_QUIET=1` and a draft whose writer lock is held, **when** `draft discard --json` runs, **then** it exits 1 and stderr names the `busy` code.
2. **Given** any refused draft command in text mode, **when** it exits 1, **then** stderr carries `draft <action>: <code>: <message>`.
3. **Given** JSON mode without quiet, **when** a draft command is refused, **then** the error object stays on stdout unchanged.
4. **Given** the clear-action browser test, **when** it ends, **then** its repair save has answered, so cleanup does not race the save's writer lock.

## Design

- Every draft refusal writes one line to stderr, `draft <action>: <code>: <message>`, regardless of `HARNESS_QUIET`. JSON mode still prints its error object to stdout through `say`. Text mode now writes its reason only to stderr, where an error belongs, so a terminal does not show it twice.
- The browser test counts answered saves and waits until every save it sent has answered before it ends.
- **Rejected.** Making `say` ignore quiet for errors, because that changes every command; widening the retry, because the cleanup was already correct once it could see `busy`.
- **Unchanged.** Exit codes, the JSON error shape, and discard's refusal while a writer holds the lock.

## Regression test

`tests/test_draft_refusal_reason.py`: a busy discard under quiet names `busy` on stderr and then succeeds once the lock is released; a text-mode refusal says why on stderr; JSON mode keeps its error object on stdout. All three fail on the base commit.
