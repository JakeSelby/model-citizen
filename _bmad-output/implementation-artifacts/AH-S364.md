## Story

As a developer in a long session, I want the harness to save the task state just before the context resets and to keep a fallback snapshot of it, so that the reset loses nothing and I am never told to start a fresh session.

## Context and value

Today the `usage-feed` Stop block tells the user to write a handoff and start a fresh session. With the reset automatic (AH-S363), the block's job becomes saving state before the reset, and a PreCompact snapshot covers anything the agent's own save missed.

## Acceptance criteria

1. **Given** context at 90% of the reset point, **when** the turn ends, **then** the block reads: "context N tokens; it resets automatically at M. Before this turn ends, save the task store (`harness task save`) and progress.md: state, next step, open decisions. Then carry on." and contains no instruction to start a session.
2. The once-only release logic is unchanged: `handed_off`, re-armed when context drops, which it now does after every reset.
3. **Given** an auto compaction, **when** PreCompact fires with `trigger: auto`, **then** `.agent-harness/handoffs/auto-<session>-<ts>.md` holds the last five user prompts, the git branch and status summary, open todo items from the transcript and the task-store revision; the hook calls no model and never blocks.
4. `harness task save` records the saving `session_id` in `task.json`.
5. The adherence event `fresh-session-handoff` is renamed `context-reset-handoff`, counted as followed when the task store was saved between the block and the reset; ledger readers keep folding the old name.
6. `tests/test_session_handoff.py` updated and new `tests/test_context_reset.py` green.

## Design

### Approach

- Rewrite `handoff_reason()` in `policy/hooks/usage-feed.py` and move the block to `session_handoff_at`.
- New `policy/hooks/pre-compact.py`, registered in `lib/harness_core/lifecycle.py` for Claude Code only.
- `lib/harness_core/tasks.py` records `session_id` on save.
- Rename the event in `policy/hooks/adherence.py`, keeping the old name folded.

### Decisions and alternatives

- **The snapshot never blocks:** a block runs the context toward the window limit. Rejected: blocking compaction until the save lands.
- **Deterministic snapshot.** Rejected: a model-written summary, which costs a call at the worst moment.

### Do not implement

- Shaping the compaction summary; PreCompact cannot supply it.
- The reseed (AH-S365).
