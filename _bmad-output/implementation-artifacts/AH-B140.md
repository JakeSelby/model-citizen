## Reproduction

On an Apple M5 Pro (5 + 10 cores) with load average 7 to 12 from a parallel suite:

1. `python3 -m unittest test_studio_live_updates` from `tests/`. The overflow test measured 0.33 to 0.36 s of CPU for five polls against its 0.25 s limit; the same work measured 0.20 s at load 5.
2. `STUDIO_E2E=1 python3 -m unittest test_e2e_studio_budgets.LiveBudgetTests.test_library_api_p95_over_five_hundred_modules_is_within_budget` from `tests/`. It measured a p95 of 103.1 ms (median 78.0 ms) against 100 ms at load 7.9, and passed alone on a quieter machine.

## Root cause

Two things, one in the measurement and one in the product.

- CPU time per unit of work is not constant under load. User and system time rose together by about 1.7x at load 9: a contended thread runs on a slower core or a lower clock, so the same scan costs more CPU seconds. `time.process_time()` also counts every other thread in the test process.
- Both budgets had little headroom because the product did avoidable work. The watch scanner built two or three `pathlib.Path` objects for every directory entry on every poll. That round trip was about half of the 4,097-path poll's user time, and the poll used 80% of its 5% budget on an idle machine. The library inventory opened each module file three or four times per request (source text, rendered text, context cost) and parsed the root's `manifests.json` once per module. That was 71 ms of CPU for 593 modules against a 100 ms latency budget.

## Acceptance criteria

1. **Given** 4,097 watched paths and an idle tree, **when** five polls run at load average above 10, **then** the 5% of one core budget passes unchanged.
2. **Given** a regression that adds work to every poll, **when** the CPU budget is measured, **then** it still fails.
3. **Given** 500 fixture modules, **when** `/api/library` is served 120 times under load, **then** its p95 fits the unchanged 100 ms budget.
4. **Given** any library, **when** the inventory is built, **then** each module file and each root's `manifests.json` is read once, and the payload equals the one built before the change.

## Design

- **Measurement.** `least_cpu_seconds` in `tests/test_studio_live_updates.py` takes the least of five runs of this thread's CPU time (`time.thread_time`). Load only adds CPU time to the same work, so the least run is the closest reading of the scanner's own cost. A real regression adds work to every run, the least one included, so the limit still binds. A test proves this by adding 0.1 ms per fingerprint and checking that the budget fails. The 500-module scan budget uses the same helper.
- **Scanner.** Directory entries reach `_add` as absolute strings and skip the pathlib round trip. Sorted topic tuples are memoised. `_fingerprint` builds a `Path` only for a symlink. The snapshot keys and values are unchanged; a script compared the base and the new scan of the repository and a fixture library and found them equal.
- **Library inventory.** Each `inventory()` call keeps a memo of the text it has read and of each root's parsed `manifests.json`. Each module gets its own deep copy of its manifest entry. A failed read raises and is not remembered. The payload is equal to the base commit's apart from `generated_ms`.
- **Rejected.** Raising either limit, scaling it by load average, or adding retries: each would hide a real regression as easily as load. Raising the thread's QoS class was tried and made no difference.
- **Unchanged.** Every budget value in `scripts/studio_budgets.py` and both test limits. The 20-stream test still uses process time over wall time, because the server's threads do that work.

## Regression test

- `tests/test_studio_live_updates.py`: the overflow and 500-module budgets measured by `least_cpu_seconds`; `test_a_regression_that_adds_work_to_every_poll_still_fails_the_budget`; `test_least_cpu_seconds_judges_the_least_run_of_this_thread`; `test_nested_modules_record_each_file_and_its_parent_once`.
- `tests/test_studio_module_library_reads.py`: each module file and manifests file is read once (this fails on the base commit with `3 != 1`); shared manifest entries are separate copies; an unreadable module stays empty; the helpers still work without a memo.
