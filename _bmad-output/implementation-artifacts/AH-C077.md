## Goal

Make the repository's `## Gate` block in `AGENTS.md` run the BMad checks CI's `test` job runs, so a
green local gate means a green `test` job. Filling a story skeleton changes its derived status, so
`sprint-status.yaml` goes stale, and until now only CI caught it; that happened on #786.
[Source: https://github.com/JakeSelby/model-citizen/issues/820]

Decided by the owner on 2026-09-26: build the issue as filed, adding the audit and the
sprint-status check to the Gate block, with the commands taken from `.github/workflows/ci.yml`.

## Acceptance criteria

1. **Given** the `## Gate` block, **when** the `stop-gate` hook parses it, **then** its commands
   include `python3 scripts/bmad_issue_sync.py audit` and
   `python3 scripts/bmad_issue_sync.py sprint-status --check`, both before the unit tests.
2. **Given** CI's `test` job, **when** its audit step is read, **then** it is the same command the
   Gate block runs.
3. **Given** a stale `sprint-status.yaml`, **when** the gate runs, **then** it fails.
4. **Given** the change, **when** the gate runs, **then** lint is clean, the audit reports 0
   findings and the suite passes.

## Dev notes

- **Commands:** CI's `test` job runs `python3 scripts/bmad_issue_sync.py audit`, which already
  includes the sprint-status drift finding; `sprint-status --check` runs first so a stale file
  fails with its own message. [Source: .github/workflows/ci.yml#test],
  [Source: scripts/bmad_issue_sync.py#audit_manifest]
- **Hook parsing:** `gate_commands` in `claude/hooks/stop-gate.py` takes each non-comment line of
  the first fence under `## Gate` and runs them under `bash -e -o pipefail`; two more lines need
  no parser change. Both commands take under a second, well inside the hook's 240-second budget.
- **Not added:** the `test` job's cost figure check, 3.9 floor parse and sync dry run. The dry run
  overwrites the real config outside a temporary home, and the floor needs a 3.9 interpreter; both
  stay CI-only, as the issue scoped only the BMad checks.
- **Testing:** `tests/test_agents_gate_block.py` loads the hook, parses this repository's block
  and checks the commands, their order, CI's audit line and each subcommand's `--help`.
