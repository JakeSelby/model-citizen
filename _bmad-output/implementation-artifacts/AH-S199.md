## Story

As a developer using the harness, I want to switch individual rules, skills, workflows and roles off
and have sync project exactly what I selected, so that a unit I do not want is absent from every
runtime rather than merely ignored.

## Context and value

Epic #552 turns every installed unit into a switch [Source: #552]. Sync today links the harness rules into the Claude
home as one directory symlink (`rules/harness` pointing at `claude/rules` in `bin/harness`), so a single
rule cannot be withheld. This story replaces that link with per-file links and makes sync and the Codex
projections honour `off`. The PRD's FR-15 states the outcome: a disabled primitive is absent from every
projection.
[Source: https://github.com/JakeSelby/agent-harness/issues/556]

## Acceptance criteria

1. **Given** `harness config set rules.decisions-and-plans off`, **when** `harness sync` runs, **then**
   no link for that rule remains and `harness diff` is clean; setting it back restores the link.
2. **Given** an existing directory symlink, **when** sync migrates it to per-file links, **then** both
   states are in the ownership journal and `harness uninstall` restores the prior state.
3. **Given** an `off` skill, workflow or role, **when** sync runs, **then** the skill has no link under
   either skills home, the workflow has no command projection and no generated Codex skill, and the
   role has no agent file in either home.
4. **Given** a role that a cost row moves and that is `off`, **when** sync and routing run, **then** it
   is neither rendered nor linked, and the routing hook does not route to it.
5. **Given** any selection, **when** lint runs, **then** the lint cap figure is unchanged, while
   `harness selection` reports the effective always-loaded line count.
6. **Given** the change, **when** the suite runs, **then** `tests/test_harness.py` covers per-file links,
   retirement, migration, uninstall and `diff`.

## Design

### Approach

- `rules`, `skills`, `workflows` and `roles` are switch kinds; sync reads the resolved selection.
- The harness rules directory in the Claude home becomes a real directory of per-file links; an `off`
  unit is not linked or rendered, and a stale link is retired.
- Codex projections skip the same units.

### Decisions and alternatives

- **The lint cap counts the distribution's worst case**, not the selection in force; the effective
  count is reported by `harness selection` for information.
- **Migration is journaled both ways**, so uninstall can restore the directory symlink.

### Do not implement

- Hooks as a switch kind (#555) and the selection document (#554).
- Trimming a layered library's own skills; FR-16 puts that out of scope.

### Completion notes

- `~/.claude/rules/harness/` is a real directory of one link per rule. `migrate_rules_link` turns
  the directory link an earlier release made there into that directory: the harness's own link
  (to this checkout, to what the manifest recorded, or dangling) is journaled under `migrated` in
  the link manifest with its prior (`symlink` and target) and applied (`directory`) states, and its
  `links` entry is dropped in the same write. A link the user made there is reported, or moved
  aside with `--adopt`.
- Uninstall removes the per-rule links, then the directory once empty, before adopted files come
  back. Restoring the prior state means the state before the harness: the directory link was the
  harness's own, so uninstall does not recreate it, and a user's link moved aside by `--adopt`
  returns. This reads the story's "uninstall can restore the directory symlink" as that; confirm
  or override on the PR.
- Sync reads the user's layers with `load_selection` (session layers stay in the session, as for
  stances). An `off` rule is not linked and not rendered into the Codex `AGENTS.md`; an `off` skill
  has no link in either skills home; an `off` workflow has no command link and no generated
  `harness-<name>` Codex skill; an `off` role is neither rendered nor linked in either home. A
  projection an earlier sync made retires; a redirected link is preserved and reported. A root in
  `primitive_roots` has its `off` rules and skills withheld the same way.
- `harness diff` compares the switched-off units with the ones recorded at the last sync
  (`manifest.config.off`), so a switch set but not synced is `pending sync`, and a synced one is
  clean.
- `harness config set <rules|skills|workflows|roles>.<unit> on|off` writes a switch, refusing a
  value other than `on` or `off` and a unit nothing installs.
- `tier-agent-spawns.py` does not route an unnamed spawn to a band worker the selection in force
  switches off, even while the definition an earlier sync wrote is on disk; the spawn falls to the
  one-rung rule and says why. `brief-guard` prices through the same function.
- An isolated worker run (`workers.resolution`) refuses an `off` role and leaves the launching
  session's `off` rules and skills out of its instructions and read roots, which review of #554
  deferred here.
- `harness selection` prints the always-loaded line count for the selection in force beside the
  lint's worst-case figure; the lint cap and its figure are unchanged. The JSON output is
  unchanged so it still reads back as a session file.
