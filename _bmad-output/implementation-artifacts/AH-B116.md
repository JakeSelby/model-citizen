# AH-B116 — git -C with ~ or a variable resolves a push to an unknown repository

## Reproduction

The governance check on `git push` resolves the repository from `git -C <path>`, but only from a literal absolute path. With `~` or a shell variable, the repository resolves to `repo:unknown/local`, the push gets the default level for an unknown repository, and a session that cannot prompt refuses it. The same push with the literal absolute path resolves the repository and runs.

Reproduction, in a checkout whose repository has its own push level:

```sh
git -C ~/worktrees/<repo>/<branch> push origin <branch>
W=<absolute path of that worktree>; git -C $W push origin <branch>
```

Expected: both resolve to the checkout's repository. Observed: both report `coding.git_push on repo:unknown/local is level 2`.

## Root cause

`_static_dir` already expands the current user's `~`, so the tilde case no longer reproduces on
the current base and needed a regression to keep it working. The command walk discards leading
assignment tokens before governance classification, however, and retained no static environment
for a later segment. An exact `$VAR` used by `git -C` therefore remained dynamic and forced the
counterparty to `repo:unknown/local`.

## Acceptance criteria

1. Given `git -C` with a path starting `~/`, then the check expands it against the home directory before resolving the repository.
2. Given a variable assigned earlier in the same command line, then the check resolves `git -C $VAR` from that assignment.
3. Given a path it still cannot resolve, then the refusal names that path and says to pass it literally, instead of reporting an unknown repository.

## Design

Track literal, assignment-only segments across a straight semicolon-separated command line and
resolve an exact `$VAR` or `${VAR}` operand from that static map. Reject values containing runtime
expansions, glob characters, whitespace or a leading tilde, reject variable references that are
single-quoted or escaped in the source, and disable the map for conditionals, pipelines, subshells
and background jobs. This is a lexical model only: it never invokes a shell or evaluates text.
Keep the four-element `governed_text` result stable and collect unresolved `git -C` diagnostics
beside it, one per push, from the same walk.

## Regression test

`Counterparty` proves `~/beta`, `$WORKTREE`, `"$WORKTREE"` and `${WORKTREE}` resolve to the other
repository. `UnknownDirectory` proves missing, computed, globbed, whitespace-bearing,
single-quoted, escaped, tilde-valued, same-simple-command, conditional and subshell-scoped
assignments remain unknown, and verifies the refusal names the unresolved operand and asks for a
literal repository path.

## Dev notes

The resolver accepts only data already visible in the command string. Assignment values cannot
refer to other variables, substitutions or globs. A normal command between an assignment and
`git` clears the static map rather than assuming that command preserves shell state. [Source:

## Review findings

Parent review identified six fail-open edges in the first lexical model. Source-aware resolution
now rejects quoted or concatenated pseudo-expansions, changed `HOME`, embedded tilde and arithmetic
assignment contexts, assignments whose redirect can fail, and assignment flow across intervening,
pipeline or background commands. Transparent shell diagnostics follow their inner push, while an
unresolved operand on an earlier non-push command is no longer attached to a later push.

The second security pass found split option spelling, quoted option provenance, shell-special
assignment semantics, and nested-command diagnostic ordering. Continuations now follow shell
tokenization, quoted `-C` retains the following operand's provenance, shell-special assignments
disable static state, and diagnostics recurse through `eval` and substitutions in execution order.

The final bounded pass found that continuation normalization ignored single-quote semantics,
`OPTIND` arithmetic was treated as inert text, and diagnostic walking stopped at `sudo` and task
runners. A first correction that tracked only single and double quotes opened a worse hole: an
apostrophe in a comment switched it into single-quote state and hid a later `-\<newline>C`.
Continuations are now removed by a lexer that follows unquoted, single-quoted, double-quoted,
ANSI-C, comment, `${…}`, `$(…)` and backtick states, nested, each rule checked with `bash -c`.
Where bash versions disagree (a comment or `case` inside a substitution, quotes inside `${…}`) or
a construct is left open, the line is read both ways, graded at the worse reading and never 0,
and every directory it governs is unknown; when neither reading decomposes, a line naming `git`
and `push` is governed as a grade-2 push to `repo:unknown/local`. `OPTIND` and `OPTARG` disable
static assignments, and the `getopts` NAME is set by a command, which already ends them.
Diagnostics are no longer a second walk: `_governed` records each push's unresolved `-C` operand
as it looks through `sudo`, `env`, runners, shells, `eval` and substitutions, so each operand is
named once, in execution order, beside its own push, and `govern` pairs one per push entry.
