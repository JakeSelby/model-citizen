# AH-B150 — grade-bash misses directory changes from sourced scripts, traps and a redefined cd, and crashes on long prefix chains

## Reproduction

Walked from a repository `alpha` with a sibling `beta`, `grader.governed_text` placed each push below in a concrete directory bash is not in (bash behaviour checked with `/bin/bash -c '…; pwd'`, GNU bash 3.2, in a scratch tree with a script `s.sh` that runs `cd b`): `. ./s.sh; git push` and `source s.sh && git push` stayed at the start where bash is in `b`; `trap 'cd x' DEBUG; git push` stayed where bash runs in `x`; `shopt -s cdable_vars; cd name` went to `./name` where bash goes to `$name`; `enable -n cd; cd D`, `cd() { :; }; cd D` and `shopt -s expand_aliases; alias cd=:` then `cd D` went to `D` where bash stays put. `trap 'cd .agent-harness' DEBUG; echo {} > governance.json` got no policy hit. A thousand `time` words before a forced push raised `RecursionError` in `allow-readonly-bash.segment_ok` and in `grade-bash.grade_tokens`, and the hook emitted nothing.

## Root cause

`_walk` changed the directory only at a `cd`, `pushd` or `popd` it could read, and after `eval` or an expanded command word; a sourced script, a trap's text and a function body run where the walk does not look, and it took every `cd` to be the builtin. `_moves_cd_resolution` knew CDPATH and the physical options but not `cdable_vars`. `segment_ok` and `grade_tokens` looked through a prefix by recursion, one frame per word, and the hook's `__main__` swallows any exception, so a recursion error fails open. [Source: policy/hooks/grade-bash.py#_walk] [Source: policy/hooks/allow-readonly-bash.py#segment_ok]

## Acceptance criteria

1. **Given** `. ./s.sh` or `source s.sh`, **when** a later push runs, **then** its directory is unknown, even after a later literal `cd`, because the sourced script may redefine `cd`.
2. **Given** `trap '…' DEBUG`, `ERR`, `RETURN` or any signal but EXIT, **when** a later push runs, even after a `cd`, **then** its directory is unknown; an EXIT trap, `trap -p` or a reset keeps the `cd`.
3. **Given** `shopt -s cdable_vars` or `setopt cdablevars`, **when** `cd name` runs, **then** the directory is unknown; an absolute operand still resolves.
4. **Given** `enable -n cd`, an alias, or a function defined on the line, `cd` included, **when** a later push runs, **then** its directory is unknown, in substitutions and inner shells too.
5. **Given** any of the above before a write to `governance.json`, **when** it is graded, **then** it asks as a level-1 policy write.
6. **Given** a thousand `time`, `nice`, `command`, `env`, `nohup`, `noglob` or `exec` words before a forced push, **when** it is graded, **then** it grades 3 without an exception, inside a tenth of the hook timeout.
7. **Given** a parser exception, **when** either hook reads the command, **then** grade-bash grades it 3, governs a push at an unknown directory, and allow-readonly-bash allows nothing.

## Design

`_sources` names `.` and `source`: after one the directory is unknown until the next `cd`, like `_runs_unseen`, but HOME and `cd` resolution stay known, so `source .venv/bin/activate && cd /abs && git push` resolves. `_resets_cd` names a trap with text on any signal but EXIT, `enable` with a name and `alias` with a value; from one on, a new flag `untrusted` follows no `cd`. `_defines_function` finds a function definition at a command position in `_unquoted_structure`; such a line starts untrusted, since the segmenter walks a body as if it ran at once and `cd` may itself be redefined. The flag reaches substitutions and inner shells through `cd_untrusted` and the `_CD_UNTRUSTED` context key. `CDABLE_OPTION_RE` joins `_moves_cd_resolution`, which now reads `shopt` and an option named by an expansion. `segment_ok` and `grade_tokens` loop over prefixes, bounded by `MAX_PREFIXES` (64): past it `segment_ok` is False and `grade_tokens` returns `PREFIX_CHAIN`, grade 3; redirects and substitutions are checked once, keeping the cost linear. `grade_text` returns `UNREADABLE`, grade 3, when its reading raises at depth 0; `govern` places a walk that raises at an unknown directory; allow-readonly-bash's `main` allows nothing when `command_ok` raises. Rejected: tracking function names and calls, which the segmenter's flattening of bodies makes unsound; a sticky unknown after `source`, which would stop the common virtualenv form resolving. Must not change: every existing `cd`, `git -C` and read-only expectation.

## Regression test

`tests/test_governance_cd_unseen.py`: each form in the issue with its bash-verified expectation and resolving controls, the thousand-word chains, the CPU bound, and the exception paths. Against a `git archive` of `origin/main` the module fails 14 of its 15 tests (25 failures and 12 errors across subtests).

## Dev notes

Runtime changes in `policy/hooks/grade-bash.py` and `policy/hooks/allow-readonly-bash.py`. A relative `cd` after a sourced script is unknown by necessity, since the script may have moved. Any function definition on a line, not only one named `cd`, leaves every `cd` on it unknown. Not changed here: a sourced script or `eval` that redefines `cd` before a later literal `cd`, an exported function reaching a child shell on a later line, and `BASH_ENV` or `ENV` prefixed to an inner shell. [Source: policy/hooks/grade-bash.py#_resets_cd] [Source: tests/test_governance_cd_forms.py]
