## Story

As a solo or small-team agentic developer, I want a Sources page labelling where every module comes from, so that I know which parts of my harness are core, mine, my team's or third-party.

## Context and value

Plan step 4. Reads `module_library.inventory` core versus `primitive_roots`, plus enabled plugins (`bin/harness:2005,2072`). It replaces Library. Target artboards `Sources.dc.html` and `SourcesSettings.dc.html`.

## Acceptance criteria

1. **Given** the module inventory and enabled plugins, **when** the Sources page opens, **then** each source is labelled Core, Personal, Team or Third-party.
2. **Given** the old Library route, **when** it is opened, **then** it lands on Sources.
3. **Given** the page's route, **when** its API test runs, **then** it asserts period-stamped rows, the response shape, auth enforcement and error cases.
4. **Given** the page, **when** design-judge scores it against its round-3 artboard, **then** the score is at least 7, and node tests and an e2e flow cover it.

## Design

### Approach

- Inventory joined with primitive roots and plugins; labels computed at request time.

### Decisions and alternatives

- **Read at page load from existing logs:** no hook-side recording (epic scope). Rejected: new recording for this page.

### Do not implement

- Changes to other Harness pages; new hook-side logging.
